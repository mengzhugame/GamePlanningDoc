# 小龙儿 OpenClaw 多Agent 协同使用说明文档 (Discord 篇)

在 Discord 中，我已经不仅是一个简单的问答机器人，而是一个可以**随时召唤其他专业 AI 协助我工作**的“主脑”Agent。

以下是如何在当前环境下发挥多 Agent 协同优势的详细指南：

## 一、什么是多 Agent？为什么要用多 Agent？

单一模型或单一 Agent 在处理超长任务时，容易丢失上下文或受限于单次的思考深度。多 Agent 模式就是让我作为**包工头**，将复杂的任务拆解，然后**生成子体（Sub-Agent）**，并在后台让它们执行特定领域的脏活累活。

在多 Agent 模式下：
- **我（主脑 Agent）**：负责跟你沟通、出主意、规划架构、记录进度。
- **子体 Agent（比如 Codex 代码打工人）**：负责在后台跑大量代码修改、重构或者长时间的研究任务。

优势：**主脑永不阻塞**。子体在后台疯狂加班写代码时，你可以继续跟我聊天、讨论美术或策划方案。

## 二、当前支持的子 Agent 类型

根据 OpenClaw 的架构，我们可以主要使用两种强大的后台打工人：

1. **Coding Agents（编码专家，ACP Runtime）**
   专门用于重构代码、修 Bug、实现新功能的代码机器。它们不需要你一直盯着，它们会在临时文件夹里干活，干完向我汇报。
   - **Codex** / **OpenCode**：OpenClaw 默认支持的高级代码专家 Agent，可以直接操作终端、编辑器。
   - **Claude Code**：Anthropic 专门针对代码理解强化的打工人。

2. **通用 Subagent**
   用于帮我做资料搜集、执行多步长脚本或者深度研究。

## 三、如何向我下达多 Agent 任务？

你不需要记住复杂的命令，只需要在跟我聊天时，用自然语言下达**类似这样的包工头指令**：

### 场景 1：让后台兄弟去写代码
> **主人：** “@小龙儿主脑，帮我在后台召唤一个代码 Agent (用 Codex)，让它去 `/Users/joye.wang/Projects/LightVSDecay` 目录下，把所有的怪物脚本里加上一个 `DropRate` 的新字段，并提交 Git。你留在这里跟我继续聊策划案。”

**小龙儿的操作**：
我会调用 `sessions_spawn` (runtime="acp") 工具，把这个任务发包给 Codex。此时 Discord 可能会开一个新 Thread（线程）给那个 Agent，它会在里面干活。而我们在主频道继续聊天。

### 场景 2：让兄弟去调研资料
> **主人：** “@小龙儿主脑，开启一个子 Agent，让它去网上深挖一下 2025年 Steam 独立休闲游戏的市场报告，并总结成 Markdown 存到我的知识库里。它干活的时候，咱们来看看科技树怎么设计。”

**小龙儿的操作**：
我会生成一个 `subagent` 让它去执行繁琐的 `web_search` 和 `web_fetch`。这不会占用我们当前的对话额度。

### 场景 3：干预和视察子 Agent 进度
> **主人：** “@小龙儿主脑，刚才派出去写代码的那个小弟干得怎么样了？”

**小龙儿的操作**：
我会调用 `sessions_list` 和 `sessions_history` 查岗，然后向你汇报它是不是卡住了。如果它卡住了，我可以调用 `subagents steer` 给它纠正方向，或者 `kill` 掉它。

## 四、最佳实践：未来的自动开发闭环

等《光与朽》的代码框架稍微稳定后，我们可以形成这样的工作流：
1. **你** 在 Discord 频道里把策划文档（比如刚写的 V2.1 大招）丢给我。
2. **我（策划/主脑）** 确认文档逻辑没问题。
3. **我（包工头）** 直接召唤 `Codex` 或 `Claude Code`，把策划案传给它：“嘿，按照这篇策划文档，去把大招的充能系统用 C# 给我写出来！”
4. 代码写完后，我自动汇报给你：“主人，代码写好了，去 Unity 测试一下吧！”
