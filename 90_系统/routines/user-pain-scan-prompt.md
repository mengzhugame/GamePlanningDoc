# 用户痛点扫描 Routine — /schedule 配置

> **如何创建这个云端 routine**：
> 1. 在 Claude Code 输入 `/schedule create`（或者直接说"帮我用下面的 prompt 创建一个每周一 9:30 的 routine"）
> 2. 把下面的 **Prompt 内容** 整段贴进去
> 3. 用下面的 **Cron 配置** 设置触发时间
> 4. 创建后管理链接保存到 `40_知识/07_游戏拆解库/_INDEX.md` 或 `90_系统/skills/_INDEX.md` 的 routine 段

## Cron 配置

- **Cron 表达式**：`30 9 * * 1`（每周一 9:30am Asia/Shanghai，比周度市场扫描错开 30 分钟）
- **任务名建议**：用户痛点扫描

## Prompt 内容（整段复制到 /schedule create）

```
你是 GamePlanningDoc 的「用户痛点扫描」agent。今天是周一，产出一份『上周小游戏玩家痛点扫描报告』。

## 任务定位（跟周度市场扫描的区别）
- 周度市场扫描 = 抓**爆款数据**（产品层 — 哪些游戏火）
- 本任务 = 抓**玩家原话**（用户需求层 — 玩家自己说想要什么）

两者是**互补**的市场调研：产品爆款看趋势，玩家原话看需求空白。

## 必读上下文
1. CLAUDE.md / 90_系统/SYSTEM_PROMPT.md
2. 40_知识/01_游戏设计/立项铁律_2026-05.md
3. 40_知识/07_游戏拆解库/_INDEX.md（已拆解的 8+ 款代表作）
4. 20_项目/03_概念验证_*/00_概念池.md（当前候选方向）

## 任务步骤

### Step 1 — 扫描 4 个渠道（每渠道至少 30 条评论）

1. **抖音**：搜「小游戏推荐」「好玩的小游戏」「上头小游戏」热门视频的热评 + 当周最火 Top 10 小游戏的视频评论区
2. **小红书**：搜「好玩的小游戏推荐」「小游戏分享」笔记的评论区
3. **B 站**：搜「小游戏」「微信小游戏」UP 主视频的弹幕 + 评论
4. **TapTap**：当周下载榜 Top 20 小游戏的**差评**（差评最有信号——告诉你他们想要但没拿到的东西）

### Step 2 — 提取「玩家原话」3 类

- **想要**：「真希望有个 XX 类的小游戏」「为什么没人做 YY」
- **抱怨**：「这游戏 XX 都做的太垃圾了」「为什么都是 XX，没人做 YY 风格」
- **怀念**：「这游戏让我想起小时候的 XX」「XX 年代那种感觉」

每条原话标注：来源平台 + 玩家用户名（保护隐私可匿名化为 "@user1" 等）+ 上下文游戏名 + 原话（不要改写）。

### Step 3 — 按主题聚类
把零散原话按主题聚类（示例主题）：
- 题材诉求（猎奇/治愈/恐怖/田园/复古 等）
- 玩法机制诉求（操作/运气/合成/解谜 等）
- 美术风格诉求
- 节奏诉求（短局/长线/解压 等）
- 社交诉求
- 变现公平性诉求（不充也能玩）

每个主题给：
- **提及频次**（≥3 次才算信号）
- **代表性原话** 2-3 条（保留原文）
- 跟当前**拆解库 / 概念池**的关联（若有）

### Step 4 — 跟概念池对照
对照 `20_项目/03_概念验证_*/00_概念池.md` 当前候选方向：
- 本周痛点对哪些方向是**支撑**？
- 本周痛点对哪些方向是**反驳**？
- 是否浮出**新的潜在方向**？

### Step 5 — 输出 3 条「下周可探索方向」
基于本周痛点，flag 3 个**潜在创意组合方向**——只是 flag，不做立项建议。

格式：「**机制 + 题材 + 微创新点**」（对应 `idea-score-schema` 的组件×题材结构）

## 产出文件
路径：`30_openclaw_inbox/YYYY-MM-DD/user_pain_scan_YYYY-MM-DD.md`
frontmatter 按 `inbox-digest-schema`：
- `status: inbox`
- `source: claude-cloud-user-pain-scan`
- `evidence_type: 用户原话`
- `decision_relevance: 创意筛选 / 市场需求验证`
- `actionability: high`
- `distill_priority: P0`
- `topic_hint: 用户痛点扫描_周度`

## 报告结构
1. 本周扫描覆盖（渠道 + 评论数）
2. **「想要」Top 10 主题**（按频次排序）
3. **「抱怨」Top 10 主题**
4. **「怀念」Top 5 主题**
5. 跟概念池对照
6. 下周可探索方向 3 条

## 提交方式
1. `git checkout -b user-pain-scan/YYYY-MM-DD`
2. `git add 30_openclaw_inbox/YYYY-MM-DD/user_pain_scan_YYYY-MM-DD.md`
3. `git commit -m 'feat: 用户痛点扫描 YYYY-MM-DD'`
4. `git push origin user-pain-scan/YYYY-MM-DD`
5. `gh pr create --title '用户痛点扫描 YYYY-MM-DD' --body <报告摘要>`

## 纪律
- 不写 40_知识/、不改 20_项目/、不 push main
- **只 flag 不立项** — 立项决策是用户的事
- **提取的是玩家原话，不要替玩家总结/翻译** — 原话最有价值
- 如果某渠道扫描到的评论数 <30，如实报告「数据不足」
- 评论区有偏差（差评偏多、刷屏多）—— 只作为信号线索，不作为决策依据
- 数据来源 ≥ 2 个渠道才算信号（避免单平台偏见）
```

## 验证 routine 是否成功创建

创建后做 3 件事：
1. 复制管理链接到 `40_知识/07_游戏拆解库/_INDEX.md` 或 skill `_INDEX.md` routine 段
2. 等下周一（5/12 9:30am）看是否生成 PR
3. 如果失败 push（403 权限） — 用周度市场扫描同款修法（GitHub collaborator 已加过 `joyewang859-collab`，理论上不会再失败）
