# AI 工具成本与模型路由策略

## 来源: `10_流水/Openclaw知识库文件/api_cost_optimization.md` · 提取日期 2026-05-26

## 1. 核心判断

AI API 成本优化不能只看“哪个模型最便宜”，而要把任务分层：简单整理、批量分类、代码生成、架构判断、长文蒸馏、关键决策分别需要不同模型。把所有任务都用同一个高价模型，成本会失控；把所有任务都切到免费小模型，又会在关键判断上降智。

源文件里的具体价格、免费额度和模型名称应视为 2026-02-09 的当时快照，后续实际使用前必须查供应商当前文档。

## 2. 成本路由原则

| 任务类型 | 推荐模型层级 | 成本策略 |
| --- | --- | --- |
| 文件分类、表格清洗、摘要初筛 | 免费/低价 7B-14B | 批量跑，失败可重试 |
| 普通问答、轻量脚本、格式转换 | 低价通用模型 | 以速度和稳定为主 |
| 代码生成、bug 定位、技术方案 | 中高能力 coding 模型 | 少量使用，必须有验证命令 |
| 长文蒸馏、战略判断、架构设计 | 高能力模型 | 只在高价值节点使用 |
| 关键商业/法律/财务判断 | 高能力模型 + 人工复核 | 不因省钱牺牲准确性 |

模型路由的目标不是把日成本压到 0，而是让“高价推理”只发生在真的需要它的节点。

## 3. 多 Provider 策略

源文件推荐 SiliconFlow、OpenRouter、Google AI Studio、Groq 等多 Provider 方案。长期可沉淀的不是某个平台，而是分层结构：

- 主力 Provider：承担日常稳定调用。
- 低价 Provider：承担批量分类、摘要和草稿。
- 高能力 Provider：承担复杂代码、架构和关键判断。
- 备用 Provider：应对限额、故障和网络不稳定。

所有 Provider 配置都应通过统一的模型别名管理，例如 `default`、`coding`、`cheap`、`deep_reasoning`，而不是在脚本里硬编码具体模型名。这样供应商换价、模型下线或限额变化时，只改配置不改业务。

## 4. 成本监控清单

| 检查项 | 原因 |
| --- | --- |
| 每日 token / 费用上限 | 防止后台脚本或 Agent 循环烧钱 |
| 按任务记录模型 | 复盘哪些任务其实可降级 |
| 免费模型质量抽检 | 免费不等于可用，要看错误率 |
| 高价模型白名单 | 只允许关键任务调用 |
| 失败重试上限 | 避免同一错误无限重跑 |

## 5. 对个人开发者的使用顺序

1. 先把任务分类，不要急着换模型。
2. 把批量低风险任务迁到低价/免费模型。
3. 对代码和长文保留中高能力模型，但强制验证。
4. 每周看一次费用和失败率，按证据调整路由。
5. 供应商价格或免费额度变动时，重新评估，不把旧报价当永久事实。

省钱的底线是：不能把需要深度判断的任务交给明显不够的模型。真正贵的不是 API 费，而是低质量输出误导了项目决策。
