# 数值迭代方法论（Roguelite 塔防）

> 来源：《光与朽》数值设计实战经验 + 数值专家对话记录。适用于激光/塔防/Roguelite 类游戏。

---

## 核心认知：静态值 vs 成长值

**Roguelite 最常见的数值陷阱：用固定数值对抗乘法成长的怪物体系。**

```
怪物是按倍率成长的（W9 = 1.7×，W11 = 2.0×）
技能如果是固定伤害值 → 必然在后期失效
```

**案例（光与朽聚能透镜爆炸）**：
- ❌ `cachedFocusExplosionDamage = 100f;` → 后期坦克 300HP，爆炸无效
- ✅ 改为 `killDamage × 2.5f`（基于当前激光单次伤害的百分比）

**规则**：怪物血量是乘法成长，玩家伤害也必须是乘法成长。用加法（固定值）对抗乘法，必死无疑。

## 数据采集：BattleLog CSV 系统

**原则**：数值问题不靠猜，靠数据。每次版本调整必须用实战 Log 验证。

### 每波次必采集的字段

```
Wave, Result, Player_Level, Build_Type,
Enemy_Total_Spawned, Enemy_Total_HP,
Player_Total_Damage, Dmg_Overkill,
DPS_Peak, Time_To_Clear,
Damage_Taken, Player_HP_Remaining,
Tank_Absorbed_Ratio
```

### 关键指标解读

| 指标 | 正常范围 | 异常信号 |
|------|---------|---------|
| Dmg_Overkill（溢出伤害） | 10–30% | >50% = 单发伤害太高但频率低（鞭尸） |
| Tank_Absorbed_Ratio | <40% | >70% = 坦克完全堵路，AOE 不足 |
| Time_To_Clear | 模型预期 ±20% | >50% 偏差 = 波次设计问题 |
| 胜率 | 75–85% 是健康区间 | <60% 太难；>90% 太简单 |

### 样本量要求

- 建立/重建数值模型：至少 **15–20 局**
- 单次参数调整验证：至少 **5 局**
- 不足样本量的数据只能作为线索，不能作为决策依据

## 数值模型的有效范围

**光与朽的教训**：V1.0 数值模型基于第一章怪物构成，用在第二章时全部失效。

原因：第二章 W1 是「分裂者×11」而非「史莱姆×20」，等效 HP 和清波节奏完全不同。

**规则**：
- 每个章节/关卡包，单独建立数值基准模型
- 模型文件头部明确标注「基于哪个章节 / 哪批数据」
- 跨章节直接复用模型 = 用错误地图导航

## 炮手出场时机：数据驱动的案例

**问题**：炮手（LavaGunner）在所有波次中一出场即被秒杀，无法完成射击。

**诊断方法**：
1. 用实战 DPS 数据算出坦克存活时长
2. 对比坦克死亡时刻 vs 炮手当前出场时刻
3. 发现炮手每次都出现在「战场清空」真空期

**两种解法（按场景选择）**：

| 方法 | 适用波次 | 原理 |
|------|---------|------|
| **熔浆液掩护法** | W4/W5/W8（爆炸者先出） | 爆炸者死后 4–5s，熔浆液阵形成（HP=60000，阻挡激光），炮手在其后出场 |
| **坦克护送法** | W6/W7/W9（坦克晚出） | 提前坦克出场时机，炮手随坦克出场 2s 后跟进，利用坦克存血期作掩护 |

**调整结果**：炮手从「<1s即死」→「存活 3–10s，完成 1–2 次射击」

**通用规则**：怪物出场时序问题，先用 DPS 数据算清场时刻，再设计出场节奏，不要凭感觉设定 spawnTime。

## 流派平衡：前期可用性 vs 后期强度

**常见错误**：用数值惩罚来平衡"强力技能"，导致前期劝退。

**案例（分裂棱镜 Prism）**：
- ❌ Lv1 倍率 30%（主激光打 100，分裂只有 30，玩家心理负反馈）
- ✅ Lv1 调整为 50%（「选了不亏」是前期最低心理门槛）

**原则**：
- 前期（Lv1–3）必须让玩家「选了这个流派，体验不会变差」
- 高惩罚的前期会导致玩家不选该流派 → 测不出后期真实强度 → 永远无法完成流派平衡

---

## 数值修改优先级

当游戏"感觉难"时，按以下顺序诊断（不要直接改怪物血量）：

```
1. 检查技能是否有「静态值」 → 替换为「基于攻击力的百分比」
2. 检查流派前期是否有「数值惩罚」 → 降低初始惩罚至心理门槛
3. 检查怪物出场时序 → 用数据验证掩护机制是否有效
4. 最后：如果上述都正常，再考虑调整怪物血量
```

直接削弱怪物血量是「治标」，它掩盖了技能成长逻辑的问题，后续版本必然反复。

## Roguelite 数值健康指标速查

| 检查项 | 健康标准 |
|-------|---------|
| 任意技能伤害 | 必须是攻击力的倍数，不能是固定值 |
| 流派初始强度 | Lv1 时体验不应比无技能差（心理底线 50% 倍率） |
| 胜率目标 | 75–85%（休闲游戏）/ 60–70%（硬核） |
| 模型数据量 | 建模前 ≥15 局，单次参数验证 ≥5 局 |
| 模型适用范围 | 明确标注章节/版本，禁止跨章直接复用 |
