# 数值迭代方法论 2026

> 核心更新：光与朽的数值“能玩”，但没有做到“差一点就过、愿意看广告救回来”。下一款游戏的数值目标不是调平，而是设计出可解释失败、可补救广告点和可复盘数据。

## 光与朽的真实教训

| 问题 | 后果 |
| --- | --- |
| 需要手动跑几十局 | 迭代成本高，容易疲劳，样本不足时仍然凭感觉 |
| 数据采集有了，但指标不够贴近商业目标 | 能分析 TTK/DPS，却不一定能判断玩家愿不愿意看广告 |
| 数值“能玩”但不够好 | 玩家没有稳定形成“差一点就过”的心理 |
| 单局偏长 | 失败成本高，广告救助不一定有吸引力 |
| 爽感反馈不足 | 即使数值接近，也不觉得奖励值得 |

## 好数值的目标

小游戏尤其是 IAA 方向，数值不是单纯“公平”，而是让玩家产生四种感受：

| 玩家感受 | 数值设计含义 |
| --- | --- |
| 我知道自己为什么输了 | 失败原因可解释 |
| 我刚才差一点 | 失败发生在 80%-95% 进度附近 |
| 看一次广告能救回来 | 广告奖励能解决当前困境 |
| 我下次可能不用看广告 | 玩家保留掌控感，不觉得被勒索 |

## 阶段版 SOP

### 阶段 A：纸面阶段

先定义失败条件，再填数字。

| 必答问题 | 示例 |
| --- | --- |
| 玩家为什么会输 | 时间到、血量归零、槽位满、Boss 未击杀 |
| 玩家失败时看到什么 | 还差 3 秒、Boss 剩 8% 血、只差 1 格 |
| 广告能补什么 | 加时、复活、撤销、清槽、补伤害、免费刷新 |
| 一局理想时长 | 1-3 分钟 / 3-5 分钟 / 10 分钟 |
| 第一次失败应发生在什么时候 | 第 3 关、第 5 波、第 2 分钟后 |

### 阶段 B：7 天切片阶段

只验证一件事：能不能稳定制造“差一点”。

最小字段：

| 字段 | 作用 |
| --- | --- |
| level_id | 关卡或波次 |
| result | 胜利/失败 |
| fail_reason | 时间到、血量归零、槽位满等 |
| progress_at_fail | 失败时完成度 |
| time_spent | 单局时长 |
| retry_count | 玩家是否愿意再来 |
| ad_offer_shown | 是否出现救助 |
| ad_watched | 是否看广告 |
| result_after_ad | 看广告后是否过关 |

### 阶段 C：Demo 阶段

开始建立可复盘数据模型。

| 数据量 | 用途 |
| --- | --- |
| 自测 10-20 局 | 建立初始难度锚点 |
| 每次参数调整 5 局以上 | 验证方向，不做最终判断 |
| 陌生玩家 20 人以上 | 看失败原因是否和自测一致 |
| 上线真实数据 | 决定是否继续扩张 |

## 调参优先级

当玩家说“太难”时，不要第一反应改血量。

按顺序检查：

1. 教学是否让玩家知道目标。
2. 失败原因是否可见。
3. 操作反馈是否让玩家相信自己有掌控。
4. 广告奖励是否能解决当前失败。
5. 关卡节奏是否过长。
6. 最后才调怪物血量、时间、伤害、价格等基础数值。

## 休闲游戏广告点设计

| 失败类型 | 好广告奖励 | 坏广告奖励 |
| --- | --- | --- |
| 时间差一点 | 加 10 秒、冻结、减速 | 给金币但本局过不了 |
| Boss 血量差一点 | 临时伤害、复活、护盾 | 给随机道具且不解决 Boss |
| 空间差一点 | 多 1 格、撤销、重排 | 给无关资源 |
| 资源差一点 | 补差额、免费刷新 | 给远期成长货币 |
| 操作失误 | 撤销一步、重试当前小段 | 直接重开 |

## Roguelite / 战斗数值保留规则

光与朽里的部分战斗数值经验仍然有效，但只能作为战斗类项目的子规则。

| 规则 | 说明 |
| --- | --- |
| 不用固定伤害对抗乘法成长 | 怪物血量倍率成长时，技能也要跟攻击力或成长值挂钩 |
| 每章节单独建模型 | 不同怪物构成会让旧模型失效 |
| 出场时序用 DPS 数据验证 | 先算清场时刻，再设计炮手/坦克/分裂怪出场 |
| 流派前期不能惩罚过重 | Lv1 体验不能比不选还差 |

## 判断标准

| 现象 | 结论 |
| --- | --- |
| 失败进度常低于 50% | 太难、教学失败或节奏过快 |
| 失败进度在 80%-95%，广告观看率低 | 奖励不够诱人或玩家不相信能救回来 |
| 广告后仍大量失败 | 广告奖励设计错了 |
| 不看广告也轻松过 | 广告点不存在 |
| 玩家连续重试但不看广告 | 失败可接受，但广告价值不足 |

## 核心原则

- 能玩不等于好玩。
- 平衡不等于赚钱。
- 广告不是惩罚玩家，而是在“差一点”时给玩家一次合理补救。
- 下一款游戏从第一天就要记录失败原因和广告后的结果。

## BattleLog 先把指标定义清楚，再谈调参

数值复盘不能只看“过没过”和平均 DPS。尤其是有爆发、反射、连锁、溢出伤害的游戏，指标定义错了会把问题藏起来。

建议最小字段：

| 字段 | 定义 |
| --- | --- |
| Wave | 当前波次 |
| Build | 当前主要流派/关键技能组合 |
| Level | 玩家等级或升级次数 |
| Result | 胜利、失败、超时、Boss 未击杀等 |
| Time | 波次耗时或整局耗时 |
| PeakDPS | 1 秒时间桶内的最高 DPS，不是整波平均 |
| EnemyTotalHP | 本波敌人理论总血量 |
| PlayerTotalDmg | 玩家造成总伤害 |
| TankDmgRatio | 坦克/肉盾吸收伤害占比 |
| MaxExplosionDmg | 单次爆炸或连锁峰值 |

`Overkill` 必须按每次命中计算：`本次伤害 - 命中前剩余血量`，不能用整波总伤害减总血量。否则爆炸、暴击和溢出会把真实击杀效率污染成虚假的超高输出。

## 数值诊断顺序：先定位层级，再改参数

遇到“后期打不动”或“某流派爆炸”时，不要第一反应改怪物血量。更稳的顺序是：

1. 判断问题属于系统失控、单技能过强、成长断层还是关卡节奏。
2. 对比玩家成长曲线和怪物 EHP 曲线是否同阶。
3. 查看 PeakDPS、TankDmgRatio、MaxExplosionDmg 和 Overkill，确定是输出不足、肉盾吃伤、还是连锁崩坏。
4. 只改一层：技能倍率、冷却、怪物构成、经验供给或波次长度。
5. 用同一组日志字段复测，不凭一局手感定结论。

调参的核心不是把数值压平，而是让“爆发可控、失败可解释、广告点可设计”。

## 暴击、攻速和多段伤害要统一折算到 EffectiveDPS

暴击、攻速、多段伤害、命中率和覆盖率如果各算各的，很容易把构筑强度看错。更稳的工作尺是先统一到 EffectiveDPS，再看 TTK、溢伤、稳定性和触发收益。

基础公式：

```text
EffectiveDPS =
每次攻击期望伤害
* 每秒有效攻击次数
* 命中率
* 占空比
* 覆盖率
```

暴击期望增益优先写成：

```text
CritExpectedGain = 1 + CritChance * (CritMultiplier - 1)
```

多段伤害不能只看总倍率，要拆成：

| 维度 | 为什么要拆 |
| --- | --- |
| 总倍率 | 决定理论上限 |
| 段数 | 影响防御减免、命中次数和反馈密度 |
| 每段防御损耗 | 按段减防时，多段可能显著吃亏 |
| 溢伤浪费 | 高频小段更容易把伤害打在已死目标上 |
| 触发收益 | 多段可能更容易触发暴击、特效或 on-hit |

攻速也要区分面板攻速和有效攻速。有效攻速要扣掉转向、停火、换轨、过热、首发延迟、目标丢失等战斗现场损耗。否则高攻速武器会在 Excel 里很强，在实战里反而浪费。

如果暴击或触发率直接跟攻速相乘，容易形成失控乘法。需要时可以改用按秒触发率、PPM 或 proc coefficient，削掉高攻速天然碾压低攻速的一层耦合。

## 塔防数值先对齐击杀时间和敌人行进时间

塔防 / Roguelike 的早期数值锚点，不是先追求所有单位强度“看起来合理”，而是先让玩家主要输出的击杀时间和敌人从刷出到威胁点的行进时间对齐。只有这两个时间尺度接近，玩家才会感觉自己是在补短板和做取舍，而不是被血量表碾压。

基础公式先保持朴素：

```text
upgradeCost = expBase + (level - 1) * expGrowth
damagePerTick = baseDPS * tickRate
killTime = enemyHealth / (baseDPS * skillMultiplier)
```

波次调参时优先看 4 个指标：

| 指标 | 用途 |
| --- | --- |
| KillTime | 判断当前输出是否能在敌人越线前解决问题 |
| EnemyTravelTime | 判断玩家还有多少反应和补救窗口 |
| SkillPickRate | 判断某流派是不是被数值逼成唯一答案 |
| DeathCause | 区分输出不足、控场不足、经济断档还是题型读不懂 |

Roguelike 数值还要额外守住三条边界：

- DPS 等价只是起点，操作难、覆盖窄、成型慢的路线应获得补偿。
- 高风险路线要有更高上限，但不能让失败完全无收益。
- 单体、范围、控制和经济路线要分别有能验证自己的波次，不要只用一个总 DPS Check 评价所有 Build。

早期最实用的表不是复杂模拟器，而是敌人 HP 曲线、玩家 DPS 曲线和关键波次 TTK 表。先确认“第几波开始打不动”和“为什么打不动”，再改血量、经验、奖励或技能倍率。

## 数值表要同时看波次压力和 Build 强度

塔防 Roguelike 的数值迭代至少要有两张表：一张看波次压力，一张看 Build 强度。只看波次会误判流派差异，只看 Build 会忽略第几波突然变成生死线。

波次压力表的最低字段：

| 字段 | 用途 |
| --- | --- |
| wave | 时间轴 |
| enemy_count | 本波规模 |
| enemy_hp | 单体血量或 EHP |
| spawn_interval | 生成节奏 |
| required_dps | `enemy_count * enemy_hp / 可处理时间` |
| actual_dps | 实测或模拟玩家 DPS |
| pressure_ratio | `required_dps / actual_dps` |

`pressure_ratio` 不应一直平。更好的曲线是在 0.8-1.2 附近波动，并在关键波次制造短峰值；如果某一波突然超过太多，要确认这是教学、构筑、敌人题型还是纯数值断崖。

Build 强度表要看组合增益，而不是只加总技能描述：

```text
base_dps = attack * attack_frequency
actual_dps = base_dps * (1 + bonus_a) * (1 + bonus_b) * ...
build_power = actual_dps / base_dps
```

单个技能可以稳定但不出彩，组合技能才负责质变。一个可用的粗分层：

| 强度 | 体感 |
| --- | --- |
| 3-5 倍基础 DPS | T1，可能过强，需要看成型成本和可读性 |
| 2-3 倍基础 DPS | T2，理想主流构筑 |
| 1.5-2 倍基础 DPS | T3，可用但需要补偿操作、安全或控制价值 |
| 低于 1.5 倍 | T4，容易被玩家抛弃 |

当某个通关 Build 和失败 Build 账面 DPS 只差 10%-15%，却决定生死时，不要只看总 DPS。要拆第几波、什么敌人、什么题型造成失败：控制流可能缺的不是总伤害，而是对关键波次的爆发、破盾、清杂或 Boss 前补救窗口。
