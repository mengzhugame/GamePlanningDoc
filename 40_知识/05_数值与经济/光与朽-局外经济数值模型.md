# 光与朽·局外经济数值模型

> 这条知识回答的是：战斗内掉落如何接到局外科技树、装备升级和长期成长，让玩家既有一周内容量，也有一个月以上投入空间。

---

## 局外经济先看“收入-出口-瓶颈”是否同量级

《光与朽》的经济系统有三类核心对象：

| 资源 / 物品 | 获取来源 | 消耗 / 用途 |
| --- | --- | --- |
| 金币 | 战斗击杀、结算奖励 | 科技树升级、装备升级 |
| 图纸 | 波次通关、Boss 奖励 | 装备升级 |
| 装备 | 战斗结算掉落、合成 | 提升战力、形成长期追求 |

经济设计第一步不是给每个按钮填价格，而是检查资源出口是否同量级。早期配置的问题是：科技树和装备金币消耗很便宜，几局 D1 就能完成大量成长；但图纸需求要几十局，导致金币失去长期约束，只剩图纸单瓶颈。

可复用检查：

1. 单局收入按 D1-D5 分别预算，不只看 D1。
2. 每个成长系统算“升满需要多少局”。
3. 多资源升级要比较两种资源耗尽速度。
4. 如果一种资源 5 局耗尽、另一种 50 局耗尽，双资源系统其实只有一个瓶颈。

## 科技树负责中期广度，装备负责长期深度

科技树和装备不要抢同一个成长职责。更稳的分工是：

| 系统 | 职责 | 节奏 |
| --- | --- | --- |
| 科技树 | 多路线永久增益，给玩家 1-2 个月的横向规划 | 中期目标，节点多但单项不太深 |
| 装备升级 | 少数槽位的长期深度追求 | 长期目标，高品质满级需要大量资源 |
| 图纸 | 装备专用耗材 | 控制装备深度，不挤压科技树 |

《光与朽》的参考模型：

| 模块 | 目标总投入 |
| --- | --- |
| 科技树 26 节点 | 约 38 万金币，约 40+ 局 D1 |
| 单件 Legendary 满级 | 金币与图纸都约 50+ 局 D1 |
| 3 个槽位 Legendary 满级 | 约 150+ 局 D1，对应长期目标 |

这些数值不是可直接照抄的最终答案，而是一个比例关系：科技树提供较快的横向展开，装备提供更长的纵深。

## 装备双资源升级要让金图消耗速度接近

装备升级如果同时消耗金币和图纸，两个资源应当在高品质阶段接近同速耗尽。否则玩家只会关心稀缺资源，另一项变成形式消耗。

示例原则：

| 品质 | 金币基数 | 目标 |
| --- | --- | --- |
| Uncommon | 低 | 让玩家尽快体验升级循环 |
| Rare | 中 | 进入稳定刷局阶段 |
| Epic | 高 | 要求玩家做装备选择 |
| Legendary | 很高 | 金币总消耗接近图纸总消耗 |

Legendary 这种长期目标最适合做双门槛平衡：金币代表通用活跃度，图纸代表装备专用进度。两者接近时，玩家既要继续战斗，也要明确知道“我还差多少图纸”。

## 新手周、入门月、长期目标要同时有

经济模型要同时回答三个时间尺度：

| 阶段 | 玩家应该看到什么 |
| --- | --- |
| 新手周 | 3-4 个科技根节点有明显升级，至少 1 件低品质装备接近成型 |
| 入门月 | 多个科技节点到中等级，1 件 Rare 或多件 Uncommon 稳定成长 |
| 长期 | 科技树接近全满，Epic / Legendary 成为主要追求 |

如果新手周没有明显成长，留存会掉；如果入门月就全满，项目没有长尾；如果长期目标只剩无尽刷同一种资源，玩家会疲劳。

## 首次免费是教学成本，不是经济漏洞

科技树首次升级免费、装备首次合成免费，表面上是少收一次资源，实际上是在买断玩家理解成本。

处理原则：

1. 只免费一次，写入持久化标记。
2. 免费按钮要有明确视觉标签，例如“免费”。
3. 免费后立刻给属性变化、装备变化或战力提升反馈。
4. 不把首次免费计入长期经济预算。

首次免费不是为了慷慨，而是为了让玩家第一次进入局外系统时马上完成“操作 -> 变强”的因果闭环。

## 经济设计可以先预算，但上线后必须看真实收支

初版经济可以用配置预算完成：读取敌人金币、波次数量、难度倍率、Boss 奖励，推算 D1-D5 单局收入。它足以暴露大问题，例如科技树 4 局就能点满、装备金币 5 局就够但图纸要 50 局。

但实装后至少要补四类数据：

| 数据 | 用途 |
| --- | --- |
| 单局金币收入 | 验证战斗预算是否准确 |
| Boss 奖励是否发放 | 区分通关与未通关收益 |
| 科技树累计消耗 | 判断金币是否被科技树吃掉 |
| 装备金币 / 图纸消耗 | 判断双资源门槛是否同速 |

经济系统的真实风险往往不在“公式写错”，而在玩家行为分布：他们是先点科技树，还是憋装备；是卡在图纸，还是金币短缺。预算表只能给初始平衡，真实收支才决定后续调参。

## 战斗金币表现要和真实入账解耦

击杀掉金币的表现不应该决定金币是否真正入账。更稳的结构是：怪物死亡时逻辑金币立刻进本局数据，表现层再用金币 Sprite 做散射、停留、吸附和 HUD 数字缓增。

这样即使玩家暂停、切结算、金币对象被回收或场景切换，也不会丢真实金币。

推荐数据流：

1. 敌人死亡触发金币奖励。
2. `ProgressManager` 或 session 数据立即记账。
3. `CoinPickupSpawner` 只负责表现生成。
4. 单个 `CoinPickup` 到达 UI 后通知 HUD 做 punch / 音效 / 数字追赶。
5. HUD 最终兜底同步到真实 session coins。

经济数据和金币飞行动画不要绑死。表现可以慢，账必须准。

## 金币掉落要压缩表现数量

如果 1 金币 = 1 个对象，怪多时很容易污染画面和性能。更好的方案是用少量“表现金币”承载真实奖励值，总值不变，但对象数受控。

参考规则：

| 真实金币 | 表现金币数量 |
| --- | --- |
| 1-4 | 同等数量 |
| 5-12 | 4 枚 |
| 13-24 | 5 枚 |
| 25-49 | 6 枚 |
| 50-79 | 7 枚 |
| 80+ | 8 枚 |

每枚表现金币携带 `visualValue`，最后几枚补齐余数，保证总和等于真实金币。玩家感知到的是“有金币爆出并飞入金币栏”，不会关心每枚代表 1、5 还是 20。

## UI Punch 必须从固定原始缩放开始

金币飞到金币栏后做 punch，如果每次都拿当前缩放当基准，就会越放越大，最后把 UI 撑出屏幕甚至拖垮战斗。正确做法：

1. 初始化时记录金币栏原始缩放。
2. 每次 punch 前先停止旧动画并恢复原始缩放。
3. punch 从固定原始缩放放大再回落。
4. `OnDisable/OnDestroy` 强制恢复原始缩放。

所有可重复触发的 UI 动画都要避免“在上一次动画的结果上继续叠加”。

## 局内战术箱奖励要先定“普通、稀有、契约”的价值阶梯

战术箱如果同时承担局内 Build 成长和局外资源补偿，奖励价值要有清晰台阶。一个早期可用结构是：

| 档位 | 示例奖励 | 价值定位 |
| --- | --- | --- |
| Normal | 基础伤害 +10%、固定伤害 +150、暴击 +3%、宽度 +5%、长度 +10% | 常见小成长 |
| Epic | 基础伤害 +25%、固定伤害 +500、暴击 +8%、宽度 +12%、长度 +20%、生命恢复 +300 | 明显改变一局手感 |
| Nothing 补偿 | 金币 50/100 | 避免空结果破坏期待 |
| 红色契约 | 消耗当前 HP / Shield，换约 1.5 倍 Normal 奖励 | 有代价的下注，强度低于 Epic |

奖励池要同时照顾局内爽感和长期经济。固定伤害适合早中期有体感，百分比适合后期成长；金币补偿负责兜底情绪；契约负责制造“我敢不敢贪”的决策。不要让所有奖励都只加同一种属性，否则玩家会很快把战术箱读成单调的数值抽奖。

## 契约代价要“显示什么扣什么”

红色契约箱如果文案写 `HP -100`，就应该直接扣本体血量；如果调用普通 Boss 伤害接口，很可能先被护盾吸收，玩家看到血量没变，会觉得契约失效或欺骗。

| 文案 | 应用规则 |
| --- | --- |
| `HP -100` | 直接扣血，不走护盾承伤 |
| `SHLD -50` | 直接扣护盾 |
| 护盾不足 / 血量不足 | 扣到保留 1 点，避免契约直接杀死玩家 |
| 护盾破碎 | 从扣盾随机池剔除，补给池可加入低概率护盾恢复大奖 |

契约的公平感来自可预测：玩家接受代价，但不能接受“文案和实际扣除对象不一致”。

## 随机池异常先打印池大小、总权重和随机值

ScriptableObject 配置看起来有 4 个条目，不代表运行时权重真的进入了随机池。排查随机不生效时，先打印：

1. 池大小。
2. 每个条目的原始权重和使用权重。
3. 总权重。
4. 随机值。
5. 最终命中的条目。

如果池大小是 4 但总权重是 1，优先怀疑 Inspector 序列化、资源未保存、字段默认值或过滤逻辑。随机系统要有可读日志，否则很容易把配置问题误判成算法问题。
