# 广告点与差一点通关数值原则

> 核心判断：好的 IAA 数值不是让玩家一直输，而是让玩家相信“我差一点就能过”，并愿意看广告补足最后一口气。

## 好广告点的体验

| 玩家感受 | 设计含义 |
| --- | --- |
| 我刚才差一点 | 失败点要可解释 |
| 我知道哪里错了 | 失败不能像随机惩罚 |
| 看一次广告就能补救 | 广告奖励要解决当前困境 |
| 我下次可能不用看广告 | 玩家保留掌控感 |

## 差一点通关的常见场景

| 类型 | 表现 | 适合广告奖励 |
| --- | --- | --- |
| 时间差一点 | 还差 3 秒完成清屏/逃脱/收纳 | 加时、冻结、减速 |
| 血量差一点 | Boss 只剩 5%-15% 血 | 复活、临时伤害、护盾 |
| 空间差一点 | 只差 1 格放下/清空 | 多 1 个槽位、撤销、换牌 |
| 资源差一点 | 金币/能量只差一点升级 | 补资源、免费刷新 |
| 操作失误 | 点错一个关键物件导致失败 | 撤销、重排、复活 |

## 光与朽的教训

| 问题 | 影响 |
| --- | --- |
| 需要手动跑很多局 | 数值迭代成本高，样本不足时容易凭感觉 |
| 数值“能玩”但不够好 | 玩家没有稳定形成“差一点”的心理 |
| 单局偏长 | 失败成本高，玩家不一定愿意看广告继续 |
| 爽感反馈不足 | 即使数值接近，也不觉得奖励值得 |

## 竞品给出的方向

从《噩梦守护战》《装备全靠转》《打个螺丝》《猪了个猪》《羊了个羊》《倒水杯》等小游戏体验看：

- 广告点往往出现在玩家已经投入几分钟后。
- 玩家看广告不是因为被强迫，而是觉得“我这局有希望”。
- 难度设计会制造卡点，但卡点必须让玩家觉得可被广告道具解决。

## 下一项目数值验证清单

| 阶段 | 要验证什么 |
| --- | --- |
| 纸面/原型 | 是否存在清晰失败条件 |
| 7 天原型 | 是否能制造“只差一点”的失败 |
| Demo | 失败后广告奖励是否正好解决问题 |
| 上线前 | 次留、失败率、广告触发率、广告完播率是否闭环 |

## 最小数据字段

| 字段 | 作用 |
| --- | --- |
| level_id | 识别关卡 |
| result | 胜利/失败 |
| fail_reason | 时间到、血量归零、槽位满、空间不够 |
| progress_at_fail | 失败时完成度 |
| time_spent | 单局时长 |
| ad_offer_shown | 是否出现广告救助 |
| ad_watched | 是否看广告 |
| result_after_ad | 看广告后是否通关 |

## 判断标准

- 如果失败时完成度常低于 50%，说明太难或教学失败。
- 如果失败时完成度常在 80%-95%，但广告观看率低，说明奖励不够有吸引力或玩家不相信能救回来。
- 如果广告后仍大量失败，说明广告奖励设计错了。
- 如果不看广告也轻松过，说明广告点不存在。

## 侦探寻物类广告点：提示要分层，不卖基础操作

寻物解谜的广告点不应直接卖“能不能玩”，而应解决玩家当下的具体卡点：

| 卡点 | 广告奖励 | 设计边界 |
| --- | --- | --- |
| 时间差一点 | 加时 30-60 秒 | 玩家已经接近找齐时最有效 |
| 找不到证物 | 分层提示 / 圈出可疑区域 | 不直接自动点完证物 |
| 紫外灯能量不够 | 立即充满或加速恢复 | 普通点击和放大镜仍应可用 |
| 指认错误 | 额外证词提示 / 重新指认 | 不用广告强制阻断主线 |

提示层级要从弱到强：场景弱异常 -> 工具揭示 -> 广告强提示。这样广告是“最后一口气”，不是把核心乐趣卖掉。

## IAA 版寻物需要足够多的可广告化卡点

如果一关只有 3 个证物和 3 个嫌疑人，错误空间很小，广告触发点也少，更像买断或 TapTap/Steam 的内容体验。要做纯 IAA，需要把关卡改成更密的“找破绽 / 找异常”结构：

- 每关 8-15 个异常点或证物。
- 至少 2-3 个较难隐藏点，用于提示广告。
- 支持加时、提示、跳过、看答案等自然救助。
- 剧情用文本和通用结算承接，不为每关制作重动画。

判断标准：玩家失败时应觉得“我只差几个破绽就能破案”，而不是“我根本不知道该推理什么”。前者能承接广告，后者会变成理解失败。

## 复活广告只保留死亡后一次，不要再做濒死弹层

《光与朽》IAA 设计里，死亡复活和濒死复活原本被列成两个广告位，最终合并为一个：玩家死亡后弹 RevivePanel，选择复活才触发广告或公测福利。濒死时再弹一次提示，会打断战斗，还会和死亡复活重复。

复活广告的触发原则：

| 规则 | 原因 |
| --- | --- |
| 死亡后触发，而不是低血量提前打断 | 玩家已明确失败，广告救助语义清楚 |
| 每场最多 1 次 | 防止无限续命破坏数值 |
| 前 3 波可直接结算 | 投入太少，复活动机弱，强弹反而烦 |
| 面板展示波次 / Boss 剩余 HP | 让玩家自己判断“差一点”，不需要复杂 near-miss 检测 |

near-miss 可以由上下文信息表达，不一定要靠系统提前判断。

## 即时升级系统不要硬塞加速广告

科技树如果是“材料足够就立即升级”，就不适合做“观看广告加速”。加速广告适用于模拟经营、建造、长时间等待等系统；即时升级里硬加等待，只会破坏爽感和信任。

广告点必须解决真实卡点：

| 系统状态 | 适合广告 |
| --- | --- |
| 缺资源 | 补少量金币 / 蓝图 |
| 死亡但接近成功 | 复活 |
| 胜利后正反馈 | 双倍奖励 |
| 奖励选择不满意 | 额外刷新 |
| 本来没有等待 | 不要为了广告制造等待 |

IAA 不是把每个按钮都接广告，而是把玩家已经愿意补救的瞬间变成可选广告。

## “差一点”要和局外成长出口连起来

《光与朽》的章节目标不是让玩家一次通关，而是让不同章节形成不同胜率压力：第一章偏高胜率，第二章中等，第三章明显卡点。卡点的目的不是单纯制造失败，而是让玩家相信“升级科技树 / 装备后我就能过”。

可复用目标结构：

| 阶段 | 目标体验 |
| --- | --- |
| 早期章节 | 大多数玩家能过，建立信心 |
| 中期章节 | 胜率下降，但失败原因清楚 |
| 后期章节 | 明显差一点，需要局外成长或更好 Build |

判断失败是否合格，不只看胜率，还要看失败时剩余信息：Boss 剩余 HP、死亡波次、护盾状态、战斗时长。玩家如果每次都在 Boss Phase3、Boss 剩 5%-20% 或 W9 带伤进 Boss 时失败，才容易接受“再升一点就过”。如果早早被普通怪压死，就不是广告点或成长点，而是教学 / 曲线失败。

## 高难度奖励不能让玩家觉得被克扣

高难度为了维持等级锚点，可以提高升级所需经验，但不应降低单怪 XP。原因很简单：玩家在高难度杀了更多怪，应该得到完整击杀反馈；如果每只怪奖励被砍，体验会变成“系统在暗扣我”。

这条原则对广告和局外成长也适用：当玩家已经承担更高难度或更长战斗时，奖励反馈要清楚。节奏控制放在门槛、价格、升级曲线里，不要放在玩家刚看到的击杀奖励上。

## 复活广告的奖励必须让玩家重新接管战场

《光与朽》的复活反馈暴露了一个 IAA 常见问题：如果玩家看完广告或使用复活后，仍然立刻被同一批怪压死，广告奖励就会被感知为无效。

复活奖励至少要解决三件事：

| 问题 | 奖励设计 |
| --- | --- |
| 身边怪太多 | 冲击波推开或清小怪 |
| 操作还没恢复 | 1-2 秒无敌或护盾 |
| 玩家不相信能救回 | 展示 Boss 剩余 HP、当前波次和复活后变化 |

复活广告卖的不是“继续一次”，而是“这一局还有希望”。如果复活后没有希望，就不要期待玩家第二次相信广告。

## 早期广告点要跟首局长度一起设计

如果首局太长、广告点太晚，IAA 指标会天然吃亏：玩家还没看到养成、广告点或“差一点”，就已经疲劳退出。

短关 D1 的商业化意义不是马上多塞广告，而是让玩家在 5-6 分钟内完成：

1. 看懂核心操作。
2. 体验一次构筑成型或 Lv5 质变。
3. 遇到一次有语义的复活 / 补给 / 奖励选择。
4. 结束后看到局外成长目标。

广告点不是独立按钮，它必须嵌在首局节奏里。首局节奏不成立，广告点再多也只是打扰。

## IAA 先接主链路，再接真实广告 SDK

广告接入的早期目标不是一次性铺满所有广告位，而是先把玩家最有动机点击的主链路做通。对《光与朽》这类战斗 + 局外成长小游戏，广告位优先级应按“是否解决当下卡点”排序。

推荐顺序：

| 优先级 | 广告点 | 为什么先做 |
| --- | --- | --- |
| 1 | 失败复活 | 玩家刚经历损失，且如果 Boss 血量、当前波次接近完成，就最容易相信“看一次能救回来” |
| 2 | 结算奖励翻倍 | 不打断战斗，收益清晰，适合验证广告接受度 |
| 3 | TopBar 资源补给 | 解决局外金币 / 图纸 / 升级资源短缺，但要避免变成日常强迫入口 |
| 4 | 技能选择刷新 | 只在构筑卡住时有价值，不能让玩家觉得基础构筑必须看广告 |
| 5 | Banner | 先作为低优先级展示位，避免压住核心战斗体验 |

复活广告尤其要展示“差一点”的证据。RevivePanel 不应只写“看广告复活”，还应显示当前波次、Boss 剩余血量或本局进度，让玩家知道这次复活不是随机续命，而是有机会把已经投入的这一局救回来。

在无广告 ID 阶段，可以先做 mock reward：点击按钮立即发奖，并记录 `ad_offer_show` / `ad_button_click` / `mock_reward_granted`。只要按钮位置、奖励语义和后续结果都能被记录，就已经能提前验证广告点是不是成立；真实 SDK 接入只是把“点击后发奖”替换成“完播后发奖”。

## 广告按钮的价值感来自状态清楚，不来自按钮文案变长

《光与朽》的广告重掷和顶部资源领取后来都从“按钮文案动态解释”收敛为“图标 + 数量 + 面板说明”。这是 IAA UI 的一个通用经验：按钮本身只承担动作，解释放到更宽的文本区域。

可复用结构：

| 入口 | 按钮上显示 | 说明放哪里 |
| --- | --- | --- |
| 技能重掷 | 骰子 / 摄像头图标，次数用完整体置灰 | 技能面板或旁边短提示 |
| 体力领取 | 体力图标 + `+2` | `InfoMainText` 说明恢复规则或今日已达上限 |
| 金币领取 | 金币图标 + `+500` | `InfoMainText` 说明奖励 |
| 图纸领取 | 图纸图标 + `+3` | `InfoMainText` 说明用途 |

当按钮达到上限时，按钮、图标、数量文字要一起置灰。只置灰 Image、不置灰文字，会让玩家觉得按钮仍可用；只改文案、不改图标，移动端小按钮又容易拥挤。

## 体力为 0 时可主动弹资源入口，但要尊重玩家关闭

体力不足是典型“差一点继续玩”的广告点。进入主菜单时，如果体力为 0，可以主动弹出体力领取/购买面板，减少玩家找入口的成本。

但需要两个边界：

1. 首次自动进教程战斗时跳过，避免新手流程被打断。
2. 每次主菜单激活只自动弹一次，玩家手动关闭后不要反复弹。

广告点主动出现不是骚扰玩家，而是在“玩家刚好想继续但缺资源”时递上解决方案。这个时机成立，频率也要克制。

## 领取后要立即刷新主路径按钮

资源广告或 mock reward 发奖后，必须立刻把玩家送回主路径。体力领取后如果顶部数值变了，但“开始游戏”按钮仍旧灰着，广告点就会从补救机会变成流程 bug。

因此资源领取链路至少要闭环：

```
点击领取 → 发放资源 → 刷新顶部资源 → 刷新主路径按钮 → 关闭或更新资源面板
```

广告点不是孤立按钮。它解决的是当前卡点，所以发奖后必须立刻解除那个卡点。

## 道具按钮灰态要看“本局还能不能用”，不只看库存

广告和道具按钮的状态应同时看库存、单局使用上限和具体道具条件。美妆叠叠乐里每类道具单局可先限制 2 次，按钮置灰不能只由子类各写一套判断，而应在统一基类里检查剩余次数，再让特殊道具补充额外条件，例如 `AddSlotButton` 还要检查是否已到最大临时槽数量。

可复用判断：

| 条件 | UI 状态 |
| --- | --- |
| 本局次数用完 | 按钮、图标、数量一起置灰 |
| 库存为 0 但允许看广告 | 不直接置灰，点击后打开道具说明 / 广告面板 |
| 库存为 0 且广告不可用 | 置灰并给短说明 |
| 道具条件不成立 | 置灰，例如临时槽已扩满、没有可移除订单 |

玩家看到的不是“系统代码分支”，而是“这个救援现在还救不救得了我”。灰态必须表达这个答案。

## 库存道具和广告道具要共用同一条使用链路

空间压力类小游戏适合把广告放在“库存用完后的同一救援动作”上，而不是另起一个广告按钮。美妆叠叠乐的规则可以复用：

1. 玩家有库存时，点击 `AddSlot` / `ClearSlot` / `RemoveOrder` 直接使用并消耗库存。
2. 库存为 0 时，弹出道具说明面板，告诉玩家这个道具解决什么卡点。
3. 点击“立即使用”后走广告或 mock reward。
4. 完播后调用同一套使用函数，但传入 `consumeInventory = false`。

这样广告奖励和库存奖励解决的是同一个当前困境，不会出现“看广告获得了一个以后才有用的东西”。道具广告的价值感来自立刻解除压力：多一个槽、清掉临时槽、完成一个卡住的订单。

## 低惩罚解谜的广告要“可选救局”，不要破坏重试心流

拔箭头类小游戏的广告策略非常克制：失败后给可选复活或提示，通关、登录和普通重试不强插广告。它适合的不是高频压榨，而是保护“我再来一次”的心流。

可复用规则：

| 场景 | 广告适配度 | 原因 |
| --- | --- | --- |
| 失败后差一步 | 高 | 玩家刚看见问题，愿意救局 |
| 失败后无损重试 | 中 | 不要每次失败都弹，避免伤害低压感 |
| 通关后强插 | 低 | 打断连续通关节奏 |
| 登录弹窗 | 低 | 还没进入需求，不应先索取 |
| 提示 / 跳过 | 中高 | 解决当前卡点，必须限制频率 |

低成本解谜靠口碑和自然传播时，克制广告本身就是留存设计的一部分。

## 广告点要卖“失败保险”和“构筑纠偏”，不要卖系统税

每日洞察归档反复强调同一个 IAA 原则：广告不是多塞一个按钮，而是在玩家已经产生后悔、损失或“差一点”的瞬间，给一次可信的补救。

三类最高价值广告：

| 场景 | 广告卖什么 | 错误做法 |
| --- | --- | --- |
| 濒死 / Boss 压线 | 复活、临时护盾、短时过载 | 只给固定金币或弱回血 |
| Build 歪了 | 定向补核心标签、重抽、锁定奖励 | 让玩家继续纯随机抽垃圾 |
| 资源刚好短缺 | 补差额、临时重铺、免费刷新 | 给远期成长货币，不能解决当局 |

数值上，广告收益应该只帮助玩家跨过当前断点，不直接送通关。可用规则是：单次广告收益不超过约 `1-1.5` 波自然成长价值；看完广告后通关率可以上升，但不能暴冲到“看广告必胜”。

运营上要看三连指标：

```text
广告触发场景 -> 广告完播 / 点击 -> 广告后结果 -> 次日留存
```

如果完播高、广告后仍失败，说明奖励解决错问题；如果完播高、通关率暴冲但次留下降，说明广告破坏挑战；如果玩家连续重试但不看广告，说明失败可接受但广告价值不足。

## 体力广告卖的是“继续玩”，不是系统税

体力不足广告和局内救局广告不同：它不解决某一局的失败，而是解决“我现在还想继续玩”的中断。它成立的前提是玩家已经有继续意愿。

可复用规则：

| 设计项 | 建议 |
| --- | --- |
| 触发点 | 体力不足进关，或玩家主动点体力栏加号 |
| 广告收益 | 一次补 1-2 局，允许溢出上限，避免奖励被吞 |
| 每日上限 | 单独频控，例如体力广告每日 5 次，不和金币/道具共享次数 |
| UI 表达 | 显示当前体力、上限、自然恢复倒计时和广告补给按钮 |
| 埋点 | 记录点击、完播、补给后是否继续开局 |

体力广告不要放在玩家还没形成乐趣前。首局、教学和第一次失败最好保护体验；等玩家已经理解玩法，体力才适合作为回访节奏和轻广告入口。
