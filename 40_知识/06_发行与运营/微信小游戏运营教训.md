# 微信小游戏运营教训与上线复盘流程

> 核心更新：上线不是终点，上线只是开始拿真实数据。没有自然量、CPS、买量、留存、广告触发这些数据，就不能判断一款小游戏是否值得继续投入。

## 两个已上线项目的事实

| 项目 | 已知上线/运营事实 | 当前教训 |
| --- | --- | --- |
| 美妆叠叠乐 | 2026-01-01 上线微信；截至 2026-05-05 累计 742 用户；无买量，只发朋友圈和小红书，大部分流量来自 CPS；达到后台要求后接入广告；总收入 1.04 元 | 只上线、不买量、不持续内容运营，数据会非常弱；CPS 可带来流量，但不等于商业成立 |
| 光与朽 | 发过朋友圈、小红书、B站、抖音视频；花 400+ 元做腾讯广告买量测试 | 买量必须和自然量分开记录，否则无法判断素材、产品、平台哪一环有问题 |

## 核心认知纠正

| 误区 | 正确认知 |
| --- | --- |
| 上线后平台会自然推量 | 新小游戏通常需要自己做内容、CPS、买量或发行合作获取样本 |
| 朋友圈反馈能判断产品 | 熟人数据只能做 bug 和感受参考，不做市场判断 |
| 买量是为了涨用户 | 早期买量是为了买陌生样本和数据 |
| 广告接入后就能赚钱 | 没有足够 DAU、广告触发和留存，广告收入只会很低 |
| 发行商说有潜力就代表市场认可 | 发行反馈只能作为行业意见，玩家数据才是决策依据 |

## 上线前准备

上线前必须准备这些，不然上线后数据会不可用。

| 模块 | 最低要求 |
| --- | --- |
| 数据后台 | 能看到访问、留存、来源、关卡、失败、广告 |
| 广告链路 | 激励广告触发、完成、奖励发放可记录 |
| 分享链路 | 分享入口、分享回流、CPS 来源尽量可区分 |
| 视频素材 | 至少 3 条真实玩法视频，用于小红书/B站/抖音/视频号 |
| 复盘模板 | 使用 `20_项目/上线数据复盘模板.md` |
| 止损线 | 时间、预算、关键数据下限提前写清 |

## 上线后数据记录节奏

| 时间 | 记录重点 | 决策 |
| --- | --- | --- |
| T+0 | 包体、登录、分享、广告、后台是否正常 | 先排技术污染 |
| T+24h | 新增、访问路径、首局完成、明显流失点 | 修 bug 和引导 |
| T+72h | D1、失败点、广告触发、广告完成 | 初步判断留存和广告点 |
| T+7d | 自然量、CPS、内容平台效果、买量数据 | 决定优化、补量或止损 |
| T+14d | 长尾、复访、收入、评论反馈 | 形成阶段复盘 |

## 买量数据表

光与朽之后，买量数据必须单独成表。

| 字段 | 说明 |
| --- | --- |
| 投放日期 | 哪天投 |
| 平台 | 腾讯广告/其他 |
| 素材编号 | 对应哪条视频或图 |
| 花费 | 实际消耗 |
| 曝光 | 展示量 |
| 点击 | 点击量 |
| 点击率 | CTR |
| 激活/新增用户 | 到游戏的人数 |
| 激活成本 | 花费 / 新增 |
| D1 留存 | 次留 |
| 人均广告次数 | IAA 关键 |
| 广告收入 | 回收 |
| 结论 | 素材问题、产品问题、投放问题 |

## 自然量、CPS、买量必须分开看

| 来源 | 能说明什么 | 不能说明什么 |
| --- | --- | --- |
| 朋友圈 | bug、第一感受、熟人支持 | 真实市场需求 |
| 小红书/B站/抖音 | 内容钩子、题材吸引力 | 游戏留存一定好 |
| 微信 CPS | 渠道能带来一部分量 | 用户质量和商业成立 |
| 腾讯广告买量 | 陌生用户成本、素材和产品初筛 | 长期 ROI 一定成立 |
| 发行商反馈 | 行业视角、品类经验 | 玩家一定买账 |

## 数据决策矩阵

| 情况 | 动作 |
| --- | --- |
| 自然量太少 | 不做产品结论，先通过内容或小额买量补样本 |
| 新增不少但 D1 很差 | 优先查教学、首局体验、失败点 |
| D1 还可以但广告收入很低 | 查广告触发点、奖励吸引力、广告后通关率 |
| 买量点击高但激活低 | 素材吸引但承接页或进入链路有问题 |
| 激活成本高且留存差 | 停止买量，复盘产品和素材 |
| 留存好且广告触发健康 | 小额加码，准备发行沟通材料 |

## 美妆叠叠乐给出的运营警戒线

截至 2026-05-05，742 用户和 1.04 元收入说明：

- 只靠朋友圈、小红书和 CPS，很难证明商业模型。
- 达到广告接入门槛不等于进入变现阶段。
- 如果没有持续内容运营或买量，收入数据会长期停留在噪声级。
- 后续每个上线项目都要从第一天记录来源、留存、广告、收入和素材。

## 光与朽给出的买量警戒线

400+ 元买量测试要复盘三件事：

1. 素材是否吸引点击。
2. 点击后是否真正进入游戏。
3. 进入游戏后是否留存和看广告。

任何只记录“花了多少钱”的买量复盘都不够，必须能拆到素材、产品、广告点。

## 核心原则

- 上线后 72 小时看数据，不靠情绪判断。
- 买量是买判断，不是买面子。
- 自然量、CPS、买量、熟人流量必须分开记录。
- 如果数据不足，不要强行得出“产品好/坏”的结论。
- 项目结束后必须把运营教训沉淀到 `40_知识/06_发行与运营/`。

## 微信小游戏上线补充：个人开发者的发布清单

个人开发者上线前，重点不是“把包提上去”，而是保证审核、体验和数据链路都能承接第一批真实用户。

### 提审前自检

| 模块 | 必查项 |
| --- | --- |
| 账号与资质 | 主体、类目、隐私协议、用户协议、备案/合规要求 |
| 包体与性能 | 首包大小、加载速度、低端机卡顿、黑屏/白屏 |
| 核心玩法 | 30 秒内能理解目标，首局能完成一次正反馈 |
| 广告与分享 | 广告入口合规，奖励发放稳定，不诱导分享 |
| 数据 | 新增、来源、留存、关卡、失败、广告触发可记录 |
| 素材 | 封面、图标、简介、截图和真实玩法一致 |

### 常见驳回与运营风险

- 素材与真实玩法不一致。
- 奖励广告诱导过强，或奖励发放不稳定。
- 隐私、授权、用户协议缺失。
- 首屏加载异常，审核人员无法进入核心玩法。
- 类目与玩法不匹配。

提审前至少按“新用户第一次进入”的路径完整走一遍，不要只在编辑器或熟悉账号里验证。

## 市场判断：微信小游戏规模大，不等于自然量容易

微信小游戏市场规模足够大，但对个人开发者的真实含义是：

- 流量池大，但竞争和内容噪声也大。
- 平台不会因为“新游戏上线”自动给足够样本。
- 没有内容、CPS、买量或发行合作，很多产品会停在低样本状态。
- 大盘趋势只能说明机会存在，不能替代项目自身数据。

对《光与朽》和后续项目，更稳妥的判断方式是：

```
上线可用性 → 内容/小额买量补样本 → 留存与广告触发 → 是否继续投入
```

不要用“微信小游戏市场很大”来安慰产品，也不要用“初期自然量很少”直接判死刑。
