# 微信小游戏运营教训与上线复盘流程

> 核心更新：上线不是终点，上线只是开始拿真实数据。没有自然量、CPS、买量、留存、广告触发这些数据，就不能判断一款小游戏是否值得继续投入。

## 两个已上线项目的事实

| 项目 | 已知上线/运营事实 | 当前教训 |
| --- | --- | --- |
| 美妆叠叠乐 | 2026-01-01 上线微信；截至 2026-05-05 累计 742 用户；无买量，只发朋友圈和小红书，大部分流量来自 CPS；达到后台要求后接入广告；总收入 1.04 元 | 只上线、不买量、不持续内容运营，数据会非常弱；CPS 可带来流量，但不等于商业成立 |
| 光与朽 | 发过朋友圈、小红书、B站、抖音视频；花 400+ 元做腾讯广告买量测试 | 买量必须和自然量分开记录，否则无法判断素材、产品、平台哪一环有问题 |

## 核心认知纠正

| 误区 | 正确认知 |
| --- | --- |
| 上线后平台会自然推量 | 新小游戏通常需要自己做内容、CPS、买量或发行合作获取样本 |
| 朋友圈反馈能判断产品 | 熟人数据只能做 bug 和感受参考，不做市场判断 |
| 买量是为了涨用户 | 早期买量是为了买陌生样本和数据 |
| 广告接入后就能赚钱 | 没有足够 DAU、广告触发和留存，广告收入只会很低 |
| 发行商说有潜力就代表市场认可 | 发行反馈只能作为行业意见，玩家数据才是决策依据 |

## 上线前准备

上线前必须准备这些，不然上线后数据会不可用。

| 模块 | 最低要求 |
| --- | --- |
| 数据后台 | 能看到访问、留存、来源、关卡、失败、广告 |
| 广告链路 | 激励广告触发、完成、奖励发放可记录 |
| 分享链路 | 分享入口、分享回流、CPS 来源尽量可区分 |
| 视频素材 | 至少 3 条真实玩法视频，用于小红书/B站/抖音/视频号 |
| 复盘模板 | 使用 `20_项目/上线数据复盘模板.md` |
| 止损线 | 时间、预算、关键数据下限提前写清 |

## 上线后数据记录节奏

| 时间 | 记录重点 | 决策 |
| --- | --- | --- |
| T+0 | 包体、登录、分享、广告、后台是否正常 | 先排技术污染 |
| T+24h | 新增、访问路径、首局完成、明显流失点 | 修 bug 和引导 |
| T+72h | D1、失败点、广告触发、广告完成 | 初步判断留存和广告点 |
| T+7d | 自然量、CPS、内容平台效果、买量数据 | 决定优化、补量或止损 |
| T+14d | 长尾、复访、收入、评论反馈 | 形成阶段复盘 |

## 买量数据表

光与朽之后，买量数据必须单独成表。

| 字段 | 说明 |
| --- | --- |
| 投放日期 | 哪天投 |
| 平台 | 腾讯广告/其他 |
| 素材编号 | 对应哪条视频或图 |
| 花费 | 实际消耗 |
| 曝光 | 展示量 |
| 点击 | 点击量 |
| 点击率 | CTR |
| 激活/新增用户 | 到游戏的人数 |
| 激活成本 | 花费 / 新增 |
| D1 留存 | 次留 |
| 人均广告次数 | IAA 关键 |
| 广告收入 | 回收 |
| 结论 | 素材问题、产品问题、投放问题 |

## 自然量、CPS、买量必须分开看

| 来源 | 能说明什么 | 不能说明什么 |
| --- | --- | --- |
| 朋友圈 | bug、第一感受、熟人支持 | 真实市场需求 |
| 小红书/B站/抖音 | 内容钩子、题材吸引力 | 游戏留存一定好 |
| 微信 CPS | 渠道能带来一部分量 | 用户质量和商业成立 |
| 腾讯广告买量 | 陌生用户成本、素材和产品初筛 | 长期 ROI 一定成立 |
| 发行商反馈 | 行业视角、品类经验 | 玩家一定买账 |

## 数据决策矩阵

| 情况 | 动作 |
| --- | --- |
| 自然量太少 | 不做产品结论，先通过内容或小额买量补样本 |
| 新增不少但 D1 很差 | 优先查教学、首局体验、失败点 |
| D1 还可以但广告收入很低 | 查广告触发点、奖励吸引力、广告后通关率 |
| 买量点击高但激活低 | 素材吸引但承接页或进入链路有问题 |
| 激活成本高且留存差 | 停止买量，复盘产品和素材 |
| 留存好且广告触发健康 | 小额加码，准备发行沟通材料 |

## 美妆叠叠乐给出的运营警戒线

截至 2026-05-05，742 用户和 1.04 元收入说明：

- 只靠朋友圈、小红书和 CPS，很难证明商业模型。
- 达到广告接入门槛不等于进入变现阶段。
- 如果没有持续内容运营或买量，收入数据会长期停留在噪声级。
- 后续每个上线项目都要从第一天记录来源、留存、广告、收入和素材。

## 光与朽给出的买量警戒线

400+ 元买量测试要复盘三件事：

1. 素材是否吸引点击。
2. 点击后是否真正进入游戏。
3. 进入游戏后是否留存和看广告。

任何只记录“花了多少钱”的买量复盘都不够，必须能拆到素材、产品、广告点。

## 核心原则

- 上线后 72 小时看数据，不靠情绪判断。
- 买量是买判断，不是买面子。
- 自然量、CPS、买量、熟人流量必须分开记录。
- 如果数据不足，不要强行得出“产品好/坏”的结论。
- 项目结束后必须把运营教训沉淀到 `40_知识/06_发行与运营/`。

## 微信小游戏上线补充：个人开发者的发布清单

个人开发者上线前，重点不是“把包提上去”，而是保证审核、体验和数据链路都能承接第一批真实用户。

### 提审前自检

| 模块 | 必查项 |
| --- | --- |
| 账号与资质 | 主体、类目、隐私协议、用户协议、备案/合规要求 |
| 包体与性能 | 首包大小、加载速度、低端机卡顿、黑屏/白屏 |
| 核心玩法 | 30 秒内能理解目标，首局能完成一次正反馈 |
| 广告与分享 | 广告入口合规，奖励发放稳定，不诱导分享 |
| 数据 | 新增、来源、留存、关卡、失败、广告触发可记录 |
| 素材 | 封面、图标、简介、截图和真实玩法一致 |

### 常见驳回与运营风险

- 素材与真实玩法不一致。
- 奖励广告诱导过强，或奖励发放不稳定。
- 隐私、授权、用户协议缺失。
- 首屏加载异常，审核人员无法进入核心玩法。
- 类目与玩法不匹配。

提审前至少按“新用户第一次进入”的路径完整走一遍，不要只在编辑器或熟悉账号里验证。

## 市场判断：微信小游戏规模大，不等于自然量容易

微信小游戏市场规模足够大，但对个人开发者的真实含义是：

- 流量池大，但竞争和内容噪声也大。
- 平台不会因为“新游戏上线”自动给足够样本。
- 没有内容、CPS、买量或发行合作，很多产品会停在低样本状态。
- 大盘趋势只能说明机会存在，不能替代项目自身数据。

对《光与朽》和后续项目，更稳妥的判断方式是：

```
上线可用性 → 内容/小额买量补样本 → 留存与广告触发 → 是否继续投入
```

不要用“微信小游戏市场很大”来安慰产品，也不要用“初期自然量很少”直接判死刑。

## 没有平台推量时，不要把“等待运营反馈”当主策略

微信小游戏上线后，如果没有稳定自然推荐、没有平台推量、样本又主要来自熟人，等待运营反馈会让项目进入空转。

更稳的动作顺序：

1. 先修首局中最影响留存和差异化感知的 P0 问题。
2. 用小额买量或内容平台补陌生样本。
3. 按来源拆 cohort：熟人、自然、内容、CPS、腾讯广告。
4. 再判断产品是否继续投入、转 CPS 长尾，还是启动下款。

运营反馈有价值，但它不是样本，也不是数据。没有数据时，平台意见最多解锁下一轮验证，不解锁大规模开发。

## 分享不能机械替代广告

在微信小游戏里，分享可以作为广告不可用时的兜底，也可以作为独立的邀请任务，但不适合把所有激励广告都粗暴替换成分享。

推荐三层结构：

| 层 | 处理 |
| --- | --- |
| 广告 SDK | 保留广告代码和广告语义，方便后续流量主/广告位开启后切回 |
| 兜底分享 | 广告不可用时，部分奖励可自动 fallback 到分享 |
| 独立分享任务 | 主界面或活动入口做邀请奖励，不绑死每次复活、刷新、补体力 |

原因是玩家只有在奖励足够有动机、分享对象合适、频率不烦时才愿意分享。把每个关键救助都换成分享，会同时伤体验、伤审核稳定性，也可能遇到分享频率限制。

## 微信分享图先选传播心理，再选画面

小游戏分享图不是单纯展示截图，它要回答“我为什么要点开朋友发来的这张图”。可按三种传播心理设计：

| 方向 | 驱动力 | 画面结构 |
| --- | --- | --- |
| 极端反差型 | 好奇心 | 一半腐蚀、一半净化，光与朽对角线冲突 |
| 氛围叙事型 | 共情/审美 | 小角色面对巨大遗迹，一束光照进废墟 |
| 互动挑战型 | 优越感/挑战 | 发光安全区被黑暗包围，展示生存时间或成绩 |

分享图要避免只放 Logo 或纯氛围背景。第一眼应该看到冲突、结果或挑战，而不是让用户读世界观。

## 分享图要为社交身份和回流入口预留位置

微信环境里的分享图有两个额外任务：让玩家觉得“这是我的战绩/邀请”，并让回流入口自然融入画面。

可复用规则：

1. 左上角预留头像和昵称区域，让图像像玩家专属卡片。
2. 二维码或进入按钮可以设计成游戏内“光源”或能量核心，不要生硬贴角落。
3. “光”用暖金色表达希望，“朽”用深蓝紫或炭灰，不要纯黑死块。
4. 底部三分之一可放轻微发光的点击引导，但不要做成廉价广告按钮。
5. 文案优先短句挑战或危机，例如“我坚持了 180 秒，你能更久吗？”

分享素材必须和真实玩法一致。展示生存、激光、黑暗包围和净化瞬间，比抽象 CG 更能承接点击后的首局体验。

## 微信小游戏简介要写成“审核能懂、玩家能想象”的核心玩法

小游戏简介、创意新游申请和短宣传语不是世界观作文，第一优先级是把真实可玩的差异讲清楚。《光与朽》的可复用表达是：单指控制底部炮塔，调整激光角度，用激光的物理推力击退敌人，守住核心并击败最终 Boss。

| 文案层级 | 应回答的问题 | 可复用写法 |
| --- | --- | --- |
| 审核/申请 | 和普通塔防有什么不同 | “激光物理推力”“空间位移控制”“波间空投 Roguelite 选择” |
| 商店简介 | 玩家进来要做什么 | “单指转动激光，击退变异潮，守住末日净土” |
| 20 字短描述 | 第一眼记住什么 | “激光物理推力，单指守卫末日净土！” |
| 8 字内卖点 | 视频/分享角标 | “单指激光推敌”“物理塔防” |

写简介时要避免只说“塔防”“肉鸽”“赛博废土”这类大词。审核和玩家都需要看到具体交互：不是数值 DPS 把怪打死，而是用激光推力、角度和地形压力制造防线。

## 创意游戏申请文案必须贴合真实玩法，不要为了显得创新而编机制

美妆叠叠乐申请微信“创意游戏”时，有一个典型教训：文案如果写成“物理碰撞、重心偏移、动态摇摆”，但真实游戏其实是订单匹配和临时槽规划，就会偏离产品。审核文案要突出真实差异，而不是包装一个不存在的高概念。

更贴合的表达方向：

| 文案层级 | 应强调 |
| --- | --- |
| 核心玩法 | 多订单管理解谜、化妆包槽位匹配、临时槽资源规划 |
| 关卡创新 | 锁与奖杯、钥匙/伪钥匙、手工设计的优雅困境 |
| 策略回报 | 完美订单、道具奖励、收藏馆礼盒进度 |
| 美术体验 | Chic & Clean 美妆风格、收纳满足感、轻 ASMR 反馈 |

可复用句式：`《美妆叠叠乐》是一款融合多订单管理与临时槽资源规划的 2D 益智消除游戏。玩家需要从层叠化妆品中规划点击顺序，完成不同化妆包订单，并通过完美订单和奖杯关解锁收藏馆礼盒。`

## 短简介和推广文案要分“审核说明”和“转化钩子”

同一个游戏不要用一套文案打所有场景。审核说明要稳、准、像产品说明；投放和分享文案要短、勾人、能触发点击。

| 场景 | 写法 |
| --- | --- |
| 8 字以内角标 | `一玩就上头`、`强迫症福音`、`手残党勿入` |
| 20 字以内推广语 | `强迫症福音！把化妆品都叠整齐！` |
| 创意申请 | 写清多订单、临时槽、奖杯关、收藏馆，不夸大物理机制 |
| 横版宣传图 | 用局部放大重组玩法，不直接贴截图，也不做纯美妆海报 |

推广文案可用三类钩子 A/B 测试：挑战钩子、解压整理钩子、女性向美妆钩子。不要凭感觉定稿，至少用 2-3 组图文组合测试 CTR。

## 首发扶持是加速器，不是上线理由

批次 003 记录了微信小游戏首发扶持、回流激励和小游戏收入结构变化等平台信号。执行时要把它们当作“版本已经准备好时的放大器”，不能反过来变成“为了赶扶持而上线”的理由。

上线前必须先回答：

| 问题 | 不满足时的处理 |
| --- | --- |
| 首局 30 秒是否能看懂核心玩法？ | 先改新手引导和首局爽点 |
| D1 / D3 是否有陌生用户样本？ | 先补内容平台、小额买量或测试群 |
| 关键广告点是否自然？ | 先调卡点、道具和复活逻辑 |
| 是否有版本留存计划？ | 至少准备每日/每周内容、活动或关卡补充 |
| 当前规则是否仍有效？ | 以微信后台当期政策和官方公告为准，不写死补贴金额 |

平台政策能改善 ROI，但不能补救“没人愿意玩”。独立开发者最怕的是拿一个尚未证明核心循环的版本去消耗首发资格，然后把低数据误读成平台不给量。

## 微信上线待办分为审核材料和数据材料两套

旧《光与朽》ToDo 把软著、隐私政策、截图、简介、更新日志、包体测试和广告接入放在同一组上线前任务里。执行时要拆成两套清单：

| 清单 | 目标 | 典型项 |
| --- | --- | --- |
| 审核材料 | 让版本合法、可提交、能过审 | 软著、隐私政策、适龄/健康提示、5 张截图、游戏简介、更新日志、包体小于 4MB |
| 数据材料 | 让上线后能判断产品 | 埋点、广告入口、复活/刷新/翻倍记录、首局完成、死亡波次、分享/回流来源 |

审核材料缺失会让游戏上不了线；数据材料缺失会让上线变成盲飞。两者都属于 P0，但服务的问题不同，不能互相替代。

上线前最后一轮检查建议按三问：

1. 这版能不能提交：平台材料、包体、权限和隐私是否完整。
2. 这版能不能玩懂：首局、教学、三选一、失败和复活是否清楚。
3. 这版能不能看数：留存、广告、Build、死亡原因和来源 cohort 是否能记录。

如果第 2、3 问没过，平台审核通过也只能说明“能上线”，不能说明“值得推量”。
