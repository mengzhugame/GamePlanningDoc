# AI 美术低门槛工作流 2026

> 适用场景：个人开发者不想搭 Stable Diffusion、不训练 LoRA、不依赖本地显卡，用在线 AI 工具快速完成概念图、概念视频关键帧和游戏 P0 美术资产。

## 当前真实流程

| 阶段 | 做法 | 常用工具 | 产出 |
| --- | --- | --- | --- |
| 1. 提示词生成 | 用 AI 把玩法、题材、视角翻译成美术提示词 | ChatGPT / Gemini | 风格描述、关键词、负向词 |
| 2. 概念图抽卡 | 生成 1 张最能代表游戏的概念图 | ChatGPT Image / Nano Banana / 即梦 AI | 基础风格图 |
| 3. 风格确认 | 选满意图作为基础风格参考 | 人工筛选 | Style Reference |
| 4. 资产生成 | 基于基础风格图生成角色、道具、场景、UI | Lovart / 即梦 AI / Whisk 或同类在线工具 | 游戏资源图 |
| 5. 清理切图 | 抠图、修白边、统一尺寸、导入 Unity | Photoshop / 在线抠图 / Unity | 可用 PNG 资产 |

## 这个流程的优缺点

| 维度 | 结论 |
| --- | --- |
| 优点 | 快，不需要本地显卡，不需要学 SD/ComfyUI/LoRA，适合概念视频和 7 天切片 |
| 缺点 | 抽卡痛苦，风格容易漂，描边粗细不同，白边脏，资源规格不统一 |
| 适合 | 创意验证、AI 概念视频、7 天垂直切片、低成本 Demo |
| 不适合 | 大量角色长期量产、强一致商业级美术、需要稳定换装或同角色多动作的项目 |

## 阶段版 SOP

### 阶段 A：概念验证期

目标不是做资产，而是验证“这张画面能不能让人停下来看、能不能理解玩法”。

| 要做 | 不做 |
| --- | --- |
| 1 张基础风格图 | 不批量做资产 |
| 3-4 张概念视频关键帧 | 不做完整 UI 套件 |
| 统一前缀和负向词 | 不纠结每张图 100% 一致 |
| 剪映后期叠 UI、血条、手指、文字 | 不让 AI 直接生成中文文字 |

### 阶段 B：7 天垂直切片期

目标是让原型能被陌生玩家看懂。

| 资产优先级 | 内容 | 验收标准 |
| --- | --- | --- |
| P0 | 核心操作对象、失败对象、奖励对象 | 3 秒内能看懂用途 |
| P0 | 1 个场景背景或纯色底 | 不干扰核心玩法 |
| P0 | 关键 UI：开始、失败、胜利、奖励 | 能完成测试闭环 |
| P1 | 装饰、过场、角色皮肤 | 暂缓 |

### 阶段 C：Demo / 上线版

目标从“能看懂”升级到“风格稳定、可维护、能继续迭代”。

必须建立一份 Style Bible：

| 字段 | 必填内容 |
| --- | --- |
| 游戏视角 | 俯视、侧视、45 度、卡片、UI 图标 |
| 线条 | 无描边、细描边、粗描边、手绘线 |
| 色彩 | 主色、辅助色、禁用色 |
| 材质 | 塑料、玻璃、纸片、手绘、流体、金属 |
| 光影 | 扁平、柔光、强高光、暗部层次 |
| 背景 | 透明、纯色、场景截图 |
| 导出 | PNG、透明背景、统一分辨率、统一留白 |

## 母图原则

下一项目不要只凭“这张好看”确认风格。先做 1 张母图。

母图必须同时满足：

- 能代表最终游戏画面。
- 包含 3-5 个关键资产。
- 能看清线条、材质、光影、色彩。
- 后续资源都能拿它当参考。

## 单个资产生成卡

每个正式资产生成前，先写清楚：

| 字段 | 示例 |
| --- | --- |
| 资产名 | lipstick_red_01 |
| 用途 | 可堆叠化妆品 |
| 视角 | 45 度俯视 |
| 尺寸 | 512x512，透明背景 |
| 风格参考 | 母图 / Style Reference |
| 必须保留 | 粗描边、粉色塑料材质、清晰高光 |
| 禁止出现 | 写实摄影、复杂背景、文字、水印 |

## Unity 导入检查表

| 检查项 | 标准 |
| --- | --- |
| 背景 | 透明或已统一底色 |
| 白边 | 深色/浅色背景下都不明显 |
| 尺寸 | 同类资产统一像素尺寸 |
| 留白 | 图标和道具边距一致 |
| 透视 | 同类资产视角一致 |
| 描边 | 粗细一致 |
| 颜色 | 不偏离 Style Bible |
| 命名 | 与 Unity prefab / sprite 名一致 |

## 下一项目改进策略

| 问题 | 改进动作 |
| --- | --- |
| 抽卡太痛苦 | 先固定 Style Bible 和母图，再批量生成 |
| 风格不统一 | 每批资产只允许使用同一母图、同一提示词前缀、同一负向词 |
| 描边粗细不同 | 把“line weight / outline thickness”写进提示词和验收表 |
| 白边明显 | 导入 Unity 前统一做白边检查，不合格不进项目 |
| 资产越做越乱 | 用资产生成卡 + P0/P1/P2 优先级管理 |

## 何时升级到高控制力流程

只有项目通过概念验证，并且美术一致性已经成为继续推进的核心瓶颈时，才考虑 Stable Diffusion / ComfyUI / LoRA。

触发条件：

- 同风格角色或道具数量很大。
- 在线工具抽卡成本超过学习和训练成本。
- 美术风格本身是项目护城河。
- 需要同一角色多动作、多表情、换装或长期复用。

## 核心原则

- 概念验证阶段，美术服务“看懂和想玩”。
- 7 天切片阶段，美术服务“测试不被占位图干扰”。
- Demo 阶段，美术服务“风格稳定和可迭代”。
- 不要为了追求一张神图，牺牲一整套资产的统一性。

## 概念视频关键帧连续性规则

AI 概念视频不是一组漂亮插画，而是“未来真实游戏录屏”的伪装版本。关键帧要优先保证空间、角色、场景、操作逻辑连续。

制作顺序：

1. 先生成一张 `1:1` 或 `4:3` 场景母版，而不是直接生成竖屏海报。
2. 从母版裁出 `9:16` 镜头：花圃区、门口小摊区、扩建区、升级区。
3. 每张关键帧都用同一角色、同一地图布局、同一画风参考图。
4. 文字、数字、金币数量、倒计时、按钮文案后期叠加，不交给生图模型。
5. 如果某帧场景逻辑不成立，先补承接帧，不要靠字幕硬解释。

花园经营类关键帧示例链路：

```
枯园起点 -> 第一朵花长出 -> 小摊交易 -> 回到花圃准备扩建 -> 1 格扩成 3x3
```

新增承接帧的作用不是“多做几张图”，而是避免观众觉得土地、小摊、角色和操作突然跳变。

## UI 与场景的归属规则

| 元素 | 应该放哪里 | 原因 |
| --- | --- | --- |
| 顾客订单气泡 | 只在顾客头顶 | 它属于场景对象，不应跟着角色移动 |
| 订单进度 HUD | 屏幕左上角固定 | 它属于游戏 UI，可以跨场景镜头存在 |
| 金币飞行动画 | 后期叠加 | 更容易控制路径和数量 |
| 中文、数字、倒计时 | 后期叠加 | AI 容易生成乱码 |
| 招募园丁 | 招募公告牌 | 人不能像道具一样从商店购买 |
| 洒水器 | 工具升级牌 | 工具升级和劳务招募要分开 |

## Seedance / 即梦图生视频拆段规则

图生视频生成时按“首帧 -> 尾帧”的小动作拆段，单段控制在 3-4 秒。

通用提示词应固定：

- 竖屏 9:16。
- 休闲模拟经营手游真实玩法演示。
- 2.5D 等距视角。
- 固定手机游戏镜头。
- 保持同一个角色、同一地图布局、同一套明亮卡通画风。
- 不要大幅旋转镜头，不要改变场景布局，不要生成文字或数字。

负向词重点：

- 不要写实风格。
- 不要电影镜头。
- 不要角色变形。
- 不要新增无关建筑。
- 不要文字乱码。
- 不要让 UI 扭曲。

完成后在剪映里再叠字幕、金币、按钮、倒计时、手指拖动和轻 CTA。

## 项目风格提示词要先写成 Style Bible

《光与朽》的 Synthwave / Retrowave 视觉讨论可以沉淀成一个通用规则：不要每张图临时写提示词，先把项目的风格语言压成稳定前缀，再基于前缀生成截图、UI、图标和视频关键帧。

Style Bible 最少要包含：

| 字段 | 示例 |
| --- | --- |
| 画面比例 | 9:16 竖屏手机游戏截图 |
| 核心对象 | 底部棱镜塔、旋转激光、黑色油泥怪、发光眼睛 |
| 场景语言 | 暗紫/靛蓝网格虚空、霓虹青、热粉、激光绿 |
| UI 语言 | 半透明黑色玻璃面板、高对比、干净矢量、不要 AI 生成中文 |
| 风格边界 | 不写实、不电影镜头、不厚重 3D、不暗到看不清玩法 |

提示词的目标不是“好看”，而是让陌生人 3 秒内看出游戏对象、攻击关系和操作幻想。风格词必须服务玩法可读性。

## 竖屏 HUD 先按眼睛和手指分区

竖屏动作游戏的 HUD 要遵循“上眼下手”：上半屏给眼睛看目标和状态，下半屏给手指操作，中心区域尽量留给战斗对象。

| 区域 | 适合放置 | 注意事项 |
| --- | --- | --- |
| 顶部 | 暂停、倒计时、资源、击杀数、Boss 血条 | Boss 出现后血条可替代倒计时 |
| 中央 | 怪物、激光、弱点、危险提示 | 不给普通怪堆血条，避免遮住弹性油泥表现 |
| 底部边缘 | XP 条、塔血量、护盾弧 | 靠近玩家视线和操作焦点 |
| 右下/左下 | 大招、拖动区域、短按钮 | 避免遮住来敌路线 |

如果玩法靠怪群、激光和弱点识别成立，HUD 就要少解释、多指向。章节名可以短暂出现后淡出，倒计时、Boss 血条和危险提示才是持续信息。

## 模型制作先让 AI 分析形体，再选高模降面

用 AI 辅助建模时，不要一开始就让它给制作方案。更稳的顺序是先让 AI 分析参考图的形体结构：大轮廓、体块比例、关键装饰、材质层次、哪些部分必须保留。只有形体语言被拆清楚后，再选择在线 AI 生成高模、进入 Blender 降面、清理拓扑和导出 Unity。

这条流程适合 P0/P1 低门槛资产：先用 AI 快速拿到可视化体块，再用 Blender 做可控减面和规范化。它不替代正式 3D 美术，但能减少“看起来像，但不知道像在哪里”的返工。

## 怪物 AI 图要从“玩法角色”推到“剪影、眼睛、挂件”

《光与朽》的怪物不是普通立绘资产，而是 Unity 里分层渲染的战斗对象：身体层用 RT / Metaballs 融合，眼睛层单独叠，挂件和特效层再叠上去。因此 AI 美术提示词不能只写“可爱怪物”“熔岩怪物”，要按工程结构倒推。

推荐顺序：

1. 先确定玩法角色：冲锋、分裂、远程、坦克、光环、Boss。
2. 再确定身体剪影：圆、椭圆、宽胖、碎裂、结晶、多面体。
3. 再确定眼睛规则：移动端小尺寸可读，优先简单表情，不依赖细小瞳孔、3D 凸眼或 `><` 这类容易糊的符号。
4. 再确定机制挂件：裂缝、核心、炮口、冰甲、光环、晶体、熔岩泡。
5. 最后才上章节材质：黑油、熔岩、寒冰等。

新章节不能只是换颜色。第二章熔岩应让分裂、自爆、坦克、远程、熔岩蛋 Boss 在剪影和挂件上可辨；第三章冰霜应突出秩序、几何、冰甲、光环、施法与钻石冰晶 Boss。材质是最后一层，角色功能才是第一层。

## 先生成整体参考，再拆身体、眼睛、核心、裂缝等层

AI 出图工作流可以分两步：

| 阶段 | 目标 | 注意 |
| --- | --- | --- |
| 整体参考 | 看角色是否一眼能读出玩法和章节气质 | 允许有混合层，但要明确结构 |
| 分层资产 | 分别生成 Body、Eyes、Core、Crack Overlay、Accessory | 白底或透明底、俯视、无文字、无水印 |

例如分裂怪不要让 AI 一次性输出最终 Unity 图，而是先定“1.3 倍 Slime 的不规则椭圆身体、边缘冒泡、三个黄色发光核心、裂缝覆盖层、三对惊恐眼睛”。导入时的层级可以是 Body -> Crack Overlay -> Cores -> Eyes。这样既保留 AI 的形体速度，又不把后期表现绑死在一张不可控合成图里。

## Boss 形体升级要考虑玩法与工程复杂度

章节 Boss 的形体可以按“几何复杂度”推进：

| 章节 | Boss 形体 | 设计价值 |
| --- | --- | --- |
| 第一章 | 球形 / 黑油 / 有机混沌 | 易读、适合初始 Boss |
| 第二章 | 横向开裂的熔岩蛋 | 有孕育和爆裂感，能承接召唤/吸收 |
| 第三章 | 多面体钻石冰晶 | 秩序、寒冷、坚硬，和冰墙/冻结一致 |

不要为了“更酷”轻易做多节虫、蛇形 Boss。它会额外引入多段跟随、碰撞体、推挤、Metaballs 连接和状态机同步问题。个人项目里，Boss 形体差异化要服务技能和可实现性，不能只服务设定图。

## Synthwave 怪物提示词要锁定“黑色乙烯基玩具 + 俯视资产”

《光与朽》第一章怪物的成功风格可以抽象成一个可复用提示词骨架：

| 维度 | 规则 |
| --- | --- |
| 视角 | 纯 2D 俯视 / top-down view，避免侧面和透视插画 |
| 主体材质 | glossy black vinyl toy / wet asphalt / black oil |
| 渲染 | clean vector aesthetics、cel-shaded、toy-like，不要写实噪点 |
| 背景 | white background / transparent background |
| 结构 | 基础形状 + 眼睛 + 半嵌入式挂件 |
| 反向词 | no photorealistic、no gritty dirt、no side view、no messy texture |

关键不是让 AI 画“更炫的怪”，而是让每个怪像同一个资产库里量产出来的组件。材质统一靠黑色乙烯基主体，区分度靠剪影、眼睛和挂件。

## 怪物组用“基础形状、眼睛、挂件”三列表管理

可复用怪物设计表：

| 怪物 | 基础形状 | 眼睛 | 核心挂件 |
| --- | --- | --- | --- |
| Tank | 圆角方块 / 厚块 | 半眯眼或装甲独眼 | 废土装甲、铁板、石块、钢筋 |
| Drifter | 菱形 / 新月 / 箭头 | 晕眩眼或疯狂错位眼 | 霓虹滑翔鳍、排气管、锯齿边 |
| Treasure Mimic | 臃肿扁圆 | 紧闭眼 | 半埋金币、晶体、财宝堆 |
| Sniper | 正三角 / 指向形 | 单眼准星 | 霓虹瞄准环、天线 |
| Bomber | 多刺球体 | 疯狂小瞳孔 | 引信、发光裂纹 |
| Healer | 水滴 / 软十字 | 笑眼 | 绿色医疗无人机、`+` 号标识 |

挂件要“半嵌入”黑油身体，而不是漂浮在表面。这样 Unity 后续分层时也更自然：身体层负责流体融合，挂件层负责识别机制。

## 美术诊断要把“感觉不搭”翻译成可改参数

做 AI 美术和 UI 统一时，不要只说“风格不统一”。更有效的诊断流程是：

1. 先判断整体风格：卡通、扁平、轻拟物、写实、Synthwave、超休闲等。
2. 再逐项拆 UI、角色、场景、物件、字体。
3. 对每个问题指出具体维度：线条粗细、形状语言、饱和度、明度、材质、光影、透视、信息密度。
4. 给执行级修改：圆角、描边、阴影、材质词、视角词、负向词。
5. 最后生成 Prompt 和项目级 Checklist。

AI 美术协作的价值不在“会夸好看”，而在把审美判断转译成模型能执行、人也能复查的规则。

## 无人机和奖励物要用“构图固定 + 换色换标”

为波间奖励生成一组三个无人机时，不要每个从头写完全不同的 Prompt。更稳定的方法是固定构图和材质，只替换颜色与图标：

| 类型 | 主色 | 图标 |
| --- | --- | --- |
| 补给 | 白绿 / 医疗绿 | 心、十字、护盾 |
| 随机 | 紫金 / 奖励金 | 问号、骰子、星光 |
| 契约 | 黑红 / 警示红 | 警告、破碎心、危险三角 |

提示词中明确：3/4 俯视、赛博朋克四旋翼无人机、起落架抓住补给箱、箱子正面有发光全息图标、干净玩具感 3D 渲染、纯白背景、无文字、无脏污。拿到满意造型后，再用重绘或固定 Seed 换色换标，能显著减少风格漂移。

## 角色 AI 生成先写 Style Bible，再写单个 Prompt

同批怪物要一致，必须先定义风格总纲，而不是一只一只即兴写。Style Bible 至少包括：

| 项 | 示例 |
| --- | --- |
| 游戏类型 | 2D / 俯视 / 超休闲手游 |
| 角色视角 | top-down / full frontal / centered |
| 比例 | Q 版、半 Q、夸张几何 |
| 线条 | 粗描边、细描边、无描边 |
| 上色 | 平涂、轻渐变、无复杂体积 |
| 光影 | 单一主光源、无写实阴影 |
| 小屏适配 | 清晰轮廓、少细碎、强识别 |

Prompt 结构也要固定：

- Positive：2D game asset、flat stylized、clean silhouette、mobile game、same universe。
- Style Lock：consistent proportions、same rendering style、simple shapes、high readability。
- Negative：realistic、anime、painterly、photorealistic lighting、messy proportions、complex background。
- Output：plain background、single character、full body、transparent preferred。

有参考图时，不要只写“like this image”。要先抽象比例、线条、上色、光影和材质，再生成“风格相似但不侵权”的描述。

## Chic & Clean 风格先是可读性系统，然后才是高级感

美妆 UI 的高级感不能靠闪粉、阴影和金属渐变堆出来。`Chic & Clean` 的项目规则应当先保证玩家第一眼能识别订单、槽位、道具、按钮和奖励，再用低强度材质营造精致感。

| 维度 | 规则 |
| --- | --- |
| 形状 | 主交互元素用简洁矩形/中等圆角，装饰曲线降到低层级 |
| 颜色 | 白/奶油底 + 腮红粉/柔金/冷灰，功能色对比必须高于装饰色 |
| 文字 | 正文对比度要足够，深炭灰优于纯黑，次级文字用中灰 |
| 留白 | 8px 栅格，24px 作为模块间距，主要操作区周围留更大空间 |
| 装饰 | 光斑、纹理、闪粉透明度低，不覆盖数值和图标 |
| 动效 | 点击 120-180ms，奖励 600ms 左右，可跳过 |

Prompt 里可以写“luxury cosmetics”，但必须用 `high readability`、`clear contour`、`uncluttered`、`balanced spacing and hierarchy` 限定，否则模型会默认生成广告海报而不是可玩的 UI。

## AI 美术 Prompt 的否定词要描述材质，不只写 no

在 Midjourney / Nano Banana 里，`no shadows`、`no stars` 常常不够强，因为“美妆 + luxury”会自动联想到反光、星点、镜面高光。更稳定的方式是用正向材质词压住模型倾向。

| 想避免 | 弱写法 | 更稳写法 |
| --- | --- | --- |
| 星光 | no stars | matte finish, no sparkles, no glow, no lens flare |
| 阴影 | no shadows | flat color only, no light source, no shading |
| 复杂材质 | no texture | pure color surfaces, solid vector fill |
| 风格漂移 | same style | consistent mobile game icon style, cohesive set |

美妆道具批量模板：

```text
Create a 2D vector-style illustration of [item],
in chic & clean aesthetic, flat and minimal design,
soft pastel gradients without light reflection,
clear rounded contours, matte finish,
luxury cosmetics product mockup style,
white background, consistent style across items,
high resolution, no watermark, no text on the product.
```

如果生成出来仍然有星星、强阴影或镜面反光，先降低 `luxury`、`glossy`、`gradient` 的权重，再补 `matte finish` 和 `solid vector fill`。

## UI 组件 Prompt 要按功能组件拆，不要一次生成完整游戏

美妆叠叠乐的 UI 生成经验说明：槽位栏、主界面、设置面板、胜利进度条这些组件应该分开生成。一次让 AI 生成完整关卡图，往往会把按钮、字体、背景和玩法区混成一张不可切图的概念图。

| 组件 | Prompt 重点 |
| --- | --- |
| 槽位栏 | 珍珠/玻璃质感、3 个圆角矩形槽、可放化妆品、干净背景 |
| 主界面 | 背景淡化、中景留白、按钮突出，避免背景装饰抢 UI |
| 设置面板 | 只生成面板结构；标题区和内容底板分层；不生成文字和图标 |
| 胜利进度条 | 粉金渐变、下一个藏品进度、两端奖励图标、层级清晰 |
| 关卡迭代图 | 明确堆叠区底板、按钮、字体、化妆品投影和背景层级 |

先用 AI 生成“可参考的组件视觉”，再在 Figma / Unity 中重搭真实 UI。不要指望 AI 直接给出能上线的中文按钮、精准像素布局和可交互层级。

## 截图诊断要把“画面不好看”拆成可改层级

美术迭代时，诊断顺序比灵感更重要。对一张关卡截图，可以固定按这些层级拆：

1. 整体风格是否统一：少女感、清新、时尚是否同时存在。
2. 背景是否有分区底板：堆叠区有没有柔和边界或阴影。
3. 核心物件是否可读：化妆品颜色、投影、边缘光是否足够区分。
4. 字体是否项目化：避免默认 Arial；换成可商用中文 UI 字体。
5. 按钮是否有状态：渐变、描边、阴影、点击反馈。
6. 层级是否清楚：背景 < 堆叠区 < UI 框体 < 字体。

这样产出的 Prompt 会更接近“修改方案”，而不是重新抽一张漂亮但不可用的图。

## Chic & Clean 资产要先服务点击和识别，再服务高级感

美妆叠叠乐的 `Chic & Clean` 不是“粉金 + 闪光 + 高级材质”的堆叠，而是一套移动端可读性系统。截图诊断时先看玩家能不能一眼分清订单、堆叠区、临时槽、道具和奖励，再谈质感。

| --- | --- |
| 形状 | 主操作元素用圆角矩形、软椭圆和简洁轮廓；小控件圆角约 8px，卡片约 16px，弹窗约 24px |

## 工具图标要固定功能语义，不要只画“漂亮小物件”

| --- | --- |

## 批量化妆品资产表要按“缩略图可识别”设计字段

| 字段 | 作用 |

| 品牌 / 名称 / 类型 | 保证收藏馆和订单系统能复用同一批资产 |
| 形状描述 | 先控制轮廓，避免全部变成相似瓶罐 |
| 主色 / 辅助色 | 让同品牌统一，同时保留品类区分 |
| 特征点 | 在小图里仍能识别的唯一记忆点，例如蝴蝶结、圆盖、斜切口、透明液体 |
| 点击尺寸 | 标记 S/M/L，过滤太细、太薄、太难点的物件 |
| 美术提示词 | 用同一模板量产，减少风格漂移 |

## 美妆 UI 色板要先定功能色，再让 AI 生成

美妆叠叠乐早期截图诊断里，一个可复用经验是：不要让 AI 自己理解“高级粉色”。先给它明确色板和层级，否则很容易生成死亡芭比粉、脏棕色和低对比 UI。

| 用途 | 建议色 |
| --- | --- |
| 主背景 | 柔和米白 `#F5F5F5` |
| 主品牌色 | 烟粉 / 豆沙粉 `#EAD1D1` |
| 点缀高光 | 香槟金 `#E0C9A6` |
| 文字 / 图标 | 木炭灰 `#333333` |
| 堆叠区底板 | 米灰 `#F0EBE3`，配 4%-6% 低透明内阴影 |
| 空临时槽 | 浅灰 `#E0E0E0` + `#CCCCCC` 虚线边框 |

AI Prompt 要把色板写进提示词，例如 `color palette of soft blush pink (#EAD1D1), champagne gold (#E0C9A6), off-white (#F5F5F5), charcoal gray (#333333)`。这比笼统写 `luxury pink cosmetics UI` 稳定得多。

## 订单包视觉系统用“形状即指令”，不要只靠颜色

品牌包、颜色包、类别包、普通包如果都靠包身颜色区分，会互相打架。更稳的视觉系统是：第一层用包型区分任务类型，第二层用吊牌、图标和颜色表达具体要求。

| 订单类型 | 包型 | 核心识别物 |
| --- | --- | --- |
| 普通包 | 经典托特包 | 无特殊标识，统一中性色 |
| 品牌包 | 结构化手提包 / 链条方包 | 金属品牌 Logo 或字母吊牌 |
| 颜色包 | 水桶包 | 包身用任务纯色，或挂色卡吊牌 |
| 类别包 | 专业化妆箱 | 包身正面印品类图标，例如口红、粉饼、睫毛夹 |

这套规则的好处是尺寸和槽位位置可以固定，玩家仍能快速理解订单类型。美术不是给包换皮，而是在给玩法做“视觉语法”。

## 完美订单优先加独立边框，不要改订单背景

完美订单的视觉反馈适合叠加在订单包上层，例如“星屑光环”或“珍珠链条”边框。不要优先更换订单区背景，因为背景色可能和品牌包、颜色包本身冲突。

推荐层级：

1. 底层：可选柔和聚光光晕，只做氛围。
2. 中层：订单包本体，保持品牌/颜色/类别信息清晰。
3. 顶层：动态香槟金或珍珠白边框，表达“这是高价值订单”。

Prompt 关键词可写：`shimmering stardust frame, sparkling champagne gold border, game UI asset, perfect reward effect, clean, chic, subtle animated highlight`。

## 美妆 AI 资产要拆成“风格词库 + 组件模板 + 审图清单”

美妆叠叠乐早期 AI 美术对话的长期价值，不是某一句 Prompt，而是把“高级清爽美妆风”拆成可重复生产的组件系统。对个人开发者更稳的顺序是：

1. 先锁风格词库：`2D game asset`、`flat vector illustration`、`chic and clean`、`soft pastel gradient`、`gentle highlights`、`white background`、`no text on product`。
2. 再按组件生成：单个化妆品、订单包、临时槽、道具按钮、设置面板、胜利面板、排行榜图标分别出图，不要一次让 AI 生成整屏可切图 UI。
3. 最后用审图清单过滤：缩略图是否可识别、色彩是否过粉/过棕、字体是否误生成、堆叠区边界是否清楚、按钮状态是否能分辨。

可复用的单物件模板：

```text
A single [item name], 2D game asset, flat vector illustration, chic and clean cosmetics style, soft pastel gradient, gentle glossy highlight, clear silhouette, minimal decoration, white background, no text on product, high recognizability, mobile game icon.
```

生成美妆关卡图时，要把玩法区结构写清：顶部 4 个订单包、中间 5 个临时槽、主游戏区散落但可读的化妆品、底部 3 个道具按钮。AI 输出如果只变成“漂亮化妆台海报”，就不能直接服务玩法。

## 高级清爽风不是单一粉色，而是受控色板

源对话里反复出现的问题是：单页不能全部偏棕或偏粉。美妆物件的色彩需要“统一饱和度 + 多品类层次”，否则堆叠区会变成一团粉棕噪声。

| 设计层 | 规则 |
| --- | --- |
| 主背景 | 奶白、暖灰、浅米色，降低存在感 |
| 物件主色 | 每页混合暖红、珊瑚粉、薄荷绿、烟熏紫、奶油杏、香槟金等，不让同色占满 |
| 金属点缀 | 只用玫瑰金、香槟金、磨砂银等少量统一材质 |
| 轮廓控制 | 小图优先清晰剪影，真实包装和花纹只能作为低强度细节 |
| 负面约束 | 避免厚重阴影、强闪光、星光粒子、过度写实、产品文字和水印 |

AI 生成 30/40 个化妆品表时，字段至少要包含名称、类型、尺寸、虚拟品牌、主色、特征点和辅助说明。不要让 AI 直接“自由发挥一批化妆品”，而是让它在色板和形状库里受控组合。

## 买量美术先看 3 秒识别，再看资产精度

这份美术趋势归档的长期价值不是某个具体风格，而是买量视觉的优先级：用户先在 3 秒内看懂“这是什么、爽点在哪里”，再决定是否在意细节。

低成本可用的三类视觉策略：

| 策略 | 适用场景 | 小团队做法 |
| --- | --- | --- |
| 高饱和软糖 3D | 解压、合成、经营、轻策略 | 若 3D 产能不足，只学习圆角、高光、低心理压力 |
| 极简主体 + 爆炸反馈 | 战斗、切割、清怪、破坏 | 主体 2-3 个色块，资源砸在命中、爆裂、升级瞬间 |
| 微观猎奇视角 | 日常物件、身体/清理、微缩世界 | 用熟悉物件 + 夸张尺度抓前 3 秒 |

对《光与朽》这类单人项目，最适合的是“极简 2D 矢量主体 + 廉价但密集的 Unity 光效粒子”。不要回头追厚涂或重 3D，把钱和时间花在命中反馈、升级爆点、Boss 出场轮廓和激光折射上。

## 买量封面级主视觉先行

素材测试时先做“玩家能不能被第一眼吸住”的封面级主视觉，再补系统内细节。封面不等于骗玩法，而是把真实核心动作夸张表达出来。

检查清单：

- 主体轮廓是否足够大。
- 动作是否一眼能懂，例如切割、爆炸、吞噬、拉扯、整理完成。
- 颜色是否在手机小屏上有强对比。
- 反馈是否比主体更抢眼，但不遮挡玩法。
- 画面是否表达真实可玩核心，而不是纯海报氛围。
