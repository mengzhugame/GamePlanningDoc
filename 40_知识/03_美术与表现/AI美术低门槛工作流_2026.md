# AI 美术低门槛工作流 2026

> 适用场景：个人开发者不想搭 Stable Diffusion、不训练 LoRA、不依赖本地显卡，用在线 AI 工具快速完成概念图、概念视频关键帧和游戏 P0 美术资产。

## 当前真实流程

| 阶段 | 做法 | 常用工具 | 产出 |
| --- | --- | --- | --- |
| 1. 提示词生成 | 用 AI 把玩法、题材、视角翻译成美术提示词 | ChatGPT / Gemini | 风格描述、关键词、负向词 |
| 2. 概念图抽卡 | 生成 1 张最能代表游戏的概念图 | ChatGPT Image / Nano Banana / 即梦 AI | 基础风格图 |
| 3. 风格确认 | 选满意图作为基础风格参考 | 人工筛选 | Style Reference |
| 4. 资产生成 | 基于基础风格图生成角色、道具、场景、UI | Lovart / 即梦 AI / Whisk 或同类在线工具 | 游戏资源图 |
| 5. 清理切图 | 抠图、修白边、统一尺寸、导入 Unity | Photoshop / 在线抠图 / Unity | 可用 PNG 资产 |

## 这个流程的优缺点

| 维度 | 结论 |
| --- | --- |
| 优点 | 快，不需要本地显卡，不需要学 SD/ComfyUI/LoRA，适合概念视频和 7 天切片 |
| 缺点 | 抽卡痛苦，风格容易漂，描边粗细不同，白边脏，资源规格不统一 |
| 适合 | 创意验证、AI 概念视频、7 天垂直切片、低成本 Demo |
| 不适合 | 大量角色长期量产、强一致商业级美术、需要稳定换装或同角色多动作的项目 |

## 阶段版 SOP

### 阶段 A：概念验证期

目标不是做资产，而是验证“这张画面能不能让人停下来看、能不能理解玩法”。

| 要做 | 不做 |
| --- | --- |
| 1 张基础风格图 | 不批量做资产 |
| 3-4 张概念视频关键帧 | 不做完整 UI 套件 |
| 统一前缀和负向词 | 不纠结每张图 100% 一致 |
| 剪映后期叠 UI、血条、手指、文字 | 不让 AI 直接生成中文文字 |

### 阶段 B：7 天垂直切片期

目标是让原型能被陌生玩家看懂。

| 资产优先级 | 内容 | 验收标准 |
| --- | --- | --- |
| P0 | 核心操作对象、失败对象、奖励对象 | 3 秒内能看懂用途 |
| P0 | 1 个场景背景或纯色底 | 不干扰核心玩法 |
| P0 | 关键 UI：开始、失败、胜利、奖励 | 能完成测试闭环 |
| P1 | 装饰、过场、角色皮肤 | 暂缓 |

### 阶段 C：Demo / 上线版

目标从“能看懂”升级到“风格稳定、可维护、能继续迭代”。

必须建立一份 Style Bible：

| 字段 | 必填内容 |
| --- | --- |
| 游戏视角 | 俯视、侧视、45 度、卡片、UI 图标 |
| 线条 | 无描边、细描边、粗描边、手绘线 |
| 色彩 | 主色、辅助色、禁用色 |
| 材质 | 塑料、玻璃、纸片、手绘、流体、金属 |
| 光影 | 扁平、柔光、强高光、暗部层次 |
| 背景 | 透明、纯色、场景截图 |
| 导出 | PNG、透明背景、统一分辨率、统一留白 |

## 母图原则

下一项目不要只凭“这张好看”确认风格。先做 1 张母图。

母图必须同时满足：

- 能代表最终游戏画面。
- 包含 3-5 个关键资产。
- 能看清线条、材质、光影、色彩。
- 后续资源都能拿它当参考。

## 单个资产生成卡

每个正式资产生成前，先写清楚：

| 字段 | 示例 |
| --- | --- |
| 资产名 | lipstick_red_01 |
| 用途 | 可堆叠化妆品 |
| 视角 | 45 度俯视 |
| 尺寸 | 512x512，透明背景 |
| 风格参考 | 母图 / Style Reference |
| 必须保留 | 粗描边、粉色塑料材质、清晰高光 |
| 禁止出现 | 写实摄影、复杂背景、文字、水印 |

## Unity 导入检查表

| 检查项 | 标准 |
| --- | --- |
| 背景 | 透明或已统一底色 |
| 白边 | 深色/浅色背景下都不明显 |
| 尺寸 | 同类资产统一像素尺寸 |
| 留白 | 图标和道具边距一致 |
| 透视 | 同类资产视角一致 |
| 描边 | 粗细一致 |
| 颜色 | 不偏离 Style Bible |
| 命名 | 与 Unity prefab / sprite 名一致 |

## 下一项目改进策略

| 问题 | 改进动作 |
| --- | --- |
| 抽卡太痛苦 | 先固定 Style Bible 和母图，再批量生成 |
| 风格不统一 | 每批资产只允许使用同一母图、同一提示词前缀、同一负向词 |
| 描边粗细不同 | 把“line weight / outline thickness”写进提示词和验收表 |
| 白边明显 | 导入 Unity 前统一做白边检查，不合格不进项目 |
| 资产越做越乱 | 用资产生成卡 + P0/P1/P2 优先级管理 |

## 何时升级到高控制力流程

只有项目通过概念验证，并且美术一致性已经成为继续推进的核心瓶颈时，才考虑 Stable Diffusion / ComfyUI / LoRA。

触发条件：

- 同风格角色或道具数量很大。
- 在线工具抽卡成本超过学习和训练成本。
- 美术风格本身是项目护城河。
- 需要同一角色多动作、多表情、换装或长期复用。

## 核心原则

- 概念验证阶段，美术服务“看懂和想玩”。
- 7 天切片阶段，美术服务“测试不被占位图干扰”。
- Demo 阶段，美术服务“风格稳定和可迭代”。
- 不要为了追求一张神图，牺牲一整套资产的统一性。
