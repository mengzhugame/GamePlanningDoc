# 休闲小游戏正式立项流程 v1

> 目标：当一个创意已经通过概念验证后，用阶段闸门推进到 7 天切片、Demo、上线测试和项目复盘。每一阶段都有退出机制。

## 启动条件

只有同时满足以下条件，才进入本 SOP：

| 条件 | 证据位置 |
| --- | --- |
| 创意已在总表登记 | `00_草稿/游戏创意库/00_游戏创意总表.md` |
| 已有概念卡 | `00_草稿/游戏创意库/创意名_概念卡.md` |
| 已有 AI 概念视频数据 | `00_草稿/游戏创意库/创意名_概念视频数据记录.md` |
| T+7 决策为 Push | `00B_已通过创意表.md` |
| 三条立项铁律全过 | 概念卡或立项拷问摘要 |

没有上述证据，不创建 `20_项目/`。

## 阶段总览

| 阶段 | 时长 | 目标 | 主要产出 | 通过条件 |
| --- | --- | --- | --- | --- |
| 0. 立项审查 | 0.5-1 天 | 决定是否值得创建项目目录 | 立项审查表、止损线 | 范围、风险、验证目标清楚 |
| 1. 玩法聊透 | 1-2 天 | 把核心玩法说透 | 轻量 GDD、核心循环、失败与广告点 | 能拆到 7 天切片 |
| 2. 7 天垂直切片 | 7 天 | 验证核心机制真的能玩 | 最小可玩原型 | 自己愿意连续玩，且能给陌生人测 |
| 3. 陌生玩家原型测试 | 2-4 天 | 看玩家是否理解和愿意继续 | 测试记录、问题清单 | 至少 20 个陌生玩家或足够明确的定性信号 |
| 4. 1 个月 Demo | 4 周内 | 做出可公开测试版本 | Demo、基础美术、音效、埋点、广告预留 | 可以发布视频或上传测试 |
| 5. 上线版制作 | 2-6 周 | 做到微信小游戏 80% 完整度 | 上线包、后台配置、数据表 | 能上线，崩溃/广告/存档可控 |
| 6. 上线 72 小时验证 | 3-14 天 | 用真实数据决定扩张或止损 | 上线数据复盘 | D1、广告、留存或买量信号明确 |
| 7. 项目复盘沉淀 | 0.5-2 天 | 把经验变成资产和知识 | 项目复盘、资产清单、知识更新 | 可复用内容已迁入知识区 |

## 阶段 0：立项审查

### 必答问题

| 问题 | 通过标准 |
| --- | --- |
| 为什么现在做它 | 不是因为逃避当前困难 |
| 这个方向和同类最强竞品的 3 个不同点 | 能一句话讲给陌生人 |
| 1 个月 Demo 范围 | Week 1-4 能拆出来 |
| 最小可玩版本删掉什么 | 明确不做的功能比要做的功能更重要 |
| 止损线 | 时间上限、资金上限、数据下限都写清 |
| 复用价值 | 失败后至少能留下代码、美术、音效或流程资产 |

### 立项审查结论

| 结论 | 动作 |
| --- | --- |
| 通过 | 创建 `20_项目/NN_项目名项目/` |
| 暂缓 | 回到概念验证，补视频或补拷问 |
| 否决 | 创意总表标记失败，不进入项目区 |

## 阶段 1：玩法聊透

正式写代码前，先和 AI 把玩法聊透。

### 必须产出

| 文档 | 内容 |
| --- | --- |
| 轻量 GDD | 核心循环、目标、失败、关卡、广告点 |
| 7 天切片范围 | 只写核心机制，不写完整游戏 |
| 第一版数值假设 | 玩家什么时候失败，差一点在哪里 |
| 美术 Style Bible 草案 | 视角、线条、色彩、材质、导出规格 |
| 音效需求表草案 | 核心动词、成功、失败、奖励、UI |
| 数据埋点草案 | result、fail_reason、progress_at_fail、ad_watched 等 |

### 纪律

- 不先写完整策划案再做原型。
- 不先批量生产美术。
- 不把“功能很多”当作项目完整度。

## 阶段 2：7 天垂直切片

### 目标

用 7 天证明“核心动作 + 失败条件 + 反馈”成立。

### 推荐节奏

| 天数 | 任务 |
| --- | --- |
| Day 1 | 搭建核心操作和胜负条件 |
| Day 2 | 加入第一版关卡或波次 |
| Day 3 | 加入失败反馈和最小 UI |
| Day 4 | 加入 1 个广告救助假按钮或模拟奖励 |
| Day 5 | 加入 P0 美术占位或最低限度 AI 资产 |
| Day 6 | 自测 20 局，记录失败原因 |
| Day 7 | 整理切片结论：继续、改方向、停止 |

### 不做

- 不做完整剧情。
- 不做大量关卡。
- 不做 P1/P2 美术资产。
- 不接完整广告 SDK。
- 不做复杂经济系统。

## 阶段 3：陌生玩家原型测试

### 测试对象

优先陌生玩家，不用朋友圈熟人数据做核心判断。

| 渠道 | 目标 |
| --- | --- |
| 小红书评论/私信 | 找对题材感兴趣的人 |
| B 站/抖音评论 | 找对玩法感兴趣的人 |
| 微信群/社群 | 建小样本测试池 |
| itch.io 或网页包 | 方便远程测试 |

### 记录字段

| 字段 | 说明 |
| --- | --- |
| 是否看懂目标 | 玩家能否复述怎么玩 |
| 第一次失败原因 | 教学、数值、操作、理解、性能 |
| 是否想再来一局 | 复玩欲望 |
| 是否愿意看广告救回 | IAA 方向关键 |
| 玩家原话 | 不要只写总结，要留原话 |

### 闸门

| 结果 | 动作 |
| --- | --- |
| 看得懂且愿意再玩 | 进入 1 个月 Demo |
| 看得懂但不想玩 | 回到玩法或数值 |
| 看不懂 | 先改表达/教学，不急着加功能 |
| 没人愿意测 | 回到概念视频和内容运营 |

## 阶段 4：1 个月 Demo

### Demo 的定义

不是完整游戏，而是能公开给陌生人测试的版本。

### 4 周节奏

| 周 | 目标 | 产出 |
| --- | --- | --- |
| Week 1 | 核心机制稳定 | 可连续玩 3-5 分钟 |
| Week 2 | 基础内容与 P0 美术 | 3-5 关或 1 个完整章节 |
| Week 3 | 音效、反馈、埋点、广告预留 | 数据能记录，广告点能模拟 |
| Week 4 | 外部测试与视频素材 | 测试版、宣传视频、问题清单 |

### 必须做

- 核心循环完整。
- 失败原因可记录。
- 关键数据可导出或后台可看。
- 至少一条真实玩法宣传视频。

## 阶段 5：上线版制作

### 上线版 80% 完整度

“80% 完整度”不是内容做满，而是上线测试不会被基础问题污染数据。

| 模块 | 最低标准 |
| --- | --- |
| 新手引导 | 玩家知道第一步做什么 |
| 存档 | 退出再进不丢关键进度 |
| 广告 | 激励广告流程可用或有降级方案 |
| 数据 | 能看到访问、留存、失败、广告、关键漏斗 |
| 性能 | 主流手机不卡死、不频繁崩溃 |
| 素材 | 画面足够表达玩法，不追求终极画质 |

## 阶段 6：上线 72 小时验证

### 数据记录节奏

| 时间 | 看什么 |
| --- | --- |
| T+0 | 包体、登录、分享、广告、数据后台是否正常 |
| T+24h | 新增、访问路径、首局完成率、明显 bug |
| T+72h | D1、广告触发、广告完成、失败点、留存 |
| T+7d | 判断是否继续迭代或止损 |
| T+14d | 看长尾、自然量、CPS 或买量后续 |

### 买量原则

- 自然量不足以判断时，用小额买量补陌生样本。
- 买量是为了买数据，不是为了证明自己没错。
- 买量数据必须单独记录：花费、曝光、点击、激活、留存、广告、回收。

### 决策矩阵

| 数据结果 | 动作 |
| --- | --- |
| 留存好，广告触发健康 | 小额加码测试，联系发行或继续自投 |
| 留存一般，但失败点清楚 | 优化 1-2 周后再测 |
| 留存差，广告也差 | 止损，做项目复盘 |
| 自然量太少 | 不做产品结论，先补陌生样本 |

## 阶段 7：项目复盘沉淀

项目结束或阶段性停止时，必须做复盘。

### 沉淀位置

| 内容 | 位置 |
| --- | --- |
| 项目事实、版本、数据 | `20_项目/项目名/` |
| 美术流程教训 | `40_知识/03_美术与表现/` |
| 音效流程教训 | `40_知识/04_音频与节奏/` |
| 数值与广告点教训 | `40_知识/05_数值与经济/` |
| 买量、发行、上线数据教训 | `40_知识/06_发行与运营/` |
| 可复用代码 | `40_知识/02_引擎与技术/代码模板库/` |

## 总纪律

- 没有概念视频信号，不进 7 天切片。
- 没有陌生玩家原型信号，不进 Demo。
- 没有留存或买量信号，不进完整项目扩张。
- 项目失败不删除，必须复盘并资产化。

## 四层测试流程：从手感到发行

正式立项后的测试不要只分“原型/Demo”，要分四层：

| 阶段 | 目标 | 是否找陌生玩家 |
| --- | --- | --- |
| 7 天内部手感原型 | 只验证核心动作、失败反馈和“差一点” | 不强求，自己 + AI + 1-3 个懂游戏的人 |
| 21 天可测切片 | 解决基础 UI、分发、首局理解、最小美术/音效 | 可以找 10-20 个高意图玩家 |
| 50% Demo | 核心循环完整，能通过微信体验版/TapTap/网页包分发 | 必须开始外部测试 |
| 80% Demo | 不被基础问题污染数据，可找发行/买量 | 可以联系发行、小额买量 |

7 天原型不适合直接拿给泛陌生玩家测试，因为安装、iOS、包体、低保真美术都会污染反馈。这个阶段主要用于内部验收手感和规则。

## 不同时长的目标

| 周期 | 该验证什么 | 不该做什么 |
| --- | --- | --- |
| 7 天 | 一个最小玩法模块能不能看懂、玩懂、产生继续动机 | 完整项目、外围养成、大量美术 |
| 30 天 | 是否能做出可被高意图玩家测试的小循环 | 同时做两款、直接开 Steam、追求内容量 |
| 8-12 周 | 选题 -> 视频 -> 反馈 -> Demo -> 用户池这套方法能否跑通 | 用信念替代低成本证伪 |

早期创业最需要的不是“找到一个值得长期坚持的方向”，而是稳定证明自己能从市场里找到方向。
