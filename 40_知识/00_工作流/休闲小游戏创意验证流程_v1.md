# 休闲小游戏创意验证流程 v1

> **位置**：在 `立项铁律_2026-05.md` 之前执行，是"找方向"和"验证方向"的流程。
> **下游**：通过本流程的方向，进入 `独立游戏全流程开发工作流.md` 的阶段三（Demo 开发）。
> **建立时间**：2026-05-03，针对用户两次立项失败（凭朋友圈反馈、跳过原型、过度信任好点子）的根治方案。

---

## 为什么需要这个流程

**两次失败的共同根源**：

| 立项盲区 | 美妆叠叠乐 | 光与朽 | 根治方案 |
|---------|-----------|--------|---------|
| 朋友/运营反馈 ≠ 市场反馈 | ✓ | ✓ | 阶段 4 强制陌生玩家社群调研 |
| 跳过原型，直接做完整游戏 | ✓ | ✓ | 阶段 3 AI 概念视频代替原型 |
| 过度信任"好点子=好游戏" | ✓ | ✓ | 阶段 2 立项铁律拷问 |
| 完整开发 3-6 个月才知错 | ✓ | ✓ | 全流程 1 个月内可完成第一轮 |

**核心价值**：用 12 秒视频 + 1 周陌生玩家反馈，替代 3 个月完整开发的赌注。**赌错的代价从"几个月时间"压缩到"几天时间"**。

---

## 五阶段流程

```
阶段 1：创意收集（持续进行）
    ↓
阶段 2：创意筛选（立项铁律拷问）
    ↓
阶段 3：AI 概念视频制作（每方向 2-3 条）
    ↓
阶段 4：陌生玩家社群调研（多平台发布 + 数据采集）
    ↓
阶段 5：立项决策（push / pivot / kill）
```

**总时长目标**：从"想到一个方向"到"决定是否立项"，**1 周内完成**。

## 阶段 1：创意收集（持续进行）

### 1.1 三个并行的创意来源

| 来源 | 方法 | 工具 | 频次 |
|------|------|------|------|
| **市场反推** | openclaw 周度抓 50-100 条小游戏视频，按核心动词归类 | openclaw → `30_openclaw_inbox/` | 每周 |
| **核心动词 × 题材矩阵** | 10 动词 × 10 题材随机组合，找"3 秒能看懂"的概念 | 见 `超休闲游戏设计方法论.md` | 每月一次集中产出 100 个组合 |
| **个人热点 button** | 用户自己玩游戏时记下"这个机制如果换 X 题材会怎样" | `10_流水/` 当天笔记 | 随手记 |

### 1.2 输入物清单

每周整理一次：
- openclaw 上周抓到的视频频次 Top 10 动词
- 用户自己产出的概念组合
- 用户在玩别人游戏时记下的热点

汇总到 `20_项目/03_概念验证_YYYY-MM/00_概念池.md` 的"候选方向"表格。

### 1.3 不要做的事

- ❌ 把单条 openclaw 视频直接当作"立项依据"（先归类频次再说）
- ❌ 用 ChatGPT 等 LLM 生成"100 个游戏创意"列表（产出全是平均值，无差异化）
- ❌ 在 `10_流水/` 阶段就开始画美术 / 写代码

## 阶段 2：创意筛选（立项铁律拷问）

每个候选方向通过 3 条铁律拷问，参见 `40_知识/01_游戏设计/立项铁律_2026-05.md`：

```
铁律 1：3 个核心不同点能写出来吗？
铁律 2：美术差异化路径定了吗？(风格化/猎奇/反差)
铁律 3：1 个月能出 Demo 吗？
```

**触发命令**：`/iron-rule-check <方向名>` —— 自动按 skill 流程逐条问 3 条铁律,落到拷问表 + 更新概念池(skill 定义在 `90_系统/skills/skill-iron-rule-check.md`)

**手动模式**：从 `90_系统/templates/pitch-iron-rule-audit-template.md` fork 一份到 `20_项目/03_概念验证_YYYY-MM/<方向名>_立项拷问.md`,自己填

**通过率预期**：100 个候选 → 5-10 个通过铁律 → 3-5 个进入概念视频。

**关键纪律**：拷问时**不要试图美化答案**。任何一条说不清楚就否决，不要"先做出来再说"——这就是用户两次失败的核心症结。

### 2.1 拷问形式（推荐）

每个候选方向写一份 1 页纸的"立项拷问表"放到 `20_项目/03_概念验证_YYYY-MM/[方向名]_立项拷问.md`：

```markdown
# [方向名] · 立项拷问

## 一句话游戏定位
[ 玩法参考 X，题材是 Y，视觉亮点是 Z ]

## 铁律 1：3 个核心不同点
| 同类爆款 | 我们的不同 | 陌生人能复述吗 | 能拍 3 秒视频吗 |
|---------|-----------|--------------|---------------|
| [对标 1] | ... | Y/N | Y/N |
| [对标 2] | ... | Y/N | Y/N |
| [对标 3] | ... | Y/N | Y/N |

## 铁律 2：美术差异化
- 选定路径：[风格化/猎奇/反差]
- 一句话钩子：[ 看一眼就想到 XXX 的视觉印象 ]
- 参考案例：[ 哪个游戏的美术启发 ]

## 铁律 3：1 个月 Demo 范围
- Week 1：[核心机制最小可玩]
- Week 2：[3 关 + 基础美术]
- Week 3：[上线 itch.io / 发短视频]
- Week 4：[收反馈 + 决定 pivot/push]

## 三条铁律全部通过 → 进入概念视频
```

## 阶段 3：AI 概念视频制作

### 3.1 工具链

| 环节 | 工具 | 备选 |
|------|------|------|
| 关键帧生图 | ChatGPT Image 2 / 即梦 AI | Midjourney |
| 图生视频 | Seedance 2.0 | Pika / Runway |
| 后期合成 | 剪映 | Premiere |

### 3.2 制作规范（参考已有的塔防视频模板）

**虽然 90 秒极限防线项目本身被否决，但视频制作流程是可复用的**。参考 `20_项目/03_概念验证_2026-05/90秒极限防线_关键帧提示词_最后一格防线.md`：

- 4 张主关键帧（首/中/尾 + 高潮）
- 通用风格 prefix 锁定场景一致性
- 通用负向提示词避免 AI 乱生成
- 3 段图生视频运镜词（每段 3 秒）
- 后期 UI / 文字在剪映叠加（不让 AI 生文字）

### 3.3 数量与变体

每个通过铁律的方向做 2-3 条变体视频：
- 变体 A：核心机制最直白演示
- 变体 B：高潮爽点最强放大
- 变体 C：反差/猎奇美术钩子最强（如果阶段 2 美术路径选了猎奇）

### 3.4 视频结构通用骨架

```
0-1s：视觉钩子（最强反差/猎奇画面，停下用户拇指）
1-3s：3 秒讲清楚玩法规则（核心动词 + 目标）
3-10s：玩法演示（包含一次决策 + 一次反馈）
10-15s：高潮 + 结果（成功爽点 / 失败遗憾）
```

## 阶段 4：陌生玩家社群调研

### 4.1 发布矩阵

按 `超休闲游戏设计方法论.md` 的平台优先级，AI 概念视频同步发布到：

| 平台 | 优先级 | 适用方向 | 数据采集字段 |
|------|--------|---------|-------------|
| **B 站** | ★★★ | 国内核心玩家、信息密度最高 | 完播率、收藏、评论"想玩"次数、弹幕 |
| **小红书** | ★★★ | 女性向 / 治愈 / 解压 / 收纳类 | 收藏、评论"在哪玩"、追更钩子触发率 |
| **抖音** | ★★ | 高节奏 / 反转 / 钩子强类 | 完播率、点赞、评论 |
| **YouTube Shorts** | ★★ | 出海方向 | 完播率、订阅、评论 |
| **itch.io（Demo 出来后）** | ★★★ | 早期原型测试 | 下载量、Comments、Rating |

### 4.2 陌生玩家社群组建（关键新增动作）

**这是用户两次失败缺失的环节**。建议新增：

#### A. Discord 服务器（出海方向必做）
- 在 Discord 创建项目专属服务器
- 用 #devlog 频道发开发更新（一次/周）
- 在 r/IndieDev / r/playmygame 等 reddit 板块引流
- **核心纪律**：开发者本人参与对话，不外包社群运营

#### B. 小红书私域 / 微信群（国内方向必做）
- 小红书账号"游戏开发日记"人设，发开发过程视频
- 评论区出现"想玩"的用户，私信引导加微信群
- 微信群 50-100 人就够，目标是"陌生玩家"而非"朋友圈"

#### C. itch.io Devlog（Demo 出来后）
- 早于 Steam，门槛低，专门给原型测试用
- Devlog 写"上周改了什么、下周想测什么"，玩家给具体反馈
- 数据：下载量、Rating、Comment 中的具体建议

### 4.3 数据采集表格（落到 `20_项目/03_概念验证_YYYY-MM/[方向名]_概念视频数据.md`）

| 视频 | 平台 | 发布时间 | 曝光 | 完播率 | 点赞 | 收藏 | 评论 | "想玩"次数 | 加群 / 加 Discord 数 | 结论 |
|------|------|----------|------|--------|------|------|------|------------|---------------------|------|
|      |      |          |      |        |      |      |      |            |                     |      |

### 4.4 信号判断标准

| 信号 | 含义 | 下一步 |
|------|------|--------|
| 完播率 > 60% + 评论"想玩" ≥ 20 | 强信号 | 进入阶段 5 立项 |
| 完播率 > 60% 但无"想玩" | 看得懂没人想玩 | 换钩子重做 1 次视频再测 |
| 完播率 < 30% | 看不懂 | 重做表达，不判玩法死刑 |
| 两版都无信号 | 概念暂停 | 不进入立项，归档到 `90_系统/archive/` |

**纪律**：朋友/运营/发行说"新颖 / 有潜力"，**只解锁下一层验证，不解锁完整开发**（参见 CLAUDE.md / AGENTS.md 的"立项前概念验证规则"）。

## 阶段 5：立项决策

### 5.1 决策三选一

| 决策 | 触发条件 | 下一步动作 |
|------|---------|-----------|
| **Push** | 视频信号成立（阶段 4 强信号）+ 三条铁律全过 | 启动 `/new-project`，进入 1 个月 Demo 开发 |
| **Pivot** | 视频信号成立但铁律 1 差异化不够 | 调整对标，重做立项拷问表 |
| **Kill** | 两版视频都无信号，或铁律 1 始终答不出来 | 归档到 `90_系统/archive/`，回阶段 1 |

### 5.2 Push 后的执行衔接

通过本流程的方向，立即进入：
- `40_知识/独立游戏全流程开发工作流.md` 的阶段三（Demo 开发，1 个月）
- `90_系统/skills/skill-new-project.md` 的项目目录脚手架
- 同步在 `20_项目/03_概念验证_YYYY-MM/00_概念池.md` 把该方向标记为"已立项"

### 5.3 Kill 后的资产沉淀

被否决的方向不删除，归档到 `90_系统/archive/`，并在归档说明里写：
- 否决原因（哪条铁律没过 / 哪个数据不达标）
- 视频脚本 / 关键帧提示词 / 美术资产可复用的部分
- 教训（避免下次同类方向再走一遍）

参考 90秒极限防线塔防项目的归档：
- 否决日：2026-05-03
- 原因：路 A/B/C 三条全部撞上现成游戏，铁律 1 无法通过
- 教训：早期就要做"现成对手对照"，不要等 4 张关键帧出来才发现

## 不要做的事（基于两次失败教训）

- ❌ 跳过阶段 4 直接进 Demo 开发（"我朋友说不错"不算陌生玩家信号）
- ❌ 用 1 条视频判生死（至少 2-3 条变体测试钩子）
- ❌ 完播率不行就改美术（先改钩子和文案，美术是最后才动的）
- ❌ 把"发行商感兴趣"当作市场信号（发行商懂行业不等于懂玩家）
- ❌ 因为"我已经做了 4 张关键帧"就硬上（沉没成本不是继续的理由）
- ❌ 同时跑超过 2 个方向（精力分散，每个都做不深）
