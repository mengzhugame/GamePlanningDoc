# 休闲小游戏创意验证流程 v1

> 目标：在正式立项前，用低成本的概念卡、AI 概念视频和真实陌生玩家反馈，判断一个玩法创意是否值得进入 7 天垂直切片。

## 使用边界

这份 SOP 只管“立项前验证”，不创建 `20_项目/` 项目目录。

| 可以进入本流程 | 不该进入本流程 |
| --- | --- |
| 新游戏创意、题材组合、核心动词组合 | 已正式立项项目 |
| AI 批量生成后待人工筛选的候选创意 | 已经确定要开发的功能需求 |
| 想拍概念视频观察市场反应的方向 | 纯技术学习、资产整理 |

通过本流程的创意，进入 `40_知识/00_工作流/休闲小游戏正式立项流程_v1.md`。

## 阶段总览

| 阶段 | 目标 | 产出 | 进入下一阶段条件 |
| --- | --- | --- | --- |
| 0. 原始收集 | 收集灵感，不急着判断 | `00_游戏创意总表.md` 或 `00A_待审核创意表.md` | 有一句话玩法 |
| 1. 初筛拆卡 | 把模糊想法拆成概念卡 | `创意名_概念卡.md` | 3 秒能讲清核心动词 |
| 2. 铁律预审 | 先排除明显不值得做的方向 | 概念卡中的铁律摘要或立项拷问 | 无明显红牌，核心钩子可被视频表达 |
| 3. AI 概念视频 | 用视频验证“看得懂、想不想玩” | 2-3 条 10-15 秒竖屏概念视频 | 视频可发布，且不骗玩法 |
| 4. 平台发布观察 | 用陌生玩家数据看信号 | `创意名_概念视频数据记录.md` | T+7 有明确结论 |
| 5. 决策归档 | Push / Pivot / Kill | 更新三张创意表 | Push 才能进 7 天切片 |

## 阶段 0：原始收集

### 输入来源

| 来源 | 放到哪里 | 处理方式 |
| --- | --- | --- |
| 自己突然想到的玩法、题材、情绪钩子 | `10_流水/YYYY-MM-DD.md` 或 `00_游戏创意总表.md` | 简短记录，不展开制作 |
| AI 批量组合出的候选创意 | `00A_待审核创意表.md` | 等人工筛选 |
| 市场视频、竞品、用户痛点 | `30_市场分析/` | 只做素材来源，不直接变成知识 |
| 热门游戏拆解出的动词和题材 | `40_知识/07_游戏拆解库/` | 进入题材库、核心动词库或组合库 |

### 纪律

- 不在这个阶段画正式美术。
- 不在这个阶段写代码。
- 不因为“这个点子很兴奋”就跳过铁律。

## 阶段 1：初筛拆卡

把候选创意写进 `00_草稿/游戏创意库/创意名_概念卡.md`。

概念卡最少包含：

| 字段 | 判断标准 |
| --- | --- |
| 一句话玩法 | 陌生人 3 秒内能听懂 |
| 核心动词 | 例如收纳、清洁、堆叠、切割、合成、拉扯 |
| 题材外壳 | 玩家第一眼看到的世界、物品或情绪 |
| 失败条件 | 玩家为什么会输 |
| 广告救助可能性 | 如果失败，广告能补什么 |
| 短视频钩子 | 前 1-3 秒能拍出来的反差或危机 |

### 通过线

必须同时满足：

- 核心动词清楚。
- 失败条件清楚。
- 能想象出 10-15 秒视频。

如果只能描述题材，描述不出动作和失败条件，先留在待审核表，不进入概念视频。

## 阶段 2：铁律预审

每个准备拍视频的创意先读 `40_知识/01_游戏设计/立项铁律_2026-05.md`。

三条铁律：

| 铁律 | 必须回答 |
| --- | --- |
| 差异化 | 和最火同类的 3 个核心不同点是什么 |
| 美术差异化 | 走风格化、猎奇还是反差 |
| 速度换容错 | 1 个月内能不能做出可测 Demo |

### 决策

| 结果 | 动作 |
| --- | --- |
| 三条全过 | 进入阶段 3 |
| 有一条模糊，但核心动词、失败条件和视频钩子成立 | 标记“观察期”，允许做 1-2 条低成本概念视频 |
| 差异化明显撞车、核心循环说不清、1 个月 Demo 完全拆不出来 | 否决或退回阶段 1，保留原因 |

### 铁律预审不是正式立项

阶段 2 只负责挡掉明显不值得拍视频的方向，不负责证明“这个游戏一定值得做”。真正的硬审发生在阶段 5 之后：只有视频数据出现 Push 信号，且准备进入 7 天切片或 1 个月 Demo 时，才要求三条铁律全部硬通过。

这能避免两种极端：

- 还没问市场，就用过重的立项标准把新钩子掐掉。
- 只有几张 AI 图或熟人反馈，就把观察期误当正式项目。

## 阶段 3：AI 概念视频制作

### 视频原则

概念视频必须展示未来游戏里真实可能存在的核心玩法，不做广告骗玩法。

### 推荐生产链

| 环节 | 当前低门槛工具 | 注意事项 |
| --- | --- | --- |
| 视频脚本 | ChatGPT / Gemini | 只写玩法镜头，不写虚假爽点 |
| 关键帧 | ChatGPT Image / Nano Banana / 即梦 AI | 先出 3-4 张关键帧 |
| 图生视频 | Seedance / 即梦 / Runway / Pika | 每段 3-5 秒 |
| 后期 | 剪映 | UI、血条、倒计时、手指、文字后期叠加 |

### 单条视频结构

| 时间 | 内容 |
| --- | --- |
| 0-1 秒 | 最强视觉钩子：混乱、危机、反差、即将失败 |
| 1-3 秒 | 讲清核心规则：玩家做什么，目标是什么 |
| 3-10 秒 | 展示一次决策和一次反馈 |
| 10-15 秒 | 成功爽点或失败遗憾 |

### 数量

每个通过铁律的方向先做 2-3 条变体：

- A：最直白玩法演示。
- B：最强失败危机。
- C：最强美术反差或猎奇钩子。

不要一口气做 10 条。先看前 2-3 条是否有信号。

## 阶段 4：平台发布观察

所有数据记录到 `00_草稿/游戏创意库/创意名_概念视频数据记录.md`。

### 发布平台

| 平台 | 看什么 | 适合方向 |
| --- | --- | --- |
| 小红书 | 收藏、评论“想玩/在哪玩”、女性向反馈 | 收纳、治愈、情绪、生活题材 |
| B 站 | 完播、收藏、长评论、玩法讨论 | 策略、动作、开发日志 |
| 抖音 | 前 3 秒停留、点赞、评论冲动 | 爽感、反差、猎奇、高压 |
| 微信视频号 | 熟人外扩、转发、轻互动 | 微信小游戏承接测试 |

### 记录节奏

| 时间点 | 要做什么 | 决策含义 |
| --- | --- | --- |
| T+0 | 建档，记录发布时间、标题、封面、视频版本 | 以后复盘不要靠记忆 |
| T+24h | 看是否“看得懂”：完播、评论疑问、收藏 | 表达问题优先改视频 |
| T+72h | 看是否“想玩”：想玩评论、追问入口、收藏/点赞比 | 有无进入二次变体必要 |
| T+7d | 主决策：Push / Pivot / Kill | 是否进入 7 天切片 |
| T+14d | 可选长尾复盘 | 观察平台迟到流量 |

### 最小数据字段

| 字段 | 说明 |
| --- | --- |
| 平台 | 小红书/B站/视频号/抖音 |
| 视频版本 | A/B/C |
| 发布时间 | 精确到日期即可 |
| 曝光/播放 | 平台给什么就填什么 |
| 完播率 | 没有则填“后台未提供” |
| 点赞 | 基础互动 |
| 收藏 | 比点赞更重要 |
| 评论 | 评论总数 |
| 想玩评论 | “想玩/在哪玩/什么时候出/求测试”等 |
| 新增私域 | 加微信、进群、关注、私信 |
| 初步结论 | 看不懂/想玩弱/值得继续 |

## 阶段 5：决策归档

| 决策 | 触发条件 | 文件动作 |
| --- | --- | --- |
| Push | 视频信号强，铁律全过，愿意做 7 天切片 | 加入 `00B_已通过创意表.md`，准备正式立项流程阶段 0 |
| Pivot | 有人想玩，但表达、题材或差异化不稳 | 保留概念卡，重做 1 轮视频或修改题材 |
| Kill | 两轮视频无信号，或铁律答不上来 | `00_游戏创意总表.md` 标记否决，写清原因 |

### Push 不是正式立项

Push 只代表“值得做 7 天垂直切片”。正式进入 `20_项目/`，还要通过 `休闲小游戏正式立项流程_v1.md` 的阶段 0 立项审查。

## 阶段 6：复盘沉淀

每轮概念验证结束后，至少沉淀三件事：

- 哪类题材/动词组合有信号，补到 `01_题材库.md`、`01A_核心动词库.md`、`01B_游戏创意组合库.md`。
- 哪类视频钩子有效，补到概念卡或数据记录。
- 被否决的原因，留在总表中，避免未来重复踩坑。

## 绝对禁止

- 朋友说好玩就立项。
- 发行或运营说有潜力就立项。
- 没拍概念视频就做 7 天切片。
- 没有陌生玩家信号就做 Demo。
- 因为已经生成了几张图，就继续硬做。

## AI 视频反向立项的边界

AI 概念视频不是救命稻草，而是公司化验证系统里的前置模块。它解决的是“先闷头做 2-5 个月，再问市场”的问题，但不能替代手感、留存、买量、埋点和变现测试。

正确定位：

- 先用视频测试题材、风格、核心动词是否让陌生人停下。
- 不把点赞当成唯一信号，更看完播、收藏、评论欲望、私信、求测试。
- 不用 AI 视频逃避真正难的动作：陌生用户测试、小额买量、数据复盘。
- 没有明确止损线的 AI 视频计划，会变成第三个大项目。

## 从核心动词到概念视频的最小链路

核心动词不能直接丢给 AI 生成视频。最小链路应该是：

```
核心动词 -> 概念卡 -> 3 秒钩子 -> 10-15 秒玩法片段 -> 分批发布 -> 选择 1-2 个方向
```

每个视频至少回答：

- 玩家在做什么动作？
- 为什么会失败？
- 差一点在哪里？
- 成功或失败后有什么视觉反馈？
- 这个画面是否对应未来真实玩法？

如果一个动词无法拆出失败条件和反馈，就先不拍视频。

## Push / Pivot / Kill 的实际判例

### 城市水管抢修：UI 差异不能替代机制差异

“底部 3 根管道供给”只有在制造真实选择时才有意义。它必须带来资源约束、顺序规划、空间压力或不确定性；如果玩家可以随意移动已放置管道、自动通水、每根管道只占 1 格，而且方格变化还少于六边形接水管，那么底部 3 根只是多了一步拿取 UI，不是新玩法。

可复用 Kill 规则：

| 表面差异 | 是否足够 |
| --- | --- |
| 城市抢修题材 | 只是包装差异 |
| 底部 3 根供给 | 没有空间/顺序压力时只是 UI 差异 |
| 借鉴 Block Blast 三输入 | 没有消除和空间挤压，就没有借到核心压力 |

结论：Kill / 暂停。保留城市救援、水流点亮医院、红蓝危机 UI 等可复用素材，不进入切片。

### 荒废花园：TapTap 信号只解锁 Pivot，不解锁正式立项

TapTap 8 天约 `94 预约 / 894 浏览 / 10.17% 转化`，再加上评论里多次出现“想玩”，说明方向有观察价值，但还不能证明完整项目成立。

正确动作不是立刻开项目，而是强 Pivot：

- 不做快节奏自动化工厂。
- 不把“救花”误当核心玩法。
- 方向收敛为：慢节奏种花收集 + 轻自动化扩园 + 荒废花园复苏目标。
- 核心差异来自“花的双重用途”：卖花换短期资源，投入复苏换长期解锁。

7 天灰盒只验证一个问题：

> 玩家是否理解并在意“种花 -> 卖钱 / 复苏地块 -> 解锁下一片花园”这条选择链。

通过信号必须来自陌生玩家行为，而不是“画面治愈”的夸奖。至少要有人能复述：种花、卖钱、复苏地块，并表达“想继续修复下一块”。

## 技术路线也属于验证范围

创意验证阶段不要只验证“玩法想法”，也要提前约束技术表现路线，防止原型被表现野心拖大。

以荒废花园为例，如果未来重启，更适合的验证路线是：

- 7 天灰盒：纯 2D 网格、固定视角、占位地块和花朵阶段。
- 1 个月 Demo：2D / 2.5D 斜俯视表现，Sprite / Tilemap / 简单骨骼动画。
- 不进入完整 3D，除非核心卖点就是可旋转、可拍照、可自由摆放的 3D 花园装饰。

如果玩法本身在“农场收菜”和“自动化经营”之间摇摆，先暂停路线判断，不要用 3D、美术升级或复杂角色跑动来掩盖核心循环不稳。

TapTap/Steam 数据不证明玩法好玩，但能证明“题材、画风、包装是否让游戏用户想等”。因此它应当被纳入阶段 4，而不是等 Demo 做完才出现。

## 来源: `10_流水/2026-05/2026-05-16.md` · 提取日期 2026-05-17

## 用户池不是大社群，而是低维护测试池

早期不需要大量用户，需要 20-50 个高意图试玩者。测试池的最低做法：

- 从 TapTap、小红书、评论区里邀请真正说“想玩”的人。
- 建立 QQ 群、微信群、问卷或 TapTap 测试通知中的一个触达方式。
- 每周只发一次进展，避免把时间消耗在社群运营。
- 测试时只问 3 个问题：看懂了吗、哪里卡住、还想不想玩下一关。

早期社群不是目的，只是把愿意试玩的人留住的容器。

## 双方向概念视频：先测玩家兴趣，不先做切片

当有两个方向都“能真做成游戏”时，第一步不要同时做两个可玩切片，而是先用真实玩法概念视频验证兴趣信号。

本次对照方向：

| 方向 | 测什么 | 风险 | 适合的第一动作 |
| --- | --- | --- | --- |
| 荒废花园复苏经营 | 题材吸引力、经营幻想、治愈反馈 | 美术与动画成本高，7 天切片可能偏大 | 先做 2-3 条真实玩法视频 |
| 90 秒极限防线 | 短局策略、关键放置、战斗爽点 | 容易滑回系统变重的塔防 / 肉鸽 | 用《光与朽》资产做 7 天切片候选 |

概念视频必须回答一个问题：**玩家看到这个真实玩法，会不会想玩？**

视频验证失败时，不要立刻否定玩法，先分三类处理：

| 现象 | 处理 |
| --- | --- |
| 看不懂 | 重做表达，不判定玩法失败 |
| 看得懂但没人想玩 | 换钩子或美术风格再测一次 |
| 两版都无评论欲望 / 收藏 / 想玩反馈 | 暂停概念，归档，不进入切片 |

## 真实玩法概念视频的空间连续性

AI 概念视频不能只追求单张图好看。空间逻辑混乱会污染验证结果，用户可能不是不喜欢玩法，而是看不懂这个游戏世界。

原则：

- 使用一张稳定的场景母版；同一方向的 2-3 条视频尽量共用同一地图。
- 母版建议先做 `1:1` 或 `4:3` 的较大游戏场景，再裁成 `9:16` 竖屏镜头。
- 最终视频是 `9:16`，但游戏空间不必被硬塞成一张竖屏海报。
- 镜头移动优先用剪映 / AE / Figma 对大图做平移，少让图生视频模型自己大幅变镜头。
- 建筑、小摊、公告牌、花圃位置不能突然变化；UI 数字和金币特效可以后期叠加。

允许简化：

- 金币数、倒计时和文字不精确。
- 生长、扩建、加工动画比真实游戏更快。
- 角色移动路径可以短。

不允许穿帮：

- 建筑突然出现或消失。
- 顾客气泡漂到花圃区域。
- 角色外观每帧明显变化。
- 核心操作前后矛盾。

## 概念视频拆段生产与发布变量

AI 图生视频不要一次把 5 张关键帧全丢进去生成 14 秒。更稳的方式是按动作链拆成 3-4 秒一段，再用剪映拼接。

示例拆段：

| 视频 | 动作链 |
| --- | --- |
| 最后一秒花束订单 | 顾客下单 -> 收红花种蓝花 -> 蓝花成熟 -> 花束台加工 -> 最后一秒交付 |
| 杂草扩散反转 | 杂草扩散 -> 手动清理太慢 -> 招募园丁 -> 洒水器大面积复苏 |

发布时不要三条视频共用同一个标题。它们虽然属于同一游戏方向，但测试的是不同卖点：

| 视频 | 标题策略 | 测试卖点 |
| --- | --- | --- |
| 荒废花园复苏 | 这片死掉的花园，能救回来吗？ | 复苏与扩建幻想 |
| 最后一秒花束订单 | 顾客快走了，最后一束花来得及吗？ | 限时订单与时间压力 |
| 杂草扩散反转 | 杂草快把花园吞掉了，怎么办？ | 危机扩散与自动化反转 |

正文结构可以统一，但核心玩法一句话必须不同。标签可以基本一致，以便平台识别同一方向；只对单条视频补 1 个差异标签，例如 `#时间管理游戏` 或 `#花园游戏`。

## 创意筛选应是漏斗，不是二选一

下一款游戏不应该被预设成“继续《光与朽》的动作策略路线”或“回到《美妆叠叠乐》的女性向休闲路线”。更稳的方式是把所有方向放进同一个漏斗，用创意质量、个人可执行性和市场反馈共同筛。

“摆摊”类比很准确：先去办公区、工厂区、学校区看人真实缺什么、什么摊位生意好，再判断自己能不能做得一样好或更好。对应到游戏就是：

```
观察用户需求/竞品信号 -> 组合创意 -> 做真实玩法概念视频 -> 发给陌生人 -> 用数据决定是否切片
```

方向不因历史失败被永久排除；只有在同一轮漏斗中没有钩子、没有差异、没有数据时才暂停。

## 从市场需求反推创意组合

创意筛选的目标不是证明自己已经有答案，而是尽快发现“玩家正在用行为投票的需求”。因此早期动作要从品类偏好转向需求扫描：

| 问题 | 作用 |
| --- | --- |
| 哪类玩家在评论区反复说“想玩/求入口/什么时候出”？ | 找高意图需求 |
| 同类游戏最强卖点是什么，评论里骂什么？ | 找可切入痛点 |
| 我能不能用更低成本做出一个可拍出来的差异点？ | 判断个人可执行性 |
| 这个差异点能不能在 10-15 秒视频里讲清？ | 判断验证成本 |

只有通过这四个问题的创意，才值得继续写概念卡和视频脚本。

## 概念视频复盘用软门槛，不用繁琐数据表拖住行动

早期 AI 概念视频的目标不是做精确投放归因，而是判断“这个方向有没有继续做下一版 / Demo 的必要”。在粉丝少、自然流量小、每个平台只有几十到几百观看时，强制填写完播率、收藏率、跨平台明细，容易变成新的执行阻力。

当前阶段更适合“软门槛三题”：

| 问题 | 判断 |
| --- | --- |
| Q1：看完这版视频后，自己还想接着做下一版吗？ | 判断个人持续意愿和制作痛苦度 |
| Q2：是否有 3 个以上陌生人追问“怎么玩 / 在哪玩 / 什么时候上”？ | 判断外部想玩信号 |
| Q3：能不能 1 个月内做出可测 Demo？ | 判断执行范围 |

决策方式：

| 三题结果 | 结论 | 动作 |
| --- | --- | --- |
| 3Y | Push | 进入可玩切片或正式立项前审查 |
| 2Y1N | Pivot | 改钩子、题材、动词或平台受众，重做一轮视频 |
| 1Y2N 或 0Y | Kill | 归档，记录可复用资产 |

最低记录不要超过一屏：视频版本、发布时间、平台、粗略观看量、收藏 / 评论数量、想玩评论摘录、三题结论。数据记录是为了帮助决策，不是为了证明自己“调研很完整”。

## 创意评审 Agent 只做少量候选和周度收束

休闲小游戏创意 Agent 的目标不是无限生成点子，而是把创意筛选、验证和执行闭环固定下来。输出必须收束到：

- 本周最值得做的 3 个概念视频。
- 本周最值得做的 1 个 7 天原型。
- 如果没有达标，就明确写“本周不启动 7 天原型”。

推荐两种运行模式：

| 模式 | 频率 | 输出 |
| --- | --- | --- |
| Daily | 每天或每 2-3 天 | 生成 3-5 个候选，只把通过最小过滤的写入 `00A_待审核创意表.md` |
| Weekly | 每周一次 | 读取创意库、题材库、核心动词库、近期市场信号，生成周度评审 |

Daily 评审只看最小字段：

| 字段 | 问题 |
| --- | --- |
| 3 秒钩子 | 陌生人能否一眼看懂想玩什么 |
| 差异化 | 和同类最明显不同是什么 |
| 美术成本 | 是否能用当前 TA / AI / 素材能力承接 |
| 1 周原型 | 7 天能否做出可测试主爽点 |
| IAA 变现点 | 是否有失败、补救、翻倍、提示或重试广告位 |
| 素材传播性 | 能否录出 10-15 秒真实玩法视频 |

Weekly 评审文件建议放在：

```text
00_草稿/游戏创意库/周度评审/<YYYY-Www>_休闲小游戏创意评审.md
```

自动化可以有，但必须服务验证节奏。不要把 Agent 变成“每天吐 100 个点子”的焦虑机器；它应该把候选变少，把下一步变清楚。
