# 音效设计方法论

> 来源：《光与朽》音效设计实战经验，适用于独立游戏的音效采购与设计。

---

## 音效类型分类

| 类型 | 子类 | 搜索方向 |
|------|------|---------|
| 环境音 | Loop 类（沸腾/燃烧/风声） | continuous, ambient, loop |
| 技能特效 | 技能释放/激活 | burst, release, pressure |
| 打击音 | 攻击/喷吐/爆炸 | impact, hit, spit |
| 状态反馈 | Buff 触发/解除 | crystal, chime, resonance, harmonic |
| 死亡音效 | 怪物消灭 | burst, hiss, pressure release |
| UI 音效 | 金币吸附/按钮/奖励 | whoosh, magnetic, multi-chain |

---

## 核心搜索方法：关键词组合 + 避坑词

**不要用单个词搜索**，要用"体验感关键词组合"。

### 搜索命中率对比
- ❌ 搜"火" → 命中率约 20%（结果五花八门）
- ✅ 搜"压力释放 + 喷出 + 短促" → 命中率 80%

### 各类音效的搜索模板

| 音效需求 | 正确搜索词 | 避坑词（不要搜这些） |
|---------|-----------|-----------------|
| 火球飞行 | whoosh + fire layer | explosion, fire alone |
| 熔岩生成 | heavy rumble + freeze crack 分层 | lava eruption（太大）|
| Buff 群体触发 | harmonic + resonance | single chime（太单薄）|
| 怪物死亡（冰） | pressure burst + hiss（快/锋利）| ice break（太脆）|
| 金币吸附 | magnetic + multi-chain click | coin drop, single reward |
| 冰墙生成 | heavy rumble（升起）+ freeze crack（冰属性）| glass break（太脆）|

---

## 分层设计原则

**任何音效 = 主体层 + 细节层 + 尾巴层**

单素材直接用会显得廉价，必须叠层。

| 层级 | 作用 | 示例（喷吐音） |
|------|------|-------------|
| 主体层 | 核心感知 | 爆发核心（burst）|
| 细节层 | 质感补充 | 起始内部气泡声 |
| 尾巴层 | 收尾与余韵 | 飞溅残留（splash residue）|

---

## 音效时长控制

| 类型 | 建议时长 |
|------|---------|
| 飞行音效 | 0.2–0.5 秒 |
| 吸收/收集 | ≤ 1 秒 |
| 技能释放 | 0.3–0.5 秒 |
| 环境 Loop | 无限，确保接缝处无爆音 |

超出时长会显得拖沓，独立游戏节奏要快。

---

## 踩过的坑

1. **用真实火焰音做火球飞行** → 听不出速度感，要靠 whoosh 作主体，火焰是"贴层"
2. **群体 Buff 只用单一 chime** → 显得廉价，必须加 harmonic/resonance 做共鸣层
3. **金币吸附搜 coin + reward** → 容易得到"single coin drop"，需用 magnetic + multi-chain 保证连续爽感
4. **冰墙生成搜 glass break** → 太脆没重量，应是 heavy rumble（地面升起感）+ freeze crack（冰属性）的组合
5. **只用单素材不分层** → 低成本感明显，听众无法感知质感

---

## 打击感公式

```
打击感 = 预期建立（起始音）+ 冲击峰值（主体音）+ 余韵（尾巴音）
```

三层缺一不可。起始音给玩家心理预期，主体音提供爽感，尾巴音让感受完整不突兀。

对于激光/束类武器：主体层应该持续（Drone 音），而非一次性冲击（Impact 音）。

## 密集死亡音效要做语义去重和冷却

多个分裂怪同时死亡、旁边又有爆炸时，刺耳感通常不是单个素材太差，而是多个语义相近的音效在同一瞬间叠加：死亡音、分裂音、爆炸音、投射物爆开音一起抢峰值。

《光与朽》的处理方式：

| 问题 | 处理 |
| --- | --- |
| 分裂怪死亡同时播通用死亡音和分裂音 | 分裂怪只播 `enemySplit`，不再叠通用死亡 |
| 多类爆炸共用一个素材 | 拆成 `enemyExplode`、`grenadeExplosion`、`projectileExplode` 等语义 |
| 同帧大量触发 | 每类爆炸设置 cooldown |
| 总体刺耳 | 降低默认音量，后续再按场景调 |

音效叠层和音效叠加不是一回事。设计好的叠层服务一个事件；多个事件同时爆发时，要用 cooldown、优先级和语义去重保护听感。

## Unity AudioConfig 资源引用不要手写无效 GUID

`AudioConfig.asset` 里写入 Unity 不能解析的 GUID，会导致 `Could not extract GUID`、`Broken text PPtr`，甚至资源面板无法正常选中。音频配置文件里的 `AudioClip` 引用应通过 Unity 序列化或可靠的资源替换流程维护，不要手工写 `000000...` 这类占位 GUID。

如果为了先修 Unity 资源错误，可以临时把新字段指回一个有效通用素材，优先恢复 Inspector 可打开状态；音效素材细分可以在资源链路稳定后再补。

## 按钮点击音效应接入通用按钮组件

Unity 的 `Button` 组件不会自动播放点击声。项目里如果只给部分按钮手动绑定音效，动态背包物品、装备槽、科技树节点、关闭按钮很容易漏。

更稳的工程结构：

1. `UIButtonCommon` 统一负责点击音效、Q 弹动画和灰态。
2. 自动扫描能覆盖场景里的静态 Button。
3. 动态生成或重复 `Setup()` 的按钮显式调用 `UIButtonCommonHelper.Ensure(button)`。
4. 移除旧的手动 `PlayButtonClick()`，避免双重播放。
5. 避免 `RemoveAllListeners()` 清掉通用音效监听。

UI 点击音效是界面手感的底噪，不应靠每个面板记得手动加。统一组件能减少遗漏，也能让按钮听感和动画节奏一致。

## 战斗音效先搭“持续能量 + 命中节奏 + 结算反馈”

《光与朽》的音效目标不是单个素材好听，而是让玩家持续感到“激光正在工作，敌人正在被烧穿，局面正在推进”。最小可用音效包可以先按战斗链路拆：

| 场景 | 推荐音效 | 设计重点 |
| --- | --- | --- |
| 激光启动/停止 | `Laser_On` / `Laser_Off` | 短促、有开关感，不抢击杀反馈 |
| 激光持续命中 | `Laser_Loop` + `Hit_Tick` | Loop 低疲劳；命中 Tick 80-120ms 一次 |
| 塔旋转/吸附 | `Tower_Rotate_Loop` / `Push_Flow` | 轻微机械或磁场感，服务“转动保持流动” |
| 敌人受击/击杀 | `Hit_Fluid` / `Kill_Splash` | 黏液、破裂、水汽层可叠，但要控制同帧密度 |
| 构筑成长 | `Upgrade` / `Skill_Trigger` | 比普通 UI 更亮，提示 Build 变强 |
| 局末 | `Game_Success` / `Game_Fail` | 成功短上扬，失败低沉但不刺耳 |

激光和旋转类 Loop 应控制在约 1.5-2.5 秒无缝循环，音量低于一次性反馈，减少高频刺激，避免压住 BGM。命中反馈可以随连续命中做轻微升调，例如 +1 到 +3 半音，让玩家听到“越烧越深”，但不要把 Tick 做成机关枪。

## BGM 按战斗阶段做情绪推进，而不是一首歌循环到底

《光与朽》的 BGM 可按关卡节奏拆成五类：

| 阶段 | BGM 方向 | 节奏目的 |
| --- | --- | --- |
| 菜单/商店 | airy synthwave / lofi | 安静、未来感、可长听 |
| 普通波次 | 100-110 BPM electronic bass | 让玩家进入刷怪流 |
| 后期高压波 | 130 BPM industrial / aggressive | 增强压迫，不需要旋律太复杂 |
| 波间赌博房 | jazz-hop / lofi / neon noir | 和战斗区分，制造“下注”气质 |
| Boss | dark synth / industrial / epic bass | 低频更厚，技能预警更容易露出来 |

音量策略上，激光持续时 BGM 可轻微 ducking，技能释放时短暂下压，胜利时 BGM 淡出给结算音效让位。战斗音频的关键不是“素材越多越豪华”，而是持续声、瞬时反馈和 BGM 互相留空间。

## 搜音效要搜声音语义，不要搜玩法名词

找素材时不要直接搜“熔岩池生成”“怪物吐口水”“Boss 吸收”这类玩法名词。素材库理解的是声音语义：空气、压力、水汽、黏液、金属、冰裂、低频、冲击。

| 需求 | 推荐搜索语义 | 避免方向 |
| --- | --- | --- |
| 熔岩池生成 | lava / acid + sizzle + boiling + loop | explosion / fire whoosh |
| 怪物喷吐 | wet / spit / puff / burst / pressure release | gunshot / cartoon pop |
| 火球飞行 | whoosh / flyby / projectile + fire layer | 只搜 fire |
| Boss 吸收融合 | suction / inhale / gulp / absorb + goo / viscous | 单纯 boom |
| 冰冻死亡 | cryo / freeze + hiss / gas release / short | 长冰裂、玻璃碎 |
| 群体狂暴 Buff | crystal chime + high resonance | coin / UI click |
| 冰墙升起 | ground rumble + wall rise + ice crack + air tail | 单一 rock impact |
| 金币吸附 | coin / reward + magnetic / whoosh / multi-chain | 单个 coin click |

Boss 技能音频要分“预警”和“执行”。预警更尖、更短、更容易穿透混音；执行更厚、更连续、更有压迫。比如冲撞预警用高频 rising pitch，落下/碾压用低频 rumble 与摩擦声；吸收用 suction + gulp，强化完成再给低频 power-up。玩家需要先听懂危险将至，再听到技能真的发生。

## 章节音效要做成“怪物行为词典”，不要只按素材名找

第二、三章的音效需求说明了一个可复用规律：音效表应围绕行为语义组织，而不是围绕怪物名称堆素材。先定义玩家要听懂的行为，再映射搜索关键词。

| 章节 | 行为 | 声音语义 |
| --- | --- | --- |
| 熔岩 | 分裂怪死亡分裂 | wet pop、split、short burst |
| 熔岩 | 自爆怪预警/爆炸 | fuse、warning beep、pressure build、heavy burst |
| 熔岩 | 熔岩池存在/阻挡激光 | sizzle、boiling loop、steam hiss |
| 熔岩 | Boss 吸收/强化 | suction、viscous gulp、low power-up |
| 熔岩 | 陨石预警/坠落 | rising alarm、falling whoosh、ground impact |
| 冰霜 | 坦克破裂/死亡 | ice crack、shatter、low crunch |
| 冰霜 | 催化怪释放寒气 | cold smoke、gas release、crystal chime |
| 冰霜 | 冰墙升起/破碎 | ground rumble、ice wall rise、crack burst |
| 冰霜 | 冰霜射线/绝对零度 | continuous frost ray、accelerating alarm、freeze blast |
| 冰霜 | 炮塔被冻结/解冻 | short lock sound、frozen squeak、thaw shimmer |

Boss 级音效要保留三段：预警、执行、结果。普通怪可以用短反馈，Boss 技能则必须让玩家先听见危险正在形成，再听见技能落地，最后听见是否被打断、命中或化解。

## 休闲整理游戏的音效要按操作语义收敛

美妆叠叠乐这类高频点击游戏，不适合给每个细小动作都配一层音效。短时间内“点击、飞行、入槽、清槽、订单完成、按钮点击”全响，会让轻松整理感变成噪音。

更稳的音效语义：

| 场景 | 建议 |
| --- | --- |
| 点击可用物件 | 保留短促、轻柔的确认音 |
| 物件飞向槽位 | 可用很轻的 whoosh，音量低于点击确认 |
| 入临时槽 | 如果频率太高，可以不单独播放，避免堆叠 |
| 订单完成 / 完美订单 | 给明显上扬反馈，承担爽点峰值 |
| 清空临时槽 / 道具使用 | 使用更亮的清理声，和普通点击区分 |

工程上，`AudioManager` 至少要有音乐和音效两个 `AudioSource`。如果音量在 Inspector 固定，例如音乐 0.3、音效 0.7，就不要再从旧 PlayerPrefs 里读历史音量覆盖它；只保存开关状态即可。设置面板也不能硬编码 0.7 之类默认值，否则会把项目级音频配置冲掉。
