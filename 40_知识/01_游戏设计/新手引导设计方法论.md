# 新手引导设计方法论

> 新手引导不是把所有系统讲一遍，而是控制玩家的学习节奏：每一步只教当下必须掌握的动作，并让玩家完成一个真实操作。

---

## 来源: `10_流水/光与朽项目/Claude-2026-04-13.md` · 提取日期 2026-05-20

## 引导只教“阻塞继续玩”的内容

《光与朽》的新手引导规划最终收敛为：战斗内只教旋转激光和第一次大招，主界面只在系统解锁后教科技树 / 装备的关键操作。技能三选一、无人机奖励这类系统不做强制步骤，而是用常驻 UI 提示、流派色标签、协同发光来改善可读性。

可复用判断：

| 内容类型 | 处理方式 |
| --- | --- |
| 不会就无法继续玩 | 做一次强引导，例如核心操作、首次升级、首次装备 |
| 会影响构筑质量，但不该剥夺探索 | 做永久 UI 可读性，例如流派标签、推荐光效、协同提示 |
| 只是说明系统存在 | 用解锁 Tips、红点、弱提示，不进入阻塞式引导 |
| 玩家已经能自然发现 | 不引导，避免打断心流 |

新手引导的目标不是让玩家“知道所有功能”，而是让玩家在最少打断下建立掌控感。

## 完成条件必须是真实行为，不是看到提示

引导结束条件要绑定玩家真实动作。比如激光操作不能“触摸屏幕就算完成”，而应检测玩家已经拖动过激光；科技树不能“打开面板就算完成”，而应完成点击节点、升级、关闭面板、返回主界面的关键链路。

更稳的完成条件：

1. 核心操作：检测有效拖动、释放、命中或移动距离。
2. 系统操作：检测按钮点击后的实际状态变化。
3. 装备 / 科技：检测属性变化或装备槽变化，而不是只检测弹窗出现。
4. 大招：由玩家点击并成功释放后再写完成标记。

不要让视觉提示的出现本身推进状态机。只有玩家做过正确动作，才算学会。

## 引导进度要跨会话保存

玩家可能在第一次战斗中途退出，也可能解锁科技树后当天不点进去。如果引导只存在于本次 session，第二次回来就会丢失，最终形成“系统已解锁但没人教”的断层。

引导状态应拆成多个独立标记：

| 引导块 | 建议标记 |
| --- | --- |
| 战斗内激光操作 | `tutorial_laser_done` |
| 首次大招 | `tutorial_overload_done` |
| 科技树首次打开 | `tutorial_techtree_open` |
| 科技树首次升级 | `tutorial_techtree_upgrade` |
| 装备首次打开 | `tutorial_equip_open` |
| 装备首次安装 | `tutorial_equip_install` |

每个标记都应在真实行为完成后写入持久化。未完成的引导下次进入对应场景时继续，而不是重头播全套。

## 战斗引导和系统界面引导要用两种模式

战斗内引导强调“不打断操作”，系统界面引导强调“防误触和保证路径”。两者不应共用同一种黑遮罩。

| 场景 | 推荐模式 | 原因 |
| --- | --- | --- |
| 战斗内核心操作 / 大招 | 手指 Prefab + 弱提示，无遮罩 | 玩家需要继续观察战场和实时操作 |
| 科技树 / 装备系统 | SDF 挖孔遮罩 + 手指 / 光圈 Prefab | 需要限制误触，确保按步骤点击 |
| 解锁提示 | TipsPanel + 红点 | 负责把玩家拉到入口，不承担具体教学 |

系统界面里如果没有遮罩，玩家很容易点到别的按钮，导致引导手指留在错误位置或状态机误判。战斗里如果遮罩太强，又会遮挡威胁和削弱沉浸。

## 配置驱动优于硬编码步骤

科技树和装备引导适合用 `TutorialStepConfigSO` 这类配置资产描述每一步：

| 配置项 | 用途 |
| --- | --- |
| 目标路径 / RectTransform | 找到需要挖孔或指向的按钮 |
| 手指 Prefab 路径 | 可替换手指、光圈、左右滑动箭头 |
| `localPosition` 偏移 | 微调不同锚点按钮的手指位置 |
| `holePadding` / `cornerRadius` / `holeShape` | 调整挖孔大小、圆角或圆孔 |
| 完成事件 | 绑定点击、拖动、升级、装备等真实行为 |

这样美术和策划能在 Inspector / 配置文件里调整表现，不需要每次改代码。

## 数值反馈也属于引导

装备引导里，玩家点击“装备”后如果属性数字瞬间变化，很多新手会错过“我变强了”的因果。更好的做法是对属性 UI 做 `Scale Punch`（Q 弹缩放）和 `Rolling Number`（数字滚动），让玩家看到装备产生了明确收益。

引导不是只靠箭头和文案。所有“玩家刚刚做对了”的关键瞬间，都应该用 UI 动效把因果补齐。

## 局外系统首次进入要给选择，但给一次免费成功

科技树首次进入时，不建议把所有节点都锁住再强迫玩家点唯一节点。全锁会制造“系统还没开放”的误解，也需要额外的首节点解锁逻辑。更好的做法是保留 3-4 个根节点开放，让玩家看到未来路线，再用引导指向一个推荐起点。

可复用模式：

| 系统 | 首次体验 |
| --- | --- |
| 科技树 | 保留根节点可点，高亮最便宜 / 最通用节点，首次升级免费 |
| 装备 | 首次打开后引导合成或装备，首次合成免费 |
| 局外货币 | 高亮货币数量和消耗结果，让玩家看到“资源换永久成长” |

第一次操作的目标不是回收资源，而是建立因果：“我点了这个系统，我变强了”。免费并不等于破坏经济，只要用一次性持久化标记控制，就能降低理解成本，又不改变长期数值。

## 首次大招要提前布置“值得释放”的场面

大招教学如果只在按钮亮起时弹手指，但场上没有足够目标，玩家第一次点击就会觉得“也就这样”。教学要负责搭建第一次成功体验，而不仅是告诉玩家按钮在哪。

《光与朽》的可复用方案：

| 节点 | 处理 |
| --- | --- |
| 大招充能时间 | 约 60 秒 |
| 前置刷怪时机 | 充能约 83%，即 50 秒左右 |
| 目标数量 | 15 只小怪从屏幕顶部涌入 |
| 教学触发 | 大招 Ready 后显示手指引导 |
| 经济隔离 | 这批小怪 XP=0，金币正常 |
| 完成条件 | 玩家点击并释放大招后写入完成标记 |

新手引导的关键不是“讲完功能”，而是让玩家在第一次使用时获得一个被设计过的正反馈。尤其是大招、连锁、合成、强化这类爽点系统，第一次体验要比平均场景更饱满。

## 教学对象要计入当前流程，避免系统提前结束

如果教学额外生成敌人，却不加入当前波次计数，可能出现玩家还没放大招，波次已经判定结束的情况。教学内容虽然是额外演出，也必须和底层流程对齐。

可复用检查：

1. 教学刷出的对象是否影响波次完成、胜负、奖励或统计。
2. 如果只服务教学，是否隔离 XP / 掉落 / 通关评分。
3. 游戏结束或切场景时，教学协程是否会停止。
4. 第二次进入时，持久化标记是否能阻止重复教学。

引导不是悬浮在游戏外的一层 UI，它会进入真实战斗系统。越是“只做一次”的教学，越要检查它有没有破坏正式流程。

## 关键 UI 语义要在第一次出现时贴上标签

玩家第一次接触战斗 HUD、无人机、宝箱或契约选择时，不应该靠猜图标理解含义。《光与朽》上线反馈里，护盾/血量、三宝箱、无人机三选一都出现了“看不懂”的问题。

可复用标签规则：

| 对象 | 标签重点 |
| --- | --- |
| 护盾 / 血量 | 左边是护盾，右边是生命；护盾先掉，生命归零死亡 |
| 补给类无人机 | 治疗、护盾、装备、金币等直接收益 |
| 随机强化 / 抽奖 | 说明可能强化玩家，也可能带来怪物风险 |
| 契约 / 交易 | 明示消耗 HP / 护盾换随机属性 |

标签不需要写长说明。第一次出现时，一个短标题加颜色语义，往往比教程弹窗更不打断。

## 技能流派引导要早于玩家说“不够爽”

Roguelite 的新手不只是不会操作，还可能不知道“该怎么变强”。如果玩家每次三选一都像随机拿牌，就很难形成构筑目标，也难以感受到 Lv5 质变。

更稳的早期处理：

1. 第一波或第一次升级时出现流派提示，不强制选择。
2. 同流派卡牌用颜色、标签或协同发光连接。
3. 即将凑成 Lv5 或关键组合时给轻提示。
4. 不用大段文案解释流派理论，让玩家通过 UI 关系看懂。

新手引导不只是教按钮，也要教玩家“这一局我该追什么”。

## 引导要收敛到少量必须点击，其他内容做成常驻可读性

《光与朽》教程方案的后续修正说明：新手引导不必把所有系统都做成强制步骤。真正需要强制点击的，只是玩家不做就无法继续、或第一次一定会误触的关键动作；其余信息更适合做成常驻提示、标签、推荐光效或红点。

可复用分层：

| 内容 | 推荐处理 |
| --- | --- |
| 首次进入战斗 | 可自动进入，并免体力成本，减少主界面理解负担 |
| 科技树解锁 | 用现有 TipsPanel + 红点把玩家带到入口，再用手指 / 圆圈引导首个火系节点、升级按钮、关闭按钮、返回主界面 |
| 装备解锁 | 用 TipsPanel + 红点提示入口；进入后引导选择背包里品质最高且可装备的物品，再点装备 |
| 技能选择说明 | 不做强制引导，用固定首轮卡池和常驻信息保证理解 |
| 无人机奖励说明 | 不做强制引导，用顶部 Tips / 描述常驻化 |
| Overload 大招 | 只保留文本气泡，不额外叠金色圈，避免视觉噪音 |

这种收敛能减少引导疲劳，也能让核心玩法更早进入“我在玩游戏”的状态。

## 首次技能三选一控池是体验规则，不是 UI 引导

首局技能选择不一定要靠遮罩和箭头讲解。更稳的方式是直接控制首轮选项池：例如固定出现 Frost Beam、Focus Lens、Prism，并在玩家选择 Frost 后移除 Focus，或选择 Focus 后移除 Frost，避免激光颜色 / 机制冲突。

这类控池的本质是体验设计，不是教学 UI。玩家看到的是自然出现的选择，但系统已经帮他避开了最容易造成误解的组合。它比额外弹一层“请选择某某技能”更少打断，也更不容易削弱构筑自由感。

## 扣洞遮罩只用于需要防误触的功能界面

SDF 扣洞遮罩适合科技树、装备这种“必须按路径点对”的系统界面；战斗内或轻提示场景不应默认使用强遮罩。

使用边界：

- 科技树 / 装备：可用扣洞遮罩，洞内点击穿透，洞外阻挡，确保玩家完成首个节点或首次装备。
- 技能选择 / 无人机奖励：优先用常驻说明和推荐高亮，不做遮罩。
- 战斗内大招：只用文本气泡或弱提示，避免遮挡敌人、子弹和战场反馈。

引导遮罩的价值是防止 UI 路径走错，不是制造“被系统接管”的感觉。凡是玩家可以通过可读性自然理解的内容，都应优先让界面本身承担教学。

## 线性关卡教学可以绑定关卡号，但要明确它不是通用规则

如果游戏不允许玩家反复回到旧关，美妆叠叠乐这类线性关卡可以用 `currentLevel` 决定是否播放引导：第 1 关教点击物件，第 2 关教难度飙升提示，第 5 关教收藏奖励。这种做法省掉教程存档字段，适合“只往前走”的早期小游戏。

但它不是所有项目的默认答案。只要存在回访旧关、多入口系统、局外面板或跨天继续，就仍应使用独立持久化标记。判断标准很简单：玩家下一次是否可能在同一系统里继续一个未完成教学。如果可能，就不要只依赖关卡号。

## 教学 Prefab 和遮罩必须在结束时真正释放输入

美妆叠叠乐的经验说明，很多“按钮点不动”不是业务逻辑错，而是教学对象残留：

| 风险 | 处理 |
| --- | --- |
| 难度飙升提示动画播完只隐藏不销毁 | 动画结束后 `Destroy`，避免透明 UI 继续挡点击 |
| 透明遮罩覆盖全屏 | 需要扣洞 / `ICanvasRaycastFilter` 让洞内点击穿透 |
| 指引 Prefab 根节点是 Canvas，位置却设在根节点 | 应把位置、缩放设置到具体子节点，例如 `YinDao` |
| 默认隐藏对象用 `GameObject.Find` 找不到 | 用序列化引用或支持 inactive 搜索 |

教学系统的验收不只是“提示出现了”，还包括提示消失后输入、按钮和射线阻挡都回到正常状态。

## 难度飙升提示是预期管理，不是长教学

当第 2 关或某个节点难度明显提升时，可以用短促的“难度飙升”警告管理玩家预期。它的目的不是解释规则，而是让玩家知道“接下来会更难”，降低突然失败带来的被坑感。

推荐动画节奏：

| 阶段 | 时长 | 表现 |
| --- | --- | --- |
| 入场 | 0.3 秒 | 120% 缩放猛击到 100%，可配轻微屏幕震动和短音效 |
| 停留 | 1.0-1.2 秒 | 居中可读，红色标题 + 左右警示线 |
| 退出 | 0.5 秒 | 快速闪烁后淡出，把视觉焦点还给关卡 |

这类提示必须短、明确、可跳过，不要变成遮挡玩法的长弹窗。玩家要带着“我知道这一关有压力”的心理进入操作，而不是被系统讲解打断。

## 首小时不是教学阶段，而是价值证明窗口

FTUE 的目标不是把所有按钮讲完，而是在首局和首小时内让玩家形成三种判断：我会、我爽、我想再试一次。玩家前 10 分钟如果看不到核心系统为什么好玩，后续再加签到、活动和长线目标都很难补救。

首小时 6 条验收线：

| 验收线 | 通过标准 |
| --- | --- |
| 首局只教必要规则 | 只教活下来、做一次选择、看到一次爽点 |
| 5-10 分钟出现系统价值 | 至少一次 Build 成型、翻盘或高压波次被化解 |
| 至少两种可感知解法 | 玩家知道输出、控场、稳健或高风险路线有差异 |
| 奖励服务理解 | 玩家能说出“这次变强是因为什么” |
| 失败后 30 秒可重开 | 结算、复盘、再来一局没有废步骤 |
| 埋点盯关键行为 | 看首个 Build 分叉、首个高光波次、首败后是否重开 |

对塔防肉鸽，首轮三选一可以固定成“稳 / 补 / 赌”：一个当前路线强化，一个补短板选项，一个转型或高风险选项。这样玩家会觉得自己在构筑，而不是在随机领工资。

首败页要优先回答三个问题：

1. 我死在哪类压力：清杂、单体、控场、路径覆盖还是经济断档。
2. 我这局最强的环节是什么。
3. 下一局优先尝试哪个方向。

首小时做得好，玩家输了也会觉得“我知道该怎么改”；首小时做得差，玩家赢了也可能不知道游戏后面有什么值得留下。
