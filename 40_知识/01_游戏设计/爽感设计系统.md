# 爽感设计系统

> 来源：《光与朽》上线后玩家反馈驱动的迭代经验。核心认知：爽感问题 90% 来自视觉/听觉反馈不足，而非数值强度不够。

---

## 核心认知：爽感 ≠ 数值强度

**错误归因**：玩家说"没有爽感" → 开发者调高伤害数值
**正确归因**：爽感来自感知层，不来自数值层

```
爽感三要素：
1. 视觉反馈清晰（能看出效果在生效）
2. 音效响应及时（击中/击杀有声音峰值）
3. 质变节点明确（达到某个阶段，体验发生质的跳跃）
```

**光与朽案例**：
- 极寒光束 Lv1–4：减速效果有数值，但视觉无法感知 → 玩家认为"没用"
- 广域透镜：激光变宽了，但"宽"的感知不明显 → 玩家认为"没有用感觉"
- 修复方向：加冰晶粒子、冷雾、怪物染色+发光粒子，不是加数值

---

## 稀有度质变：金色技能必须是质变，不是加强版

**反模式**：金色技能 = 数值更高的普通技能（仍是同一种体验）
**正确模式**：金色技能（Lv5 满级）= 全新的操作体验质变

### 质变设计框架

```
Lv1–4：技能逐渐增强（量变）
Lv5（满级/金色）：触发全新机制（质变）→ 玩家形成"我要升到满级"的目标感
```

**光与朽 Lv5 质变方向**（5 个核心技能）：
| 技能 | Lv1-4 | Lv5 质变目标 |
|------|-------|-------------|
| 连锁反应 | 击杀后连锁 | 连锁可以穿越障碍物 |
| 极寒光束 | 减速 | 冻结 + 冰裂范围爆发 |
| 广域透镜 | 激光变宽 | 宽激光产生推开力场 |
| 分裂激光 | 多束分裂 | 分裂后各自追踪 |
| 聚能透镜 | 高单体伤害 | 击杀触发爆炸链 |

---

## 连杀/FRENZY 系统：纯视听，不加伤害

**为什么不加伤害**：数值提升会破坏已经平衡的战斗数值体系，且难以回收

**正确做法**：连杀 = 纯粹的视听奖励层，不触碰数值层

```
连杀反馈分级（建议）：
× 3 击杀：音效升调 + 屏幕轻闪
× 5 击杀：COMBO 文字弹出 + 暗角收缩
× 10 击杀：FRENZY 状态 + 慢动作 0.3 秒 + 专属音效
```

**COMEBACK 状态**：血量极低时触发视听强化（不给伤害加成），制造"绝地反击"感。

---

## 关卡节奏：3 段式重构

**问题**：10 分钟单一操作 → 手指疲劳、注意力流失
**根因**：不是"操作难度高"，而是"没有节奏感"

**解法：3 段式结构**（利用已有系统，无需新增功能）

```
段 1（0–3 分钟）：正常战斗 → 波次结束
段间（20–30 秒）：复用无人机三选一系统（决策 + 喘息）
段 2（3–6 分钟）：正常战斗 → 波次结束
段间（20–30 秒）：无人机三选一
段 3（6–9 分钟）：高强度收尾 → Boss 或终局
```

**关键**：段间停顿复用现有 DroneChoiceTipsPresenter / DroneRewardConfig，不是新系统，只是节奏重排，开发成本极低。

---

## 大招蓄力：双因子填充

**双因子设计**（避免纯时间等待的无聊感）：
- 时间因子：50% 填充速度
- 击杀因子：50% 填充速度

**释放设计**：
- 自动锁定一个方向（减轻操作负担）
- 不是全自动索敌（保留差异化的激光旋转手感）
- 对敌人分层伤害（保留挑战性，避免"一招清屏"破坏数值生态）

---

## 技术选型：视觉反馈的避坑

| 需求 | ❌ 避坑 | ✅ 正确路线 |
|------|--------|-----------|
| 减速/冻结视觉 | 流体 RT（不支持速度残影+Shader 覆盖） | 纯粒子路线（冰晶粒子、冷雾） |
| 怪物受击感 | Shader 全体替换 | 怪物染色+发光粒子补强 |
| 连杀反馈 | 加伤害倍率 | 纯音效+屏幕后处理（慢动作、暗角） |

---

## 爽感迭代优先级原则

**比起加功能，先修感知**：

1. 检查现有技能的 Lv5 是否有质变（先补，再加新技能）
2. 检查所有受击/击杀/升级事件是否有专属音效峰值
3. 检查视觉反馈是否"肉眼可见"（5 秒内能察觉到差别）
4. 最后才考虑加新机制或调数值

**一句话原则**：让玩家的眼睛和耳朵先爽，数字只是辅助证明。

## 爽感优先级：先修“看得懂”和“摸得顺”

上线反馈里，爽感不足并不只来自技能特效弱，还来自三个更底层的问题：

| 层级 | 问题 | 为什么影响爽感 |
| --- | --- | --- |
| 操控手感 | 旋转激光不够顺手 | 核心操作不顺，任何特效都会被抵消 |
| 视觉辨识 | 怪物与背景糊成一团 | 玩家看不清目标，就无法感受击杀反馈 |
| 差异化场景 | 侧翼来敌不够早、不够明显 | 玩家感受不到“360 度旋转”存在的必要 |

因此爽感迭代顺序应是：

1. 操作映射、灵敏度、磁吸辅助等“摸起来顺”的问题。
2. 怪物轮廓、发光、眼睛状态、击中反馈等“看得清”的问题。
3. 技能质变、连杀、慢动作、暗角等“爽点放大”的问题。
4. 最后才是加新技能、加大招或调伤害。

如果核心差异化手感没被玩家感知，后面的 Lv5 质变和肉鸽深度都会变成“我知道你做了很多，但我没感到不同”。

## Boss 技能反馈必须补齐完整因果链

VolcanoBoss 的“吸收小怪回血”如果只在数值层生效，玩家会读不懂：小怪冲向 Boss、Boss 血条变多，但没有缩小、消失、音效、特效和回血缓冲，体验上就像 bug。

Boss 技能反馈要按完整因果链检查：

| 环节 | 玩家需要看到 / 听到什么 |
| --- | --- |
| 目标明确 | 小怪朝 Boss 的明确吸收点移动，而不是推着 Boss 根节点乱撞 |
| 被吸收过程 | 小怪缩小、禁用碰撞、向吸收点消失 |
| 命中反馈 | 蒸汽 / 火焰 / 吞噬 VFX 与死亡或吸收 SFX |
| 数值反馈 | Boss 血条出现回血变化，缓冲条跟上 |
| 战术反馈 | 玩家能理解“必须阻止小怪靠近 Boss” |

这类机制的爽感不是“特效越多越好”，而是每个因果节点都要可读。少一个节点，玩家就会把机制误判为穿模、卡住、无反馈或 Boss 莫名回血。

## 不要把所有表现问题都升级成新系统

同一份修复里，Boss 眼睛曾被讨论是否要旋转或拆成独立结构。最终更稳的判断是：如果眼睛没有独立受击、独立转向、独立技能等玩法行为，就先保留单张 Sprite，不为“未来可能需要”提前拆结构。

表现层迭代顺序：

1. 先补玩家能直接感知的缺失反馈。
2. 再修会破坏视觉辨识的材质 / 染色问题。
3. 最后才考虑拆对象结构、加独立动画或新系统。

这能避免把一个本来 0.5 天能解决的反馈问题，扩张成多部件 Boss 架构重做。

## 高频命中反馈要限频，不能每帧重置

持续激光类武器如果每帧命中都重置白闪协程，会让 Boss 长时间保持最亮白色，玩家看到的不是“受击反馈”，而是“画面糊成一片”。高频命中反馈必须有最小间隔或强度衰减。

可复用原则：

| 反馈类型 | 适合做法 |
| --- | --- |
| 单次重击 | 可用强白闪、屏幕震动、重音效 |
| 高频持续命中 | 白闪限频、低强度、用飘字/命中特效补足反馈 |
| 核心弱点命中 | 红色/大字/强闪，强调有效伤害 |
| 护甲命中 | 灰色/小字/弱反馈，强调“打到了但收益低” |

受击反馈要表达伤害层级：打护甲和打核心不能用同一种白闪；打到阻挡物导致 Boss 没伤害时，也要让阻挡物本身有足够反馈，否则玩家会误以为 Boss 飘字漏了。

## 特效作用范围要和玩家语义一致

VolcanoBoss 的问题不是“白闪本身不该有”，而是白闪作用到了玩家不期待的 body02 岩石护甲层。玩家语义里，熔浆液 body03 可以闪，核心 / 眼睛被打时 body02 和眼睛可以强反馈；但护甲被普通扫到时全身闪白，会让命中层级变模糊。

因此复杂角色的表现层要先按玩家语义分组，再决定特效作用范围：

1. 可持续命中的外壳层。
2. 关键弱点 / 核心层。
3. 装饰或特殊材质层。
4. 状态强化层，例如 `redBodyEffect`。

爽感不是所有 Renderer 一起亮，而是玩家一眼能读懂“我刚刚打中了哪里，造成了什么级别的效果”。

## 伤害飘字颜色要按伤害语义少量分层

飘字颜色不是越多越好。颜色太多会花，颜色太少又让玩家感受不到伤害来源差异。《光与朽》的可复用方案是控制在少数高辨识语义：

| 伤害语义 | 推荐表现 |
| --- | --- |
| 普通伤害 | 白色 |
| 暴击伤害 | 红色 + 暴击图标 |
| 冰裂 / 碎冰 | 蓝色系 |
| 连锁反应 | 黄色 / 电弧感 |
| 爆炸 / 自爆 AoE | 橙色 |
| Boss 护甲 | 灰色小字 |
| Boss 核心 | 更大、更亮的核心伤害字 |

处理优先级要明确，避免一个伤害同时满足多个标签时随机变色。可按“特殊机制 > 来源类型 > 普通/暴击”排序，例如先判定碎冰，再判定连锁，再判定爆炸，最后落到普通或暴击。

关键原则：飘字是在帮玩家理解“刚才是哪种机制生效”，不是给每个元素都配一个颜色表。

## 剩余威胁要可视化，不能让玩家心算

Frostcaster 的“3 次 / 7 次施法”如果只存在于数值字段里，玩家感知不到威胁什么时候结束。把身体上的水晶数量和剩余施法次数绑定后，机制立刻变得可读：每施法一次少一颗水晶，玩家能判断“还要撑几轮”。

可复用规则：

| 机制信息 | 更爽的表达 |
| --- | --- |
| 剩余施法次数 | 身体水晶、背包弹药、亮灯格数 |
| 充能进度 | 发光强度、环形蓄力、音效升调 |
| 即将孵化 / 爆炸 | 裂纹、跳动、倒计时粒子 |
| 精英更强 | 更多可见 charge，而不只是血量更厚 |

爽感不只来自击杀瞬间，也来自玩家提前看懂威胁、做出判断、然后验证判断正确。

## 周期孵化比一次性爆发更适合制造割草压力

冰墙从“一次性生成一批怪”改成“每 2.5 秒孵化一只，持续 15 秒”，体验从突然堵屏变成可预期的持续压力。玩家会形成节奏：看到墙出现、预判下一只 Slime、用激光扫掉一波，再等下一波。

设计上要区分两种爽感：

| 生成方式 | 体验 |
| --- | --- |
| 一次性爆发 | 适合惊吓、瞬间危机、Boss 大招 |
| 周期孵化 | 适合割草、持续收割、制造局部战线 |

如果目标是“多怪可扫、压力可读”，周期孵化通常比一次性堆怪更稳。

## 震动只服务低频高信息节点

手机震动不是“越多越爽”。在怪物密集、护盾持续受击、激光持续命中的玩法里，高频震动会从手感变成噪音。震动应该只保留在低频、关键、能传递状态变化的节点上。

《光与朽》最终更稳的取舍：

| 节点 | 处理 | 理由 |
| --- | --- | --- |
| Boss 入场吼叫 | 保留重震 + 镜头抖动 | 低频且传达危险登场 |
| 护盾破碎 | 保留重震 | 从安全到危险的状态转折 |
| Boss 阶段切换 | 保留重震 / 镜头抖动 | 告诉玩家行为模式升级 |
| 护盾持续受击 | 删除 | 常态信息，频繁震动会烦 |
| 本体血量受伤 | 删除或仅测试保留 | 与护盾破碎信息重复 |
| Boss 死亡 | 用子弹时间 / VFX，不靠震动堆强度 | 视觉高潮更重要 |
| Boss Press 长时间角力 | 删除持续震动 | 会影响操作精度 |
| 大招就绪 | 删除震动 | 玩家可能蓄着不用，震动会造成焦虑 |

震动的标准不是“这个事件重要吗”，而是“玩家需要通过手感立即知道这个状态变化吗”。已经有强视觉、强音效或持续 UI 的事件，不一定还需要震动。

## 第一次大招爽感要用密度设计，不只靠伤害倍率

大招是否爽，不只取决于伤害倍率和特效强度，还取决于释放瞬间有没有足够目标。首次教学尤其如此：如果玩家第一次放大招时场上只剩零散小怪，再高的数值也没有割草感。

可复用公式：

```
大招首次爽感 = 可见目标密度 + 自动命中可信度 + 击杀反馈峰值 + 经济不破坏
```

设计上可以在大招快满前刷一批教学专用小怪：数量足够多、从屏幕顶部涌入、XP 设为 0、金币正常。这样玩家看到的是“我按下大招，怪群被扫掉，金币反馈出现”，而不是“按钮亮了，我点了一下”。

这类爽点可以为第一次体验临时布景，但不要用永久数值奖励污染关卡模型。

## “不够爽”优先补流派目标和质变反馈

《光与朽》上线后的“不够爽”不是单一数值问题。玩家没有形成“我正在走哪条流派、快要拿到什么质变、这一局为什么会变强”的目标感，金色技能又偏数值增强，于是即使伤害在增长，也不容易被感知为爽。

处理顺序：

1. 第一波或第一次升级时给流派方向提示，让玩家知道“选同流派会成型”。
2. Lv5 金色技能必须有质变表现，不只是数字更高。
3. Frost 减速、Wide 变宽、Chain 弹跳这类效果要有清晰粒子、颜色和飘字语义。
4. Combo / FRENZY 只做视听和节奏反馈，不加伤害，避免破坏战斗模型。

爽感的目标是让玩家看见自己正在变强，而不是把所有伤害倍率往上推。

## 复活爽点要解决“刚复活又死”的情绪

复活如果只是回血，很容易在怪群包围时变成二次死亡。更好的复活体验应包含一个短暂的场面重置：

| 元素 | 作用 |
| --- | --- |
| 冲击波 / 推怪 | 立刻拉开空间，证明复活有用 |
| 小怪清理或打断 | 解除刚才的死亡压力源 |
| 2 秒左右无敌 | 给玩家重新接管操作的时间 |
| 强 VFX / 音效 | 让广告或复活福利有价值感 |

这比“全屏清空”更稳：既给玩家喘息，又不完全抹掉挑战。

## 数值变大不等于爽，玩家要看到成长差异

低基数上的小百分比提升很容易被玩家忽略。基础伤害很低时，`+10%` 可能只多 1 到 2 点飘字；如果只是把飘字整体乘大，玩家又会失去对真实强度的判断。更稳的做法是让每个成长节点产生可见差异：伤害段位、光束宽度、颜色、粒子、命中音效、Boss 血条缓冲和怪物状态都要能证明“我刚刚变强了”。

技能之间也不能互相抵消爽感。Wide 让激光变宽后，Focus 如果又把激光变细，玩家会觉得之前的选择被作废。类似规则应优先做成乘法兼容，或者在 UI 文案里明确说明取舍，否则数值上变强，体验上仍然像削弱。

## 波间奖励要制造抉择，不只是发属性

宝箱、无人机、战术箱和逃跑宝怪的价值，不在于多给一个随机属性，而在于让玩家短暂停下来做判断：贪奖励还是守塔，选正收益还是赌负面契约，追宝怪还是清压力。奖励一旦只剩随机数值，就会变成噪音；奖励如果有清晰标签、风险收益和即时反馈，就能成为战斗节奏里的喘息点和爽点。

可复用规则：

| 奖励形态 | 爽感来源 | 风险 |
| --- | --- | --- |
| 三选一战术箱 | 明确选择、命中进度环、奖励飘字 | 文案不清会像随机惩罚 |
| 逃跑宝怪 | 贪婪追击和防守取舍 | 场面太乱时玩家看不见 |
| 金色问号箱 | 赌性和惊喜 | 负面/无效必须有保底，不能连续惩罚 |
| 波间无人机 | 给玩家休息和构筑感 | 如果只有属性，容易像打断节奏 |

## 飘字不是越多越爽，而是优先级和节奏要对

激光游戏的飘字要服务“滋滋滋切割”的连续感，但不能把屏幕炸成信息噪音。可用的基本分层：

| 类型 | 作用 | 表现 |
| --- | --- | --- |
| Normal | 证明激光正在造成伤害 | 小号白/青白字，快速上浮 |
| Crit | 奖励弱点或暴击 | 更大、霓虹红、可带图标和脉冲 |
| Status | 只显示关键控制 | 例如 `STUN!`、`BLOCK`，黄色或高亮 |
| 奖励/契约 | 表示波间选择结果 | 图标 + 英文缩写 + 数值 |

同屏 100 个 TextMeshPro 既伤性能也伤阅读。更合理的上限是 30-50 个，池满时普通伤害可以丢弃或回收最早普通字，暴击和关键状态优先显示。玩家不需要看清每一个 10 点伤害，但必须看见暴击、控制和奖励选择。

## 激光 Tick 飘字不要急着合并

持续激光每 0.2 秒跳一次伤害，正好能形成“连续烧穿”的节奏。如果把 1 秒内的伤害全合并成一个大数字，反而会像回合制结算，削弱激光的手感。

不合并适合：

- 高频低额普通伤害。
- 持续照射逐步变强的数字变化。
- 多目标同时被扫到时的满屏切割感。

需要合并或降频的场景：

- 同一帧大量小怪重叠导致读不清。
- 手机端帧率被 UI 拖累。
- 奖励/契约这类低频信息，本身就应该单独醒目显示。

飘字的目标不是精确报账，而是让玩家相信自己的操作正在发生作用。

## 无人机奖励飘字要“图标先行，文字短”

波间无人机/战术箱奖励里，玩家没有时间读“主激光宽度 +0.1”这类长文案。更好的表达是图标 + 短英文缩写 + 数值：

| 奖励 | 建议表达 |
| --- | --- |
| 攻击力增加 | `ATK +10%` |
| 暴击率增加 | `CRIT +2%` |
| 激光长度 | `RANGE ▲` / `RANGE ▼` |
| 激光宽度 | `WIDTH ▲` / `WIDTH ▼` |
| 无奖励 | `MISS` / `AIR +1`，低饱和灰色弱图标 |
| 契约 | 两行显示：代价在上，收益在下 |

空奖励也要有弱反馈。只有文字会让玩家以为漏看了奖励；一个低亮度烟雾、空盒、枯叶类图标能把“失望”转成轻微玩笑，而不是纯粹的负反馈。

## 来源: `10_流水/历史聊天/Google_光与朽美术_2026-04-02.md` · 提取日期 2026-05-22

## 波间奖励物必须像“可被激光击破的战斗对象”

普通宝箱容易和《光与朽》的霓虹网格、激光塔、防御战语境冲突。更合理的是把三选一奖励做成运输无人机或空投装置：玩家一眼知道“射爆它拿奖励”，同时它仍属于战斗空间的一部分。

可复用规则：

| 设计项 | 推荐 |
| --- | --- |
| 造型 | 3/4 俯视微透视无人机，下方抓取奖励箱 |
| 材质 | 干净玩具感金属/塑料，霓虹呼吸灯 |
| 入场 | 从屏幕上方远处飞入，落到波间位置 |
| 击破 | 爆炸 + 溶解/飞散，其它未选无人机飞走 |
| 奖励反馈 | 无人机上方图标飘字，停留约 1 秒 |

这类波间奖励的爽感不是“多给属性”，而是把选择、击破、爆炸、飘字和下一波开始连成一个小闭环。

## 乘区爽感要让玩家看见“规则被自己改写”

《Balatro》的爽感不是单纯数字变大，而是玩家先理解一个大众规则（扑克牌型），再通过小丑牌、塔罗牌、星球牌和牌库改造把规则推翻。它的核心是：**熟悉规则降低门槛，乘区和构筑负责制造突破常识的爆炸感**。

可复用到动作 / 塔防 / Roguelike 的设计原则：

| 设计点 | 作用 |
| --- | --- |
| 先给玩家熟悉基准 | 让玩家知道“正常情况下应该是多少” |
| 再开放少量高影响构筑件 | 不堆系统数量，而是让 2-3 个系统互相放大 |
| 区分加法、乘法、经济 | 加法稳定，乘法爆发，经济负责滚雪球 |
| 结算顺序可被理解 | 玩家要知道为什么这次爆了，而不是只看到随机数字 |
| 视觉反馈跟随数值层级升级 | 小加成小跳字，乘区爆发要有火焰、震动、音效和停顿 |

对《光与朽》一类持续战斗游戏，连杀、弱点击破、波间奖励和陷阱连锁都可以做“乘区爽感”。但前提是 UI 和反馈必须告诉玩家：这不是普通伤害 +10%，而是玩家亲手搭出的规则组合正在生效。

## 流派爽感要有颜色、音效和空间反馈，不只是词条

《Hades》的神明祝福之所以容易被玩家记住，是因为每个流派都有清晰的视听身份：波塞冬的蓝色击退、宙斯的闪电连锁、雅典娜的反弹、战神的延迟刀刃。玩家在高速战斗中不需要读面板，也能知道自己触发了什么。

对《光与朽》这类激光塔防，可复用为：

| 流派层 | 表达要求 |
| --- | --- |
| 元素色 | 每个流派固定主色，不频繁混用 |
| 命中反馈 | 冰、火、电、暗等命中声和粒子差异明显 |
| 空间反馈 | 击退、折射、爆炸、减速要改变战场形态 |
| 高阶反馈 | 关键 Combo 触发时给短暂停顿、音效和特效升级 |

动作爽感不是堆更多特效，而是让每种特效都能回答一个问题：“我刚刚触发的是哪条规则？”

## 基础攻击也要有手感，因为玩家会重复它几千次

《Hollow Knight》的普通攻击机制并不复杂，但 Hitstop、屏幕震动、白色打击特效和清晰音效让每次命中都有确认感。越是高频基础动作，越不能只依赖数值。

可复用原则：

- 基础攻击命中必须有最低反馈包：停顿、亮闪、音效、受击状态。
- 高频反馈要克制，不能每次都做大爆炸。
- 关键命中和普通命中要分层，否则玩家看不出成长。
- 如果同一资源同时用于回血和输出，反馈要分别明确，避免玩家不知道资源花到哪里。

塔防里“基础攻击”就是主激光、塔攻击和小怪受击。它们会出现成千上万次，最值得先打磨。

## 割草爽感要有密度曲线和开奖停顿

《Vampire Survivors》的爽感不是一开始就满屏爆炸，而是从稀疏小怪、勉强求生，逐步滚到满屏 AoE、怪潮融化。密度变化让玩家感到“我变强了”，宝箱演出则给构筑质变一个短暂停顿和开奖仪式。

可复用到动作/塔防：

| 爽感层 | 设计要点 |
| --- | --- |
| 密度递进 | 前 1 分钟稀疏可控，中期围压，后期成片清场 |
| 进化反馈 | 武器/塔/芯片质变时给新特效、音色和攻击形态 |
| 宝箱演出 | 奖励揭晓可短暂停顿，但总时长要克制 |
| 拾取反馈 | 经验、金币、碎片飞向玩家，证明清怪产生收益 |

对《光与朽》，高价值节点不是每次升级都做大演出，而是 Lv5 质变、塔芯进化、Boss 弱点击破和稀有奖励开箱时集中给反馈。日常命中保持清楚，高阶节点才爆。

## 普通击杀反馈不要稀释高阶技能的独占爽点

《光与朽》旧优化储备里曾考虑给普通怪死亡加入更强“爆浆感”，但当某个满级技能已经用爆炸作为专属反馈时，全局怪物都爆，会直接稀释高阶技能的差异。

可复用规则：

| 反馈层级 | 适合承担什么 |
| --- | --- |
| 普通怪死亡 | 清楚消失、轻粒子、金币 / XP 拾取 |
| 精英怪死亡 | 更大粒子、音效峰值、轻微屏幕震动 |
| 连杀 / 弱点击破 | 节奏停顿、局部冲击波、连击提示 |
| 满级技能 / 质变构筑 | 专属爆炸、画面变调、音色升级 |

全局反馈要抬底线，不要抢高阶节点的峰值。若要增强整体打击感，优先在精英怪死亡、Boss 弱点击破或连杀时加 Camera Shake，而不是让所有普通怪都使用同级别爆炸。

## Game Feel 要先打磨高频动作的最低反馈包

游戏爽感的底线来自高频动作：主攻击命中、敌人受击、击杀、奖励入账、关键技能释放。它们会被玩家重复数千次，不能只依赖数值结果。每个高频动作至少要有输入响应、命中确认和结果反馈三层。

基础反馈包：

| 层级 | 推荐处理 |
| --- | --- |
| 输入响应 | 点击/释放后立刻有姿态、光效或音效回应 |
| 命中确认 | 受击闪白、短停顿、轻震、命中音或粒子 |
| 结果反馈 | 击杀消失、金币/经验飞入、连杀或弱点击破提示 |
| 高阶节点 | 稀有构筑、Lv5 质变、Boss 弱点击破才使用更强停顿和屏震 |

Hitstop 和屏幕震动都要分层。普通命中用极短、低幅度反馈保持确认感；清屏、暴击、弱点击破和 Boss 阶段转换再使用更明显的停顿、变色、音色升级和镜头反馈。爽感不是每一帧都吵，而是让玩家知道“我刚刚触发了哪条重要规则”。

## 爽感命中要有准备、爆发和余韵

Game Feel 不是单个特效，而是输入、空间和润色共同形成的反馈闭环。一次完整命中可以拆成三段：

```text
动作准备期 -> 命中瞬间 -> 命中后摇
预期建立      核心爆发      余韵延伸
```

可复用到动作、塔防和 Roguelike 的反馈表：

| 阶段 | 作用 | 可用反馈 |
| --- | --- | --- |
| 准备期 | 让玩家预期即将发生强结果 | 蓄力、前摇、音效预警、瞄准线、目标高亮 |
| 命中瞬间 | 证明玩家打中了、打疼了 | Hit-stop、白闪、命中音、粒子、局部屏震 |
| 命中后摇 | 让结果完整落地 | 击退、死亡动画、金币飞入、音效衰减、连击提示 |

Hit-stop 建议按事件分层，而不是全局滥用：

| 事件 | 建议 |
| --- | --- |
| 普通轻命中 | 0.05-0.08 秒以内，最好局部处理 |
| 重击 / 精英击杀 | 0.10-0.15 秒，配合明显音效和粒子 |
| 大招 / Boss 死亡 | 允许更长停顿、减速或镜头变化，但要少用 |

塔防的难点是玩家不总是直接控制攻击，因此要通过“代理打击感”补偿：敌人死亡动画、波次清除反馈、塔升级动画、关键飘字和奖励吸附，都要让玩家相信自己的布置正在产生力量。
