# 光与朽·Boss 战设计经验

> 来源：《光与朽》VolcanoBoss 与 GlacialBoss 的设计、实现和调试记录。用于沉淀“Boss 技能如何既可读、可调，又能落到 Unity 状态机里”。

---

## 来源: `10_流水/光与朽项目/分析-VolcanoBoss闪白效果系统_202604.md` · 提取日期 2026-05-19

## Boss 受击反馈要区分护甲、核心和阻挡物

Boss 反馈不能只问“有没有飘字 / 有没有白闪”，要先区分命中语义：

| 命中对象 | 玩家理解 | 推荐反馈 |
| --- | --- | --- |
| 护甲 / 外壳 | 打到了，但不是最优伤害 | 灰色小飘字，弱反馈或无白闪 |
| 核心 / 眼睛 | 打到弱点，产生有效伤害 | 红色大飘字，强白闪，音效峰值 |
| 熔浆液 / 阻挡物 | 激光被挡住，Boss 没受伤 | 阻挡物本身要有命中反馈，避免误判为 Boss 漏飘字 |

VolcanoBoss 的白闪触发本身只在 `TakeCoreDamage()`，方向是对的；问题在于白闪材质组抓得太宽，把 body02 岩石护甲也一起闪白，导致“打到核心”和“打到身体”的视觉差异被抹平。

可复用规则：**Boss 的反馈层级要和玩家策略一致。** 如果玩家应该追求打核心，就必须让核心命中的反馈明显强于护甲命中。

## Boss 技能要先定义战术职责，再映射到状态机

GlacialBoss 的实现价值在于：每个技能都有明确战术职责，然后再映射到 `BaseBossController` 的状态或自定义协程。

| 技能 | 战术职责 | 实现映射 |
| --- | --- | --- |
| 冰墙构建 | 制造路径阻断和输出损耗 | `BossState.Summon` + 召唤 IceWall |
| 冰封射线 | 打断玩家输出节奏 | 自定义协程，Boss 停止移动，射线扫屏 |
| 极寒冲撞 | 迫使玩家处理位移压力 | `BossState.Charge` |
| 绝对零度 | 高优先级惩罚技，制造打断目标 | 独立触发器，中断当前状态并覆盖协程 |

Boss 技能不要从“我想加一个酷技能”开始，而要从“它给玩家制造什么决策”开始。状态机只是落地方式。

## 高优先级技能必须能安全中断当前技能

“绝对零度”是一个典型高优先级技能：它要在冷却就绪、阶段满足时打断当前行为，进入蓄力、可被打断、失败惩罚的完整流程。

实现层的关键点：

1. 触发前记录当前 Boss 状态和关键计时器。
2. 停止当前 `stateCoroutine`，避免两个技能并行抢控制。
3. 蓄力开始时记录 HP 快照。
4. 每帧检测蓄力期承伤是否达到打断阈值。
5. 打断成功和失败走两套明确结算。
6. 结算后回到 Idle 或统一状态入口。

这类技能的风险不是写不出来，而是状态清理不干净：移动没停、协程叠加、伤害快照重复结算，都会让 Boss 行为变成随机事故。

## Boss 阶段变化要改变行为组合，不只是加数值

GlacialBoss 使用 HP 阈值切阶段：

| 阶段 | HP 阈值 | 行为变化 |
| --- | --- | --- |
| Phase 1 | >65% | 基础技能池 |
| Phase 2 | 30%-65% | 额外定时召唤 FrostTank |
| Phase 3 | <=30% | 绝对零度冷却缩短 |

这比单纯提高攻击力更可读。玩家能感受到“Boss 进入新阶段”，也能学习新的处理重点。

可复用原则：

- Phase 1 教技能。
- Phase 2 叠加压力，但不完全换规则。
- Phase 3 缩短关键技能节奏，制造终局压迫。

阶段变化应优先改“技能频率、组合方式、召唤物、打断窗口”，最后才考虑简单加伤害。

## Boss 技能接入文档要覆盖“代码以外的契约”

复杂 Boss 技能不是代码写完就能工作。GlacialBoss 的冰刺、冰封射线、冻结 QTE 都依赖一组 Unity 侧契约：Prefab、Layer、Tag、Inspector 引用、LineRenderer 坐标空间、EnemyDatabase 注册和测试清单。

可复用接入清单：

| 契约 | 典型风险 |
| --- | --- |
| Prefab 组件 | 投射体少挂 Rigidbody2D / Trigger Collider，碰撞不触发 |
| Layer | 冰刺不放到可被激光检测的层，玩家无法反制 |
| Tag | Tower / Shield Tag 错误，命中语义失效 |
| Inspector 引用 | LineRenderer、EndVFX、覆盖图、投射体 Prefab 未拖入 |
| 数据库注册 | IceWall 的 EnemyData 未进库，生成后行为退回默认 Chase |
| 测试清单 | 技能看似能播，但惩罚、隐藏、复位、QTE 没验完 |

Boss 技能文档应该明确“谁要拖到哪里、Layer/Tag 必须是什么、每个技能如何验证”。这不是琐碎说明，而是防止代码正确但运行时全错的保险。

## 惩罚型大招要给玩家可反制对象

“绝对零度”重构的核心价值，是把 Boss 大招从一次不可读的惩罚，改成了玩家能处理的物件链路：

1. 冰刺拔出，给玩家预警。
2. 冰刺旋转对准塔，明确威胁目标。
3. 冰刺射出，成为可被激光打爆的投射体。
4. 全部击破则无惩罚。
5. 任意命中塔，才触发真实伤害、冻结和额外怪物涌入。

这类设计比“蓄力失败直接扣 30% 血”更适合动作/塔防混合玩法，因为玩家能把失败归因到自己是否处理了冰刺，而不是觉得 Boss 在脚本杀。

## Boss 射线要区分护盾命中和本体命中

冰封射线重构后，命中 Shield 层只造成持续护盾伤害，不冻结；命中 Tower 层才触发冻结。这条规则让护盾有明确战术价值，也让玩家理解“护盾挡住了控制效果”。

可复用原则：

- 命中护盾：削资源，保留控制免疫。
- 命中本体：触发控制或重惩罚。
- 未命中：只显示威胁，不结算惩罚。

Boss 技能的命中语义越清楚，玩家越容易学会应对，而不是把失败理解为随机。

## Boss 状态特效和受击白闪要分层

VolcanoBoss 的经验说明：Boss 蓄力、狂暴、受击白闪如果都抢同一组 Renderer / Shader 参数，就会出现白闪刺眼、红光被洗掉、玩家读不懂状态的问题。

更稳的分层：

| 层 | 负责内容 | 是否受受击白闪影响 |
| --- | --- | --- |
| `bodyRenderers[]` | Boss 基础身体和受击白闪 | 是 |
| `redBodyEffect` | 蓄力、狂暴、技能状态红光 | 否，必须独立 Renderer |
| `body03Renderer` | 火山口熔浆沸腾 / FlowSpeed | 只做局部表现，不承担所有状态 |
| Eyes | 弱点可读性、开闭、阶段 tint | 独立接口控制 |

关键纪律：`redBodyEffect` 不要被自动 `GetComponentsInChildren<SpriteRenderer>()` 纳入 `bodyRenderers[]`。如果 Inspector 里留空让代码自动抓子 Renderer，状态层和受击层会重新混在一起。

## 护甲命中反馈可以用材质“沸腾”，不一定要白闪

护甲命中需要反馈，但不一定要闪白。对于火山 Boss，Body03 的 `_Flow_Speed` 短暂加速比白闪更贴合“熔浆被激光扰动”的语义，也更不容易和蓄力红光冲突。

可复用选择：

| 命中类型 | 反馈 |
| --- | --- |
| 护甲命中 | 灰色飘字 + Body03 轻微 FlowSpeed 加速 |
| 核心 / 眼睛命中 | 强飘字 + 短促白闪 |
| 技能蓄力中 | redBodyEffect 负责红光，受击反馈尽量短、低峰值 |

Boss 反馈的目标是“玩家知道打到了哪里”，不是所有命中都用最亮的白色。

## Boss 射线角力不一定需要碰撞体

GlacialBoss 冰封射线的“角力感”最终没有通过给 LineRenderer 加动态 Collider 实现，而是用 Raycast + ClashMeter：

| 表现 | 实现 |
| --- | --- |
| Boss 射线从中心缓慢延伸 | 1.5s 延伸阶段，长度 0 → 满长度 |
| 延伸期给玩家反应时间 | `freezeRayActive = false`，无伤害、无角力 |
| 玩家激光顶住 Boss 射线 | 玩家命中 Boss 时累积 clash meter |
| 角力视觉 | Boss 射线端点按 clash ratio 回缩 |
| 打断 / 压制结果 | 达阈值后终止射线或进入下一阶段 |

LineRenderer 形状每帧变化，用 Collider 维护成本高且边界 bug 多。只要命中语义清楚，Raycast 反而更稳定。

## 大招是否可打断，要看玩家已有反制对象

绝对零度早期曾设计成 Boss 蓄力可被打断，但后续改为不可直接打断，因为它已经有了可反制对象：飞出的冰刺可以被玩家激光打爆。

判断规则：

| 情况 | 更适合 |
| --- | --- |
| 没有可处理对象，只是 Boss 蓄力 | 给打断窗口，避免脚本杀 |
| 已经生成可摧毁投射物 / 机关 | 让玩家处理对象，而不是再打断 Boss |
| 技能视觉经常看不到 | 不要被打断过早，先保证技能完整出现 |

一个 Boss 大招不需要同时拥有“打断 Boss”和“击破投射物”两套反制链。反制方式越清晰，玩家越容易学会。

## Boss 关键血量要用实测承伤校准

Ch3 15 局数据里，胜局击杀 Boss 的实际承伤集中在约 650k，而配置曾写 750k。最终把 Boss HP 调到 650k，不是单纯削弱，而是让配置和运行事实一致。

Boss 数值校准顺序：

1. 先修 CSV 导出和技能统计，确认数据可信。
2. 看胜局 `Boss_Dmg_Dealt` 是否集中在某个实际值。
3. 对齐配置 HP 与运行时实际承伤。
4. 再调整单个技能伤害，例如绝对零度当前血量伤害 30% → 20%。

Boss 血量如果配置和实战长期不一致，后续所有 Boss 时长、技能频率和胜率讨论都会偏。

## Boss 死亡要给玩家 1-2 秒“确认胜利”的演出窗口

Boss 血量归零后直接弹结算，会吞掉最关键的高潮：玩家无法确认“是我的激光击杀了 Boss”。更稳的流程是在死亡和结算之间插入短演出窗口。

《光与朽》最终使用约 1.8 秒真实时间：

| 时间 | 事件 |
| --- | --- |
| T+0.00s | Boss 抖动缩放 + 轻震，仍保持正常时间 |
| T+0.40s | Boss Sprite 闪白数次，强调濒临崩解 |
| T+0.70s | Boss 隐藏，播放章节专属爆炸 VFX / SFX |
| T+0.70s | 子弹时间开始，`Time.timeScale = 0.1`，重型镜头抖动与震动 |
| T+1.20s | timeScale 线性恢复，色差或暗角做余韵 |
| T+1.80s | 调用 Victory，结算面板淡入 |

演出不一定要拆 Boss 图片做裂纹。对独立开发更划算的做法是：Boss 闪白 + SetActive(false) + 粒子爆炸遮盖消失瞬间。碎片感交给粒子 Texture Sheet 和主题色块，工作量远低于拆分整套 Boss 动画。

## 死亡演出第一帧必须冻结 Boss AI

给 Boss 死亡加演出窗口后，会出现一个新风险：在 Victory 还没调用前，Boss 的 `Update`、`FixedUpdate`、状态协程和 DOTween 还在跑，可能继续冲刺、碾压或攻击玩家。

可复用修复：

1. 在死亡演出协程第一帧调用 `PrepareForDeath()`。
2. `StopAllCoroutines()` 停止状态机和子协程。
3. Rigidbody 清零速度并设为 kinematic。
4. 禁用 Boss 控制器 `enabled = false`。
5. `DOKill()` 杀掉所有位移 / 缩放动画。
6. 演出结束后再由 GameManager 调 Victory。

死亡状态是一个终态，不应继续参与战斗状态机。否则“更有仪式感”的演出会变成“Boss 死了还在打人”的回归 bug。

## Boss 死亡链路要只有一个结算出口

Boss 死亡通常会被多个系统监听：BossHealth、WaveManager、GameManager、SettlementPanel。最危险的是多个监听者都调用胜利结算。

闭合链路应当是：

1. BossHealth 血量归零，触发 BossDeath 事件。
2. WaveManager 只清理波次状态，不直接弹结算。
3. GameManager 作为唯一出口启动死亡演出协程。
4. 演出结束后 GameManager 调 Victory。

如果 WaveManager 同帧 `TriggerGameVictory()`，就会绕过演出窗口；如果 GameManager 的事件订阅被 `ClearAllEvents()` 清掉，死亡事件又会完全没人接。Boss 死亡这种关键链路要在场景加载后做订阅回补，并定期按流程图模拟一次。

## Boss 入场演出要统一 timeScale 策略

Boss 入场黑线特效“有时看得到、有时看不到”的根因不是特效坏了，而是时间尺度混用：技能选择面板会把 `Time.timeScale` 设为 0，但黑线粒子使用 `useUnscaledTime=1`，它会在暂停 UI 背后按真实时间播完。

可复用规则：

| 演出元素 | timeScale 策略 |
| --- | --- |
| Boss 入场移动 | 若可能被暂停 UI 打断，用 Unscaled Time |
| 关键 VFX | 与入场移动保持同一时间语义，避免后台播完 |
| 镜头抖动等待 | 使用 `WaitForSecondsRealtime` |
| 普通战斗移动 | 继续使用 scaled time，受暂停控制 |

关键演出不能在玩家看不到的时候悄悄播完。只要游戏中存在升级面板、技能三选一、设置暂停，就要检查 Boss 入场、死亡、UI 引导这些演出是否会被 timeScale 撕裂。

## Boss 射线角力要用共享接触点，而不是整段碰撞盒

极寒 Boss 冰封射线最初用整条射线 hitbox 参与角力，玩家激光会撞到束身侧边，而不是两个激光端点相撞。结果是“看起来有碰撞，但没有对波感”。更稳结构是：

1. Boss 激光主体只负责显示和伤害区域。
2. 激光前端单独生成 `BossFreezeRayClashPoint`。
3. 玩家激光只和前端 clash 点发生角力命中。
4. Boss 激光终点 = clash 点。
5. 玩家激光终点 = clash 点。
6. 谁占优，clash 点就朝对方移动。

这样才能形成玩家能读懂的画面：Boss 射线从中心伸出，玩家转激光接住，两个顶点贴在一起，Boss 压制时接触点朝塔推进，玩家压制时接触点朝 Boss 推回。

## Boss 技能演出增强不能替代机制模型

“Boss 释放冰封射线前先回到屏幕中轴”能改善构图，但不能单独解决角力。回中是演出增强，clash 点才是机制核心。

可复用区分：

| 层 | 作用 |
| --- | --- |
| 回到中轴锚点 | 让玩家预判技能、让画面对波更清楚 |
| 1s 蓄力 / 预警 | 给玩家旋转激光的反应时间 |
| 前端 clash 点 | 决定角力是否成立 |
| 统一清理入口 | 防止 LineRenderer 残留、端点还跟 Boss 跑 |

Boss 技能出问题时，先问是“构图不可读”还是“机制模型不对”。前者靠演出，后者必须重做交互点。

## 反制方式只能有一个主语义

绝对零度早期有“蓄力期间打 Boss 本体可打断”逻辑，但实战中玩家持续照 Boss，导致技能几乎永远放不出来。后来改为蓄力不可打断，唯一反制变成击落后续冰刺。

这条经验可复用：

| 设计状态 | 风险 |
| --- | --- |
| 打 Boss 本体也能打断 | 玩家会用最直接输出覆盖其他机制 |
| 冰刺也能被击落 | 已经有清晰反制对象 |
| 两者同时存在 | Boss 大招无法稳定展示，学习目标混乱 |

如果一个技能的核心乐趣是“处理飞来的冰刺”，就不要再让“持续打 Boss 本体”成为更强反制。

## 对波数值要先相持，再分胜负

冰封射线共享接触点落地后，又出现了玩家一碰上去 Boss 射线就缩回的问题。根因是玩家压力公式太强：`damage + knockback * 1.25`，即使只点一次击退，也大于 Boss 基础推进。

更稳的角力手感：

1. 玩家压力不要瞬间满功率，增加 0.4-0.8 秒爬升。
2. 中断照射后快速衰减。
3. 击退属性有用，但权重要保守，例如伤害和击退都降权。
4. Boss 前 0.5-1.0 秒有开场压制优势。
5. 护盾存在时先推进到护盾，护盾破后继续推到塔本体。

参数调试优先级：

| 参数 | 作用 |
| --- | --- |
| `freezeRayBossAdvanceSpeed` | Boss 持续推进强度 |
| `freezeRayOpeningAdvantageMultiplier` | 开场压制强度 |
| `freezeRayOpeningAdvantageDuration` | Boss 强势期时长 |
| `freezeRayPlayerPressureScale` | 玩家压力总换算 |
| `freezeRayKnockbackPressureWeight` | 击退属性贡献 |

只调阈值通常无效，因为真正驱动的是接触点推进速度。角力系统要调“速度与爬升”，不是只调“打断值”。

## Boss 不应被友方小怪物理挤压

极寒 Boss 曾被冰墙孵化的小怪从屏幕上方一路顶到光棱塔脸上，但又没有接触伤害，看起来非常怪。把这个现象合理化成“贴塔伤害”不是好方案，因为那是在把 bug 变成惩罚。

更稳结论是：Boss 与友方普通小怪之间不发生实体阻挡和推挤，允许小怪穿过 Boss；但 Boss 对玩家系统仍保持碰撞、受击和技能交互。

| 交互 | 处理 |
| --- | --- |
| 普通小怪 / 孵化怪 vs Boss | 不阻挡、不推挤 |
| 冰墙等静止地形 | 保留，不随意穿过 |
| 玩家激光 vs Boss | 保留受击与角力 |
| Boss 技能 vs 玩家塔 | 保留伤害/冻结 |

Boss 的站位应该由 Boss 状态机和技能决定，不应被友方小怪物理系统无意决定。

## Boss 角力不能把交互门槛锁死在单一技能上

Boss 角力阶段如果“没选冲击模块就完全推不动”，会出现 Boss 贴脸发呆、塔不受伤、玩家也无能为力的尴尬状态。核心机制的底线是：即使没有抽到特定技能，玩家也要有最小交互能力。

更稳的角力模型：

| 状态 | 处理 |
| --- | --- |
| Boss 普通状态 | 高击退抗性，基本推不动 |
| Boss 角力 / 冲撞状态 | 抗性降低，允许激光产生少量反向力 |
| 无冲击模块 | 初始微量推力只能减缓，推不走 Boss |
| 有冲击模块 | 明显推开，形成无伤或低伤反制 |
| 推力不足 | Boss 对护盾造成持续摩擦伤害，避免贴脸无事发生 |

这样冲击模块仍然有价值，但不是“没有就系统死机”。Boss 战的反制可以有强弱差异，不能有交互断层。

## Boss 弱点在身体内部时，要分离视觉阻挡和伤害转发

恶魔之眼弱点在外圈碰撞体内部，激光按常规射线会被 Boss 身体挡住，打不到眼睛；如果强行穿透到眼睛，视觉上又像激光穿过了 Boss，破坏反馈。更稳的方案是：视觉端点仍停在 Boss 外圈，伤害逻辑再按命中口、弱点窗口或内部映射转发给眼睛。

设计原则：

| 层 | 推荐 |
| --- | --- |
| 视觉命中 | 激光顶端停在外壳或开口处 |
| 伤害语义 | 只有打到弱点窗口才转为核心伤害 |
| 反射/分裂适配 | 可给 Boss 多个弱点口或特定角度窗口 |
| 反馈 | 核心伤害大飘字/强白闪，外壳伤害弱反馈 |

不要让“内部弱点”变成看不懂的穿模。玩家看到的是打到 Boss 的哪一层，系统再决定这一下是否算核心伤害。

## 污秽球、火球、陨石等 Boss 投射物要避开出生即碰撞

Boss 投射物刚出生就和 Boss 身体碰撞爆炸，会出现“看不到子弹，只看到大飘字”的问题。所有从 Boss 身上发射的投射物都要检查生成点、Layer、初始碰撞忽略和出膛延迟。

可复用检查：

1. 从身体左右侧或下侧生成，不在 Boss Collider 内部。
2. 刚生成时短暂忽略 Boss 自身碰撞。
3. 投射物 Layer 与激光检测 Layer 明确。
4. 爆炸 VFX、飞行 VFX、命中伤害分离。
5. 被激光击落的 HP 与 Boss 技能伤害分开配置。

Boss 投射物的第一帧很关键。出生点错了，后续所有视觉和数值都会像“凭空爆炸”。

## BaseBossController 要抽公共生命周期，不抽具体技能

第二章熔岩火山和第三章极寒之核都能继承第一章 Boss 的入场、狂暴、受击、死亡、血条、技能调度框架，但具体技能应该留给子类实现。

推荐边界：

| 抽到基类 | 留在子类 |
| --- | --- |
| 入场/死亡流程 | 熔岩吸收、冰墙构建等章节专属技能 |
| 血量/阶段/通用事件 | 技能前摇、轨迹和特殊反制 |
| 目标点/朝向/公共移动 | 投射物种类、墙体、冻结、岩浆 |
| 统一受击反馈接口 | 特殊弱点、护甲、临时无敌 |

Boss 架构的目标是减少重复生命周期代码，不是把所有技能都硬塞进一个巨大的父类。

## 低血狂暴要改变节奏，不只是把 Boss 涂红

Boss 低血狂暴的触发点可以放在 HP 30% 左右。触发后需要同时给视觉、音频和机制一个明确变化，让玩家知道“下一段开始了”：

| 层级 | 可用变化 | 注意 |
| --- | --- | --- |
| 视觉 | 红色 emission / 体表闪光 / 入狂暴演出 | 可复用已有红色受击效果，但要控制透明度 |
| 音频 | BGM pitch 或强度上升 | Boss 死亡或战斗结束必须重置 |
| 节奏 | idle 间隔从 3-5s 缩到 1.5-2.5s | 让技能更密，不是单纯堆伤害 |
| 召唤 | 召唤 CD 15s -> 10s | 不盲目加小怪数量，优先加召唤物速度 |
| 压迫 | 下压/冲撞力度 +20%，移动速度 +15-20% | 保持可躲和可读 |
| 控制抗性 | 冻结/眩晕时长衰减 | 避免狂暴阶段被无限控死 |

狂暴的设计目标是改变战斗呼吸：前半段让玩家熟悉技能，后半段压缩决策时间。它不是一个单独的数值 Buff，而是一组跨表现和机制的阶段切换。

## Boss 控制效果要有递减和短暂无敌窗

普通怪可以被冰冻、减速、眩晕完整控制，但 Boss 如果吃完整控制链，会很容易失去威胁；如果完全免控，又会让冰系 Build 失去意义。更好的折中是 Boss 专属控制递减：

| 次数 | 效果 |
| --- | --- |
| 第 1 次控制 | 完整持续时间 |
| 第 2 次控制 | 50% 持续时间 |
| 第 3 次控制 | 25% 持续时间 |
| 第 4 次触发 | 进入约 6s 不可阻挡 |

不可阻挡期间 Boss 免疫冻结、减速、眩晕，但仍正常受伤。下压/推挤等表现可以保留约 30% 效果，不要完全消失。Boss 冻结期间应暂停暴露值或阶段积累，避免玩家在控制窗口里把下一段也提前触发。不可阻挡结束后再回到正常状态机。

## Boss 弱点命中不要依赖藏在身体里的小 Collider

如果 Boss 外壳是一个大的 `CircleCollider2D`，眼睛弱点是身体内部很小的 `BoxCollider2D`，玩家激光很容易永远先命中外壳，弱点实际不可达。这时继续缩放眼睛 Collider 会带来两个坏结果：太大像打空气，太小仍然打不到。

更稳的规则是：

| 激光命中对象 | 判定 |
| --- | --- |
| 命中 Boss 身体，眼睛睁开 | 视为弱点命中，走高伤害/暴击 |
| 命中 Boss 身体，眼睛闭合 | 视为外壳命中，走普通伤害 |
| 命中眼睛 Collider | 可保留为调试、未来狙击技能或特殊命中 |

玩家感知上，眼睛睁开时“打到 Boss 就是在打弱点”；工程上，弱点逻辑由 Boss 状态控制，而不是押注物理检测顺序。眼睛 Collider 可以保留给 Scene Gizmos、调试和未来精准技能，但不要让当前核心战斗依赖它。

## Boss 角力阶段要允许命中身体产生推力

下砸/Press 这种角力阶段，如果只有命中眼睛才能推，玩家会因为弱点 Collider 不可达而误判“冲击模块没用”。更好的交互是：

| 命中部位 | 作用 |
| --- | --- |
| 身体 | 产生基础推力，可阻挡或减缓下砸 |
| 眼睛/睁眼状态 | 在基础推力外增加伤害或弱点倍率 |

角力反馈必须宽容，弱点反馈可以精确。阻挡 Boss 行为时，先保证玩家能看懂“激光顶住了”，再用弱点加成奖励更好的时机。

## Boss 投射物出生点和自碰撞要先设计清楚

污秽球、火球这类 Boss 投射物如果从身体内部或过近位置生成，会第一帧就和 Boss 身体 Collider 重叠，出现“没看到子弹，但 Boss 或玩家突然跳伤害”的错觉。

可复用规则：

1. 投射物从 Boss 球体边缘或炮口点生成，不从中心偏移一点硬算。
2. 生成后短时间忽略 Boss 自身碰撞；如果玩法不需要反弹回 Boss，就永久忽略 Boss 碰撞。
3. Boss 自己的投射物不要默认能伤 Boss，除非这是明确机制。
4. 激光击毁投射物时，先确认投射物 Layer 和激光检测层一致。

投射物第一帧的出生位置、Layer 和忽略碰撞关系，比飞行脚本本身更容易制造假 Bug。

## Boss 弱点也需要视觉通道，不只是代码状态

当 Boss 外壳挡住眼睛时，代码上可以用“眼睛睁开状态”判定弱点，但美术上仍要给玩家一个能理解的攻击通道。设计红色眼睛弱点时，可以在外壳上做底部或左右裂口、分块岩壳、发光导向缝隙，让激光射向核心这件事变得合理。

弱点视觉的最低要求：

| 维度 | 规则 |
| --- | --- |
| 亮度 | 弱点必须是全 Boss 上最高亮度区域之一 |
| 通路 | 外壳裂缝宽度要明显大于主激光束宽度 |
| 方向 | 裂缝和高亮边缘把视线导向眼睛 |
| 状态 | 闭眼/开眼、可打/不可打要有可读差异 |

Boss 弱点不是藏起来让玩家猜的彩蛋，而是“危险中露出的机会”。视觉、碰撞和伤害倍率三者要讲同一个故事。

## 章节 Boss 要复用完整状态机，不要只换皮

多章节 Boss 不能只做一个更大、更厚、更亮的怪物。每章 Boss 都要继承同一套完整语义：入场、待机、普通技能、强化/狂暴、受击僵直、冻结/减速、霸体、护甲/外壳、死亡与结算。这样玩家学到的是“Boss 战规则”，而不是每章重新猜一套隐藏脚本。

| 状态/语义 | 设计要求 |
| --- | --- |
| Intro | 用镜头、预警或入场音效告诉玩家战斗升级 |
| Idle/Move | 让玩家能观察弱点、攻击窗口和危险方向 |
| Enrage/Super Armor | 控制链不能无限锁死 Boss，但仍可正常受伤 |
| Hit-Stun / Interrupt | 打断要服务关键技能，不要让 Boss 全程木桩化 |
| Frozen/Slow | 冻结期间暂停阶段积累，避免控制窗口顺手跳阶段 |
| Carapace / Shield | 护甲、外壳、弱点伤害要给不同反馈 |
| Death | 死亡前后不要立刻切黑，保留玩家胜利确认 |

护盾和碰撞也要有一致规则：盾先吃伤害并触发短暂无敌帧；盾破后下一次命中才伤本体；小怪撞盾可以自毁，大型怪/Boss 则击退、继续施压或进入碰撞冷却。无敌帧不是“没反应”，而是防止同一接触帧把玩家瞬间打死。

## Boss 可以是阶段门槛，不只是关底血条

《Terraria》的 Boss 价值不只是战斗挑战，而是阶段解锁器。击败 Boss 后，新矿物、新 NPC、新事件、新生态或世界状态发生变化，玩家会明确感到“游戏进入下一章”。

对《光与朽》这类项目，Boss 战可以承担三层职责：

| 层级 | 设计问题 |
| --- | --- |
| 战斗验证 | 玩家当前 Build 是否能应对本章压力 |
| 系统解锁 | 击败后是否解锁新塔、新插件、基地功能或敌人规则 |
| 世界变化 | 下一章是否在视觉、敌人、资源和波次结构上发生质变 |

如果 Boss 只是不停加血，它只是阻塞；如果 Boss 带来系统级变化，它就是目标。

## 战前准备也应该进入 Boss 设计

《Terraria》把沙盒建造融入 Boss 战：玩家铺平台、放回血物、搭陷阱，本质是在战前改变战场条件。这个思路可降维到塔防：在 Boss 波前给玩家有限的防线调整、地形改造、陷阱布置或资源换购。

可复用边界：

- 准备阶段要短，避免打断节奏。
- 每个准备项必须能在 Boss 战里看见效果。
- 准备不是保送，仍要让 Boss 技能考验核心操作和 Build。
- 早期获得的模块可以在后期合成或升级，避免旧资产完全报废。
