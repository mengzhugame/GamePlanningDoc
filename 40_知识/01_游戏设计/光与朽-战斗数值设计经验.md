# 光与朽·战斗数值设计经验

> 来源：《光与朽》实战数据（BattleLog + 策划文档），可直接复用于同类型激光/塔防/Roguelite 项目。

---

## 核心原则：DPS vs EHP 逆推法

**永远不要凭直觉填怪物血量。** 所有怪物血量必须从"该波次预期玩家 DPS"逆推。

### DPS 基准曲线（光与朽参考值）

| 阶段 | 波次 | 玩家预期 DPS | 怪物血量上限参考 |
|------|------|------------|----------------|
| 前期 | W1–3 | 1000–1500 | Slime ≈ 3000 |
| 中期 | W4–6 | 3000–5000 | Tank ≈ 20000 |
| 后期 | W7–8 | 10000+ | 精英怪 ≈ 50000 |

**严禁"感觉差不多"填表**，每次数值调整后必须用实战 BattleLog 验证。

---

## 伤害公式：乘区独立设计

```
最终伤害 = (基础伤害 × 功率加成) × (1 + 暴击倍率) × (1 + 碎冰倍率) × (1 + 数据破碎倍率)
```

每条乘区互不干扰，优点：
- 可以单独调整任何一个乘区而不破坏整体平衡
- 后期数值爽感来自多项乘区叠加，而非单一数值暴涨
- 玩家理解曲线平滑（每个技能有独立感知区）

---

## 经验值精细控制：等级锚点系统

### 设计目标
通过 15 局数据验证等级锚点的一致率，达到 100% 则视为合格。

### 光与朽实际锚点（W1–W9）
- W1→Lv3，W2→Lv5，W3→Lv8，W4→Lv9（W1-W4 一致率 100%）
- W5–W8 变化率 60–87%（正常，中期差异化正常）
- W9 结束→Lv17（一致率 100%）

### 踩过的坑
- Ch2 孵化怪（Slime）初设 XP=20 导致经验过多，玩家 W7 前就满级 → 调整为 Splitter 20→11、Slime 20→11、Exploder 16→10、Tank 80→45
- 孵化怪子体（Lava_Puddle 障碍物）给 XP=20 → 应改为 0，障碍物不应给任何奖励
- **关键教训**：父体怪 + 子体怪的所有奖励参数必须联动调整，遗漏一个就会导致经验过多/过少

---

## 难度峰值：机制叠加才是真凶

单独调一个参数往往效果微弱，难度峰值来自多机制同时叠加。

### 案例：W7 清波时间 93.8s（目标 70–85s）
根因分析：
1. EliteFrostcaster 在 t=30 登场（太早）
2. 同时峰值 13 面 IceWall 阻断激光路径
3. FrostSlime 孵化次数翻倍（74–101 次）

解法：推迟 EliteFrostcaster 登场至 t=35，预期降低 10–15s。

**方法论**：难度问题优先用实际清波时间数据诊断（而非理论推断），然后逐个排查机制叠加的组合。

---

## Boss 数值一致性：配置与运行必须一致

**典型事故**：第三章 Boss HP，asset 配置写 750000，实际运行 650000（相差 13.3%）。

- 发现方式：多局胜利数据中 Boss_Dmg_Dealt 集中在 650000 而非 750000
- 教训：**关键数值不能只看配置文件，必须定期用实战数据验证运行时行为**
- 建议：每周跑一次"数值一致性检查"，对比配置表 vs BattleLog 实际值

---

## 可直接复用的数值设计规则

1. 所有怪物血量从 DPS 曲线逆推，不凭直觉
2. 伤害乘区分离，每个增益在独立乘区
3. 等级锚点设计 + 15 局数据验证，W9 锚点偏差不超过 5%
4. 孵化怪/分裂怪的子体奖励必须与父体联动调整
5. 障碍物类敌人 XP = 0
6. 难度峰值诊断先看"机制叠加"，再看"单参数偏高"
7. 关键数值每周验证配置 vs 实际运行

## 成长上限要配补偿机制，不能只硬砍

激光长度这类“可见成长”最容易在 Roguelite 局内成长中失控：技能升级、局内奖励、无人机奖励等多个来源叠加后，会突破屏幕边界，导致视觉不可控和数值膨胀。

这类问题不要只用 `Clamp` 粗暴截断，否则玩家拿到“加长”奖励时会感觉奖励失效。更好的做法是“上限 + 溢出补偿”：

| 设计项 | 原则 |
| --- | --- |
| 主效果上限 | 给视觉空间相关属性设硬上限，例如激光长度最多到屏幕边缘附近 |
| 副效果补偿 | 达到上限后，把溢出成长转成伤害、暴击、范围、冷却等仍可感知的收益 |
| 选项池过滤 | 当某属性已到上限，从三选一奖励池中移除该属性，避免废选项 |
| 文案同步 | 满级说明要告诉玩家“长度已满，额外转为伤害”，避免误解 |

关键不是“防止玩家变强”，而是让成长继续有效，同时把视觉边界控制在可读范围内。

## 波次难度要看真实总 HP 和机制时序

Ch2 的数据复盘说明：波次表面配置不等于真实难度。精英怪、分裂物、障碍物、召唤物是否计入日志，会直接影响判断。

可复用检查：

| 检查项 | 目的 |
| --- | --- |
| 真实总 HP 曲线是否单调上升 | 防止 W6 比 W7 更难这类倒退 |
| 清场耗时是否随波次逐步增长 | 看玩家压力是否真实上升 |
| 玩家受伤是否集中在设计目标波次 | 判断难度峰值是否落对 |
| Boss 实际承伤是否接近配置 HP | 检查配置和运行时是否一致 |
| 机制怪出现顺序是否正确 | 例如自爆怪必须先布置障碍，主力怪再进入障碍区 |

Ch2 的关键经验是：自爆怪的熔浆液如果只存在 3 秒，而下一批怪物 15 秒后才出现，它就完全没有战术意义。机制敌人的数值必须和波次时序一起设计。

障碍类对象还要额外检查：

- 存活时间不能短到机制无效。
- 也不能永久存在导致屏幕完全封死。
- HP 要让玩家可以主动清除，但需要付出可感知代价。
- XP / 金币奖励通常应为 0，避免玩家刷障碍物收益。

## 数值模型不能跨章节硬套

Ch2 的 5 局日志里，胜率 4/5，表面看是 80% 胜率，属于可接受区间。但 Ch1 的 V1 模型不能直接套到 Ch2：Ch2 的 W5 不再是“技能爆发点”验证波，而是自爆怪、坦克、炮手、分裂怪混合的高压波，方差明显更高。

章节模型要单独建，至少等 15-20 局数据后再判断曲线是否稳定。跨章节复用时，只复用分析框架，不复用具体锚点：

| 可复用 | 不能直接复用 |
| --- | --- |
| DPS vs EHP 逆推法 | Ch1 的 W5 爆发假设 |
| 等级锚点检查 | Ch1 的清波时间目标 |
| 机制叠加诊断 | Ch1 的怪物组合压力判断 |

## 机制怪出场时机要和掩护条件绑定

炮手这类远程机制怪如果“裸出场”，很容易刚刷出来就被激光扫死，玩家既感受不到威胁，也看不到章节差异。Ch2 的 LavaGunner 问题不是单纯血量低，而是出场时间落在了坦克死亡后、下一批掩护形成前。

可复用两种时序设计：

| 方法 | 适用条件 | 调整方向 |
| --- | --- | --- |
| 障碍覆盖法 | 自爆怪能先铺出熔浆液 / 地形压力 | 炮手在障碍形成后进入，例如 W4 22s → 10s、W5 22s → 14s |
| 坦克护送法 | 坦克能吸引火力并挡线 | 坦克提前，炮手跟随，例如 W6 坦克 28s → 20s，炮手 20s → 22s |

远程怪、召唤怪、施法怪都不该只问“几秒刷”。更准确的问题是：**它出现时，场上有没有足够的掩护让它完成一次有效行为？**

## D1 难度要按章节根因拆分，不能全局一刀切

D1 血量分析说明：同一个 `enemyHealthMultiplier` 在不同章节含义完全不同。Ch1、Ch2、Ch3 的问题根因不一样，不能用一个全局血量倍率同时解决。

| 章节 | 观察 | 调整结论 |
| --- | --- | --- |
| Ch1 D1 | 整体健康，只是舒适度略紧 | 可小幅降血量，例如 1.0 → 0.80 |
| Ch2 D1 | 分裂怪子体链式堆积，W1 就打穿护盾 | 要切断子体压力链，例如 1.0 → 0.60 |
| Ch3 D1 | 小怪 W1-W5 零伤害，问题集中在 Boss | 不应砍小怪血量，应查 Boss |

Ch2 的真实问题是分裂链：16 个 Splitter 各分 2 个子体，会制造 32 个子体；低等级玩家在 W1 就被挤压，后续 W5 死亡只是结果。此时降血量的目的不是“让所有怪更脆”，而是让父体和子体在链式压力形成前被清掉。

可复用规则：

1. D1 调参先按章节拆日志，不看全局平均。
2. 判断“死因在小怪、Boss、还是机制链条”。
3. 对分裂 / 召唤 / 孵化类敌人，调血量要看父体和子体总 EHP。
4. 若早期零伤害但 Boss 死亡，不能为了通关率去削小怪。

## 章节等级锚点要检查“奖励被削过头”

Ch3 的 3 局失败日志显示：W9 结束等级只有 Lv14-15，而目标是 Lv17。根因不是玩家输出一定过低，而是冰墙孵化史莱姆 XP 从 20 直接削到 1，导致奖励链被砍断。

召唤 / 孵化类单位的奖励要防两种极端：

| 极端 | 后果 |
| --- | --- |
| 奖励过高 | 玩家提前满级，后续波次失去成长压力 |
| 奖励过低 | 玩家到 Boss 前等级不足，输出不达标 |

更稳的做法是把子体奖励设成父体/普通怪的一小段比例，而不是从 20 一刀砍到 1。Ch3 这批数据给出的中间建议是 5-8 XP，目标是让普通构建 W9 结束回到 Lv16-17。

## 高压波次要区分“清波慢”和“进 Boss 状态差”

Ch3 W7 是普通波次中的高压点，3 局清波时间约 88-99 秒，显著高于其他波次。它的危害不只是“这一波久”，更关键是会把护盾和血量打空，导致玩家以劣势状态进入 W10 Boss。

诊断高压波次时要同时看：

| 指标 | 含义 |
| --- | --- |
| 清波时间 | 玩家输出是否被阻断、怪物总 EHP 是否过高 |
| 承伤 | 这波是否消耗了进入 Boss 的关键资源 |
| 动态障碍峰值 | 是否有 IceWall / Puddle 等对象造成路径阻断 |
| 后续 Boss 剩余血量 | 前一波状态差是否转化为 Boss 战失败 |

所以 W7 的调整不一定先砍所有怪物 HP，可以先调整机制时序，例如推迟 EliteFrostcaster 出场，或减少 Catalyst 数量，让“冰墙 + 孵化 + 施法者”的叠加峰值晚一点出现。

## 失败样本能定位问题，但不能建立完整胜利锚点

3 局全失败数据依然有价值：它能定位 W9 等级不足、W7 高压、Boss 绝对零度未被打断等问题。但它不能直接定义“合格曲线”，因为没有胜利构建作为对照。

可复用样本规则：

1. 失败样本用于定位卡点和死因。
2. 胜利样本用于建立目标 DPS、等级和承伤锚点。
3. 每章至少需要 5-8 局，且包含 2-3 局胜利，才适合固化数值模型。
4. 构建类型要分开看，极端构建不能代表普通构建。

## 新章节波次要按“机制教学 → 组合压制 → Boss”递进

Ch3 波次配置的价值在于，它把怪物机制逐波引入，而不是第一波就把所有系统倒给玩家：

| 波次 | 设计职责 |
| --- | --- |
| W1 | FrostSlime 导入，让玩家适应章节美术与基础敌人 |
| W2 | FrostTank 登场，建立高血量慢速压力 |
| W3 | FrostCatalyst 登场，引入死亡暴走机制 |
| W4 | Frostcaster 登场，引入冰墙地形压力 |
| W5 | EliteIceShieldGuard 登场，引入前置冰盾 |
| W6 | EliteFrostcaster 登场，形成冰墙 + 冰盾双重封锁 |
| W7 | 全怪种组合压制，作为 Boss 前压力峰值 |
| W8 | Boss 波，交给 BossManager 生成 |

可复用规则：每个新机制至少给一波“单独亮相”的窗口，再进入组合压制。这样玩家能学会机制，策划也能通过 BattleLog 分辨是哪一类机制导致失败。

## 波次配置要同时设计数量、时间和入场方向

同样的怪物数量，因为 `SpawnPattern`、`SpawnZone` 和出场时间不同，压力完全不同。Ch3 使用 Trickle / Normal / Burst / Swarm / Flood / Instant 以及 TopOnly / TopRandom / SideRandom / AllEdges 来调节体验。

配置时不要只看“这一波有多少怪”，要同时看：

| 维度 | 设计作用 |
| --- | --- |
| 数量 | 总 EHP 和总压力 |
| 时间点 | 是否与其他机制形成叠加峰值 |
| 生成模式 | 是持续压迫、瞬间爆发，还是洪水式堆叠 |
| 生成方向 | 是否逼玩家旋转激光、处理侧翼和全屏威胁 |
| 全局上限 | 防止召唤 / 孵化类机制把场面推爆 |

Boss 前最后一波可以做高压组合，但要特别谨慎：如果 W7 把血量和护盾打空，W8 Boss 失败可能不是 Boss 过强，而是普通波把入场状态打坏了。

## 成长来源叠加要用增量状态追踪

反射透镜和无人机奖励同时增加激光长度时，问题不只是“缺上限”，还有升级时把完整加成重复应用。`SetReflexFromConfig()` 如果每次都把当前等级的总加成重新加一遍，长度会被多次叠加，最终飙到 40+。

可复用规则：

| 问题 | 处理 |
| --- | --- |
| 多来源加同一属性 | 在属性入口统一上限，例如主激光 29、副激光 26 |
| 等级配置是总值 | 运行时记录已应用值，只应用 delta |
| 溢出后奖励失效 | 溢出转成伤害、暴击或其他可感知收益 |
| 奖励池继续刷废选项 | 达上限后移除或降低该选项权重 |

“上限 + 增量状态 + 溢出补偿 + 选项池过滤”是一整套，缺一块都会让玩家要么数值失控，要么觉得奖励无效。

## 障碍物奖励必须从总经验模型里剔除

Ch2 的 LavaPuddle 是战场障碍，不是敌人。如果它给 XP / 金币，玩家就会因为清障获得额外成长，破坏 W9 达到 Lv17 的等级锚点。

分裂 / 召唤 / 留场对象的经验设计要按真实贡献计算：

| 对象 | 经验原则 |
| --- | --- |
| 父体怪 | 给主要奖励 |
| 分裂子体 | 给低比例奖励，和父体总和一起校准 |
| 自爆后障碍 | XP / coin = 0 |
| Boss 技能召唤物 | 看是否是战斗目标；若只是机制物件，通常不给奖励 |

经验模型不能只数波次表里的“直接出怪”。像 Splitter 分裂出 LavaSlime 这种派生单位，才是等级锚点最容易失真的地方。

## 数值锚点只能建立在干净配置样本上

Ch2 的 15 局日志中，曾出现“中途改过配置”的混合样本。此时直接从数据推导 Boss 治疗上限、波次难度或等级锚点，都会把旧配置和新配置混成一个假结论。

数值建模前先做数据卫生检查：

1. 确认这一批日志使用同一份 Wave / Enemy / Boss 配置。
2. 若中途改过配置，旧样本只用于定位问题，不用于建立锚点。
3. 配置改动后至少重跑一组干净样本，再定模型。
4. AI 或表格分析给出反常建议时，先查样本是否被污染。

脏数据最危险的地方不是“没价值”，而是会给出看似精确、实际错误的调参方向。

## 章节模型要独立，最后再做横向总结

《光与朽》的数值模型不适合把三章硬揉进一个总模型。更稳的方式是：Ch1 做 V1，Ch2 做 V2，Ch3 做 V3；每章单独维护等级锚点、Boss 目标时长、机制压力和胜率，再在全部章节完成后做横向附录。

这样做的好处：

| 做法 | 结果 |
| --- | --- |
| 每章独立模型 | 允许章节机制差异存在，调整范围清楚 |
| 强行统一模型 | 容易为了平均值反复推翻已稳定章节 |
| 最后横向总结 | 沉淀共性方法，而不是共用具体数值 |

数值方法可以跨章复用，具体锚点不要跨章硬套。

## Boss 战时长要给局外成长留余量

Boss 目标时长如果设得太短，比如 35-65 秒，后续一旦加入科技、装备、局外成长，Boss 会迅速变成“进场秒融”，章节终局失去存在感。

Ch2 调整后的方向更适合作为参考：

| 构筑 | 目标关系 |
| --- | --- |
| 暴击构筑 | 约 75 秒，作为高输出基准 |
| 分裂构筑 | 约为暴击的 1.3 倍 |
| 冰冻构筑 | 约为暴击的 1.6 倍 |

这不是追求所有构筑完全等时，而是让不同构筑有明显体感差异，同时保留局外成长空间。分裂激光多束命中 Boss 如果是设计意图，就应该在模型中承认它，而不是当成 bug 强行抹平。

## 孵化型机制要同时设计经验上限和风险收益

Frostcaster 的冰墙如果孵化 FrostSlime，就不能只看“墙本身强不强”。它同时改变了场面压力、击杀爽感、玩家等级和 Boss 前状态。

更稳的模型是：

| 玩家选择 / 局面 | 结果 |
| --- | --- |
| 早杀施法者 | 冰墙数量少，压力低，少拿一部分子体经验 |
| 放任施法者 | 冰墙孵化更多 Slime，压力高，但能获得更多击杀和经验 |
| 波次表基础 Slime 不下调 | 总经验和同屏压力都会超标 |

因此孵化机制上线前要同步减少波次表里的基础 Slime 数量，把“施法者 charge 可产生的子体”纳入总 XP / 总 EHP 预算。否则玩家不是提前满级，就是被召唤物堆死。

## 同类机制不要重复占用同一种玩家决策

冰盾卫士已经承担了“必须先破盾 / 处理屏障”的决策，如果 IceWall 再做成可攻击 HP 墙，玩家会连续处理两个类似障碍，体验容易变成消耗战。

最终把 IceWall 改成非攻击目标、15 秒存在、每 2.5 秒周期孵化 Slime 的地形压力，是更清晰的分工：

| 机制 | 玩家决策 |
| --- | --- |
| IceShieldGuard | 集火破盾，决定激光是否能穿透 |
| IceWall Hatchery | 处理孵化出的怪群，承受/收割周期压力 |
| Frostcaster charge | 早杀减少未来墙数 |

同一章里每个机制怪都要回答不同问题。不要让所有机制都变成“打掉这个血条”。
