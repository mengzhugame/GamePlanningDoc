# 光与朽·战斗数值设计经验

> 来源：《光与朽》实战数据（BattleLog + 策划文档），可直接复用于同类型激光/塔防/Roguelite 项目。

---

## 核心原则：DPS vs EHP 逆推法

**永远不要凭直觉填怪物血量。** 所有怪物血量必须从"该波次预期玩家 DPS"逆推。

### DPS 基准曲线（光与朽参考值）

| 阶段 | 波次 | 玩家预期 DPS | 怪物血量上限参考 |
|------|------|------------|----------------|
| 前期 | W1–3 | 1000–1500 | Slime ≈ 3000 |
| 中期 | W4–6 | 3000–5000 | Tank ≈ 20000 |
| 后期 | W7–8 | 10000+ | 精英怪 ≈ 50000 |

**严禁"感觉差不多"填表**，每次数值调整后必须用实战 BattleLog 验证。

---

## 伤害公式：乘区独立设计

```
最终伤害 = (基础伤害 × 功率加成) × (1 + 暴击倍率) × (1 + 碎冰倍率) × (1 + 数据破碎倍率)
```

每条乘区互不干扰，优点：
- 可以单独调整任何一个乘区而不破坏整体平衡
- 后期数值爽感来自多项乘区叠加，而非单一数值暴涨
- 玩家理解曲线平滑（每个技能有独立感知区）

---

## 经验值精细控制：等级锚点系统

### 设计目标
通过 15 局数据验证等级锚点的一致率，达到 100% 则视为合格。

### 光与朽实际锚点（W1–W9）
- W1→Lv3，W2→Lv5，W3→Lv8，W4→Lv9（W1-W4 一致率 100%）
- W5–W8 变化率 60–87%（正常，中期差异化正常）
- W9 结束→Lv17（一致率 100%）

### 踩过的坑
- Ch2 孵化怪（Slime）初设 XP=20 导致经验过多，玩家 W7 前就满级 → 调整为 Splitter 20→11、Slime 20→11、Exploder 16→10、Tank 80→45
- 孵化怪子体（Lava_Puddle 障碍物）给 XP=20 → 应改为 0，障碍物不应给任何奖励
- **关键教训**：父体怪 + 子体怪的所有奖励参数必须联动调整，遗漏一个就会导致经验过多/过少

---

## 难度峰值：机制叠加才是真凶

单独调一个参数往往效果微弱，难度峰值来自多机制同时叠加。

### 案例：W7 清波时间 93.8s（目标 70–85s）
根因分析：
1. EliteFrostcaster 在 t=30 登场（太早）
2. 同时峰值 13 面 IceWall 阻断激光路径
3. FrostSlime 孵化次数翻倍（74–101 次）

解法：推迟 EliteFrostcaster 登场至 t=35，预期降低 10–15s。

**方法论**：难度问题优先用实际清波时间数据诊断（而非理论推断），然后逐个排查机制叠加的组合。

---

## Boss 数值一致性：配置与运行必须一致

**典型事故**：第三章 Boss HP，asset 配置写 750000，实际运行 650000（相差 13.3%）。

- 发现方式：多局胜利数据中 Boss_Dmg_Dealt 集中在 650000 而非 750000
- 教训：**关键数值不能只看配置文件，必须定期用实战数据验证运行时行为**
- 建议：每周跑一次"数值一致性检查"，对比配置表 vs BattleLog 实际值

---

## 可直接复用的数值设计规则

1. 所有怪物血量从 DPS 曲线逆推，不凭直觉
2. 伤害乘区分离，每个增益在独立乘区
3. 等级锚点设计 + 15 局数据验证，W9 锚点偏差不超过 5%
4. 孵化怪/分裂怪的子体奖励必须与父体联动调整
5. 障碍物类敌人 XP = 0
6. 难度峰值诊断先看"机制叠加"，再看"单参数偏高"
7. 关键数值每周验证配置 vs 实际运行

## 成长上限要配补偿机制，不能只硬砍

激光长度这类“可见成长”最容易在 Roguelite 局内成长中失控：技能升级、局内奖励、无人机奖励等多个来源叠加后，会突破屏幕边界，导致视觉不可控和数值膨胀。

这类问题不要只用 `Clamp` 粗暴截断，否则玩家拿到“加长”奖励时会感觉奖励失效。更好的做法是“上限 + 溢出补偿”：

| 设计项 | 原则 |
| --- | --- |
| 主效果上限 | 给视觉空间相关属性设硬上限，例如激光长度最多到屏幕边缘附近 |
| 副效果补偿 | 达到上限后，把溢出成长转成伤害、暴击、范围、冷却等仍可感知的收益 |
| 选项池过滤 | 当某属性已到上限，从三选一奖励池中移除该属性，避免废选项 |
| 文案同步 | 满级说明要告诉玩家“长度已满，额外转为伤害”，避免误解 |

关键不是“防止玩家变强”，而是让成长继续有效，同时把视觉边界控制在可读范围内。

## 波次难度要看真实总 HP 和机制时序

Ch2 的数据复盘说明：波次表面配置不等于真实难度。精英怪、分裂物、障碍物、召唤物是否计入日志，会直接影响判断。

可复用检查：

| 检查项 | 目的 |
| --- | --- |
| 真实总 HP 曲线是否单调上升 | 防止 W6 比 W7 更难这类倒退 |
| 清场耗时是否随波次逐步增长 | 看玩家压力是否真实上升 |
| 玩家受伤是否集中在设计目标波次 | 判断难度峰值是否落对 |
| Boss 实际承伤是否接近配置 HP | 检查配置和运行时是否一致 |
| 机制怪出现顺序是否正确 | 例如自爆怪必须先布置障碍，主力怪再进入障碍区 |

Ch2 的关键经验是：自爆怪的熔浆液如果只存在 3 秒，而下一批怪物 15 秒后才出现，它就完全没有战术意义。机制敌人的数值必须和波次时序一起设计。

障碍类对象还要额外检查：

- 存活时间不能短到机制无效。
- 也不能永久存在导致屏幕完全封死。
- HP 要让玩家可以主动清除，但需要付出可感知代价。
- XP / 金币奖励通常应为 0，避免玩家刷障碍物收益。

## 数值模型不能跨章节硬套

Ch2 的 5 局日志里，胜率 4/5，表面看是 80% 胜率，属于可接受区间。但 Ch1 的 V1 模型不能直接套到 Ch2：Ch2 的 W5 不再是“技能爆发点”验证波，而是自爆怪、坦克、炮手、分裂怪混合的高压波，方差明显更高。

章节模型要单独建，至少等 15-20 局数据后再判断曲线是否稳定。跨章节复用时，只复用分析框架，不复用具体锚点：

| 可复用 | 不能直接复用 |
| --- | --- |
| DPS vs EHP 逆推法 | Ch1 的 W5 爆发假设 |
| 等级锚点检查 | Ch1 的清波时间目标 |
| 机制叠加诊断 | Ch1 的怪物组合压力判断 |

## 机制怪出场时机要和掩护条件绑定

炮手这类远程机制怪如果“裸出场”，很容易刚刷出来就被激光扫死，玩家既感受不到威胁，也看不到章节差异。Ch2 的 LavaGunner 问题不是单纯血量低，而是出场时间落在了坦克死亡后、下一批掩护形成前。

可复用两种时序设计：

| 方法 | 适用条件 | 调整方向 |
| --- | --- | --- |
| 障碍覆盖法 | 自爆怪能先铺出熔浆液 / 地形压力 | 炮手在障碍形成后进入，例如 W4 22s → 10s、W5 22s → 14s |
| 坦克护送法 | 坦克能吸引火力并挡线 | 坦克提前，炮手跟随，例如 W6 坦克 28s → 20s，炮手 20s → 22s |

远程怪、召唤怪、施法怪都不该只问“几秒刷”。更准确的问题是：**它出现时，场上有没有足够的掩护让它完成一次有效行为？**

## D1 难度要按章节根因拆分，不能全局一刀切

D1 血量分析说明：同一个 `enemyHealthMultiplier` 在不同章节含义完全不同。Ch1、Ch2、Ch3 的问题根因不一样，不能用一个全局血量倍率同时解决。

| 章节 | 观察 | 调整结论 |
| --- | --- | --- |
| Ch1 D1 | 整体健康，只是舒适度略紧 | 可小幅降血量，例如 1.0 → 0.80 |
| Ch2 D1 | 分裂怪子体链式堆积，W1 就打穿护盾 | 要切断子体压力链，例如 1.0 → 0.60 |
| Ch3 D1 | 小怪 W1-W5 零伤害，问题集中在 Boss | 不应砍小怪血量，应查 Boss |

Ch2 的真实问题是分裂链：16 个 Splitter 各分 2 个子体，会制造 32 个子体；低等级玩家在 W1 就被挤压，后续 W5 死亡只是结果。此时降血量的目的不是“让所有怪更脆”，而是让父体和子体在链式压力形成前被清掉。

可复用规则：

1. D1 调参先按章节拆日志，不看全局平均。
2. 判断“死因在小怪、Boss、还是机制链条”。
3. 对分裂 / 召唤 / 孵化类敌人，调血量要看父体和子体总 EHP。
4. 若早期零伤害但 Boss 死亡，不能为了通关率去削小怪。

## 章节等级锚点要检查“奖励被削过头”

Ch3 的 3 局失败日志显示：W9 结束等级只有 Lv14-15，而目标是 Lv17。根因不是玩家输出一定过低，而是冰墙孵化史莱姆 XP 从 20 直接削到 1，导致奖励链被砍断。

召唤 / 孵化类单位的奖励要防两种极端：

| 极端 | 后果 |
| --- | --- |
| 奖励过高 | 玩家提前满级，后续波次失去成长压力 |
| 奖励过低 | 玩家到 Boss 前等级不足，输出不达标 |

更稳的做法是把子体奖励设成父体/普通怪的一小段比例，而不是从 20 一刀砍到 1。Ch3 这批数据给出的中间建议是 5-8 XP，目标是让普通构建 W9 结束回到 Lv16-17。

## 高压波次要区分“清波慢”和“进 Boss 状态差”

Ch3 W7 是普通波次中的高压点，3 局清波时间约 88-99 秒，显著高于其他波次。它的危害不只是“这一波久”，更关键是会把护盾和血量打空，导致玩家以劣势状态进入 W10 Boss。

诊断高压波次时要同时看：

| 指标 | 含义 |
| --- | --- |
| 清波时间 | 玩家输出是否被阻断、怪物总 EHP 是否过高 |
| 承伤 | 这波是否消耗了进入 Boss 的关键资源 |
| 动态障碍峰值 | 是否有 IceWall / Puddle 等对象造成路径阻断 |
| 后续 Boss 剩余血量 | 前一波状态差是否转化为 Boss 战失败 |

所以 W7 的调整不一定先砍所有怪物 HP，可以先调整机制时序，例如推迟 EliteFrostcaster 出场，或减少 Catalyst 数量，让“冰墙 + 孵化 + 施法者”的叠加峰值晚一点出现。

## 失败样本能定位问题，但不能建立完整胜利锚点

3 局全失败数据依然有价值：它能定位 W9 等级不足、W7 高压、Boss 绝对零度未被打断等问题。但它不能直接定义“合格曲线”，因为没有胜利构建作为对照。

可复用样本规则：

1. 失败样本用于定位卡点和死因。
2. 胜利样本用于建立目标 DPS、等级和承伤锚点。
3. 每章至少需要 5-8 局，且包含 2-3 局胜利，才适合固化数值模型。
4. 构建类型要分开看，极端构建不能代表普通构建。

## 新章节波次要按“机制教学 → 组合压制 → Boss”递进

Ch3 波次配置的价值在于，它把怪物机制逐波引入，而不是第一波就把所有系统倒给玩家：

| 波次 | 设计职责 |
| --- | --- |
| W1 | FrostSlime 导入，让玩家适应章节美术与基础敌人 |
| W2 | FrostTank 登场，建立高血量慢速压力 |
| W3 | FrostCatalyst 登场，引入死亡暴走机制 |
| W4 | Frostcaster 登场，引入冰墙地形压力 |
| W5 | EliteIceShieldGuard 登场，引入前置冰盾 |
| W6 | EliteFrostcaster 登场，形成冰墙 + 冰盾双重封锁 |
| W7 | 全怪种组合压制，作为 Boss 前压力峰值 |
| W8 | Boss 波，交给 BossManager 生成 |

可复用规则：每个新机制至少给一波“单独亮相”的窗口，再进入组合压制。这样玩家能学会机制，策划也能通过 BattleLog 分辨是哪一类机制导致失败。

## 波次配置要同时设计数量、时间和入场方向

同样的怪物数量，因为 `SpawnPattern`、`SpawnZone` 和出场时间不同，压力完全不同。Ch3 使用 Trickle / Normal / Burst / Swarm / Flood / Instant 以及 TopOnly / TopRandom / SideRandom / AllEdges 来调节体验。

配置时不要只看“这一波有多少怪”，要同时看：

| 维度 | 设计作用 |
| --- | --- |
| 数量 | 总 EHP 和总压力 |
| 时间点 | 是否与其他机制形成叠加峰值 |
| 生成模式 | 是持续压迫、瞬间爆发，还是洪水式堆叠 |
| 生成方向 | 是否逼玩家旋转激光、处理侧翼和全屏威胁 |
| 全局上限 | 防止召唤 / 孵化类机制把场面推爆 |

Boss 前最后一波可以做高压组合，但要特别谨慎：如果 W7 把血量和护盾打空，W8 Boss 失败可能不是 Boss 过强，而是普通波把入场状态打坏了。

## 成长来源叠加要用增量状态追踪

反射透镜和无人机奖励同时增加激光长度时，问题不只是“缺上限”，还有升级时把完整加成重复应用。`SetReflexFromConfig()` 如果每次都把当前等级的总加成重新加一遍，长度会被多次叠加，最终飙到 40+。

可复用规则：

| 问题 | 处理 |
| --- | --- |
| 多来源加同一属性 | 在属性入口统一上限，例如主激光 29、副激光 26 |
| 等级配置是总值 | 运行时记录已应用值，只应用 delta |
| 溢出后奖励失效 | 溢出转成伤害、暴击或其他可感知收益 |
| 奖励池继续刷废选项 | 达上限后移除或降低该选项权重 |

“上限 + 增量状态 + 溢出补偿 + 选项池过滤”是一整套，缺一块都会让玩家要么数值失控，要么觉得奖励无效。

## 障碍物奖励必须从总经验模型里剔除

Ch2 的 LavaPuddle 是战场障碍，不是敌人。如果它给 XP / 金币，玩家就会因为清障获得额外成长，破坏 W9 达到 Lv17 的等级锚点。

分裂 / 召唤 / 留场对象的经验设计要按真实贡献计算：

| 对象 | 经验原则 |
| --- | --- |
| 父体怪 | 给主要奖励 |
| 分裂子体 | 给低比例奖励，和父体总和一起校准 |
| 自爆后障碍 | XP / coin = 0 |
| Boss 技能召唤物 | 看是否是战斗目标；若只是机制物件，通常不给奖励 |

经验模型不能只数波次表里的“直接出怪”。像 Splitter 分裂出 LavaSlime 这种派生单位，才是等级锚点最容易失真的地方。

## 数值锚点只能建立在干净配置样本上

Ch2 的 15 局日志中，曾出现“中途改过配置”的混合样本。此时直接从数据推导 Boss 治疗上限、波次难度或等级锚点，都会把旧配置和新配置混成一个假结论。

数值建模前先做数据卫生检查：

1. 确认这一批日志使用同一份 Wave / Enemy / Boss 配置。
2. 若中途改过配置，旧样本只用于定位问题，不用于建立锚点。
3. 配置改动后至少重跑一组干净样本，再定模型。
4. AI 或表格分析给出反常建议时，先查样本是否被污染。

脏数据最危险的地方不是“没价值”，而是会给出看似精确、实际错误的调参方向。

## 章节模型要独立，最后再做横向总结

《光与朽》的数值模型不适合把三章硬揉进一个总模型。更稳的方式是：Ch1 做 V1，Ch2 做 V2，Ch3 做 V3；每章单独维护等级锚点、Boss 目标时长、机制压力和胜率，再在全部章节完成后做横向附录。

这样做的好处：

| 做法 | 结果 |
| --- | --- |
| 每章独立模型 | 允许章节机制差异存在，调整范围清楚 |
| 强行统一模型 | 容易为了平均值反复推翻已稳定章节 |
| 最后横向总结 | 沉淀共性方法，而不是共用具体数值 |

数值方法可以跨章复用，具体锚点不要跨章硬套。

## Boss 战时长要给局外成长留余量

Boss 目标时长如果设得太短，比如 35-65 秒，后续一旦加入科技、装备、局外成长，Boss 会迅速变成“进场秒融”，章节终局失去存在感。

Ch2 调整后的方向更适合作为参考：

| 构筑 | 目标关系 |
| --- | --- |
| 暴击构筑 | 约 75 秒，作为高输出基准 |
| 分裂构筑 | 约为暴击的 1.3 倍 |
| 冰冻构筑 | 约为暴击的 1.6 倍 |

这不是追求所有构筑完全等时，而是让不同构筑有明显体感差异，同时保留局外成长空间。分裂激光多束命中 Boss 如果是设计意图，就应该在模型中承认它，而不是当成 bug 强行抹平。

## 孵化型机制要同时设计经验上限和风险收益

Frostcaster 的冰墙如果孵化 FrostSlime，就不能只看“墙本身强不强”。它同时改变了场面压力、击杀爽感、玩家等级和 Boss 前状态。

更稳的模型是：

| 玩家选择 / 局面 | 结果 |
| --- | --- |
| 早杀施法者 | 冰墙数量少，压力低，少拿一部分子体经验 |
| 放任施法者 | 冰墙孵化更多 Slime，压力高，但能获得更多击杀和经验 |
| 波次表基础 Slime 不下调 | 总经验和同屏压力都会超标 |

因此孵化机制上线前要同步减少波次表里的基础 Slime 数量，把“施法者 charge 可产生的子体”纳入总 XP / 总 EHP 预算。否则玩家不是提前满级，就是被召唤物堆死。

## 同类机制不要重复占用同一种玩家决策

冰盾卫士已经承担了“必须先破盾 / 处理屏障”的决策，如果 IceWall 再做成可攻击 HP 墙，玩家会连续处理两个类似障碍，体验容易变成消耗战。

最终把 IceWall 改成非攻击目标、15 秒存在、每 2.5 秒周期孵化 Slime 的地形压力，是更清晰的分工：

| IceWall Hatchery | 处理孵化出的怪群，承受/收割周期压力 |
| Frostcaster charge | 早杀减少未来墙数 |

同一章里每个机制怪都要回答不同问题。不要让所有机制都变成“打掉这个血条”。

## 派生怪奖励要“低但有”，再用数据复测

IceWall 孵化 FrostSlime 的奖励从 20 XP 直接砍到 1 XP 后，3 局测试显示 W9 结束只有 Lv14-15，低于目标 Lv17。最终更稳的方向是：孵化怪给低额奖励，例如 5 XP，而不是 0 或 1。

| --- | --- |
| 防止孵化刷爆等级 | 孵化怪 XP 明显低于普通刷怪 |

“无奖励”解决的是数值问题，却会制造体验问题。召唤 / 孵化单位更适合低奖励 + 数据复测。

## 15 局模型先修采集，再做 P1 数值调整

## 多难度关卡要用“倍率 + 构成变化”两层结构

《光与朽》把 3 个章节扩成 15 个关卡时，最关键的判断不是“每个难度都复制一份波次”，而是分清哪一档只需要数值压力，哪一档需要构成变化。

可复用结构：

| 难度层 | 处理方式 | 设计作用 |
| --- | --- | --- |
| D1 | 基准 WaveConfig | 教章节机制，建立胜率锚点 |
| D2 | 共享 D1 波次，只调倍率 | 让玩家感到数量和强度上升，但不改变学习内容 |
| D3-D5 | `overrideWaveConfig` + 倍率 | 精英怪提前、机制叠加、Boss 压力增强，形成真正的重复挑战 |

纯倍率的优点是低成本，但它只能改变“更厚 / 更多 / 更快”；一旦目标是“精英怪提前登场”“炮手更早在掩护后输出”“Boss 前压力峰值前移”，就必须给高难度一份构成差异。

## 难度命名要承担玩家预期管理

五档难度命名最终收敛为：虚空之触、侵蚀之潮、精英冲击、噩梦深渊、混沌崩解。它们不是装饰文案，而是在告诉玩家压力来自哪里：

| 难度 | 玩家预期 |
| --- | --- |
| 虚空之触 | 原版体验，学习机制 |
| 侵蚀之潮 | 怪物更多、节奏更快 |
| 精英冲击 | 精英怪提前，普通解法开始吃力 |
| 噩梦深渊 | Boss 与机制叠加，需要强 Build |
| 混沌崩解 | 极限密度，章节特色机制暴走 |

难度文案要和真实配置一致。若 D3 叫“精英冲击”，配置里就必须真的有精英怪提前登场，而不能只是 HP 多 60%。

## 高难度不要压缩单怪奖励，改调升级门槛

D2-D5 最初用 `expDropMultiplier = 1 / enemyCountMultiplier` 来抵消“更多怪物带来的更多 XP”，纸面上能保持总 XP 不变，但体验上有问题：玩家在高难度杀了更多怪，却发现每只怪“不值钱”。

更好的结构是：

| 维度 | 旧方案 | 新方案 |
| --- | --- | --- |
| 单怪 XP | 难度越高越低 | 始终保持完整奖励 |
| 总怪物数 | 难度越高越多 | 难度越高越多 |
| 升级速度控制 | 砍奖励 | 提高升级所需 XP |
| 玩家感受 | 多杀怪但被扣收益 | 多杀怪有收益，但升级门槛也更高 |

新字段可命名为 `playerLevelUpExpMultiplier`，让 D1-D5 约等于 `1 / 1.15 / 1.30 / 1.45 / 1.60` 的升级门槛倍率；同时把 `expDropMultiplier` 重置为 1。

这条规则尤其适合 Roguelite 局内成长：**奖励反馈要保留，节奏控制放到升级曲线里。** 直接砍击杀奖励，会损伤玩家对“我变强了 / 我清掉了更多怪”的正反馈。

## 数值字段定义后必须确认真的被读取

这次真正导致 D3 W9 达到 Lv19 的根因，不是补偿公式数学上完全错，而是 `expDropMultiplier` 在代码里只有定义，没有实际读取。结果就是高难度怪物更多、经验也更多，升级门槛却没变。

数值字段上线前要做三件事：

1. 搜索字段是否只存在于 SO / 配置类，还是进入了运行公式。
2. 用一局实测验证字段改动是否真的改变结果。
3. 对关键锚点做回归，例如 W9 结束等级是否仍在 Lv17 左右。

“配置里有字段”不等于“游戏里有机制”。数值系统最怕这种安静失效。

## 教学专用刷怪要隔离 XP 经济

首次大招教学需要在大招充满前制造一批可收割小怪，让玩家第一次释放就感到爽。但这批小怪如果给正常 XP，会破坏 W9=Lv17 的等级锚点。

可复用处理：

| 项 | 规则 |
| --- | --- |
| 生成时机 | 大招充能约 80%-85%，例如 60 秒充能时在 50 秒左右刷 |
| 数量 | 足够形成割草画面，例如 15 只小怪 |
| XP | 设为 0，避免影响局内升级曲线 |
| 金币 | 可保留正常掉落，强化击杀反馈 |
| 波次计数 | 若处于 Spawning / Battle，追加到当前波次总数，避免波次提前结束 |
| 触发次数 | 只在首次大招引导发生，完成后持久化 |

教学刷怪是“演出型样本”，不是正式波次经济。它可以服务爽感，但必须从 XP、胜率和波次完成逻辑里隔离清楚。

## 短关卡不是把长关卡等比例压缩

《光与朽》从 9-10 分钟 D1 改到 5-6 分钟短关时，关键不是“砍一半波次”，而是重新定义 D1 的职责：新手钩子、买量承接、差异化展示、首局爽感。

更稳结构：

| 内容 | 短关 D1 处理 |
| --- | --- |
| 波次 | W1-W5 常规 + W6 Boss |
| 总时长 | 约 5.3-5.5 分钟 |
| 怪物引入 | 每波只引入 1 个主要新威胁 |
| 侧翼比例 | 从 0% 逐步到 40%，突出旋转激光差异 |
| 精英怪 | D1 移除，D2+ 再引入 |
| 爽感峰值 | W5 明确做割草爆发 |

不要直接复制竞品 5 分钟结构。竞品如果是多炮台常驻火力，5 分钟能成立；《光与朽》依赖激光构筑成型，就必须保留足够升级和流派引导。

## 短关 XP 可以加速，但必须限定语义

短关为了让 W5 前构筑成型，可以提高 `expDropMultiplier`，但这和高难度“不要砍单怪奖励”的原则不是矛盾，而是两种不同语义：

| 场景 | 推荐 |
| --- | --- |
| D1 短关 | 可用短关专属 XP 倍率，让 5-6 分钟内看见构筑 |
| D2-D5 高难 | 不砍单怪奖励，改用升级门槛控制成长 |

短关 XP 加速是为了保留首局爽点；高难奖励完整是为了保留挑战回报。两个字段必须清楚隔离，不能让 D1 的补偿倍率污染长期经济。

## 数值问题一次只改一个主变量

D1 体验挫败时，表面上可能同时想改怪物 HP、玩家等级、Boss HP、出怪密度。但如果同时改，下一轮测试就不知道到底是哪一项生效。

《光与朽》的顺序更稳：

1. 先确认 `expDropMultiplier` 是否真的生效，让 W5 前等级达到预期。
2. 如果等级修正后仍挫败，再看分章节 D1 的 `enemyHealthMultiplier`。
3. Ch2 这种分裂链路强的章节，可以先把 D1 小怪 HP 从 1.0 降到 0.6。
4. Ch3 如果小怪阶段无伤，问题就不是小怪 HP，而是 Boss 时长或 Boss 机制。

玩家说“怪太硬”时，可能真正的问题是等级不够、技能没成型或字段没生效。先查构筑进度，再查怪物血量。

## 胜率梯度要服务局外成长，不要只追最难

旧汇总里的难度目标最终收敛为：第一章 D1 约 80% 胜率，让玩家第一局轻松过关并解锁装备/科技树；D2 或第二章 D1 约 50%，让玩家感到需要局外成长；最高难度不建议 10%，更稳是 20%-25%，让玩家连输几局后仍相信能通过升级、Build 和操作解决。

可复用梯度：

| 难度 | 目标体验 |
| --- | --- |
| D1 | 轻松过关，建立信心和系统理解 |
| D2 / 下一章 D1 | 明显压力，驱动装备和科技树 |
| D3-D4 | 需要较强 Build 和章节机制处理 |
| D5 | 高压挑战，但不要低到让休闲玩家绝望 |

数值目标的作用不是“让难度看起来有五档”，而是把失败自然导向局外成长和再次挑战。

## 进度条要先定义它表示哪段流程

波次进度条最初写死 `1/12`，后来改成读当前 10 波配置，又短暂尝试把第 10 波 Boss 血量算进总进度。实测后收敛为：进度条 0-1 只表示第 1 波开始到第 9 波结束，第 10 波是 Boss 战，进入后直接满格。

经验：

| 进度条口径 | 适用 |
| --- | --- |
| 已完成波数 | 简单，但会慢一拍 |
| 当前波 + 波内进度 | 适合普通波推进感 |
| 普通波进度 + Boss 血量 | 可能和 Boss 血条语义重复 |
| 第 1-9 波进度，Boss 波满格 | 适合 10 波结构，Boss 单独看 Boss 血条 |

UI 进度条不是越“实时”越好。它要表达玩家当前关卡流程中的哪一段，Boss 血量已有专门血条时，不必再挤进波次进度。

## 宽度成长要让玩家同时感到更粗和更容易命中

广域透镜这类宽度成长，如果只看数值表，`1.2/1.4/1.6/1.8/2.0` 已经是翻倍；但基础激光宽度只有 `0.5`，Lv5 也只是到 `1.0`，在 HDR/Bloom 下玩家可能只感觉更亮，不觉得更粗。

这类成长要同时满足三件事：

| 维度 | 要求 |
| --- | --- |
| 视觉 | 宽度变化能被肉眼识别，不能被发光糊成“变亮” |
| 命中 | 伤害盒随宽度变大，确实减少漏怪 |
| 平衡 | 宽度成长不和大招、分裂激光产生重复倍率 |

《光与朽》最终把广域透镜提高到 `1.3/1.6/1.9/2.2/2.5`，并同步做亮度补偿。经验是：命中类成长一定要让玩家感受到“这个选择改变了我的操作容错”，否则它会被误读成普通伤害或普通特效。

## 弹球怪的反压迫感来自“被打后更危险”，不是慢慢等它回来

Dark_Drifter 的核心机制是被激光击退、撞墙、再回来。如果击退后回来的过程太慢，玩家体验会从“弹球怪有弹性”变成“我在等怪爬回来”。后续设计收敛为：只要被主激光/副激光命中，就进入持续强化状态，提高追塔速度和后续弹飞力度。

可复用判断：

| 状态 | 体验 |
| --- | --- |
| 被打飞后慢速返回 | 节奏空窗，玩家等待 |
| 被打飞后短冲一段 | 短期改善，但状态结束后又可能拖沓 |
| 被激光命中后持续强化 | 机制清楚：玩家越打它，它越有反扑压力 |

这类敌人的乐趣不是让玩家等碰撞模拟，而是把“我击退了它”转成“它会更快回来”的风险。参数上可以从 `3.5x` 追塔速度、`1.75x` 弹飞力度这类明显变化开始，再根据首章压力回调。

## 阻挡物要定义对连锁、穿透和溅射的共同边界

熔浆液和冰墙作为 `Stationary` 障碍，只阻挡主激光还不够。如果连锁反应能越过它们跳到后排敌人，玩家会觉得“墙挡住了激光，却挡不住技能”，语义不一致。

设计层要先定义：

| 效果 | 是否应被熔浆液/冰墙阻挡 |
| --- | --- |
| 主激光穿透 | 是 |
| 副激光穿透 | 是 |
| 连锁反应跳跃 | 通常是，除非明确设计为越墙电弧 |
| 爆炸 AOE | 可按半径穿墙或被墙挡，但要有一致规则 |

障碍物一旦进入波次设计，就不只是碰撞体。它代表“战场空间被切断”，所有传播型技能都要服务这个空间语义。

## 大招临时加成不要污染常规成长上限

“光与朽”大招期间主激光和分裂激光额外 `+5` 长度，适合做临时爆发感。但它不应该改写常规激光长度上限、技能池过滤或永久成长公式。

更稳的分层：

| 来源 | 语义 |
| --- | --- |
| 广域透镜 / 长度技能 | 永久成长，参与上限、掉落和过滤 |
| 无人机奖励 | 局内成长，参与局内 Build |
| 大招长度 +5 | 临时状态，只在 Overload 期间生效 |

临时爽点要能明显改变当下战场，但不能悄悄改变后续成长模型。否则玩家会在大招结束后感到手感断裂，数值系统也更难校准。

## Demo 技能池要用“机制技能 + 数值被动”制造取舍

早期《光与朽》只有 4 个机制技能时，5 分钟局内很容易出现“技能全满，没有流派取舍”。低成本扩容的方式不是立刻做一堆新机制，而是加入少量纯数值被动。

可复用模型：

| 类型 | 示例 | 作用 |
| --- | --- | --- |
| 机制技能 | 折射、击退、冰冻、聚能 | 改变玩法手感和战术 |
| 数值被动 | 伤害提升、宽度提升 | 增加成长选择和流派厚度 |

如果 6 个技能，每个 5 级，总共 30 级内容；一局只有约 15-18 次三选一，玩家就必须取舍。Demo 阶段不必一次性做完整卡池，但必须让玩家感到“我这局在朝某个方向构筑”。

## 数值调试要先设验收目标，再改 WaveConfig 或技能

“怪太多”“坦克杀不完”“进入 Boss 前经验已经满级”“宝箱怪没存在感”都不是单点 bug，而是 WaveConfig、经验产出、技能强度和敌人职责没对齐。调试前要先定义验收目标：

| 模块 | 验收目标 |
| --- | --- |
| 怪物数量 | 每波结束前能清掉主体威胁，进入 Boss 前没有大规模残留 |
| 经验节奏 | 第 7 波前能成型一个主技能，9 波结束接近目标等级 |
| 技能伤害 | 每个主流派在中后段有可验证的清群手段 |
| 特殊怪 | Drifter、宝箱怪等能被看见并产生独立决策 |
| Boss 前状态 | 玩家带着成型 Build 和可理解压力进入 Boss |

不要在没有验收目标时同时改怪物血量、技能倍率和经验表。下一轮测试会完全不知道哪个变量生效。

## 调技能还是调怪物，先看问题来自“成长端”还是“压力端”

流派 A 第 7 波后打群怪吃力，流派 B 前期像纯特效，这不一定说明怪物血量过高。要先判断问题来自哪端：

| 现象 | 优先检查 |
| --- | --- |
| 所有流派都清不动 | 怪物 HP / 数量 / 到达时间过高 |
| 某个流派前期完全无感 | 技能初始值或成长曲线太保守 |
| 升级很多次仍没感觉 | 伤害基数低、百分比太小、飘字不可感知 |
| Boss 特定技能无法反制 | 流派反制机制缺失，不只是 DPS |

例如聚能爆炸固定 100 伤害，后期对坦克无效，问题在技能成长没有跟上；分裂前期 30%-40% 伤害，玩家会觉得亏，问题在技能初始心理底线太低。

## 高频 Build 可以用判定次数反制 Boss，而不一定靠单次击退

流派 B（反射 + 分裂 + 广域）无法抵挡 Boss 冲撞时，不一定要给它和冲击模块一样的击退力。更符合流派特性的设计是“动量抵消”：每一次激光伤害判定给 Boss 一个微小反向阻力。

这样三类 Build 有不同解法：

| Build | 反制方式 |
| --- | --- |
| 单激光暴力流 | 单次伤害高，但判定频率低，需要冲击模块或高伤害窗口 |
| 分裂反射流 | 单次弱，但每秒几十次判定，形成“光墙”抵消冲锋 |
| 控制流 | 通过减速、冻结、眩晕改变 Boss 行为节奏 |

可复用原则：流派反制要来自流派优势。不要把所有流派都改成同一种击退力，否则 Build 差异会消失。

## 第二、三章数值锚点要一起规划，代码分章实现

接入第二章熔岩怪物前，先要求拿到第三章极寒怪物描述，这是对的。HP 锚点需要看三章全貌，否则第二章定得过高，第三章就没有提升空间。

但实现必须分章推进：

1. 先用 TTK 模型确定三章 HP 与伤害锚点。
2. 第二章先做数据层和关键新机制：岩浆斑、远程炮手、分裂怪。
3. 第二章 Boss 和波次稳定后，再进入第三章。
4. 每章至少跑 10 局数据，验证目标胜率和成型节奏。

战略上看全局，工程上切分风险。不要为了全局平衡一次性实现两章新机制。

## 宝箱怪的价值是制造贪婪抉择，而不是混在怪堆里送奖励

宝箱怪如果和普通怪一样从上往下冲塔，玩家会顺手打死，几乎没有决策。更好的设计是“捕鱼游戏式横穿屏幕”：

| 设计项 | 推荐 |
| --- | --- |
| 路径 | 左右横穿或波浪线，不攻击塔 |
| 血量 | 普通怪 10-15 倍，需要聚焦 2-3 秒 |
| 击退 | 霸体，不被推走 |
| 失败 | 飞出屏幕直接消失，无奖励 |
| 奖励 | 大金币 + 大经验，低等级时可给超级经验球补偿 |

它的爽点不是奖励本身，而是那一秒犹豫：保命清怪，还是贪这个会逃跑的宝箱。这个决策会让局内节奏更有波峰。

## XP 补偿要绑定“漏怪惩罚”，不是无条件发福利

如果只有激光击杀才掉 XP，撞塔自爆或结构击杀不掉或少掉 XP，那么新手活到中后段也可能等级不足。宝箱怪可承担 DDA 补偿：检测玩家在 3:30 或某波间隙低于目标等级，就让宝箱掉落大经验球。

这不是破坏难度，而是修复“活下来了但 Build 没成型”的断层。补偿触发条件必须绑定玩家实际落后，而不是固定每局发。

## 无人机/战术箱奖励要采集正负值对战局的真实影响

金色问号箱如果连续负收益或“无事发生”，玩家会直接觉得这局被毁。它不是普通随机奖励，而是局内构筑变量，必须采集每波选择增加/减少了什么属性，并观察后续胜负和伤害曲线。

建议字段语义：

| 字段语义 | 目的 |
| --- | --- |
| 本波选择箱类型 | 医疗、属性、契约 |
| 属性增减类型和值 | 攻击、暴击、宽度、长度、血量、护盾等 |
| 是否负面/无事发生/大奖 | 控制连续坏体验 |
| 选择后下一波表现 | 清怪速度、受伤、是否死亡 |
| Boss 前总加成 | 看箱子是否过强或过弱 |

不要只统计“选了几次箱子”。要能看到随机奖励是否真的改变了战局。

## 新章节怪物按“角色覆盖”规划，不按数量堆怪

章节扩展时，怪物数量不是越多越好。每章先保证战斗角色覆盖，再让外观和机制体现章节差异。一个可控章节包大致是：4 个基础角色 + 2 个精英变化 + 1 个 Boss。

| 角色 | 设计重点 | 风险控制 |
| --- | --- | --- |
| 冲锋/基础怪 | 提供主清怪节奏 | 不要只换色，要换轮廓或移动感 |
| 分裂怪 | 制造局部压力 | 限制子代继续分裂，避免指数爆场 |
| 远程怪 | 打断站桩输出 | 需要投射物池、停留点、拦截规则 |
| 坦克怪 | 拉长单点输出 | 全免疫推力会不爽，冰甲可用独立护甲 HP / 推力 -80% |
| 光环/施法怪 | 改变战场优先级 | 半屏 50% 减速过强，可从 30% 起，精英 40% |
| Boss | 章节机制总考 | 形体和技能要服务工程可实现性 |

不要把章节差异压在颜色上。第二章熔岩可以强调分裂、自爆、防御、远程炮击和熔岩蛋；第三章冰霜可以强调几何秩序、冰甲、光环、冻结和钻石晶核。每个角色都要回答“玩家为什么要改变瞄准或走位”。

## 数值放大要让升级有体感，同时同步放大 HP

如果基础伤害太低，+10% 只增加 1-2 点，玩家几乎感受不到成长。早期方案曾把基础 DPS 从 100 提到 1000，并同步把怪物 HP 乘以 10。这样不改变大体 TTK，却能让奖励、飘字和 Build 成长更可见。

调整这类全局数值时要一起看：

| 项 | 经验规则 |
| --- | --- |
| 基础 DPS / 怪物 HP | 同比例放大，保持清怪节奏 |
| 暴击基础值 | 可从 10% 降到 5%，给成长留空间 |
| 暴击上限 | 设上限，例如 50%，避免随机箱溢出 |
| 局内等级目标 | 固定 8 波时，可把 Boss 放第 8 波，目标等级约 Lv18 |
| XP 倍率 | 缩短波数后要提高 XP，例如 x2.0 |

数值放大不是“通胀”，而是让玩家看得见成长；前提是 DPS、HP、XP、波数和暴击上限一起重算。

## 聚能透镜应保留“重炮穿透”，不要只变成单体激光

聚能透镜的核心爽感是把激光从扫怪工具变成重炮，而不是简单牺牲范围换单体。如果只让视觉停在第一个敌人且完全没有后排收益，玩家会觉得变窄变弱。

更好的定位是高伤害 + 有限穿透：

| 等级 | 方向 |
| --- | --- |
| Lv1-Lv4 | 伤害逐级提高，穿透 1/2/3/4 个目标，每次穿透轻微衰减 |
| Lv5 | 无限穿透或对 Boss 无视部分护甲，删除旧的爆炸尾效 |

视觉上激光可以停在第一目标，后排伤害用飘字和命中特效表达。这样既保留“重炮聚焦”的画面，又保留群伤流的构筑价值。

## Frost 流派要把“直击减速”和“范围传播”分开

冰系技能如果所有效果都塞进 Frost Beam，会难以平衡，也难以让玩家读懂 Build 进化。推荐拆成：

| 技能 | 职责 |
| --- | --- |
| Frost Beam | 直击目标减速、变色，不负责大范围 VFX |
| FrostSpread | 命中目标周围扩散慢速/冻结，负责范围 VFX |
| Shatter / 冰结碎灭 | 冻结后的爆发或 Lv5 爆炸奖励 |

`FrostSpread` 可以由 `SkillData` 前置条件控制，只在 Frost 已获得后进入候选池，并通过权重提高后续出现概率。范围逻辑不依赖粒子碰撞，而是从被直击敌人位置做 `OverlapCircle`。如果扩散冻结积累太慢，例如每 0.1s 只加 0.3，需要把速率提高到 0.5-0.6 才能让玩家在战斗里看见结果。

## 战术箱负面效果要制造下注感，不要毁局

随机箱的负面效果可分为“下一波挑战”和“永久小削弱”。前者适合给明显更高的即时奖励，后者适合低幅度、可承受。

| 负面类型 | 示例 |
| --- | --- |
| 下一波增强 | 怪物速度 +30%、HP +40%、伤害 +25% |
| 玩家永久小削弱 | 攻击 -5%、暴击 -2%、宽度 -3%、长度 -5% |
| 无事发生 | 改为金币 50/100，避免纯空结果 |
| 红色契约 | 消耗当前 HP / Shield，换 1.5 倍普通奖励，强度低于 Epic |

“坏结果”也要有游戏性：玩家应该觉得自己是在下注，而不是被系统随便惩罚。

## 主激光、副激光和宽度成长要让玩家肉眼看见

激光类 Build 的数值变化必须转成明显视觉变化，否则玩家会觉得升级没生效。一个可用的 Demo 口径：

| 项 | 建议 |
| --- | --- |
| 主激光长度 | 从约半屏提升到 20 单位，保证覆盖感 |
| 主激光基础宽度 | 提高到 1.0 左右，别从过细基线开始 |
| 副激光宽度 | 固定 0.65，并随宽度技能同倍率增宽 |
| 副激光长度 | Lv1 约 10，Lv5 约 18 |
| Wide | 每级 +30% 宽度，靠光束实体宽度和光晕共同表现 |

副激光不必和主激光一样强，但长度不能太短。3 单位的副激光更像装饰，10 单位以上才会让玩家相信“分叉真的在清怪”。

## Focus 不一定要缩窄激光；可以只做高伤害与变色

“聚能透镜：宽度 80%”很容易造成歧义，玩家会以为宽度增加到 80%，实际却是缩窄。更稳的 Demo 方案是：Focus 不再缩宽度，只增加伤害并把主激光变红。

这样几种 Build 的认知更清楚：

| Build | 玩家理解 |
| --- | --- |
| Wide | 光束更粗，清怪更稳 |
| Focus | 光束变红，伤害更高 |
| Wide + Focus | 又粗又红，是“高火力主炮” |
| Frost | VFX/命中效果变蓝，表示控制效果 |

如果未来一定要做“收束变细”，文案应写成“光束收束 20%，伤害 +X%”，并用收缩图标表达代价。

## 僵直对普通怪价值低，主要服务 Boss 打断和特殊目标

在敌人只会向塔移动的早期版本里，普通怪被击退后再加 0.1-0.5 秒僵直，玩家很难感知差异。僵直的真正价值在于：

1. 打断 Boss 蓄力、召唤、AOE 等技能。
2. 留住漂移怪、宝箱怪这类特殊目标。
3. 和 Frost 减速/冻结形成控制链。

因此 Impact 的卖点应优先写“击退力 +X%”，僵直作为高等级或 Boss 交互出现。普通怪表现可用 Shader 凝固或短暂停顿，别让抖动和击退互相抵消。

## 左右边刷怪要随阶段解锁，近塔突袭必须有预警

第一波高潮直接从左右近塔位置刷怪，会让玩家觉得被偷袭而不是被挑战。更合理的难度曲线：

| 阶段 | 刷怪规则 |
| --- | --- |
| 早期 | 主要从上方刷，建立规则 |
| 中期 | 开启左右边，但 Y 坐标至少在屏幕高度 50% 以上 |
| 后期高潮 | 可允许更靠近塔的左右突袭，但要有边缘预警 |

“惊喜”可以有，但必须给反应窗口。没有预警的近塔刷怪会被玩家归因成刷怪器不公平。

## Frost 视觉不要直接改全局 Metaballs 颜色

如果 Metaballs Shader 只能整体换色，就不适合用它表达单个敌人的冰冻状态。否则一个敌人被 Frost 命中，整团怪物都变蓝，反馈会失真。

更稳的 Frost 表现：

| 状态 | 表现 |
| --- | --- |
| 减速 | 叠加半透明冰蓝 Sprite / 冰霜边缘 |
| 完全冰冻 | 速度倍率 = 0，冰层覆盖更明显 |
| 解除 | 覆盖层淡出，速度恢复 |
| Frost Build | 命中 VFX 或粒子变蓝，主激光颜色可不覆盖 Focus |

局部状态优先用叠层表现，整体材质色只适合章节基调或全局状态。

## Demo 技能池要够用，但不要把复杂组合提前端上来

早期 Roguelite Demo 如果只有 4 个技能、每个 5 级，总计 20 次升级，很容易在一局内被抽完，三选一变成“没有选择”。但如果一开始就加入复杂联动、全新武器和大量机制，又会让调参失控。

一个更稳的技能池结构是 `4 + 2 + 2`：

| 类型 | 示例 | 作用 |
| --- | --- | --- |
| 4 个核心机制 | Prism、Focus、Impact、Frost | 形成可感知流派 |
| 2 个数值被动 | Damage Up、Width/Power Up | 保证抽池深度和成长感 |
| 2 个补位/消耗项 | 临时护盾、回血、金币/空投 | 防止抽池耗尽，也服务局中节奏 |

MVP 阶段先用数值叠加、形态变化和少量控制关系建立爽感，不急着做复杂组合。核心技能的 Lv1 也不能“像亏了”，例如分裂/折射初始伤害 30% 很容易让玩家觉得变弱，50% 更接近心理可接受线。

## 静态技能值不能对抗倍率成长

如果怪物血量按波次倍率增长，技能伤害却写死为固定值，前几波可能爆强，后几波会突然失效。典型风险是类似 `cachedFocusExplosionDamage = 100f` 的静态爆炸值：它看起来可控，但本质上没有跟随玩家攻击面板和敌人 EHP 曲线成长。

更稳的做法：

| 问题 | 修正 |
| --- | --- |
| 固定爆炸伤害后期刮痧 | 爆炸以玩家面板 DPS / 基础伤害为基准再乘倍率 |
| 击杀伤害参与下一次爆炸 | 改用基础面板值，避免击杀溢出递归放大 |
| 爆炸链无限触发 | 加全局 CD 0.15-0.25s 和单敌免疫 0.25s |
| Burst Build 峰值不可读 | 记录 1 秒桶的 PeakDPS，而不是只看整波均值 |

原则是：允许局内爆发，不允许系统失控。爆炸、反射、连锁、分裂这类机制必须同时有成长来源和防连锁保险。

## 8 波制不是删波数，而是重排整局节奏

《光与朽》从 12 波/10 波压到 8 波的讨论，本质是缩短垃圾时间，让每一波都有新压力。推荐结构是 6 个小波 + 1 个精英压力波 + 1 个 Boss：

| 波次 | 作用 |
| --- | --- |
| W1 | 暖场，建立操作和清怪反馈 |
| W2 | 引入章节机制或新怪 |
| W3 | 引入坦克/阻挡压力 |
| W4 | 第一波群体压力，制造 Build 需求 |
| W5 | 混合考验，检查控制/输出短板 |
| W6 | 精英 DPS Check |
| W7 | Boss 前高密度经验和补强 |
| W8 | Boss 战与最终验证 |

改成 8 波时要同步改 XP、无人机奖励和怪物成长。只删中间波会让等级不足；可把经验约提高 1.5 倍、在 W4/W6 增加空投或奖励点，并让怪物曲线更陡，避免前中期继续无聊。

## 强机制怪不要早于反制系统解锁

旧优化储备里提到的“装备系统与第二、三章机制怪强绑定”适合沉淀成一条通用规则：如果某个章节怪物必须靠特定装备词条、合成系统或局外能力才能稳定反制，就不能在玩家真正解锁和理解该系统前把它做成硬门槛。

更稳的顺序：

| 阶段 | 设计原则 |
| --- | --- |
| 系统未解锁 | 基础构筑和科技树仍能勉强通关，机制怪只做软压力 |
| 系统刚解锁 | 用低风险场景展示“装备能更好解决问题” |
| 系统被理解后 | 才能放必须用特定词条或反制能力处理的强机制怪 |

如果上线后发现第二、三章留存低，或装备追求动力不足，可以考虑提前解锁装备合成，或把强机制怪放到装备教学之后。但这类重构必须看测试数据，不要只因为“机制更有深度”就提前制造硬墙。
