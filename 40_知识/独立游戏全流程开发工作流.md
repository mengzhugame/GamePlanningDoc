# 独立游戏全流程开发工作流

> **基于依据**：《美妆叠叠乐》和《光与朽》两款游戏的完整开发周期——从立项决策到上线运营的全程真实经历提炼。每一条都有踩坑代价作为背书。

---

## 工作流总览

```
阶段一：立项决策（2-4 天）
    ↓
阶段二：核心原型（7 天）
    ↓
阶段三：Demo 开发（4–12 周）
    ├── 技术实现
    ├── AI 美术管线
    ├── 数值迭代
    └── 数据埋点
    ↓
阶段四：发行商对接（持续 + 并行）
    ↓
阶段五：冷启动（上线后 72 小时）
    ↓
阶段六：数据驱动迭代（2–4 周循环）
    ↓
阶段七：商业化决策（止损线触发 or 扩张）
```

---

## 阶段一：立项决策（2–4 天）

### 1.1 选品框架（TA 视角）

选择那类**视觉表现本身就是玩法**的游戏——让 Shader/VFX 成为护城河。

**三个高成功率方向**（TA 主场）：
- 物理/流体模拟类（Metaballs、GPU 粒子）
- 视觉错位/空间解谜（Stencil Buffer、SDF）
- 解压爽感类（清洁/破坏/割草，有激光/粒子爆发的视觉爽点）

**避坑**：不要选靠原画赢的游戏类型（角色扮演、二次元）——这是短板。

### 1.2 核心动词 × 题材矩阵

```
1. 列出 10 个核心动词（从 Top 50 超休闲游戏提取：推、切、叠、旋转…）
2. 列出 10 个题材（市场趋势 + 个人兴趣）
3. 组合 → 筛选"3 秒直觉理解"的概念
4. 保留 5–10 个做核心循环推演
```

**立项的"3 秒测试"**：向陌生人描述这个游戏，他能在 3 秒内理解吗？

### 1.3 竞品分析

- 搜索最相似的爆款竞品，分析其核心操作范式
- **核心问题**：我们的差异化是什么？这个差异化在前 2 分钟能被玩家感知吗？
- 如果竞品体量极大（如网易系），改变目标：成为该细分品类的**长尾代表作**，不正面竞争

### 1.4 止损线设定（在开始开发前就设好）

```
时间止损线：项目开发 X 周（建议 ≤ 12 周到可测版本）
资金止损线：买量测试 X 元（建议 ≤ 5000 元）
两者先到先执行
止损触发后的下一步：[提前定好，不能到时再决策]
```

没有止损线的项目会无限延长，是独立开发者最常见的致命陷阱。

## 阶段二：核心原型（7 天）

### 2.1 原型目标

7 天只验证一件事：**核心动词是否有趣**。

用最简单的形状图（矩形、圆形）代替真实美术，只做核心玩法循环，不做音效、UI、过场。

### 2.2 原型验证标准

- 拿去给 3–5 个陌生人（不是朋友）玩 5 分钟
- 观察他们的表情和操作，不要解释玩法
- 他们玩到第 3 分钟还在玩 = 核心循环有效
- 如果 3 分钟内他们放下手机 = 核心循环无效，先不要继续

### 2.3 发行商预验证（可选）

原型完成后可以先找 1–2 家发行商非正式探讨：
- 发几张截图 + 核心玩法说明
- 看是否有兴趣"等 Demo 完成后来聊"
- 如果多家直接表示无兴趣 = 市场信号，考虑调整方向

## 阶段三：Demo 开发（4–12 周）

### 3.1 技术框架搭建（第 1–2 周）

**Unity 微信小游戏的必备模块**（优先级顺序）：

| 模块 | 优先级 | 原因 |
|------|--------|------|
| 核心战斗/玩法系统 | P0 | 所有决策基础 |
| 数据埋点系统（BattleStatistics） | P0 | 没数据等于瞎飞 |
| 广告接入（AdsManager + RewardManager） | P0 | 变现基础，早接早省事 |
| 对象池系统 | P1 | 微信小游戏性能强依赖 |
| 新手引导系统 | P1 | 发行商必看 |
| 音效管理（AudioManager） | P1 | 完成度信号 |
| 存档系统 | P1 | — |
| UI 动效 | P2 | 完成度，可最后做 |

**包体控制**：微信小游戏主包 < 4MB，分包异步加载资源。

### 3.2 AI 美术管线（并行进行）

**工具链**：

```
概念图 → MidJourney / Lovart（付费，省时间）
      → 本地 ComfyUI（精细控制，需要 Checkpoint + LoRA 配置）
生产级 → Stable Diffusion WebUI + ControlNet（批量生产）
后期    → Photoshop（统一配色、修补）
```

**关键决策**：不要在开发冲刺期死磕 ComfyUI 技术，充值 Lovart 等商业工具买效率。ComfyUI 等上线后再深度学习。

**Style Bible 必须在开始生产前建立**（避免"换了批次就像换了团队"）：
- 固定：游戏视角、角色比例、线条风格、上色方式、光影规则
- 生产每批资产前附加"风格锁定 Prompt"
- 每批产出后过"风格自审清单"（6 项）

**怪物设计工作流**（机制驱动）：
```
1. 机制描述 → AI 出设计方案 + 提示词
2. 生成完整体图 → PS 手工拆三层（Body RT / Eyes / Accessories）
3. Unity 挂 Shader，分层控制
```

### 3.3 数值设计流程

**核心原则**：数值是科学，先建模再调参，不要凭感觉改数字。

```
Step 1. 建立单局数值循环模型（DPS × 波次 × 怪物血量）
Step 2. 推演 8–10 波的体验曲线（哪波会玩家感到压力？哪波爽感爆发？）
Step 3. 设计 Wave 节奏（压力波 → 喘息波 → 压力波 → 高潮波）
Step 4. 用 BattleLog 数据验证（实测 vs 模型）
Step 5. 按数据调参，不是按主观感受
```

**数值迭代红线**：
- 差异化核心机制（如"旋转激光手感"）的数值不可以为了降低门槛而阉割
- 辅助系统只能辅助，不能替代核心操作（如"自动索敌"会杀死"旋转激光"的价值）

### 3.4 音效设计流程

**分层结构**：

```
基础音效（必须）：
  核心动词反馈音（点击/消除/击中 < 0.3 秒）
  背景 BGM（循环，符合情绪）
  
中层音效（应该）：
  胜负反馈（升级/关卡完成/失败）
  UI 交互（按钮点击/界面切换）
  
高级音效（可选）：
  连击/连杀反馈（音效阶梯）
  Boss 出场/技能音效
```

**来源推荐**：Freesound.org（免费）、Epidemic Sound（付费）、AI 生成（ElevenLabs Sound Effects）

### 3.5 数据埋点（贯穿全开发周期）

**必须在 Demo 阶段就接入的埋点**（上线后补埋等于白上线）：

```
每波结束时记录：
- 当前波次 / 玩家存活状态
- 本波击杀数 / 受到伤害
- 当前技能 Build（所有选择的技能组合）
- 本波 DPS / 总伤害

局结束时记录：
- 胜/负
- 最终波次
- 总游戏时长
- 完整技能 Build
- 触发复活次数（广告观看次数）
```

**数据使用**：每 10 场数据可以做一轮 Build 平衡分析（哪个 Build 胜率高，哪波死亡集中）。

## 阶段四：发行商对接（并行进行，Demo 完成度 70%+ 开始）

### 4.1 Demo 送审前检查清单

- [ ] 美术统一（无"拼凑感"，分辨率 720p+，有完整动效）
- [ ] 音效完整（点击、消除/击中、BGM、胜负反馈）
- [ ] 新手引导（前 3 关强制教学，0 零经验玩家可自行玩通）
- [ ] 单局时间 ≤ 10 分钟（微信碎片化场景）
- [ ] 包体 < 4MB
- [ ] 录制 30 秒核心玩法视频（前 3 秒必须是最强视觉钩子）

### 4.2 发行商反馈过滤原则

| 反馈类型 | 处理方式 |
|---------|---------|
| 有具体建议（"前 3 波难度太高"）| 分析合理性，合理则执行 |
| 模糊拒绝（"感觉没把握"）| 无信息量，记录不分析 |
| 要求做个人开发者无法实现的功能（内购）| 直接忽略 |
| "玩法太老" | 分析：是玩法类型问题还是缺乏创新点？经典玩法+微创新永远有效 |

### 4.3 谈判节奏

1. 同时联系 20–30 家（不要逐一等待回复）
2. 有数据的 Demo 比没数据的 Demo 成功率高 10 倍
3. 如果 20+ 家都无实质兴趣 → 检视产品问题，而不是发行渠道问题
4. 部分认可玩法 + 可调问题 → 改了再联系，不要放弃

## 阶段五：冷启动（上线后72小时）

### 5.1 发布时间选择

- **最优发布时间**：工作日上午 10:00–11:30
- 避开：早上 8 点通勤盲区、晚上 10 点后（次日留存数据延迟）

### 5.2 社媒引流（同步执行）

发布时同步在以下平台发布：
- 小红书：个人开发者人设 + 游戏视频（核心玩法 15 秒录屏）
- 抖音：同样的视频，配文字更简短
- 朋友圈：最后一个，质量比覆盖更重要

**小红书文案原则**：情绪优先，说人话，加"追更钩子"（"接下来会继续更新数据"）

### 5.3 72 小时数据决策

```
目标：获得 100–300 个真实陌生用户的种子数据

Day 1：等自然流量
Day 2：自然量 < 100 → 花 100-200 元补量；≥ 100 → 静观
Day 3-4：看 D1 次留 + 人均 IMP

D1 < 20%  → Plan B（止损 + 下款立项）
D1 20-35% → 针对性优化 + 小量重测
D1 > 35% + IMP > 4 → 投入 1000 元测 ROI
ROI > 1   → 联系发行商垫资买量
```

**铁律**：不用熟人数据做决策——朋友反馈有正向偏差，留存数据会虚高。

## 阶段六：数据驱动迭代（2–4 周循环）

### 6.1 玩家反馈三层过滤

```
原始反馈（100%）
    ↓ 过滤"主观感受"（"感觉不好"类）
有效反馈（~30%）
    ↓ 过滤"与核心差异化冲突"的建议
值得执行（~20%）
    ↓ 按 P0/P1 优先级排序
本周执行
```

**核心过滤原则**：差异化维度的建议要特别慎重。"加自动索敌降低门槛"会杀死"旋转激光手感"这个差异化核心。

### 6.2 爽感问题诊断框架

爽感不足的根因通常不是"技能数值不够高"，而是：

| 真实根因 | 症状 | 修复方向 |
|---------|------|---------|
| 视觉反馈不足 | "用了技能看不出效果" | 强化视觉粒子、屏幕震动、慢动作帧 |
| 稀有度与体验脱节 | "金色技能和普通没差" | 质变级改造（不是数值+20%，是全新行为） |
| 缺少正反馈里程碑 | "打了很久没有成就感" | 连杀提示、FRENZY 状态、里程碑特效 |
| 核心操作疲劳 | "一直做同一动作累了" | 关卡 3 段式结构（3+3+3 分钟，段间停顿） |

### 6.3 Build 平衡迭代

**Build 数据信号**：
- 某 Build 胜率 > 70% = 过强，需要削弱
- 某 Build 无人使用 = 过弱，需要增强或改设计
- 玩家技能分散（4–5 种） = 系统没有引导，需要加"流派引导提示"

**迭代节奏**：每 2 周一个迭代周期，每次只改 1–2 个核心变量，否则无法判断因果。

## 阶段七：商业化决策

### 7.1 IAA 触发时机优化

**高效触发点**（损失厌恶驱动）：
- 游玩 10 分钟后死亡（时间损失感强）
- 死亡时持有稀有装备/Build（物品损失感）

**低效触发点**：
- 任意死亡立即弹出（没有足够损失感）

### 7.2 DAU 门槛管理

- 微信流量主开通 DAU ≥ 500（部分要求 1000）
- 流量主开通前，不要用广告变现数据做产品判断（都是噪声）
- 买量目标之一是"冲 DAU 到门槛"，不只是测留存

### 7.3 止损执行

**止损线触发条件**（6 周 OR 5000 元，先到先执行）：
- 数据没有明显改善
- 执行：接入 IAA 广告放置 + CPS 联运分成合作 + 开始下款立项
- **Plan B 资产分解**：美术 / 代码模块 → Asset Store / itch.io（已沉没成本变现）

## 两款游戏的工作流差异对比

| 维度 | 美妆叠叠乐 | 光与朽 | 教训 |
|------|-----------|--------|------|
| 核心动词 | 点击+叠放+消除 | 旋转+切割 | 光与朽的动词更有视觉爽感，更适合TA |
| 美术风格 | AI生成为主，风格不统一 | 2D像素，有 Style Bible | 立项时就锁定风格 |
| 发行结果 | 32家均拒绝（完成度低） | 26家中少数认可玩法 | 完成度是发行门槛，不是加分项 |
| 数值设计 | 较简单（消除型无复杂数值） | 有 BattleLog 数据支撑 | 动作类游戏必须埋点驱动 |
| 运营决策 | 做了发行商反馈分析但停止开发 | 转自研自发，自费买量 | 没发行商≠没有出路 |
| 最终状态 | 已搁置（精力集中光与朽） | 已上线，持续迭代 | 一次只打一仗 |

## 工作流核心纪律（10 条）

1. **止损线先设**：开发前就定好，不能到时再决策
2. **数据驱动，不靠感觉**：没有 100 人真实用户数据，不做版本决策
3. **熟人数据不算**：朋友反馈有偏差，上线后必须买量获取陌生用户数据
4. **差异化是护城河**：核心差异化维度宁可接受更高上手门槛，不能被"降低门槛"建议妥协
5. **完成度是门槛，不是加分项**：发行商看的是"这个产品能上线"，不是"这个产品有多厉害"
6. **Style Bible 先建立**：批量生产美术资产前，必须锁定风格
7. **数据埋点同步进行**：不要等上线再补埋点，上线时没数据等于白上线
8. **IAA 早接入**：广告模块开发第一个月就接，不要最后才想到
9. **一次只打一仗**：同时维护两个游戏 = 两个都做不好
10. **爽感 > 内容深度**：玩家在前 5 分钟感受到爽感，才会愿意体验内容深度
