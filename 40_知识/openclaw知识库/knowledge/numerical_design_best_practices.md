# 游戏数值最佳实践：PRD (Pseudo-Random Distribution) 伪随机算法

## 1. 理论基础
PRD（伪随机分布）广泛应用于《War3》、《Dota2》等游戏，主要用于解决“真随机”下玩家可能面临的极端“非酋”或“欧皇”体验（例如连续10次不暴击，或者连续3次暴击秒人）。
其核心机制是：设定一个初始极低的概率常数 $C$。
- 玩家第1次攻击，暴击率为 $C$。
- 如果不暴击，第2次攻击暴击率为 $2C$。
- 每次不触发，概率都会累加（$3C, 4C \dots$），直到达到100%强制触发。
- 只要触发一次暴击，下一次攻击的暴击率立刻重置回初始值 $C$。

通过这种机制，实际统计期望会收敛在设计概率 $P$ 上，但方差极小，确保了触发间隔的均匀性，避免了连续触发或长时间不触发的问题。

## 2. 数学公式与常数 C 求解
对于目标显示概率 $P$，其对应的递增常数 $C$ 并不是简单的数学关系，通常需要通过马尔科夫链或蒙特卡洛模拟求解。
例如，当面板显示暴击率 $P = 20\%$ 时：
- 对应的 $C \approx 5.57\%$
- 第一刀暴击率: $5.57\%$
- 第二刀暴击率: $11.14\%$
- 第三刀暴击率: $16.71\%$
- ...
- 期望触发次数为 $\frac{1}{0.2} = 5$ 刀。

### 常见 P 对应的 C 值对照表：
| 面板概率 P | 初始常数 C |
| ---------- | ---------- |
| 5%         | 0.38%      |
| 10%        | 1.47%      |
| 15%        | 3.22%      |
| 20%        | 5.57%      |
| 25%        | 8.47%      |
| 30%        | 11.90%     |

## 3. 在《光与朽》中的应用实操
1. **暴击机制的平滑化**：玩家后期由于射速极快，如果是真随机，短时间内可能打出大量暴击瞬间秒杀Boss。引入 PRD 可以让暴击分布更加平滑，DPS 输出更加稳定，方便测试 TTK（击杀时间）。
2. **抽卡/掉落“保底”**：PRD 是天然的软保底机制。比如设定局内精英怪掉落“高级回血包”的概率为15%，则首杀掉率只有3.22%，但如果连续不掉，概率会不断叠加。这既保留了随机的惊喜感，又杜绝了玩家脸黑导致崩盘的情况。
3. **实现思路**：在 Unity 中，维护一个变量 `current_prob_multiplier`，初始为1。每次触发事件判定：
   - 随机 `Random.Range(0f, 1f) < C * current_prob_multiplier`
   - 触发成功：`current_prob_multiplier = 1`
   - 触发失败：`current_prob_multiplier += 1`

# 游戏数值最佳实践：战力评估模型（Combat Power / Stat Weights）

## 1. 为什么战力模型是下一步必学核心
战力评估模型不是做个唬人的战斗力数字，而是把攻击、攻速、暴击、生存、控制这些不同属性，统一折算到同一价值尺子上。当前《光与朽》已经有TTK与波次压力的基础，如果没有战力模型，后续装备、科技树、局内三选一都会持续出现“某个词条一骑绝尘，其他全成垃圾”的失衡。

## 2. 核心思想：一切属性都看边际收益
最基础的期望DPS可写为：

`DPS = ATK × APS × CritFactor × SkillFactor × EnemyModifier`

其中：
- `ATK`：单次伤害 / 单Tick伤害
- `APS`：每秒攻击次数
- `CritFactor = 1 + CritRate × CritDamageBonus`
- `SkillFactor`：分裂、弹射、穿透、连锁等额外乘区
- `EnemyModifier`：敌方护甲、抗性、减伤修正

任意属性X的价值，不看面板加多少，而看：

`Value(X) = ΔDPS / 当前DPS`

这就是边际收益。谁带来的 `ΔDPS / DPS` 更高，谁就更强。

## 3. 输出属性怎么统一折算
假设当前角色：
- `ATK = 100`
- `APS = 2.0`
- `CritRate = 20%`
- `CritDamageBonus = 100%`

则：
- `CritFactor = 1 + 0.2 × 1 = 1.2`
- `DPS = 100 × 2 × 1.2 = 240`

现在比较三个词条：
1. `+10 ATK`
2. `+10% APS`
3. `+10% CritRate`

更新后：
- `+10 ATK` → `110 × 2 × 1.2 = 264`，收益 `+10%`
- `+10% APS` → `100 × 2.2 × 1.2 = 264`，收益 `+10%`
- `+10% CritRate` → `100 × 2 × (1 + 0.3×1) = 260`，收益 `+8.33%`

结论：在这个状态区间里，攻击≈攻速 > 暴击率。

### 暴击的互相抬价
若 `CritFactor = 1 + CR × CD`，则：
- `∂DPS/∂CR = ATK × APS × CD`
- `∂DPS/∂CD = ATK × APS × CR`

所以：
- 暴击率越高，爆伤越值钱
- 爆伤越高，暴击率越值钱
- 两者会形成乘区爆炸，天然容易超模

这也是为什么暴击与爆伤通常必须配软上限、稀缺度限制、或拆乘区处理。

## 4. 生存属性统一到 EHP
经典减伤模型：

`DR = DEF / (DEF + K)`

则有效生命值：

`EHP = HP / (1 - DR) = HP × (DEF + K) / K`

含义：
- 生命提升 → 线性提高EHP
- 防御提升 → 通过减伤间接提高EHP
- 护盾、回复、减速、冻结，本质上都可以折算为“单位时间少吃多少伤害”

对《光与朽》这类短局高压游戏，建议用：

`SurvivalScore = EHP + HPS × 预期存活时长`

别把回复按长线MMO那套乱抬价，短局里回复常常没你想的那么值钱。

## 5. 阈值效应：真正决定爽感的核弹
期望收益不等于实战收益，因为击杀是离散事件。关键公式：

`ShotsToKill = ceil(EnemyHP / HitDamage)`

例子：怪物HP=100
- 49伤害 → 3下打死
- 50伤害 → 2下打死

面板只涨2.04%，清怪效率却直接提升33%。

所以数值策划绝不能只看DPS，还必须盯住关键波次的 breakpoint：
- 是否一束激光就能秒杂兵？
- 是否一次Overload能清掉自爆怪？
- 是否W6前能稳定穿过精英坦克波？

这才是割草爽感的真正来源。

## 6. 适合《光与朽》的战力三轴模型
建议拆成三轴，而不是把所有东西硬塞成一个假数字：

### 6.1 输出轴
`OutputScore = BaseDPS × AoEWeight × UptimeWeight × RangeWeight`

### 6.2 生存轴
`SurvivalScore = EHP × AvoidanceWeight × RecoveryWeight`

### 6.3 功能轴
`UtilityScore = CrowdControl + ResourceGain + BuildSynergy + Stability`

最终可写为：

`TotalPower = OutputScore × SurvivalMultiplier + UtilityAdjustment`

理由很简单：
- AoE、穿透、连锁、射程，本质上会改变单位时间击杀数
- 冻结、击退、减速，本质上在减少吃伤频率
- Build联动、定向补齐核心组件，会大幅降低烂牌局概率

## 7. 局内三选一的估值公式
在Roguelike三选一中，建议直接算：

`PickValue = (ΔOutput + λ×ΔSurvival + μ×ΔUtility) × SynergyFactor`

建议参数：
- `λ = 0.6 ~ 0.8`
- `μ = 0.2 ~ 0.5`
- `SynergyFactor = 1.0 ~ 1.8`

例子：
- 单纯 `+15%攻击` 只是稳定增伤
- 如果玩家已有“分裂+连锁”，再给“穿透”可能触发AoE覆盖率跳变，实际估值应该额外乘 `1.35~1.5`

## 8. 装备与科技树的成本定价
统一折算后，再决定经济成本：

`Cost = BaseCost × PowerGain^α`

其中 `α > 1` 用于控制后期性价比递减。

如果某节点不仅提升总战力，还跨过了关键 breakpoint（比如刚好从3下击杀变2下击杀），那它不能按普通线性收益卖，必须额外加“阈值税”。

## 9. 商业化与DDA的挂钩方式
当系统检测到：

`CurrentPower / RequiredPower < 0.85`

说明玩家进入明显劣势局。此时最优设计不是乱弹回血广告，而是：
1. 给一次激励广告入口
2. 奖励“定向补齐核心词条”或“短时核心乘区增益”
3. 让玩家感知为“这把还有救”，而不是“我纯粹脸黑”

这才是数值、心理和IAA真正合流的地方。

## 10. 《光与朽》实操表格字段
建议表格至少有这些列：
- `BaseATK`
- `APS`
- `CritRate`
- `CritDamage`
- `Penetration`
- `AoECoverage`
- `Range`
- `Uptime`
- `EnemyHP`
- `EnemyArmor`
- `ExpectedDPS`
- `EHP`
- `ShotsToKill`
- `WavePressure`
- `PowerGap = CurrentPower / RequiredPower`

只要这些字段齐了，装备、科技树、局内三选一、广告救援点位就能共用同一套数值尺子。

## 11. 外部资料提炼结论
- 知乎数值文章对“战力两种计算方法”的共识：**解析公式法适合前期建模，回归拟合法适合后期校准显示战力**。
- 另一类战斗力文章的共识：**有效攻击 × 有效生命** 是最稳的底层框架，能避免玩家无限追单一属性。
- GameRes 属性设计文章强调：**属性价值必须来源于换算链路，而不是策划主观拍脑袋**。
- TapTap 社区的战力研究给了一个实用提醒：**如果线上数据足够，确实可以用相关分析/回归去反推权重，但项目早期千万别迷信黑箱。**

## 12. 今日结论
最硬的一句：**不要用面板值判断强弱，要用边际收益 + 阈值效应判断真实价值。**

对《光与朽》来说，下一步别再只盯着怪物血量微调，先把攻击、攻速、暴击、穿透、AoE、控制统一换算成 `输出 / 生存 / 功能` 三轴评分，再重点监控 `ShotsToKill` 的关键断点。模型一立起来，装备、科技树、三选一和广告救援都会从玄学变成工程。

# 游戏数值最佳实践：成长曲线建模（经验值升级曲线：指数型 / 多项式型 / 对数型）

## 1. 为什么今天必须补成长曲线
成长曲线不是“升级要多少经验”这么简单，它本质上是在定义：
- 玩家多久获得一次正反馈
- 中期卡点出现在哪里
- 后期是否进入疲劳与流失区
- 局外成长会不会把局内战斗直接碾碎

对《光与朽》来说，经验曲线直接决定：
1. 单局内升级三选一出现的频率；
2. 玩家什么时候拿到第一套核心 Build；
3. 波次压力曲线和玩家成长曲线是否同步；
4. 后续局外科技树带来的“降维打击”会不会失控。

一句话：**经验曲线就是玩家成长节奏的节拍器。**

## 2. 三类经典成长曲线的底层差异

### 2.1 指数型（Exponential）
常见写法：

`ExpToNext(L) = A × r^(L-1)`，其中 `r > 1`

或累计经验：

`TotalExp(L) = A × (r^L - 1) / (r - 1)`

特点：
- 每级所需经验按比例上升；
- 前期升级快，后期升级明显变慢；
- 非常适合“前期爽、后期拉长追求”的长线养成。

优点：
- 能自然拉开高等级玩家与低等级玩家的进度差；
- 容易制造“越往后越珍贵”的升级感；
- 对长线商业化与日活留存友好。

缺点：
- 如果倍率 `r` 稍大，后期会陡得离谱；
- 会导致某些等级段出现“坐牢区”；
- 若局内战斗成长也走指数，会与怪物膨胀叠乘，直接炸表。

适用：
- MMO、重养成 RPG、长生命周期局外成长。

### 2.2 多项式 / 幂函数型（Polynomial / Power）
常见写法：

`ExpToNext(L) = A × L^k + B`，其中 `k > 1`

特点：
- 增长强度可控；
- 比纯指数更稳、更容易调参；
- 是中期成长最好用的骨架公式之一。

当：
- `k = 1` → 线性
- `1 < k < 2` → 温和加速
- `k = 2` → 二次增长，明显变陡
- `k > 2` → 后期压力急剧上升

优点：
- 可控性强，方便按等级段微调；
- 不容易像指数那样一不小心炸穿；
- 很适合“中期要有成长重量，但不能太折磨”的游戏。

缺点：
- 若只用单一幂函数覆盖全程，阶段感不够清晰；
- 后期依旧可能数值失控；
- 需要结合分段和目标时长校正。

适用：
- 中短周期养成；
- Roguelike 局内升级；
- 中期成长主干曲线。

### 2.3 对数型（Logarithmic）
常见写法：

`Gain(L) = A × ln(L + c) + B`

注意：对数更常用于“属性收益”而不是“升级所需经验”。
如果直接把“升级所需经验”做成纯对数，越后期越容易升级，通常会破坏等级稀缺性。

它更适合表达：
- 某项属性前期收益大、后期收益递减；
- 满级后突破系统、专精系统、重复投入系统；
- 防数值膨胀的终局收敛段。

优点：
- 天然边际递减；
- 能压住后期膨胀；
- 非常适合做终局数值收敛。

缺点：
- 玩家容易觉得“投入越来越不值”；
- 如果提前引入，会严重损伤成长爽感；
- 不适合做主升级骨架。

适用：
- 满级后养成；
- 防御转减伤、暴抗等收益衰减模型；
- 终局数值收口。

## 3. 行业共识：主曲线通常不是单一函数，而是分段组合
根据 GameRes 关于等级成长感的讨论、腾讯云关于数值拆解的经验，以及近期 CSDN 养成模型文章的共同结论：

**真正能打的成长曲线，通常不是“全程一条神公式”，而是分段建模。**

推荐结构：

`前期线性 / 低阶幂函数 → 中期多项式 → 后期缓冲或收敛段`

原因很直接：
- 前期要保证学习成本低、反馈密；
- 中期要制造“我真的变强了”的重量感；
- 后期要防膨胀、防毕业过快、防内容被吃穿。

### 推荐分段模板

#### 模板A：局内 Roguelike 升级曲线
`ExpToNext(L) =`
- `A + B×L`，当 `L = 1~5`
- `C × L^1.4`，当 `L = 6~15`
- `D × L^1.8`，当 `L = 16+`

用途：
- 前5级快速给玩家成型感；
- 中段开始让 Build 选择产生分化；
- 后段限制无限滚雪球。

#### 模板B：局外长线成长曲线
`ExpToNext(L) = A × L^1.6 + B × L + C`

当高等级段逼近版本上限时，再插入缓冲：

`ExpToNext(L) = Base × 1.08^(L-L0)`（仅用于顶级段）

用途：
- 绝大多数等级保持平滑；
- 顶级段拉长追求，不让玩家几天毕业。

## 4. 设计成长曲线时必须盯住的四个指标

### 4.1 每级耗时（Time Per Level）
核心换算：

`TimeToNext(L) = ExpToNext(L) / ExpIncomePerMinute(L)`

只看经验需求没意义，必须结合经验产出速度一起算。

如果怪物经验也随波次上涨，那么真正决定体感的是：

`升级耗时变化率 = TimeToNext(L+1) / TimeToNext(L)`

建议：
- 单局前段：每次升级耗时增长不超过 `1.15x`
- 中段：控制在 `1.15x ~ 1.30x`
- 后段：可上到 `1.30x ~ 1.45x`，再高就容易坐牢

### 4.2 成长收益比（Power Gain per Level）
定义：

`LevelValue(L) = ΔPower(L) / TimeToNext(L)`

如果升级越来越慢，但每级战力提升也越来越小，玩家就会觉得系统在耍流氓。

所以要保证：
- 升级时长变长时，等级奖励要么更重，要么更关键；
- 至少要给玩家“这级很值”的感知节点。

### 4.3 波次同步率（Wave Sync）
对《光与朽》最关键的指标：

`WaveSync = 玩家当前战力 / 当前波次需求战力`

经验曲线必须保证：
- 前期 `WaveSync > 1`：玩家学习和爽感优先；
- 中期 `WaveSync ≈ 1`：开始逼迫构筑判断；
- Boss前短暂下探到 `0.9~0.95`：制造压力；
- 如果低于 `0.85` 太久，玩家会觉得不是难，是脏。

### 4.4 关键成型等级（Build Milestone）
必须先定义：
- 第一次“能清杂兵”的等级；
- 第一次“能稳定处理精英”的等级；
- 第一次“核心流派成型”的等级；
- 第一次“Overload 能救场”的等级。

再反推经验需求，而不是先拍经验表。

## 5. 常见公式与调参手感

### 5.1 线性公式
`ExpToNext(L) = a + bL`

适合：
- 新手教学段；
- 低等级短局体验；
- 需要让玩家快速形成“每隔几十秒升一次”的稳定预期。

风险：
- 后期太平，缺少层次；
- 容易让玩家觉得升级像发工资，没有峰值体验。

### 5.2 幂函数公式
`ExpToNext(L) = aL^k + b`

调参经验：
- `k = 1.2~1.4`：温和，适合局内成长；
- `k = 1.5~1.8`：中度陡峭，适合中后段；
- `k >= 2.0`：慎用，除非就是要制造强卡点。

### 5.3 指数公式
`ExpToNext(L) = a×r^L`

调参经验：
- `r = 1.03~1.08`：可控
- `r = 1.10+`：很容易后期爆炸

除非是超长线游戏，否则别乱用纯指数做全程主曲线。

### 5.4 分段缓冲
当某等级段增长太陡时，可以人为插缓冲：

`ExpToNext(L) = min(原公式值, 上一级 × 缓冲倍率)`

例如：
`ExpToNext(L) ≤ ExpToNext(L-1) × 1.25`

这招很脏，但极其实用。它能防止某一级突然变成断崖。

## 6. 《光与朽》的直接应用方案
《光与朽》不是传统 MMORPG，而是塔防 + 肉鸽 + 波次压力游戏，所以不该照搬“越后面越难升”的老 RPG 习惯。

更合理的做法是：

### 6.1 局内经验曲线目标
- 前3~5级：高速升级，60~90秒内让玩家拿到基础构筑
- 6~12级：进入构筑分化期，升级速度开始放缓
- 13级后：明显变贵，防止后期无限叠强词条

推荐原型：

`ExpToNext(L) = 20 + 8L + 2L^1.5`

如果实测前期过慢，可改：

`ExpToNext(L) = 15 + 7L + 1.6L^1.45`

### 6.2 波次同步原则
把每波怪物总血池记为 `WaveHP(w)`，把玩家当前期望秒伤记为 `ExpectedDPS(L, Build)`。

则该波的理论压力：

`Pressure(w) = WaveHP(w) / 有效输出窗口`

升级曲线需要满足：
- 普通波：玩家升级后能明显感到“清得动了”
- 精英波前：最好刚好来一次升级或三选一
- Boss前：保留一次强选择窗口或大招冷却回合

**别让 Boss 波前 90 秒都不升级。那不是压迫感，是反人类。**

### 6.3 经验奖励也要分层
怪物经验建议不要纯线性给。

推荐：
- 杂兵：稳定基础经验
- 精英：按当波压力给经验奖金
- Boss：大额一次性经验，服务下局/结算成长
- 漏怪惩罚：不是直接砍经验，而是减少局面控制能力

原因：
经验是成长节奏的油门，不能和失败惩罚完全绑死，不然逆风局会越打越废。

## 7. 验证方法：别迷信公式，最后一定回到模拟
成长曲线验证必须做三层检查：

### 第一层：表格粗算
至少拉这些列：
- 等级 `L`
- 升级所需经验 `ExpToNext`
- 累计经验 `TotalExp`
- 每分钟经验产出 `ExpPerMin`
- 升级耗时 `TimeToNext`
- 预期 DPS
- 波次需求 DPS
- `WaveSync`

### 第二层：离散模拟
模拟：
- 玩家正常操作
- 一般选牌
- 欧皇牌序
- 非酋牌序

看核心流派分别在第几级成型。

### 第三层：体验修正
即便数学上平滑，也要检查：
- 是否 30~45 秒内有一次正反馈；
- 是否存在 2 分钟以上无显著成长；
- 是否出现“升了级但屁用没有”的空心奖励。

## 8. 今天的硬结论
1. **经验曲线设计的对象不是等级，而是时间感。**
2. **主成长曲线优先用分段多项式，不要迷信纯指数。**
3. **对数更适合做收益衰减和终局收口，不适合做主升级经验。**
4. **真正要校验的不是公式长得好不好看，而是每一级是否恰好把玩家送进下一个爽点、险点或构筑点。**

## 9. 外部资料提炼
- GameRes《基于等级的成长感》强调：经验曲线本质上是在设计玩家感受到成长的节奏，而不仅是经验表本身。
- 腾讯云数值拆解文章强调：升级公式往往是分段的，前期、中期、后期服务的体验目标根本不同。
- CSDN 近期养成建模文章提供了一个实用提醒：线性、二次、对数更适合做复合阶段控制，单一函数覆盖全程往往会牺牲体验。

## 10. 给未来调表时的红线
如果出现以下情况，说明经验曲线设计有问题：
- 连续两个关键波次之间没有升级或关键奖励；
- 玩家在同一构筑成熟前被迫熬过过长空窗期；
- 局外科技树一开，前10波全部被碾碎；
- 高级段每级耗时增长超过30%，但升级收益没有同步放大。

那就别嘴硬，赶紧回去改曲线。

# 游戏数值最佳实践：VBA / Excel 批量模拟与波次-DPS 联动验证

## 1. 为什么这个专题必须现在学
《光与朽》已经有 TTK、成长曲线、战力评估这些骨架了，但如果你还停留在“改一列怪物血量，手测一把看看”的阶段，那就是典型低效。真正的资深数值不是手调表，而是建立一套**可批量验证的模拟流水线**，一次性回答这几个关键问题：
- 第几波开始玩家理论 DPS 追不上怪物总血池？
- 哪个三选一词条会跨过“一击秒杂兵 / 一轮清线”的关键断点？
- 哪些波次是硬卡点，哪些只是牌序黑？
- 经验、金币、广告补救点位有没有和难度峰值对齐？

一句话，Excel 管结构，VBA 管批跑，二者合在一起才是能落地的数值实验室。

## 2. 核心框架：把波次压力拆成四层
建议把《光与朽》的单局验证拆成四张核心表：

### 2.1 Wave 表，描述敌方压力
每波至少有这些列：
- `WaveID`
- `EnemyType`
- `SpawnCount`
- `EnemyHP`
- `EnemyArmor`
- `MoveSpeed`
- `SpawnDuration`
- `PathLength`
- `ExpReward`
- `GoldReward`

关键派生字段：

`WaveHP = Σ(SpawnCount_i × EnemyHP_i × ArmorModifier_i)`

`ArmorModifier = 1 / (1 - DR)` 或直接并入有效生命

`LaneTime = PathLength / MoveSpeed`

`PressureDPS = WaveHP / LaneTime`

这条 `PressureDPS` 很硬，它表示如果玩家在该波的有效秒伤长期低于这个值，理论上就清不完。

### 2.2 Build 表，描述玩家期望成长
字段建议：
- `Level`
- `BaseATK`
- `APS`
- `CritRate`
- `CritDamage`
- `Penetration`
- `AOEFactor`
- `Uptime`
- `SkillMultiplier`
- `PickQuality`（普通/优质/欧皇）

核心公式：

`ExpectedDPS = ATK × APS × (1 + CritRate × CritDamage) × SkillMultiplier × AOEFactor × Uptime × EnemyModifier`

其中：
- `AOEFactor` 表示穿透、连锁、分裂、激光覆盖导致的等效清怪效率提升
- `Uptime` 表示转火、移动、过热、大招空窗等真实损耗
- `EnemyModifier` 用于处理护甲、抗性和体型克制

### 2.3 Progression 表，描述资源回流
字段建议：
- `WaveID`
- `CumExp`
- `LevelAfterWave`
- `CumGold`
- `TalentGain`
- `ShopGain`
- `AdRescueAvailable`

关键换算：

`LevelAfterWave = f(CumExp)`

`PowerAfterWave = g(Level, Picks, MetaUpgrades)`

波次难度不是孤立的，它必须和经验、金币、三选一出现节奏绑死。否则你会得到一种很蠢的体验，玩家明明该变强了，但奖励窗口死活不来。

### 2.4 Simulation 表，负责联动验证
核心字段：
- `WaveID`
- `ExpectedDPS`
- `PressureDPS`
- `PowerGap = ExpectedDPS / PressureDPS`
- `ShotsToKill = CEILING(EnemyHP / HitDamage, 1)`
- `ClearMargin = LaneTime - WaveHP / ExpectedDPS`
- `FailRisk`

解释：
- `PowerGap > 1.10`：明显碾压，爽但可能太白给
- `0.95 ~ 1.10`：可接受主战区
- `0.85 ~ 0.95`：高压区，适合放精英波、广告救援点
- `< 0.85`：大概率脏卡，除非你故意做难度墙

## 3. 先做静态公式，再做 VBA 批跑
别一上来就写宏，那是找死。正确顺序：

### 第一步，先把表算通
用普通公式把单次验证跑通：
- `SUMIFS / XLOOKUP / INDEX-MATCH` 拉波次数据
- `IF / MIN / MAX / ROUNDUP` 做阈值判断
- 数据透视表看各波压力峰值

如果单把样例都算不对，VBA 只会把错误放大 1000 倍。

### 第二步，再让 VBA 做参数扫描
VBA 的工作不是替你思考，而是替你重复劳动。最适合批跑这些场景：
1. 扫描怪物血量倍率 `0.9 ~ 1.3`
2. 扫描玩家升级收益倍率 `0.8 ~ 1.2`
3. 扫描不同牌序质量（普通 / 偏好 / 欧皇）
4. 扫描广告救援触发点对通关率的影响

最常用方法就是双层或三层循环，把结果写入结果表。

伪代码如下：

```vb
For hpMul = 0.9 To 1.3 Step 0.05
  For pickMul = 0.8 To 1.2 Step 0.05
    For seedType = 1 To 3
      Call RecalcWaveTable(hpMul, pickMul, seedType)
      gap = Sheets("Sim").Range("B2").Value
      clearWave = Sheets("Sim").Range("B3").Value
      Call AppendResult(hpMul, pickMul, seedType, gap, clearWave)
    Next seedType
  Next pickMul
Next hpMul
```

输出不是一句“平衡了”，而是一张热力图：
- 横轴 `怪物压力倍率`
- 纵轴 `玩家成长倍率`
- 颜色 `通关波次 / 平均剩余血量 / 广告触发率`

这玩意才是真正能指导调表的证据。

## 4. 波次-DPS 联动验证的三个硬公式

### 4.1 总血池压力
`WaveHP(w) = Σ Count_i(w) × EHP_i(w)`

其中：
`EHP = HP / (1 - DR)`

### 4.2 玩家清线能力
`ClearTime(w) = WaveHP(w) / EffectiveDPS(w)`

`EffectiveDPS = SingleTargetDPS × TargetCoverage × Uptime`

塔防和割草最容易犯的蠢错，是把单体 DPS 当清线能力。AOE 覆盖、激光穿透、连锁命中数，都会让真实清线效率和单体面板完全不是一回事。

### 4.3 波次安全余量
`ClearMargin(w) = AvailableTime(w) - ClearTime(w)`

其中：
`AvailableTime = LaneTime + ControlTime + NukeTime`

解释：
- `LaneTime` 是怪物从出生到撞线的自然时间
- `ControlTime` 是冻结、减速、击退带来的额外输出窗口
- `NukeTime` 是 Overload 等爆发技能在该波相当于“白送”的时间补偿

只看 DPS 不看 `ClearMargin`，你会误判很多“理论能打过，实战老翻车”的波次。

## 5. Breakpoint 才是最值钱的观察指标
在批量模拟里，必须单独监控这些离散断点：
- `ShotsToKill` 是否从 3 变 2
- 精英是否从“必须开大”变成“平推可解”
- 激光宽度 / 连锁次数是否让 `TargetCoverage` 突然跳档
- 某个升级是否让 Boss 的 `PhaseTime` 缩短到技能窗以内

示例：

`ShotsToKill = CEILING(EnemyHP / HitDamage, 1)`

当杂兵 HP = 100：
- 49 伤害，`STK = 3`
- 50 伤害，`STK = 2`

面板只涨了 2.04%，清线效率却会因为攻击动画、转火损耗、AOE 溢出一起发生质变。这个跳点必须单独打标，别和普通线性收益混一起。

## 6. 最适合《光与朽》的三套模拟场景

### 6.1 基线局
默认牌序、平均操作、无广告救援。
目的：找自然进度下的真实卡关波。

### 6.2 黑脸局
低质量三选一、低覆盖率构筑、关键波前没拿大招。
目的：找玩家最容易骂街的波次。

### 6.3 救援局
在 `PowerGap < 0.9` 时给一次广告刷新或定向补核心词条。
目的：验证广告不是单纯续命，而是真的把失败边界从 `0.82` 拉回 `0.97` 以上。

这三套一起看，才能决定广告点位、波次强度、奖励发放是不是合理。

## 7. Excel 字段模板，直接可抄
建议最少有这些列：
- `WaveID`
- `MobCount`
- `MobHP`
- `MobEHP`
- `LaneTime`
- `WaveHP`
- `ExpIncome`
- `GoldIncome`
- `PlayerLevel`
- `ATK`
- `APS`
- `CritFactor`
- `AOEFactor`
- `Uptime`
- `EffectiveDPS`
- `ShotsToKill`

- `AdOpportunity`

再加两个统计页：
1. `ResultHeatmap`，看批跑后的热区
2. `BreakpointLog`，专门记击杀断点变化

## 8. 行业资料交叉提炼
根据本次检索到的 GameRes、知乎、Game Developer 与塔防平衡讨论，结论高度一致：
- **知乎 / 数值策划经验贴**：优秀数值策划不会只拉 Excel 表，往往会再学一点 VBA 或脚本，把战斗工具和数表联调起来，否则大量改动根本验证不过来。
- **GameRes《游戏数值策划凭一张Excel表就可以一招鲜？》**：成熟数值表通常至少拆成“总节奏控制 + 系统参数 + 表现配置”多层 sheet，最上层节奏表会决定全局结构，不能乱改。
- **GameRes《策划如何用VBA调试游戏数值》**：VBA 的核心价值不是炫技，而是把重复试算、参数回填、结果归档自动化。
- **Tower Defense Proof Part 1: Excel**：塔防平衡至少要同时看 `DPS、射速、单发伤害、冷却、射程、造价`，单看某一个属性会把防御塔价值看歪。
- **Game Developer《Balance in td-games》**：波次平衡本质上是“敌方总生命和推进时间”对“玩家可建造火力和经济曲线”的联立问题，敌人数量、生命、金钱奖励和基础塔输出必须放在同一公式里核算。
- **Monte Carlo 相关讨论**：当构筑、暴击、牌序、掉落存在随机性时，批量模拟最好分“确定性总表 + 随机扰动场景”两层，避免把整套系统做成完全不可解释的黑箱。

## 9. 《光与朽》的直接落地办法
我建议你下一步别再手调一堆波次配置，而是直接做一个 V2 验证表：

### 9.1 先定义敌方压力
每波先算：
`WavePressure = 总血池 / 有效路径时间`

### 9.2 再定义玩家火力
每级、每个关键三选一、每个无人机强化都换算成：
`EffectiveDPS`

### 9.3 然后找差值
`Gap = EffectiveDPS / WavePressure`

调表目标：
- 普通波 `1.05 ~ 1.20`
- 精英波 `0.92 ~ 1.05`
- Boss 前小压迫 `0.88 ~ 0.98`
- 广告救援后至少拉回 `0.97+`

### 9.4 最后盯断点
只要某次升级让杂兵 `3 hit -> 2 hit`，或者让 Overload 能刚好秒掉一组自爆怪，这个升级就必须在估值上加权，不然你会严重低估它的真实强度。

## 10. 今日结论
最硬的一句：**批量模拟的目标不是求一个完美数值，而是快速定位“哪一波、哪种构筑、在哪个断点出问题”。**

对《光与朽》来说，下一步应该立刻做一张“波次压力 × 期望DPS × 击杀断点 × 广告救援”的联动表，再用 VBA 扫怪物倍率、升级倍率和牌序质量。这样你不是在凭感觉调难度，而是在用工程化方法抓出真正的卡关波和赚钱节点。

# 游戏数值最佳实践：水池模型（Faucet & Sink）与局外资源闭环

## 1. 为什么今天该学这个
《光与朽》已经把局内战斗骨架、成长曲线、波次压力跑出来了，接下来最容易翻车的，不是战斗，而是局外经济。玩家刷一局给多少金币、多少碎片、多少广告补偿，升级节点吃掉多少，30小时能不能毕业，这些如果没有“水池模型”，最后一定会变成两种傻逼结果之一：要么玩家三天毕业，后面全是空；要么玩家刷到怀疑人生，直接流失。

水池模型的本质只有一句：

`库存变化 = 资源产出(Faucet) - 资源消耗(Sink) + 运营补偿/活动注入`

所有经济平衡问题，先回到这条总账，不要先聊情怀。

## 2. 基础定义：什么是 Faucet，什么是 Sink
### 2.1 Faucet，产出水龙头
指所有把资源注入系统的入口，例如：
- 局内通关金币
- 精英/Boss 首杀奖励
- 日常任务
- 广告双倍结算
- 活动邮件补偿
- 新手礼包、签到、成就

### 2.2 Sink，消耗排水口
指所有把资源永久移出系统的出口，例如：
- 科技树升级消耗
- 装备合成、升阶、洗练
- 商店刷新
- 局内复活、临时 Buff 购买
- 抽卡、碎片兑换、制造材料消耗

### 2.3 假 Sink，不是真回收
以下动作看着像花钱，其实如果资源转化后还能完整回流，不算真 Sink：
- A 货币换 B 货币，但 B 能 1:1 换回来
- 纯仓库搬运式合成
- 玩家对玩家交易手续费为 0 的流转

数值策划最常犯的蠢病，就是把“转移”当“回收”。那会导致你以为系统很稳，其实只是换了个口袋。

## 3. 经济平衡的核心公式
### 3.1 单位时间净流量
对任意资源 R：

`NetFlow_R(t) = Faucet_R(t) - Sink_R(t)`

当：
- `NetFlow > 0`，库存长期膨胀
- `NetFlow = 0`，系统稳态
- `NetFlow < 0`，资源趋于稀缺，可能卡死成长

### 3.2 分层统计，别只看全局均值
必须至少拆三层：

`NetFlow_per_run = AvgFaucet_per_run - AvgSink_per_run`

`NetFlow_per_day = DAU行为总产出 - DAU行为总消耗`

`NetFlow_per_lifecycle = 生命周期总产出 - 毕业总消耗`

很多项目死就死在“单局看着合理，30天一算直接爆仓”。

### 3.3 库存安全区
给每种核心资源设安全库存区间：

`StockTarget = [LowerBound, UpperBound]`

如果玩家主流样本长期满足：
- `Stock < LowerBound`，说明缺资源，节奏过紧
- `Stock > UpperBound`，说明产出溢出，资源失去价值

### 3.4 毕业时长反推
如果目标是玩家自然毕业时长 `T_goal`，则：

`RequiredNetGainPerHour = TotalGraduationCost / T_goal`

若《光与朽》想要 30 小时自然毕业，且核心科技树 + 装备合成总成本为：

`TotalCost = 180000 金币 + 900 碎片`

则目标净获取速率应为：

`GoldNet/hour = 180000 / 30 = 6000`

`ShardNet/hour = 900 / 30 = 30`

之后再反推每局应给多少、广告补偿占多少，而不是先拍掉落，再祈祷玩家别骂。

## 4. 五特性视角下的水池模型
结合本技能的五特性模型，水池设计不能只看产出和消耗，还要看它在生命周期内如何运动：

### 4.1 生成
资源从哪里来，玩家怎么拿到，是否可控。

### 4.2 成长
玩家中前后期的产出效率是否变化，是否存在滚雪球。

### 4.3 消亡
资源是否真实离开系统，还是只是换皮存在。

### 4.4 变化
活动、广告、礼包、版本更新会不会打破原来的净流量。

### 4.5 联系
金币、碎片、体力、广告次数、构筑强度是不是彼此耦合。

真正成熟的经济设计，一定是联动图，不是单列数字表。

## 5. 行业资料提炼出的硬共识
### 5.1 知乎/中文数值文章的共识
- 游戏经济平衡本质上是**产出与消耗可量化**，要能算出单位时间最大产出与关键消耗强度。
- 通胀不一定全是坏事，**温和通胀**能给玩家“我变富了”的感知，但过量通胀会让软货币迅速失去意义。
- 新玩法/活动如果只加产出、不加对应排水口，会直接制造结构性通胀。

### 5.2 GameRes 的提醒
- 能长期活的网游/长线产品，通常坚持朴素原则：**可计算总产出 ≤ 可计算总消耗**，至少不能长期大幅高于后者。
- 外挂、复制、黑产属于极端外部注水，会瞬间摧毁经济系统，因此高价值资源必须可控、可追踪。
- 结构性通胀往往来自“某一类奖励给得过肥”，不是全局每项都错。

### 5.3 Lost Garden / 海外经济设计文章的提醒
- 玩家愿意去“捡木棍”不是因为木棍本身有趣，而是因为木棍能串进后续目标链。资源价值来自**价值链终点的动机锚点**。
- 设计 faucet-drain economy 时，不能只看一跳资源流，必须把“采集 → 制造 → 建筑/强化 → 目标达成”的整条链拉出来。
- 如果后续目标失真，前端资源就立刻贬值，产出再平衡也救不回来。

## 6. 水池设计常见模型
### 6.1 单资源闭环
最简单：

`金币产出 -> 科技树升级消耗 -> 战力提升 -> 更高金币产出`

风险：一旦提升收益过高，会形成正反馈爆炸。

### 6.2 双资源交叉闭环
例如：

`金币 -> 装备强化`

`碎片 -> 装备合成`

`强化后的装备 -> 提升通关效率 -> 增加金币/碎片获取`

优点：可以分别控制“频繁成长”和“长期追求”。

### 6.3 软硬货币耦合
例如：

`软货币不足 -> 看广告补偿 / 付费替代`

关键原则：硬货币不能直接把软货币价格打穿，否则软货币整个存在意义就废了。

## 7. 《光与朽》的落地模型
### 7.1 先定义三种核心资源
我建议至少拆成：
1. `金币 Gold`，局外科技树主货币
2. `碎片 Shard`，装备/无人机长期成长资源
3. `广告补偿券 AdBoost` 或等价临时补偿，作为 IAA 节奏阀门

### 7.2 每种资源都建立这四列
- `来源 Source`
- `单局期望产出 AvgFaucet`
- `关键消耗 Sink`
- `目标库存区间 StockTarget`

### 7.3 金币净流量公式

`GoldNetPerRun = BaseGold + WaveGold + EliteBonus + AdBonus - MetaUpgradeCostAllocated - RefreshCost - ReviveCost`

其中 `MetaUpgradeCostAllocated` 不是每局都真实扣，但你在生命周期验证里必须把它分摊回每局，否则会高估玩家财富。

### 7.4 碎片净流量公式

`ShardNetPerRun = BaseShardDrop × SurvivalFactor × DifficultyFactor + BossShard - CraftConsumptionAllocated`

碎片最适合承担“长期毕业速度”的控制职责，因为它天然稀缺、掉落离散、体感强。

### 7.5 广告补偿的红线
广告不是新 faucet，而是**纠偏阀门**。建议：
- 只在 `CurrentPower / RequiredPower < 0.9` 或资源短缺明显时触发高价值补偿
- 平时只给轻补偿，避免广告成为主经济来源

否则结果会很丑：玩家最佳策略变成“主动打烂一点，骗系统吐资源”。

## 8. 反通胀手段
### 8.1 成本递增

`Cost_n = BaseCost × n^α`，其中 `α > 1`

用于科技树、洗练、制造，控制后期边际收益递减。

### 8.2 动态回收
当玩家库存高于阈值时，开放高价值 Sink：
- 高级词条洗练
- 限时商店
- 风险换收益玩法

### 8.3 产出软上限
例如：
- 每日前 X 局高收益，后续递减
- 广告双倍次数上限
- 某类资源集中掉落但总量封顶

### 8.4 版本注水必须配新 Sink
版本加新产出时，必须同步加新消耗，否则老资源直接泛滥。

## 9. 验证表怎么建
至少拉这些列：
- `ResourceType`
- `Source`
- `Sink`
- `PerRunFaucet`
- `PerRunSink`
- `PerDayFaucet`
- `PerDaySink`
- `CurrentStock`
- `TargetStock`
- `GraduationCost`
- `TimeToGraduation`
- `InflationRisk`

关键检查式：

`TimeToGraduation = RemainingCost / NetGainPerHour`

如果结果不是你想要的 30 小时附近，就别嘴硬，直接改。

## 10. 数值红线
如果出现下面任意一条，就说明经济设计已经开始烂了：
1. 玩家主资源连续 3 天只增不减，没有强力 Sink。
2. 广告补偿占总收入超过 25% 且为最优策略。
3. 新手期和中期的资源缺口都靠同一种货币解决，导致单资源超载。
4. 大版本更新后，旧资源仍大量积压却没有新出口。
5. 玩家毕业耗时波动极大，欧皇和非酋差出两倍以上。

## 11. 对《光与朽》的硬建议
最值得立刻落表的不是“再加几个掉落”，而是先做一张 **资源总账表**：
- 每局金币净增
- 每局碎片净增
- 每小时广告补偿等效资源
- 科技树各层累计消耗
- 装备毕业累计消耗
- 30小时毕业目标偏差

然后定一个简单规则：

`自然游玩贡献 70% ~ 80%`

`广告补偿贡献 15% ~ 25%`

`活动/补偿贡献 < 10%`

这样既能让玩家刷得动，又不至于把经济做成广告驱动的垃圾场。

## 12. 今日结论
最硬的一句：**资源系统不是“给多少”的问题，而是“净流量是否长期可控”的问题。**

对《光与朽》来说，下一步别急着调掉落表现，先把金币、碎片、广告补偿三条水池拆开，按“单局 / 单日 / 毕业周期”三层核算净流量，再用 30 小时自然毕业目标反推每个 faucet 和 sink。只要这张总账一立起来，局外成长、广告转化和反通胀就都能从玄学变成工程。

# 游戏数值最佳实践：等价交换物与时间标价（1钻=多少金币=多少体力=多少分钟）

## 1. 为什么这个专题是经济系统的命门
水池模型只解决“有没有漏水”，等价交换物解决的是“每一滴水到底值多少钱”。
如果你没有统一价值尺子，就一定会出现这些蠢事：
- 商店里 60 钻买的金币，还不如打两分钟怪。
- 看一次广告送的奖励，直接等于半小时自然进度，玩家策略瞬间变成“先看广告再玩”。
- 体力包、碎片包、金币包各自独立定价，最后互相打架，把整套经济打穿。

所以资深数值不会先问“卖多少”，而是先问：

`这个资源帮玩家节省了多少有效时间？`

时间，才是所有货币、资源、补偿、礼包的底层锚点。

## 2. 核心定义：先统一成“时间价值”
最稳的做法，是先定义一个基础单位：

`1 分钟有效推进值 = V_min`

这里的“有效推进”，不是挂机挂着，而是玩家正常游玩时，能稳定换来的综合成长价值。对《光与朽》来说，它至少由三部分组成：
- 金币成长值
- 碎片成长值
- 局内失败纠偏值（例如广告复活、额外刷新）

因此可写为：

`V_min = GoldPerMin × W_gold + ShardPerMin × W_shard + ProgressPerMin × W_progress`

其中 `W` 是统一换算权重，最终都要折回同一锚点，建议先折到“钻石价值”或“RMB价值”。

## 3. 经典换算链：RMB → 钻石 → 时间 → 二级货币
中文数值经验贴、知乎双货币讨论和商业化项目的通用做法，高度一致：

### 3.1 先用高级货币做锚点
设：
- `1 RMB = 10 Diamonds`
- 即 `1 Diamond = 0.1 RMB`

这是商业锚，不代表真实游戏价值已经成立。真正的关键是下一步。

### 3.2 再用时间反推钻石的实际购买力
如果目标玩家在《光与朽》中：
- 平均每分钟获得 `120 Gold`
- 平均每分钟获得 `0.6 Shard`
- 30 小时自然毕业

再定义：
- `1 Shard = 150 Gold` 的成长等价

则每分钟有效成长价值：

`V_min = 120 + 0.6 × 150 = 210 Gold-equivalent`

如果你希望“6元首充”大约购买 30 分钟到 40 分钟的成长捷径，而不是直接买半天进度，那么：

`60 Diamonds ≈ 30~40 min ≈ 6300~8400 Gold-equivalent`

则可反推：

`1 Diamond ≈ 105 ~ 140 Gold-equivalent`

这才是定金币包、体力包、碎片包的起点。

**先定时间，再定汇率。别反过来。**

## 4. 通用公式：资源价值 = 节省时间
### 4.1 单资源时间定价
对任意资源 `R`：

`Value(R) = TimeSaved(R) × V_min`

若某礼包给 `G` 金币，则：

`TimeSaved_gold = G / GoldPerMin`

`Value_gold = (G / GoldPerMin) × V_min`

若某礼包给 `S` 碎片，则：

`TimeSaved_shard = S / ShardPerMin`

`Value_shard = (S / ShardPerMin) × V_min`

### 4.2 体力的定价
体力不能按“1 点体力 = 固定金币”粗暴拍，因为它的价值取决于单位体力产出。

若：
- 每 1 点体力平均打出 `Gold_per_energy` 金币
- 每局耗 `E_run` 体力
- 单局时长 `T_run`

则：

`EnergyValue = (Gold_per_energy × W_gold + Shard_per_energy × W_shard)`

或转成时间：

`1 Energy = T_run / E_run` 分钟的进入门票价值

如果 10 点体力只能换 2 分钟内容，却卖得和 10 分钟收益一样贵，玩家一定骂你黑。

### 4.3 广告奖励的定价
IAA 项目里广告奖励最危险，因为它不是付费货币，却在抢时间价值。

建议直接算：

`AdRewardTime = RewardValue / V_min`

经验红线：
- 单次激励广告的常规奖励，建议控制在 `3~8 分钟` 自然收益
- 强卡点救援型奖励，可放大到 `8~15 分钟`
- 长期平均不要让广告成为最高性价比行为

否则最优玩法就会从“打游戏”变成“刷广告”，那就是傻逼设计。

## 5. 价值表是所有经济设计的母表
知乎经济数值文章里有个很对的共识：

**数值策划至少要有一张“价值表”，把所有资源统一折成同一种价值。**

推荐《光与朽》直接建这张表：

| 资源 | 产出速率 | 时间等价 | 钻石等价 | 主要用途 |
| --- | --- | --- | --- | --- |
| 金币 | `GoldPerMin` | `1` 基准 | `Gold / DiamondRate` | 科技树 |
| 碎片 | `ShardPerMin` | `Shard / ShardPerMin` | 折算后写入 | 装备/无人机成长 |
| 体力 | `RunTime / EnergyCost` | 入场时间 | 折算后写入 | 限制节奏 |
| 广告复活 | 按纠偏收益算 | `SavedFailTime` | 折算后写入 | 失败救援 |
| 商店刷新 | 按期望增益算 | `ExpectedPowerGain / V_min` | 折算后写入 | 构筑修正 |

注意，广告复活和刷新不是按“道具价格”算，而是按**它挽救了多少失败时间、抬高了多少通关概率**来算。

## 6. 两种最常用的定价方法
## 6.1 成本法，按时间成本定价
这是最硬的底层方法：

`Price = TimeSaved × DiamondPerMinute`

优点：
- 全系统统一
- 不容易互相打架
- 容易推毕业节奏

缺点：
- 太机械时，惊喜感弱
- 对高情绪价值商品不够灵活

## 6.2 效用法，按功能溢价定价
某些资源不是简单节省时间，而是节省失败风险、减少挫败、补齐构筑。

这时可写：

`Price = BaseTimeValue × UtilityMultiplier × ScarcityMultiplier`

例如：
- 普通金币包：`UtilityMultiplier = 1.0`
- 定向核心碎片：`1.2 ~ 1.5`
- Boss 前复活券：`1.5 ~ 2.0`
- 稀有定向构筑刷新：`1.3 ~ 1.8`

但记住，**效用溢价只能加在基础时间价值之上，不能脱离时间价值乱飞。**

## 7. 《光与朽》的落地算法
### 7.1 先定义目标毕业时长
已知目标：

`T_graduate = 30 小时 = 1800 分钟`

若总毕业成本为：
- `GoldTotal = 180000`
- `ShardTotal = 900`

则：

`GoldNeedPerMin = 180000 / 1800 = 100`

`ShardNeedPerMin = 900 / 1800 = 0.5`

如果设 `1 Shard = 150 Gold-equivalent`，则：

`V_min = 100 + 0.5 × 150 = 175 Gold-equivalent`

### 7.2 再反推钻石汇率
若希望 `1 Diamond ≈ 1 分钟有效推进值`，则：

`1 Diamond ≈ 175 Gold-equivalent`

如果觉得商业化太肥，可压到 `0.7~0.8 分钟 / Diamond`；如果想让首充特别爽，可局部拉到 `1.2~1.5 分钟 / Diamond`，但只限首购或一次性礼包。

### 7.3 再统一所有商品
例如：
- `1200 Gold` → `1200 / 175 ≈ 6.86 Diamonds`
- `10 Shards` → `(10 × 150) / 175 ≈ 8.57 Diamonds`
- `1 次广告复活` 若平均挽回 `6 分钟` 进度 → `≈ 6 Diamonds`

这样金币、碎片、复活、体力补给就终于能放在同一个坐标系里比较。

## 8. 常见坑，别踩
### 8.1 软货币直购打穿日常循环
如果 `1 Diamond` 能买到 `5 分钟以上` 的稳定成长，而玩家充值门槛又低，那日常刷本价值会被瞬间打烂。

### 8.2 广告奖励高于付费包性价比
这会导致小R不买，白嫖党狂刷，商业化和留存一起畸形。

### 8.3 体力价格和单位体力产出脱节
玩家一旦发现“买体力不如买金币”或“买金币不如直接复活硬过”，系统就裂了。

### 8.4 稀缺资源和常规资源混一个汇率
定向核心碎片、随机普通碎片、通用金币不能完全等价，因为稀缺性不同，至少要加：

`ScarcityMultiplier`

但这个稀缺溢价建议控制在 `1.1 ~ 2.0`，别乱翻十倍，那是神经病礼包。

## 9. 外部资料交叉提炼
- 知乎关于双货币系统的讨论有一个稳定共识：**高级货币先锚定 RMB，再按玩家节省的游戏时间反推二级货币汇率。**
- 知乎回合制经济数值文章强调：**价值表是产出、消耗、掉落、商城全套计算的共同底板，最终最好统一成钻石价值或 RMB 价值。**
- CSDN 与腾讯云相关文章都在重复一个本质：**经济系统本质是价值创造、转化与实现，货币只是表现层，真正该算的是价值流。**
- 海外 faucet & sink / value chain 文章强调：**资源价值来自它通向终局目标链路的效率，而不是它名字叫“稀有”就值钱。**

## 10. 今天的硬结论
1. **时间才是最稳的母货币。**
2. **钻石只是商业锚，真正的兑换率要靠“节省了多少有效推进时间”反推。**
3. **广告、体力、金币、碎片必须进同一张价值表，否则商城、掉落、广告奖励一定互相打脸。**
4. **任何能绕过正常成长链路太多的资源，都必须加上用途隔离、递减倍率或每日上限。**

## 11. 给《光与朽》的直接执行命令
你下一步别再凭感觉写礼包，直接做三张表：
1. `资源产出表`：每分钟金币、碎片、体力消耗、广告收益
2. `价值换算表`：全部折成 Gold-equivalent / Diamond-equivalent
3. `商品定价表`：所有礼包、广告奖励、体力购买按统一汇率排一遍

先把这三张表拉出来，再谈商城，不然就是瞎几把卖。

# 游戏数值最佳实践：保底机制（Pity System）的期望值计算

## 1. 为什么今天必须学这个
保底不是“安慰奖机制”，而是把概率体验、玩家情绪、资源消耗、商业化转化绑在一起的数值阀门。你如果只会写“2%掉落，50抽保底”，但不会算期望、不知道方差、不知道软保底会把分布推成什么鬼样子，那就是纯拍脑袋。

对《光与朽》来说，这套模型未来直接决定三件事：
1. 稀有模块 / 金装 / 核心碎片到底多久出一次。
2. 广告补偿、商店兑换、碎片合成要给到什么档位才不打穿经济。
3. 玩家在第几局开始感到“差一点就出了”，从而继续玩、继续看广告、继续养成。

## 2. 三种保底机制，先分清楚

### 2.1 硬保底（Hard Pity）
前 `N-1` 次每次独立概率都是 `p`，如果前面都没中，第 `N` 次必出。

- 第 `k` 次首次命中的概率（`1 <= k < N`）：
`P(X = k) = (1-p)^(k-1) * p`
- 第 `N` 次首次命中的概率：
`P(X = N) = (1-p)^(N-1)`

期望抽取次数：

`E[X] = Σ(k * (1-p)^(k-1) * p), k=1..N-1  +  N * (1-p)^(N-1)`

累计命中概率：

`F(n) = 1 - (1-p)^n ,  n < N`

当 `n = N` 时，`F(N)=1`。

### 2.2 软保底（Soft Pity）
前期按基础概率 `p0`，从某个阈值 `T` 开始，每失败一次就提升概率，直到某次触发或到上限强保。

若第 `k` 次概率为 `p_k`，则：

- 生存概率（前 `k-1` 次都没中）：
`S(k-1) = Π(1-p_i), i=1..k-1`
- 第 `k` 次首次命中概率：
`P(X=k) = S(k-1) * p_k`
- 期望：
`E[X] = Σ(k * S(k-1) * p_k)`

软保底的本质，是把长尾黑脸区间狠狠干掉，让“多数人出货区间”更集中。

### 2.3 井 / 兑换保底（Spark）
抽满 `N` 次直接可兑换目标物，不一定要求前 `N-1` 次概率变化。它的本质是“期望封顶”。

如果单抽中目标概率为 `p`，抽满 `N` 次可直接换，则期望和硬保底同构：

`E[X] = Σ(k * (1-p)^(k-1) * p), k=1..N-1  +  N * (1-p)^(N-1)`

区别不在数学，而在玩家感知。硬保底是“系统送你”，井是“你自己攒够了换”，后者对付费与囤积策略影响更大。

## 3. 最关键的两个指标：期望与分位数
只看期望是低级错误。你至少要同时看：

1. **期望次数 `E[X]`**：平均要多少次出货。
2. **分位数 `Q90 / Q95`**：90% / 95% 的玩家在多少次内能拿到。

因为玩家不活在平均数里，玩家活在自己的脸黑里。

举例，若基础概率 `p=2%`，硬保底 `N=50`：
- 期望出货次数约为 `31.79`
- 50次前自然抽中的累计概率仅 `63.58%`
- 也就是说，大量玩家其实会贴着保底线拿货

这意味着什么？
这意味着该池子的体感不是“偶尔欧一下”，而是“多数时候都在熬保底”。如果这是高价值终局内容，可以；如果是中期核心Build组件，就太拖了。

## 4. PRD 和传统保底的区别
根据知乎、腾讯游戏学堂、CSDN 对 PRD / 伪随机的讨论，行业共识很明确：

- **真随机**：每次独立，期望稳定，但方差大，容易连黑。
- **PRD**：每次失败后提高下一次概率，命中后重置，长期期望接近面板值，但触发间隔更平滑。
- **保底**：给最坏情况封顶，解决极端长尾。

PRD 更适合：
- 暴击
- 掉治疗包
- 局内关键事件触发
- 高频、短周期概率事件

硬/软保底更适合：
- 抽卡
- 金装掉落
- 核心碎片获取
- 低频、高价值概率事件

别乱用。高频战斗触发如果做死板硬保底，会让手感像脚本；低频稀有掉落如果只做真随机，会把玩家心态狠狠干碎。

## 5. 《光与朽》该怎么落地

### 5.1 先定义目标，再反推概率
你要的不是“金装概率 1.5% 看起来很高级”，你要的是：
- 普通活跃玩家在第几小时拿到第一件金装
- 30小时自然毕业目标下，需要多少核心碎片
- 看广告补偿一次，相当于推进多少次掉落尝试

正确顺序：

`目标体验 -> 目标期望次数 -> 目标分位数 -> 反推 p / T / N`

不是反过来。

### 5.2 推荐一套《光与朽》碎片掉落结构
假设你希望某核心模块碎片：
- 玩家平均 `30` 次精英击杀拿到 1 个
- 最黑脸不超过 `50` 次

那你可以先用：
- 基础概率 `p = 2.28%`
- 硬保底 `N = 50`

这样期望大约就是 `30.02` 次。

如果你还想减少“贴保底拿货”的烦躁感，可以改成软保底：
- 前30次：`2%`
- 第31次开始：每失败1次，额外 `+3%`
- 第50次强保

这个示例下：
- 期望出货次数约 `26.19`
- 40次内累计出货概率约 `93.33%`
- 50次内几乎必出

这套体感会明显比纯硬保底顺滑，因为多数人会在 30~40 次区间出货，不会都挤在 50 次门口哭。

## 6. 广告、商店、合成，必须和保底共尺子
一旦有保底，你所有补偿渠道都要统一折算成“保底进度价值”。

定义：
`PityValue = 1 / E[X]`

如果一个核心碎片池期望 `E[X]=30` 次出1个，那么：
- 1次有效尝试 ≈ `1/30` 个目标碎片期望价值
- 1次广告补偿如果直接送 `5` 次尝试进度，就等于送了 `1/6` 个目标碎片

这值不值？得看它一天能看几次。

建议：
- 单次广告补偿控制在 `0.5 ~ 1.5` 次等效尝试
- 局外商店每日限购可卖 `2 ~ 4` 次等效尝试
- 碎片合成做高保真兜底，但单件合成总成本应高于平均欧皇路径，低于最黑非酋路径

这样欧皇爽，非酋不退坑，经济也不会炸。

## 7. 实操表格怎么建
建议在 Excel / Google Sheet 里直接建这些列：
- `PoolID`
- `TargetItem`
- `BaseRate p`
- `SoftPityStart T`
- `RateIncreasePerFail`
- `HardPity N`
- `E[X]`
- `MedianPulls`
- `Q90`
- `Q95`
- `AdCompensationValue`
- `ShopPrice`
- `SynthesisCost`
- `NaturalHoursToTarget`

关键校验公式：

`NaturalHoursToTarget = 目标次数 * 单次尝试时间 / 60`

只要这个字段和你“30小时自然毕业”的总目标对不上，你前面所有概率设计都是屁话。

## 8. 今日硬结论
1. **保底不是写个上限就完事，必须算期望和分位数。**
2. **低频高价值掉落，优先用软保底 + 强保，而不是纯真随机。**
3. **所有广告补偿、商店兑换、碎片合成，都必须按“保底进度价值”统一定价。**
4. **《光与朽》里核心Build组件绝不能让大量玩家贴着最终保底拿，不然中盘构筑会变成纯坐牢。**

## 9. 外部资料提炼来源
- 根据知乎关于“真随机 vs 伪随机”的讨论，核心结论是：玩家厌恶的不是低概率，而是无法感知进度的长尾黑脸。
- 根据腾讯游戏学堂关于 PRD 的文章，伪随机的价值在于压缩方差、减少极端连续失败，并天然具备“软保底”属性。
- 根据 CSDN 关于抽卡概率模型与保底算法的讨论，行业常见做法是用基础概率 + 阈值抬升 + 上限强保，目的不是提高期望本身，而是重塑出货分布。

# 游戏数值最佳实践：抽卡 / 掉落权重池设计与全毕业平均时长建模

## 1. 为什么这个专题现在必须补
保底解决的是“最黑多惨”，权重池解决的是“平时怎么掉”，而全毕业时长建模解决的是“玩家到底要刷多久才毕业”。这三个不打通，数值就是假的。

对《光与朽》尤其关键：
1. 金装、核心模块、碎片的掉落不能只看单件概率；
2. 玩家中盘 Build 成型速度，常常是被“最后那一件”拖死；
3. 30 小时自然毕业目标，必须从掉落结构反推，而不是写完表再祈祷。

## 2. 权重池的底层，不是概率，是两段概率链
任何掉落都先拆成两层：

`p_i = p_slot × (w_i / Σw)`

其中：
- `p_slot`：本次击杀/结算有没有进入该掉落槽（例如是否出装备）
- `w_i`：目标物在槽内的权重
- `Σw`：该槽所有候选物权重总和
- `p_i`：单次尝试得到目标物 i 的真实概率

这条公式是今天最重要的一刀。很多人只盯 `w_i`，不盯 `p_slot`，最后把整套掉落体感算歪。

### 示例
假设《光与朽》精英怪：
- `p_slot = 30%`（30% 概率掉装备）
- 装备槽内有 8 个候选，权重分别不同
- 某件目标金装 `w_target = 5`
- 全部权重和 `Σw = 100`

则：

`p_target = 0.3 × 5/100 = 1.5%`

这才是玩家每次击杀真正拿到该金装的概率。

## 3. 单件期望、分位数、体感区间
### 3.1 单件平均尝试次数
若每次独立，单件目标的期望次数：

`E[target] = 1 / p_i`

上例中：

`E = 1 / 0.015 ≈ 66.67 次`

别高兴太早，均值不等于体感。

### 3.2 指定把握度所需次数
玩家更在意“刷多少次大概率能出”。

`P(至少出1次, n) = 1 - (1-p_i)^n`

反推在置信度 `q` 下需要多少次：

`n_q = ceil( ln(1-q) / ln(1-p_i) )`

上例：
- `q = 50%` → `n50 ≈ 46`
- `q = 90%` → `n90 ≈ 153`
- `q = 95%` → `n95 ≈ 198`

这就是真相：**1.5% 掉率的单件，平均 67 次，但想让大多数玩家都拿到，往往要 150 次以上。**

## 4. 凑齐整套，不是单件概率相加，是收藏家问题
### 4.1 等概率全套的经典公式
若同一槽中有 `n` 件目标物，且每次进入该槽后等概率掉任意一件，则凑齐全套的期望掉落次数：

`E_full_slot = n × H_n`

其中 `H_n = 1 + 1/2 + 1/3 + ... + 1/n` 为调和数。

若该槽触发概率为 `p_slot`，换算到真实尝试次数：

`E_full_try = (n × H_n) / p_slot`

例如 8 件套、装备槽概率 30%：
- `H_8 ≈ 2.7179`
- `E_full_slot ≈ 21.74 次装备掉落`
- `E_full_try ≈ 72.46 次击杀`

注意，这只是**等概率**且**不区分稀有度**时的理想值。

### 4.2 非等概率全套：加权收藏家问题
如果每件概率不同，最后一件稀有物会主宰毕业时长。小规模精确解可用容斥：

`E_full = Σ[ (-1)^(|S|+1) / Σ_{i∈S} p_i ]`，对所有非空子集 `S`

这个公式很硬，但件数一多就不适合手算。它真正传达的结论只有一句：

**全毕业时长往往不是被“平均概率”决定，而是被尾部最稀有的那几件决定。**

## 5. 实战里最该用的，不是闭眼套公式，而是 Monte Carlo
当存在以下因素时，直接模拟比手推更靠谱：
- 分层掉落槽（装备 / 碎片 / 金装 / 核心模块）
- 保底、软保底、PRD
- 重复物可分解成碎片
- 商店兑换、广告补偿、合成兜底
- 不同 Boss / 不同波次掉不同池子

建议直接跑三组模拟：
1. **纯自然掉落**：验证真实毕业时长；
2. **自然 + 重复分解 + 合成**：验证中长期收敛；
3. **自然 + 广告补偿 + 商店兑换**：验证 IAA 是否只是纠偏，而不是打穿经济。

推荐输出至少四个结果：
- `E[毕业次数]`
- `Median`（中位数）
- `Q90`
- `Q95`

只看均值，是低级错误。

## 6. 数值设计的正确顺序
### 第一步：先定体验目标
例如《光与朽》：
- 第 3~5 小时：至少成型 1 套核心 Build 骨架
- 第 10~15 小时：玩家稳定拿到 2~3 个关键金装/模块
- 第 30 小时：自然毕业或接近毕业

### 第二步：再定掉落池结构
推荐拆成三层：
1. **基础层**：高频、低稀缺，保证成长反馈
2. **构筑层**：中频、定向，决定 Build 成型
3. **毕业层**：低频、稀有，用于长期追求

### 第三步：再反推单次概率与权重
不要反过来。反过来就是拍脑袋。

## 7. 《光与朽》最适合的掉落结构
### 7.1 别把所有稀有物塞进一个大池
如果把金装、核心模块、无人机碎片、科技材料全塞进同一装备池，结果一定是：
- 单件稀有度看着不低
- 实际定向获取极难
- 中盘成型速度极差
- 玩家一直掉“不是我想要的”垃圾

更合理的结构是：
- **精英池**：核心模块 / 构筑碎片
- **Boss池**：高价值定向金装
- **结算池**：稳定碎片与保底进度
- **商店池**：把重复物转换成可控追赶路径

### 7.2 中盘成型件必须定向，不要纯大池赌博
中盘决定留存的，不是终局毕业件，而是“我这流派到底成不成”。

建议核心 Build 部件采用：
- 基础掉落 + 定向兑换 + 重复分解补进度

否则大量玩家会死在“理论能成型，实战就是不来”这条线上。

### 7.3 最后一件毕业物要防拖尾
最后一件最容易把 30 小时毕业拖成 60 小时坐牢。

解决思路：
1. 重复物分解成通用碎片；
2. 关键稀有件设置低频兑换；
3. 当某件长期未出时，允许软保底抬权重；
4. 把广告和商店奖励折成“毕业进度值”，而不是直接送成品。

## 8. 可直接落表的核心公式
### 8.1 目标物真实单次概率
`p_i = p_slot × w_i / Σw`

### 8.2 单件期望次数
`E_i = 1 / p_i`

### 8.3 q 分位所需次数
`n_q = ceil( ln(1-q) / ln(1-p_i) )`

### 8.4 等概率全套期望
`E_full_try = (n × H_n) / p_slot`

### 8.5 毕业时长换算
若每局平均有 `r` 次有效掉落尝试、每局时长 `t_run` 分钟，则：

`HoursToGraduate = E_full_try / r × t_run / 60`

### 8.6 重复物分解等效进度
若重复物平均可转化为 `c` 点通用碎片，目标物需要 `C` 点合成，则每次重复的毕业推进约为：

`DuplicateProgress = c / C`

这个值能极大压缩长尾。

## 9. 常见坑，别犯
1. **只配权重，不算真实概率链。**
2. **只看单件期望，不看整套毕业。**
3. **只看均值，不看 Q90/Q95。**
4. **把中盘成型件和终局炫耀件放同一稀有池。**
5. **没有重复分解与兑换，导致最后一件拖死全局。**
6. **广告直接送成品，打穿自然成长。**

## 10. 外部资料交叉提炼
- 根据知乎《游戏机制设计（1）：掉落机制的设计思考过程》，掉落设计至少要区分“逐个百分比掉落”与“权重子集掉落”；前者适合独立判定，后者适合控制组合和维护复杂掉落结构。
- 根据知乎/数值文章对“凑齐 AB 期望值”的讨论，收藏型掉落不能只看单件概率，第二件、最后一件会显著抬高总期望。
- 根据 CSDN《游戏中掉落系统的设计》，成熟掉落通常采用“母集 + 子集 + 权重”的双表结构，以便同时控制组合丰富度、类型隔离和维护成本。
- 根据 coupon collector 经典理论与 weighted coupon collector 研究，等概率全收集的期望近似 `n ln n` 级增长；当概率不均时，最稀有项会主导总毕业时长。
- 根据 Game Developer 关于 ARPG loot table 的讨论，掉落池设计真正服务的是“玩家构筑目标”和“追逐循环”，不是单纯把随机做深。

## 11. 《光与朽》今日硬结论
1. **先拆概率链，再谈掉率；不拆就是假概率。**
2. **中盘成型件必须提供定向路径，不能全靠大池赌脸。**
3. **30 小时自然毕业要盯整套分布，不是盯单件均值。**
4. **最后一件稀有物通常才是真正的毕业杀手，必须用分解、兑换、软保底压长尾。**
