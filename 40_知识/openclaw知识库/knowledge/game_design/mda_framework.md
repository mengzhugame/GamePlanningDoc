# 游戏策划进阶学习笔记：MDA框架（Mechanics, Dynamics, Aesthetics）

## 1. 核心概念解析

MDA 框架是现代游戏设计的经典分析模型，将游戏解构为三个层级：
*   **Mechanics (机制)**：游戏的基础代码、数据结构、算法和规则。这是设计师直接创造的东西（如跳跃的高度、扣血的数值）。
*   **Dynamics (动态)**：玩家与机制互动后产生的系统级行为。这是游戏运行时的状态（如为了回血而采取的“风筝”战术、刷怪的循环）。
*   **Aesthetics (美学/体验)**：玩家在参与动态过程时产生的情感反应与主观体验。这是玩家直接感知的东西（如爽快感、恐惧感、成就感）。

## 2. 视角的双向性 (The Two-Way Flow)

*   **设计师视角 (Designer's perspective)**：机制 -> 动态 -> 美学。我们只能通过编写底层代码和设计死板的规则（机制），去引导出复杂的交互（动态），最终希望玩家能感受到特定的情感（美学）。
*   **玩家视角 (Player's perspective)**：美学 -> 动态 -> 机制。玩家首先感受到的是爽不爽、恐不恐怖（美学），然后逐渐摸索出游戏怎么玩、怎么赢（动态），只有极少数硬核玩家才会去深究底层的算法和数据结构（机制）。

## 3. 对《光与朽》的落地启发

对于我们正在开发的塔防游戏《光与朽》：
*   **预期美学 (Aesthetics)**：割草的爽快感、深思熟虑后的掌控感。
*   **所需动态 (Dynamics)**：玩家不断寻找最优站位，尝试不同的流派组合，面对不同波次敌人采取不同防守策略。
*   **底层机制 (Mechanics)**：塔的攻击范围、敌人的移动速度、资源的获取速率、升级的数值变化。
*   **落地**：如果玩家觉得“不够爽”（美学反馈差），我们不能直接修改“爽度”，而是必须去调整底层的“机制”（如增加敌人密度、缩短塔的攻击前摇），从而改变“动态”（玩家能更频繁地触发AOE伤害），最终实现“爽”的“美学”。

## 4. 技能化思考 (Skill Integration)

**如果将其转化为 OpenClaw 的 Skill：**
可以编写一个名为 `mda-analyzer` 的辅助策划 Skill。
*   输入：游戏的简单描述或一小段玩法设想。
*   处理：AI 自动将其按照 M、D、A 三层拆解，并反问设计师：“你想让玩家产生哪种 Aesthetic？如果你想要这个，目前的 Mechanics 够不够支撑？”
*   输出：结构化的游戏设计诊断报告，帮助梳理混乱的设计思路。
