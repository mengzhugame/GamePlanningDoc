# AI代码编写Agent工作流指南 (Coding Agent Pipeline)

> 创建时间: 2026-02-11
> 来源: Addy Osmani, Anthropic, TeamDay, Faros AI 等多个行业资源综合

## 一、什么是Agentic Coding（智能体编程）

从"AI辅助补全"进化到"AI自主执行"：
- **传统AI编码**: 自动补全、聊天问答（Copilot早期）
- **Agentic编码**: AI理解整个仓库、规划任务、多文件修改、运行测试、自动迭代

核心转变：**你不再写代码，你在指挥写代码的Agent。**

## 二、五大Agent设计模式（来自Anthropic研究）

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| **Prompt Chaining** | 任务分解为串行步骤，每步输出→下步输入 | 内容生成、文档处理 |
| **Routing** | 分类输入→分发给专门处理器 | Bug修复/新功能/重构分流 |
| **Parallelization** | 多个LLM调用并行执行 | 独立子任务（文件分析、测试生成） |
| **Orchestrator-Workers** | 中央LLM分解任务→委派给专业Worker | 复杂编码项目（最常用模式） |
| **Evaluator-Optimizer** | 一个生成，一个评审，迭代循环 | 代码审查、质量优化 |

**对我们最有价值的是 Orchestrator-Workers 模式**：主Agent负责架构规划，子Agent负责模块实现。

## 三、实战工作流（独立游戏开发适用）

### 3.1 规范先行：Spec → Plan → Code

```
1. 需求讨论 → 生成 spec.md（需求、架构、数据模型、测试策略）
2. 基于spec → 生成 plan.md（分步实现计划，拆成小任务）
3. 逐步执行 → 每步实现+测试+验证
```

> "先花15分钟做一次快速瀑布式规划，后面编码效率翻倍。" — Addy Osmani

### 3.2 小步迭代，不要一次性生成大段代码

- 每次只让Agent做一个功能/一个Bug修复
- 每步完成后测试验证再继续
- 避免"10个互不沟通的开发者"式混乱

### 3.3 我们的多Agent协作架构

```
主人（创意方向 + 美术）
  ↓ 需求
小龙儿（主Agent：架构 + 协调）
  ├── 子Agent A: 功能模块实现
  ├── 子Agent B: 测试编写
  ├── 子Agent C: Bug修复
  └── 子Agent D: 文档/注释
```

### 3.4 实操步骤（基于OpenClaw + Claude Code）

1. **需求阶段**: 主人描述需求 → 小龙儿整理成spec
2. **规划阶段**: 拆解成3-5个可独立完成的小任务
3. **执行阶段**: 用 `sessions_spawn` 派出子Agent逐个完成任务
4. **验证阶段**: 运行测试、检查代码质量
5. **集成阶段**: 合并代码、更新文档

## 五、关键最佳实践

### 5.1 上下文工程（Context Engineering）
- 用 CLAUDE.md / AGENTS.md 等文件给Agent提供项目上下文
- 维护清晰的项目结构和README
- 关键架构决策写在文档里，不要只存脑子里

### 5.2 质量控制
- **不要盲信AI输出**，每次都review
- 让Agent解释它的改动
- 警惕幻觉（hallucination）：AI可能编造不存在的API
- 小步提交，方便回滚

### 5.3 Token效率
- 明确的prompt = 更少的token浪费
- 每次失败的Agent运行都是烧钱
- 给足上下文，减少来回次数

### 5.4 子Agent规范（Claude Code风格）

在 `.claude/agents/` 目录下创建专门的子Agent：

```markdown
# unity-coder.md
你是Unity C#代码专家。
- 只写Unity相关代码
- 遵循项目编码规范
- 每个函数必须有注释
- 优先使用对象池和事件系统
```

## 六、我们的具体应用场景

### 场景1: 光与朽新功能开发
```
主人: "加一个新的激光塔类型"
→ 小龙儿: 生成spec（塔属性、行为、数值）
→ 子Agent: 实现TowerBase子类
→ 子Agent: 写单元测试
→ 小龙儿: 集成验证 + 报告
```

### 场景2: Bug修复流程
```
主人: "敌人在第5波卡住了"
→ 小龙儿: 分析日志、定位问题
→ 子Agent: 修复代码
→ 运行测试验证
→ 小龙儿: 报告修复结果
```

### 场景3: 代码重构
```
小龙儿: 发现某模块耦合度高
→ 生成重构计划
→ 子Agent: 逐步重构（保持功能不变）
→ 跑全量测试
→ 提交
```

## 七、避坑指南

1. **不要一次让Agent改太多文件** — 超过5个文件就要拆分任务
2. **不要跳过规划直接开干** — spec.md是最值得花的时间
3. **不要完全信任AI的架构建议** — 独立判断仍然关键
4. **Token用量要监控** — 设定预算，避免无限循环
5. **保持Git提交颗粒度** — 每个小任务一个commit，方便回滚
