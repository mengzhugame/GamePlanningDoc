# 单人独立游戏开发的极简敏捷实践指南
**分类**：维度四·资深项目管理【初级课题】
**日期**：2026-03-20
**课题**：敏捷开发 (Agile) 与 SCRUM 在单人独立开发中的极简应用

---

## 一、为什么单人开发者需要敏捷？

传统的"瀑布式"开发（设计→开发→测试→上线）对独立开发者是一场灾难：
- **需求锁死**：游戏感觉好不好玩，在写第一行代码之前根本不知道
- **范围蔓延(Scope Creep)**：一边做一边加功能，永远做不完
- **动力衰减**：长时间没有可见的里程碑，非常容易放弃

敏捷的核心哲学：**用小循环快速验证，而不是一次性赌注式开发**。

---

## 二、极简SCRUM框架（单人版）

标准SCRUM有产品负责人、Scrum Master、开发团队三个角色。
**单人版 = 你一个人身兼三职**。但流程可以大幅简化：

### 核心循环：2周迭代 Sprint

```
┌─────────────────────────────────────────┐
│  Sprint 规划 (30分钟)                   │
│  ↓ 从总任务池(Product Backlog)取任务    │
│  ↓ 放入本期冲刺(Sprint Backlog)         │
│  每日站会 (5分钟)                       │
│  ↓ 昨天做了什么？今天做什么？啥阻碍了我？│
│  Sprint 结束                            │
│  ↓ 回顾：哪里做好了？哪里要改进？        │
└─────────────────────────────────────────┘
```

### 单人开发的关键简化：
1. **2周 Sprint → 可缩短为1周**（独立游戏变化快，1周一个小循环更灵活）
2. **每日站会 → 每天打开Notion/Obsidian写3行**："做了X，今天做Y，卡在Z"
3. **Sprint Review → 给自己/朋友/小红书展示本周成果**（外部压力是最好的推进器）
4. **Retrospective → 每2周周末花15分钟复盘**，只问3个问题：
   - 什么进展顺利？
   - 什么拖慢了我？
   - 下次我要改变什么？

## 三、独立开发最重要的敏捷实践

### 3.1 Product Backlog —— 你的游戏任务总池

把游戏里 **所有想做的功能** 都丢进一个列表（Notion/Trello/HacknPlan），然后按优先级排序。

格式建议（用户故事格式）：
```
作为 [玩家角色]，我希望 [完成某个动作]，以便 [获得某种体验]
示例：作为玩家，我希望激光能反射，以便体验策略布置的成就感
```

**重要**：Backlog里的任务不需要全做！随时可以砍掉或推迟。

### 3.2 Definition of Done —— 完成的定义

每个任务必须有明确的"完成"标准，否则永远在优化：
```
✅ 功能可以正常运行（不崩溃）
✅ 在主要设备上测试过
✅ 代码已提交到Git
✅ 任务从"进行中"移到"完成"
```

### 3.3 时间盒(Timebox) —— 对抗完美主义的铁律

敏捷最核心的反完美主义工具：
- 每个任务设定**最大时间**（如：激光反射系统最多花3天）
- 时间到了，无论如何都停下，进入下一个任务
- **残酷规律**：游戏60%的polish/优化，玩家感知不到10%。先做可玩，再谈完美。

### 3.4 Kanban看板 —— 单人的可视化神器

三列看板，简单有效：
```
| 待办 (Todo) | 进行中 (Doing) | 完成 (Done) |
|-------------|----------------|-------------|
| 敌人AI改进   | 激光反射系统    | 基础塔防逻辑 |
| 音效系统     |                | 关卡编辑器  |
| UI优化      |                | 存档系统    |
```

**铁律**："进行中"永远只放 **1-2个任务**。多线程是效率杀手。

## 四、单人独立开发的推荐工具栈

| 场景 | 推荐工具 | 理由 |
|------|----------|------|
| Kanban/任务管理 | **Notion** (免费) 或 **HacknPlan** | HacknPlan专为游戏开发设计，有GDD集成 |
| Sprint规划 | Notion数据库 | 免费且足够强大 |
| Bug追踪 | GitHub Issues | 与代码仓库无缝集成 |
| 每日站会记录 | Obsidian本地日记 | 速度快，隐私 |
| 时间追踪 | Toggl (免费) | 了解你的时间都花在哪里 |

**极简方案（零成本）**：GitHub Projects = Kanban + Issues + 里程碑，全免费搞定。

## 五、《光与朽》 4月上线专用冲刺计划模板

### 当前情况（2026-03-20）：距离4月上线约2-3周

**推荐：最后3周 Ultra Sprint计划**

**Sprint 1（Week 1）**：核心功能闭环
- [ ] 游戏爽感优化（Hit-stop + 震屏）
- [ ] 关卡波次平衡最终调整
- [ ] IAA广告接入测试

**Sprint 2（Week 2）**：上线前修缮
- [ ] Bug修复冲刺（专注crash类问题）
- [ ] UI打磨（主界面、结算界面）
- [ ] 性能优化（手机端帧率）

**Sprint 3（Week 3）**：上线准备
- [ ] 提交审核（预留3-5天审核期）
- [ ] 营销素材制作（买量视频、截图）
- [ ] 社区冷启动（小红书、TapTap）

## 六、核心反模式警告（独立开发的死亡陷阱）

| 反模式 | 表现 | 敏捷解药 |
|--------|------|----------|
| 范围蔓延 | "再加一个功能就好" | 严格的Backlog优先级，新需求推入下个Sprint |
| 无限打磨 | "这个手感再优化一下" | Definition of Done定义完成标准，时间盒强制截止 |
| 秘密开发 | 一直闷头做不展示 | Sprint Review强制展示，外部反馈是最好的镜子 |
| 多线并行 | 同时做5件事 | 看板"进行中"限制1-2个任务 |

## 七、可以转化的OpenClaw Skill构想

**Skill名称**：`solo-dev-scrum`
**触发场景**：用户说"帮我规划这周/这个Sprint的任务"
**Skill能力**：
1. 读取用户的项目Backlog（从文件或描述）
2. 根据截止日期自动拆解Sprint任务
3. 评估任务的时间估算
4. 输出格式化的Sprint计划表
5. 每次对话时检查"进行中"任务，防止多线并行

**难度**：中等，可复用`planning-with-files`技能的思路。
