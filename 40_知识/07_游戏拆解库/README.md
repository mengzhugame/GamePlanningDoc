# 40_知识/07_游戏拆解库/

## 这是什么

游戏拆解资料库——存储对具体游戏的结构化拆解，作为方法论的"案例底座"。

**定位**：跟 `01_游戏设计/` 的方法论是上下游关系——
- `07_游戏拆解库/` = 具体案例（垂直、单游戏、有 frontmatter）
- `01_游戏设计/` = 抽象方法论（横向、共性、需 `/distill` 蒸馏才进入）

## 命名规则

`<YYYY-MM>_<游戏名>.md`（按拆解日期 + 游戏名扁平命名）

举例：
- `2026-02_羊了个羊.md`
- `2026-05_噩梦守护战.md`
- `2026-05_装备全靠转.md`

## 写入规则

- 任何 AI（Claude Code / Codex）都可以在用户确认任务范围后写
- **写之前必须 grep `_INDEX.md` 的 `game_name`，避免重复拆解**
- 必须按 `90_系统/schemas/game-teardown-schema.md`
- 必须按 `90_系统/templates/game-teardown-template.md` 12 段结构
- status 三态：`draft` → `refined` → `distilled`

## 怎么用

| 场景 | 怎么用 |
|------|------|
| **找方法论灵感** | 直接 grep 关键词（"弹球"、"持久玩"、"三消"等） |
| **避免重复拆解** | 先看 `_INDEX.md` 的 game_name |
| **蒸馏到方法论** | 周度 `/distill` 时把多份拆解的共性提取到 `40_知识/01_游戏设计/` |
| **立项参考** | 拆解 ≠ 立项依据。要立项还要走 `/iron-rule-check` |

## 拆解原则（4 条）

1. **拆机制不抄玩法**——重点是"为什么爽"、"为什么持久玩"，不是直接复制
2. **必须含"差异化"段落**——第 11 段强制写"不该照抄的 1 个点"，防铁律 1 fail
3. **必须含"相邻度"段落**——第 9 段判断跟用户已有项目的关系
4. **不立项**——拆解只是知识储备，不是立项推荐

## 提取共性 → 方法论的节奏

拆完 P0 + P1（约 7 款）后，做一次**共性对比分析**：
- 哪些机制让游戏"持久玩"？
- 哪些机制让游戏"靠堆量"？
- 抖音 vs 微信赛道的玩法差异？

把分析结论蒸馏到 `40_知识/01_游戏设计/超休闲游戏设计方法论.md` 或新建专题文件。

## 拆解库的产出应分三层

拆解一款游戏时，不要只保存“这游戏怎么玩”。更好的产出分三层：

| 层级 | 产物 | 用途 |
| --- | --- | --- |
| 事实层 | 平台、类型、核心循环、系统、变现、数据表现 | 方便未来复查，不混入主观结论 |
| 机制层 | 哪个规则制造了爽点、压力、传播或留存 | 进入具体游戏拆解文件 |
| 方法层 | 可跨项目复用的设计原则 | `/distill` 后进入 `40_知识/01_游戏设计/` |

快速拆解 10 分钟版只回答 5 个问题：一句话玩法、短中长循环、核心体验 3 词、最值得借鉴 3 点、最不该照抄 1 点。

深度拆解 1 小时版要补齐：操作方式、进度系统、成长系统、变现系统、数值/经济、创新点、问题点、适用场景和可融合机制。

标签不要只写品类，要覆盖 5 类：

| 标签类 | 示例 |
| --- | --- |
| 玩法 | 塔防、消除、放置、射击 |
| 机制 | Roguelike、Build、随机、技能树 |
| 平台 | 微信、抖音、App、Steam |
| 变现 | IAA、IAP、混变、买断 |
| 体验 | 爽快、策略、挑战、治愈、社交 |

每周 2-3 款即可，关键不是数量，而是能不能在下一次立项、调关卡、做广告点或修首局体验时被真正调用。
