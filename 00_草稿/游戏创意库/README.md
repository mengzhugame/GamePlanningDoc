# 游戏创意库 README

> 这里是 wangyongcheng 的游戏创意工作台。从一个灵感到一个 AI 概念视频再到一个正式立项，整条流水线都跑在这个文件夹里。
> **本文档是这个文件夹的操作手册** — 不知道下一步该去哪个文件、不知道某个创意现在该走到哪一阶段，都先回这里翻。

---

## 1. 这个文件夹是什么 / 为什么存在

历史教训：美妆叠叠乐（同质化抄袭+发行迟） · 光与朽（不断加功能拒绝面对市场） · 90秒极限防线（视频还没拍同质化已经暴露）。三次失败都指向同一个问题——**没有一条机械化的「灵感 → 拷问 → 视频 → 信号 → 立项」流水线，全靠个人意愿硬推**。

这个创意库的目标：用文件结构强制走流程。每个文件只负责一件事，每一步都有明确的进入条件和退出条件。意愿不够时流程能托底，意愿太冲时流程能拦截。

## 2. 流水线（6+1 阶段）

```
[来源]                              [文件]               [出口判据]
─────────────────────────────────────────────────────────────
0. 灵感                                                   有一句话能讲清玩家在做什么
   ├ 玩到/灵感
   ├ 题材 × 动词 AI 组合
   └ 市场/痛点扫描信号
        ↓
0.5 周度评审 Agent
                 周度评审/YYYY-Www_休闲小游戏创意评审.md  只选 3 个概念视频 + 1 个 7 天原型
        ↓
1. 待审核        00A_待审核创意表.md                     3 秒钩子能讲清 + 跟铁律 1 有戏
        ↓
2. 已通过初筛    00B_已通过创意表.md                     差异化拷问 3 条全过
                 + 创意名_概念卡.md
        ↓
3. 概念视频      创意名_概念视频流程.md                  3 条 AI 视频做完发布
                 （04_概念视频流程模板.md）
        ↓
4. 平台观察 T+7d                                          填第 7 段「复盘」软门槛三题
        ↓
5. 决策          (Push / Pivot / Kill)
   ├ Push (3Y) → 进 6
   ├ Pivot (1N) → 改概念卡 + 重做视频 (回 3)
   └ Kill (2N+) → 进 00_总表标记 abandoned + 记录复用资产
        ↓
6. 正式立项      20_项目/NN_创意名项目/                   走 40_知识/00_工作流/休闲小游戏正式立项流程_v1.md
```

**Push/Pivot/Kill 判据**（软门槛三题，详见 §8）：
- Q1 这版视频让你自己还想接着做下一版吗？
- Q2 有 3 个以上陌生人追问「怎么玩 / 什么时候上」吗？
- Q3 能不能 1 个月内出 Demo？

## 4. 创意生成方法论

### 来源 1：玩到 / 灵感
偶遇好玩的游戏 → 立刻在 `00A_待审核创意表.md` 加一行（临时编号 + 一句话钩子 + 来源备注）。**不要直接进概念卡**，先放 00A 等审核。

### 来源 2：题材 × 动词 AI 生成
从 `01A_题材库.md` 选 1 个题材，从 `01B_核心动词库.md` 选 1-3 个动词，让 AI 随机产生若干玩法点子 → 进00A_待审核创意表.md。
- 一次最多生成 5-10 条，宁少勿多。
- 生成后立刻 ✓/✗，否决的直接进 00_总表。


当用户说“从题材库随机抽取 1 个 + 核心动词库随机抽取 1-3 个，生成 20 个创意”时，按下面流程执行：

1. 读取 `01A_题材库.md` 和 `01B_核心动词库.md`。
2. 从题材库随机抽取 20 个题材对象；允许重复题材组，但尽量不要连续重复同一题材名。
3. 每个题材随机搭配 1-3 个核心动词；第一版概念视频默认只突出 1 个主动词，其他动词只作辅助。
4. 每条创意必须写清：
   - 创意名
   - 赛道
   - 一句话玩法
   - 当前判断
   - 状态：`待审核`
   - 下一步
5. ID 接续 `00_游戏创意总表.md` 和 `00A_待审核创意表.md` 中当前最大 `IDEA-XXXX` 编号，不使用临时编号。
6. 写入 `00A_待审核创意表.md`，字段必须和 `00_游戏创意总表.md` 保持一致：

```text
ID | 创意名 | 赛道 | 一句话玩法 | 当前判断 | 状态 | 下一步
```

进入 `00A` 前先过最小过滤：

| 问题 | 不成立时 |
| --- | --- |
| 3 秒钩子能讲清吗？ | 不写入 00A，重新生成 |
| 是否有失败条件或“差一点成功”？ | 不写入 00A，重新生成 |
| 广告救助是否自然？ | 标记为“商业化风险”，优先级降低 |
| 1 个月能否做出可测 Demo？ | 标记为“体量风险”，不优先做视频 |

推荐调用语：

```text
从 00_草稿/游戏创意库/01A_题材库.md 随机抽取 1 个题材，
从 00_草稿/游戏创意库/01B_核心动词库.md 随机抽取 1-3 个核心动词，
生成 20 个适合纯 IAA 小游戏验证的玩法创意，
按 00_游戏创意总表.md 的字段格式追加到 00A_待审核创意表.md。
```

### 来源 3：市场扫描 / 用户痛点反推
读最近一周的 `30_市场分析/休闲游戏周度市场扫描/` 和 `30_市场分析/用户痛点周度扫描/`，从「想要 / 抱怨 / 怀念」原话和爆款新机制中反推 → 进 00A。

### 创意公式

```
核心动词 × 题材对象 × 状态变化 × 失败/反转点 × 3 秒视频钩子
```

示例：`收纳 × 化妆包 × 乱→整 × 差一格放不下 × 最后一秒刚好塞满`（IDEA-0001 美妆叠叠乐）

**纪律：**
- 不把题材当玩法。题材只回答「玩家愿不愿意看」，不回答「玩家为什么继续玩」。
- 每个组合必须能写出一个具体的 `失败条件`，否则不进 00A。
- 每个组合必须能写出一个 `差一点通关` 的广告点，否则不进概念卡。
- 第一版概念视频只突出一个主动词。多动词组合留到 Demo 阶段。

## 5. 三张表的流转规则

### 00_游戏创意总表.md
- 只记一行：ID / 创意名 / 赛道 / 一句话玩法 / 当前判断 / 状态 / 下一步 / 来源
- **任何创意只要被记录过，就在这里有一行，包括已否决的**
- 当前判断字段不超过 50 字。详细讨论去概念卡。
- 状态值见表内「状态说明」段。

### 00A_待审核创意表.md
- 字段：临时编号 / 创意名 / 题材 / 核心动词 / 3 秒钩子 / 初筛判断 / 去向
- **审核三问**：
  1. 3 秒钩子能讲清吗？讲不清 → 否决（进 00_总表）
  2. 跟最火同类的核心 3 个不同点能讲出来吗？讲不出 → 否决
  3. 1 个月能出 Demo 吗？做不出 → 否决
- 通过的复制 `02_创意卡模板.md` 新建 `创意名_概念卡.md`，进 00B。
- 长期没动的（卡 1 个月以上）转否决，不准在这无限期养着。

### 00B_已通过创意表.md
- 字段：ID / 创意名 / 通过原因 / 当前阶段 / 当前结论 / 对应文件
- 进入条件：概念卡填完 + 差异化拷问 3 条全过
- 通过本表不等于立项成功，只代表「值得用 AI 视频验证」

## 6. 概念卡填写指南（02 模板 5 段）

复制 `02_创意卡模板.md` → 重命名为 `创意名_概念卡.md`。

| 段 | 怎么填 | 填不出怎么办 |
|----|--------|--------------|
| 1. 一句话玩法 | 玩家做什么 + 为了什么 + 失败会怎样，一句话三件事说完 | 讲不清 → 创意没成型，回 00A |
| 2. 3 秒可懂画面 | 第一眼看到什么 / 角色/物件怎么动 / 最后 1 秒的反转或爽点 | 画不出 → 视频做不出来，回 00A |
| 3. 核心规则 | 玩家输入 / 目标 / 限制 / 失败条件 / 爽点 / 广告点（6 子字段） | 任一不成立 → 玩法不闭环，回 00A |
| 4. 差异化拷问 | 3 条铁律自答：3 不同点 / 美术差异 / 1 月 Demo（详见 §7） | 任一不过 → 进 00_总表标 abandoned |
| 5. 关卡成长预期 | 一句话即可：长线靠什么避免重复？不细展 | — |

**纪律：概念卡保持轻量。视频工艺细节、关卡详细设计、上线运营方案都不写在这。**

---

## 7. 立项铁律（拷问详见 §6 第 4 段）

来自 `40_知识/01_游戏设计/立项铁律_2026-05.md`。任何新方向进入视频阶段前必须自答。

1. **差异化拷问** — 和最火同类比，核心 3 个不同点是什么？答不上来不做。
2. **美术差异化** — 走风格化 / 猎奇 / 反差，避免和大厂卷画质。
3. **速度换容错** — 1 个月内能出 Demo 测试。

> 配套 skill：`/iron-rule-check <方向名>` 可以让 AI 拷问，详见 `90_系统/skills/skill-iron-rule-check.md`。

## 8. 概念视频流程指南（04 模板 7 段）

复制 `04_概念视频流程模板.md` → 重命名为 `创意名_概念视频流程.md`。

7 段：
1. **美术风格定调** — AI 提示词 / 选定参考图 / 用到的 AI 工具
2. **工艺路径** — 风格图 → 关键帧 → UI 抠图 → PS 合成 → 视频生成 → 剪映 → 封面 → 发布
3. **关键帧画面清单** — 视频 A/B/C 各自的画面 01-08（含修改后描述）
4. **UI 提示词** — 主界面 / 子界面 / 抠出 UI（纯白底）
5. **视频脚本** — 视频 1/2/3 操作流 + 字幕
6. **发布文案** — 标题 / 正文 / 号召语 / 标签
7. **复盘** — 软门槛三题（Q1 个人意愿 / Q2 陌生人追问 / Q3 1 月 Demo）

**软门槛 Push / Pivot / Kill**（视频发布后 T+7d 在第 7 段填）：

| 三题结果 | 结论 | 下一步 |
|---------|------|--------|
| 3Y | **Push** | 进 `20_项目/`，走正式立项流程 |
| 2Y1N | **Pivot** | 改概念卡 + 重发新版视频，回到 §8 第 5 段 |
| 1Y2N 或 0Y | **Kill** | 进 00_总表标 abandoned + 在概念卡末尾记录可复用资产 |

**关键纪律：3 个视频 3 个评论 3 天 的数据样本就够判断**。不要硬等 50 评论 100 收藏的硬数字——那种数字门槛在你当前阶段（独立开发、平台粉丝少）大概率永远不到，反而成了「逃避发布」的借口。软门槛主观判断比硬数字更适合你。
