# 荒废花园 7 天切片

> 本切片目标不是做完整游戏，而是验证一句话：  
> **玩家是否觉得“种花是为了复苏花园”，比普通种花收菜更有动力。**

当前结论：荒废花园创意有高意图预约信号，但正式立项前必须先验证核心循环。

---

## 1. 切片总目标

### 1.1 要验证什么

| 问题 | 判断方式 |
| --- | --- |
| 玩家是否看懂核心循环 | 能不能复述“种花、卖花、复苏地块、解锁更多花园” |
| 玩家是否想继续复苏下一块地 | 完成第一块地后，是否主动继续第二轮 |
| 复苏目标是否比普通种花更有动力 | 玩家是否提到“想把花园修好”，而不是只说“种花挺可爱” |

### 1.2 不验证什么

- 不验证完整商业化。
- 不验证长期花种收集。
- 不验证装扮深度。
- 不验证小动物长期养成。
- 不验证发行数据。
- 不验证最终美术品质。

---

## 2. 对关键问题的回答

### 2.1 是否只保留一个核心动作？

不只保留一个动作。  
模拟经营类切片不能只做“播种”或“浇水”，否则测不到经营驱动力。

本切片保留一个**最小完整循环**：

```text
播种
→ 浇水
→ 等待成熟
→ 收获花朵
→ 卖花获得金币
→ 用花朵 + 金币复苏荒废地块
→ 解锁新可种地块
→ 再次种花
```

只保留一个花种、一个订单、一个复苏地块、一个升级项，避免范围失控。

### 2.2 是否需要失败条件？

不需要硬失败，不做 Game Over。

但需要**软阻塞/轻压力**，否则玩家没有目标感。

| 软阻塞 | 作用 |
| --- | --- |
| 花朵不足 | 不能交订单，不能复苏地块 |
| 金币不足 | 不能修复地块或升级工具 |
| 未浇水 | 花朵不继续成长 |
| 订单等待过久 | 订单刷新或奖励降低，不惩罚玩家 |

本切片的“失败”不是输掉，而是：

> 玩家暂时做不了下一步，需要再种一轮花。

### 2.3 明确反馈

每个核心动作必须有立即反馈。

| 玩家动作 | 必须反馈 |
| --- | --- |
| 播种 | 地块变成播种状态，出现种子/小土堆 |
| 浇水 | 水滴效果，成长条开始推进 |
| 等待成熟 | 小芽变花朵，或进度条完成 |
| 收获 | 花朵飞入背包，花朵数量 +1 |
| 卖花 | 花朵减少，金币飞入金币栏，金币增加 |
| 复苏地块 | 花朵/金币消耗，灰地变绿，新地块可种植 |
| 解锁新地块 | 地块从锁定/荒废状态变为可播种状态 |
| 升级水壶 | 浇水次数减少或成长时间缩短 |

### 2.4 本轮不做什么

- 不做多花种。
- 不做花束加工。
- 不做装扮系统。
- 不做小动物完整系统。
- 不做商店。
- 不做广告/IAP。
- 不做好友/社交。
- 不做活动。
- 不做花朵图鉴。
- 不做完整存档系统。
- 不做完整美术，只做灰盒和少量色块/图标反馈。
- 不做大地图，只做完整花园的一角。

### 2.5 外部朋友测试只看哪 3 个信号

只看 3 个信号，不收集泛泛评价。

| 信号 | 通过标准 |
| --- | --- |
| 看懂 | 不解释规则时，玩家能复述“种花、卖钱、复苏地块” |
| 想修 | 完成第一块地后，玩家是否主动想继续修下一块地 |
| 继续玩 | 玩家是否自发多玩一轮，而不是第一轮结束就停 |

不把“画风可爱”“挺治愈”“感觉不错”当通过信号。

## 3. 切片范围

### 3.1 地图范围

只做完整花园的一角。

```text
小地图元素
├─ 3 块初始可种地
├─ 3 块荒废地
├─ 1 个顾客订单牌
├─ 1 个复苏目标牌
├─ 1 个水壶升级按钮
└─ 远处灰化区域占位，不可进入
```

### 3.2 资源范围

| 资源 | 数量 | 用途 |
| --- | --- | --- |
| 白花 | 1 种 | 收获后可卖钱或用于复苏 |
| 金币 | 1 种 | 卖花获得，用于复苏或升级 |
| 可种地块 | 3 起步，最多 6 | 验证扩张反馈 |
| 荒废地块 | 3 块 | 验证复苏动机 |

### 3.3 系统范围

| 系统 | 本轮做到什么程度 |
| --- | --- |
| 种植系统 | 播种、浇水、等待、成熟、收获 |
| 订单系统 | 1 个普通订单：提交白花获得金币 |
| 复苏系统 | 1 种复苏任务：提交白花 + 金币，灰地变绿 |
| 升级系统 | 1 个水壶升级：减少等待或浇水次数 |
| 引导系统 | 简单箭头/文字提示，帮助玩家完成第一轮 |
| UI 系统 | 花朵数量、金币数量、订单需求、复苏需求 |

### 3.4 最小数值假设

| 项目 | 初始假设 |
| --- | --- |
| 白花成长时间 | 10 秒 |
| 播种成本 | 免费 |
| 普通订单 | 2 朵白花 → 10 金币 |
| 复苏地块 | 2 朵白花 + 5 金币 → 1 块荒地变可种 |
| 水壶升级 | 20 金币 → 白花成长时间从 10 秒降到 6 秒 |
| 初始金币 | 0 |
| 初始可种地 | 3 块 |
| 第一轮目标 | 完成 1 次订单 + 复苏 1 块地 |

数值只为验证节奏，Day 6 可以快速调整。

## 4. 验收标准

### 4.1 内部验收

- 可以从 0 开始完成一次完整循环。
- 玩家能看到灰地变绿。
- 复苏后真的多出可种地块。
- 水壶升级能明显缩短等待。
- 单次体验 3-5 分钟内有一次完整反馈。

### 4.2 外部测试通过线

找 3-5 个朋友或高意图玩家测试。

| 指标 | 通过线 |
| --- | --- |
| 看懂 | 至少 3 人能复述核心循环 |
| 想修 | 至少 2 人主动想继续修下一块地 |
| 继续玩 | 至少 2 人完成第二轮种植/订单/复苏 |

### 4.3 否决/重做信号

- 玩家只理解成普通种花收菜。
- 玩家不知道为什么要复苏地块。
- 玩家觉得卖花和复苏没有区别，只是在凑资源。
- 玩家第一块地复苏后没有继续动机。
- 等待时间让玩家明显烦躁。

## 5. 每天任务规划

## Day 1：灰盒地图与交互框架

### 目标

搭出一个可以点击地块的小地图。

### 任务

- 创建小地图场景。
- 放置 3 块可种地、3 块荒废地。
- 做地块状态：空地、已播种、需浇水、成长中、成熟、荒废、复苏后可种。
- 做点击地块的基础交互。
- 做临时 UI：白花数量、金币数量。

### 验收

- 点击可种地能改变状态。
- 荒废地不可直接种植。
- UI 能显示基础资源。

---

## Day 2：种植、浇水、成长、收获

### 目标

完成最小种植循环。

### 任务

- 点击空地播种白花。
- 点击已播种地块浇水。
- 浇水后进入成长倒计时。
- 成熟后显示白花。
- 点击成熟花收获，白花数量 +1。
- 加入基础反馈：颜色变化、进度条、简单飞入动画或数字跳动。

### 验收

- 玩家能连续种 3 块地。
- 10 秒内能看到花朵成熟。
- 收获后白花数量正确增加。

---

## Day 3：订单与金币

### 目标

让花朵可以变成金币。

### 任务

- 添加 1 个订单牌。
- 订单需求：2 朵白花。
- 点击订单提交白花，金币 +10。
- 白花不足时显示“还差 X 朵”的阻塞提示。
- 加入金币飞入或数字跳动反馈。

### 验收

- 玩家能通过卖花获得金币。
- 白花不足时不能交订单。
- 玩家知道“种花可以赚钱”。

---

## Day 4：复苏地块与解锁新地

### 目标

验证核心差异：花朵和金币可以复苏荒废地块。

### 任务

- 添加 1 个复苏目标牌。
- 复苏需求：2 朵白花 + 5 金币。
- 点击荒废地或复苏牌提交资源。
- 资源足够时：灰地变绿，变成可种地块。
- 资源不足时：显示缺少白花或金币。
- 加入明显复苏反馈：颜色变化、绿光、花草出现、可种标记。

### 验收

- 玩家能通过“种花 → 卖花 → 复苏地块”完成第一块地恢复。
- 复苏后的地块可以继续播种。
- 玩家能一眼看出花园变好了。

---

## Day 5：升级项与第一版节奏调试

### 目标

加入一个短期效率目标，让玩家感到经营成长。

### 任务

- 添加水壶升级按钮。
- 成本：20 金币。
- 效果：白花成长时间从 10 秒降到 6 秒，或浇水点击从 2 次降到 1 次。
- 添加简单任务链：
  - 种 1 朵花。
  - 完成 1 个订单。
  - 复苏 1 块地。
  - 升级水壶。
- 调整数值，保证 3-5 分钟内能完成第一轮复苏。

### 验收

- 玩家能理解金币除了复苏，还能升级工具。
- 升级后体感明显变快。
- 不会出现长时间无事可做。

---

## Day 6：反馈补强与测试包准备

### 目标

把灰盒做到“别人能看懂”。

### 任务

- 加入第一轮新手提示。
- 补充关键反馈：
  - 播种反馈。
  - 浇水反馈。
  - 成熟反馈。
  - 收获反馈。
  - 卖花反馈。
  - 复苏反馈。
- 调整 UI 文案，保证目标清晰。
- 做一个 3-5 分钟可完成的测试流程。
- 准备测试记录表。

### 验收

- 不解释规则时，玩家能按提示完成第一轮。
- 第一块地复苏反馈足够明显。
- 没有阻断流程的 bug。

---

## Day 7：朋友测试与决策

### 目标

用 3-5 个外部样本判断是否值得进入 1 个月 Demo。

### 任务

- 找 3-5 个朋友或高意图玩家测试。
- 每人只观察 5-10 分钟。
- 不提前解释玩法，只说“试玩一下这个小花园原型”。
- 记录玩家原话和行为。
- 只修明显 bug，不临时加新功能。
- 测完做结论：继续、重做、暂停。

### 验收

- 完成至少 3 个测试样本。
- 每个样本记录 3 个信号：看懂、想修、继续玩。
- 形成 Day 7 结论。

## 7. 进入 1 个月 Demo 的条件

只有同时满足以下条件，才进入 1 个月 Demo：

- 7 天切片自己玩不厌烦。
- 3-5 个测试者中，大多数能看懂核心循环。
- 至少 2 个测试者主动想继续修下一块地。
- 复苏反馈被认为比普通种花更有目标感。
- 1 个月 Demo 范围能控制在 3-5 种花、2-3 个复苏地块、1 个助手以内。

如果不满足，不进入 Demo，回到玩法设计或归档。
