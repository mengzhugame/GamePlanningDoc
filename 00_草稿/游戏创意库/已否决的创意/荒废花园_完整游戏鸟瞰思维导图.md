# 荒废花园完整游戏鸟瞰思维导图

> 本文件是“完整版本假设”，用于估时、预留地图/UI/资源结构，不等于正式立项承诺。
> 当前决策状态：创意有信号，值得进入 7 天灰盒验证；正式立项仍需通过核心循环验证。

## 0. 一句话定位

一款慢节奏种花收集 + 荒废花园复苏 + 轻自动化照料的治愈经营游戏。

玩家从一小块还能种花的土地开始，通过播种、浇水、除草、等待、收获、售卖和提交花材，逐步复苏整座荒废花园。

## 1. 玩家欲望

### 1.1 目标玩家

- 喜欢种花、收菜、装扮、治愈经营的女性向休闲玩家。
- 喜欢《我的花园世界》、QQ 农场、收纳、装修、治愈放置类内容的玩家。
- 希望每天上线几分钟也能看到进展的轻陪伴玩家。

### 1.2 目标情境

- 睡前、午休、通勤、刷小红书/TapTap 后想找一个轻松小游戏。
- 不想高压操作，不想复杂策略，只想照料、收获、装扮、看变化。
- 喜欢“破败空间被自己一点点变好”的情绪反馈。

### 1.3 未满足欲望

- 普通种花游戏只是在完整花园里种植、收获、装扮，缺少“我把一个地方救回来”的目标感。
- 快节奏经营游戏有扩张爽，但缺少花园题材的治愈和陪伴感。
- 装修/三消花园修复游戏常通过外围玩法推进，玩家不能直接用“种花经营”修复花园。

## 2. 核心玩法

### 2.1 主循环

```text
清理荒废地块
→ 播种
→ 浇水 / 除草 / 等待
→ 收获花朵
→ 花朵分流：售卖赚钱 / 投入地块复苏
→ 获得金币、种子、装扮材料
→ 升级工具 / 解锁地块 / 装扮花园
→ 园丁或小动物提供轻自动化照料
→ 进入下一片荒废区域
```

### 2.2 核心差异

- 花朵双用途：花既是商品，也是复苏资源。
- 地块复苏目标：每片荒废区域都有明确复苏需求和复苏后收益。
- 轻自动化照料：园丁、小动物、设备让照料变省心，但不把游戏做成鲜花工厂。

### 2.3 核心选择

```text
这批花：
├─ 卖给顾客 → 获得金币 → 升级工具 / 买种子 / 解锁设备
└─ 投入复苏 → 修复荒废地块 → 解锁新区域 / 新花种 / 新装扮位
```

### 2.4 设计边界

- 复苏是目标层，不替代种花经营。
- 自动化是减负，不做高速产线。
- 订单是节奏器，不做高压时间管理。
- 装扮是回报，不在首版堆大量家具。

## 3. 完整地图结构

### 3.1 地图总形态

- 中心：初始小花圃。
- 四周：多个待复苏主题区域。
- 外圈：长期扩展区域，可在首版地图中灰化预留。

### 3.2 建议首发完整版本规模

| 模块 | 建议规模 | 备注 |
| --- | --- | --- |
| 花园总区域 | 5-6 个主题区 | 个人制作可控上限，不追求大地图 |
| 可复苏地块 | 30-60 块 | 每块不都需要独立美术，可复用状态模板 |
| 可种植花圃格 | 24-48 格 | 随区域逐步开放 |
| 花种 | 20-40 种 | 首发别拼数百花种 |
| 花束配方 | 20-30 个 | 由花种组合复用 |
| 装扮物 | 30-60 个 | 以主题套装为单位制作 |
| 小动物/园丁 | 3-6 个 | 每个有明确照料功能 |
| 工具/设备 | 6-10 个 | 水壶、铲子、花篮、洒水器、温室等 |

### 3.3 主题区域草案

#### 3.3.1 初始花圃

- 功能：教学、第一朵花、第一次售卖、第一次复苏。
- 花种：白花、蓝花、黄花。
- 复苏目标：从 1 块可种地恢复到 3x3 小花圃。

#### 3.3.2 枯井区

- 功能：水源主题，解锁浇水效率。
- 复苏需求：蓝花、白花、基础金币。
- 复苏收益：浇水次数减少、自动补水、解锁水边花种。

#### 3.3.3 破花亭区

- 功能：花束展示和装扮主题。
- 复苏需求：指定花束、木材/装扮材料。
- 复苏收益：花束展示位、装扮入口、顾客订单加成。

#### 3.3.4 蜜蜂温室区

- 功能：授粉和产量主题。
- 复苏需求：黄色花、香味花、若干订单。
- 复苏收益：小蜜蜂助手、偶尔多产花朵、解锁温室花种。

#### 3.3.5 杂草小路区

- 功能：扩张和路线主题。
- 复苏需求：完成普通订单筹钱 + 提交基础花。
- 复苏收益：连接新区域、解锁更多花圃格。

#### 3.3.6 旧喷泉广场区

- 功能：中后期视觉高潮。
- 复苏需求：多种花束 + 多阶段复苏。
- 复苏收益：中心景观、装扮套装、后续章节入口。

## 4. 系统模块

### 4.1 种植系统

- 播种。
- 浇水。
- 除草。
- 等待成熟。
- 收获。
- 花朵品质或星级：可后置，不进 7 天灰盒。

### 4.2 花朵与花束系统

- 单朵花：基础资源。
- 花束：订单和复苏任务所需资源。
- 花束配方：由 2-4 种花组合。
- 稀有花：后期用于高级复苏和装扮，不在首轮验证中展开。

### 4.3 订单系统

- 普通顾客订单：卖花赚钱。
- 花束订单：需要指定组合。
- 复苏订单/花园愿望：提交花材修复区域。
- 节日订单：后期活动入口。

### 4.4 复苏系统

- 灰地状态。
- 半复苏状态。
- 完全复苏状态。
- 复苏反馈：土地变绿、建筑修复、花朵开放、环境音变化。
- 复苏收益：新花圃、新功能、新装扮位、新订单类型。

### 4.5 装扮系统

- 花园地面。
- 栅栏。
- 花架。
- 路灯。
- 喷泉。
- 花亭。
- 小动物窝。
- 设计原则：装扮服务“花园变好”，不要过早做自由摆放编辑器。

### 4.6 轻自动化系统

- 园丁：小范围自动浇水/除草。
- 小蜜蜂：授粉，偶尔多产。
- 小猫：提醒成熟或订单。
- 小兔：少量采花或收集掉落种子。
- 自动洒水器：固定区域补水。
- 温室：缩短特定花种等待时间。

### 4.7 经济系统

- 金币：订单收入、升级工具、解锁区域。
- 种子：种植消耗，可由商店、订单、复苏奖励获得。
- 装扮材料：复苏、订单、活动奖励。
- 花材：售卖或复苏分流。
- 高级货币：谨慎加入，首版可不做。

### 4.8 引导与任务系统

- 主线任务：复苏下一块区域。
- 日常任务：浇水、收花、完成订单。
- 成就任务：收集花种、完成花束、复苏区域。
- 回流任务：。

## 5. 玩家进程与可玩时长

### 5.1 7 天灰盒目标时长

- 单次体验：3-5 分钟。
- 总体验：15-20 分钟内部自测。
- 目标：验证“种花卖钱/投花复苏”的循环是否有继续动机。

### 5.2 1 个月 Demo 目标时长

- 单次体验：5-10 分钟。
- 可玩总时长：30-60 分钟。
- 内容：3-5 种花、2-3 个复苏地块、1 个助手、基础订单。

### 5.3 首发完整版本目标时长

- 单次体验：5-15 分钟。
- 日常生命周期：14-30 天。
- 可玩总时长：3-8 小时，取决于等待时间和复苏区域数量。
- 目标：够微信小游戏/TapTap 小规模测试，不追求长线内容型大作。

### 5.4 长期更新目标

- 每 2-4 周新增 1 个主题小区域或节日订单。
- 每次新增 3-5 种花、5-10 个装扮物、1 个复苏目标。
- 如果首发数据不成立，不进入长期更新。

## 6. 商业化框架

### 6.1 商业化定位

- 首选：轻 IAA + 少量 IAP。
- 不做强付费卡进度。
- 商业化必须围绕“差一点复苏”和“减少等待/重复操作”。

### 6.2 激励广告点

- 花朵差 1 朵完成订单。
- 复苏材料差一点。
- 等待成熟加速。
- 免费补一次浇水/除草。
- 双倍订单金币。
- 临时召唤小动物帮忙。

### 6.3 IAP 候选

- 去广告。
- 小动物皮肤。
- 主题装扮包。
- 稀有花种礼包。
- 月卡：每日种子/装扮材料。

### 6.4 商业化风险

- 慢节奏治愈玩家对强广告敏感。
- 如果等待时间故意卡人，会破坏治愈感。
- 装扮和花种需要美术内容支撑，个人制作压力大。

### 6.5 商业化验证点

- 玩家是否愿意看广告补“差一点”的资源。
- 玩家是否愿意为小动物/装扮表达偏好。
- 玩家是否在复苏区域前产生明确资源缺口。

## 7. 美术资源量预估

### 7.1 地图与场景

| 资源 | 首发建议量 | 复用策略 |
| --- | --- | --- |
| 主地图母版 | 1 张 | 大地图只开放局部，其他区域灰化 |
| 主题区域 | 5-6 个 | 每区 3 态：荒废、半复苏、复苏 |
| 地块状态 | 4-6 套 | 干枯、可种、已播种、成长中、成熟、复苏 |
| 建筑/景观 | 8-12 个 | 枯井、花亭、温室、喷泉、花架等 |

### 7.2 花与物品

| 资源 | 首发建议量 | 备注 |
| --- | --- | --- |
| 花种图标/植株 | 20-40 种 | 可先用颜色/形态变体降低成本 |
| 花束图标 | 20-30 个 | 由花种组合派生 |
| 种子包 | 10-20 个 | 可与花种共享配色 |
| 装扮物 | 30-60 个 | 按套装做，不做散乱单品 |

### 7.3 角色与动画

| 资源 | 首发建议量 | 动画需求 |
| --- | --- | --- |
| 主角园丁 | 1 个 | 走路、浇水、播种、收获、交付 |
| 顾客 | 6-10 个 | 等待、开心、离开 |
| 小动物/助手 | 3-6 个 | 待机、工作、开心 |
| UI 图标 | 40-80 个 | 花、工具、订单、资源、功能入口 |

### 7.4 个人制作风险

- 最大风险是地图与装扮资源量，不是代码。
- 如果首版就追求大量花种和装扮，会变成内容债。
- 应优先制作可复用模板：地块三态、建筑三态、花种颜色变体、订单卡片模板。

## 8. UI 鸟瞰

### 8.1 主界面

- 顶部：金币、种子、装扮材料、设置。
- 左侧：主线复苏任务。
- 右侧：顾客订单/花园愿望。
- 底部：背包、种子、工具、装扮、助手、商店。
- 地图中：可种植格、荒废地块、复苏目标提示。

### 8.2 预留但不开发的入口

- 装扮。
- 小动物。
- 商店。
- 图鉴。
- 活动。
- 好友/社交。

7 天灰盒可以显示灰色按钮或占位入口，但不实现功能。

## 9. 7 天灰盒只取大图中的一角

### 9.1 只做

- 1 个小地图角落。
- 1 种花。
- 1 个普通订单。
- 1 个复苏地块。
- 1 个升级项。
- 1 个复苏反馈。

### 9.2 不做

- 花朵图鉴。
- 装扮系统。
- 小动物完整系统。
- 商业化。
- 多区域地图。
- 长线数值。
- 完整美术。

### 9.3 灰盒目标

- 验证玩家是否理解花朵双用途。
- 验证玩家是否想继续修下一块地。
- 验证“复苏目标”是否比普通种花收菜更有动力。

## 10. 是否值得继续的闸门

### 10.1 7 天灰盒通过

- 自己连续玩 20 分钟不厌烦。
- 3-5 个玩家能复述“种花、卖钱、复苏地块”。
- 玩家主动想修下一块地。
- 玩家不是只夸画风。

### 10.2 1 个月 Demo 通过

- 10-20 个高意图玩家能完成首个区域。
- 玩家愿意第二天回来继续收花/复苏。
- 至少有玩家对小动物、装扮或下一片区域产生期待。
- 概念视频能让玩家理解“种花经营 + 花园复苏”。

### 10.3 否决条件

- 玩家只理解成普通种花收菜。
- 玩家觉得复苏只是换皮装修。
- 花朵双用途造成困惑或资源焦虑。
- 美术资源量明显超出个人制作能力。
- 1 个月 Demo 仍然拆不出可控范围。

## 11. 当前最大未决问题

- 花朵双用途会增加动力，还是只会增加资源压力？
- 复苏区域的收益是否必须功能化，还是纯视觉装扮也足够？
- 慢节奏等待和小游戏短会话是否冲突？
- 小动物是核心吸引点，还是后期锦上添花？
- 首发完整版本到底适合 IAA、IAP，还是只适合作为 TapTap/独立小体量产品？
