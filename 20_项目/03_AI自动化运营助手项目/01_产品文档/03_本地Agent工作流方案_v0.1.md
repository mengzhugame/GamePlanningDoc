# 本地 Agent 工作流方案 v0.1

## 一句话结论

v0 不做网页 SaaS，不接 API，不做服务器和数据库。

v0 先做知识库内的本地 AI 运营 Agent 工作流，用 Codex / Claude Code / ChatGPT 等包月高能力模型执行，目标是让用户先用最高质量模型跑通真实账号运营。

## 为什么从 SaaS 改成本地 Agent

当前第一目标不是商业化卖工具，而是：

- 帮用户自己的账号持续产出高质量内容。
- 用最高智商模型做选题、差异化、文案和复盘。
- 避免为了省 API 成本而牺牲内容质量。
- 先验证工作流是否真的能带来发布、互动、私信、咨询或用户池。

如果一开始做 SaaS，会过早引入：

- API 成本。
- 模型质量和价格平衡。
- 服务器、域名、部署。
- 用户计费和额度。
- 数据库和权限。
- 商用合规与售后。

这些都不是当前最关键的问题。

## 推荐目录位置

本地 Agent 工作流放在：

```text
20_项目/03_AI自动化运营助手项目/09_本地Agent工作流/
```

不建议新建到 `D:\Project\AIOpsAgent\`，原因：

- 独立目录无法天然读取知识库里的项目经验、个人 IP 方法论、商业规划和用户画像。
- 如果复制个人信息到外部目录，后续会出现两份真相，难以同步。
- 放在当前项目目录内，可以让 Obsidian、Codex、Claude Code 都按知识库规则读取。

## 知识同步原则

本地 Agent 工作流不复制完整个人信息，不把运营档案变成第二个长期知识库。

采用：

```text
运营档案 = 当前可用摘要 + source_of_truth 来源链接 + last_synced 时间
```

规则：

1. 永久事实仍以 `40_知识/`、`70_用户信息/`、`90_系统/`、`20_项目/` 为准。
2. 运营档案只保留为了发内容需要的当前摘要。
3. 每个档案必须写明来源链接。
4. 内容生成前，Agent 先读运营档案；涉及具体项目或经历时，再按链接读取源文件。
5. 如果运营中发现新的长期事实，先记录到流水或项目运营数据，不直接写入永久知识。
6. 需要长期沉淀时，再按知识库流程蒸馏到 `40_知识/` 或 `70_用户信息/`。

## v0 工作流闭环

```text
选择运营档案
-> 读取档案和必要来源
-> 生成本周选题
-> 用户选择选题
-> 生成内容包
-> 发布前审核
-> 用户手动发布
-> 用户填写发布数据
-> AI 复盘
-> 更新内容状态和下一条建议
```

## v0 不做

- 不接 OpenAI / Claude / DeepSeek API。
- 不做网页 SaaS。
- 不做数据库。
- 不做服务器。
- 不做自动发布。
- 不做自动评论。
- 不做自动私信。
- 不做平台自动爬取。
- 不做图片上传和 AI 读图。
- 不做视频解析。

## v0 做什么

- 本地运营档案。
- 本地 skills。
- 本地内容文件夹。
- 本地模板。
- 发布数据手动记录。
- 周复盘。
- Codex / Claude Code 执行工作流。

## 后续升级路线

| 阶段 | 形态 | 过闸标准 |
| --- | --- | --- |
| v0 | 本地 Agent 工作流 | 自己连续发布 8 条内容，完成至少 2 次复盘 |
| v0.5 | 本地脚本 / 简易 UI | 工作流有效，但文件操作开始繁琐 |
| v1 | 本地网页工具 | 自己和少量朋友都能使用 |
| v2 | SaaS + API + 计费 | 已经证明有人愿意为这套工作流付费 |

## 与原 PRD 的关系

原 PRD 仍作为未来 SaaS 产品定义保留。

当前执行优先级调整为：

1. 先做本地 Agent 工作流。
2. 用工作流验证真实运营效果。
3. 再决定是否产品化为网页或 SaaS。
