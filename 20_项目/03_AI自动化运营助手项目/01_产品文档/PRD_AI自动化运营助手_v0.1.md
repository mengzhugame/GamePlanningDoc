# AI 自动化运营助手 PRD v0.1

> 2026-06-03 更新：本 PRD 作为未来网页 SaaS 产品定义保留。当前 v0 执行路线已调整为“知识库内本地 Agent 工作流”，见 [[03_本地Agent工作流方案_v0.1]]。

## 1. 产品背景

过去一年，用户连续制作并上线了《美妆叠叠乐》和《光与朽》两款小游戏。两款产品都证明了用户具备独立制作、技术实现和项目推进能力，但也暴露出一个核心问题：产品本身不是唯一关键，运营、推广、获客和用户池同样关键。

无论未来继续做小游戏、AI 应用、技术美术接单、AI 工作流工具，还是旅行 IP 和旅行英语方向，都需要通过互联网持续触达陌生人，建立信任，并把公域流量转化为关注、评论、私信、测试者、咨询、预约、付费或合作机会。

过去的做法是临时把需求发给 AI，让 AI 生成一篇推广文案，再手动复制发布。这种方式很快，但无法形成长期系统：

- 每次都从零开始写 prompt。
- AI 不记得账号人设、服务边界和历史内容。
- 内容和商业目标容易脱节。
- 发布后没有数据记录和复盘。
- 无法判断哪类内容真的更好。
- 线索、私信和反馈没有进入持续跟进流程。

因此，本项目既是用户学习 AI Agent 和自动化工作流的第一个实战项目，也是未来可能开放给外部用户收费使用的产品雏形。

## 2. 产品定位

AI 自动化运营助手是一个面向个人创业者、独立开发者、接单者和内容创作者的网页 SaaS 应用。

一句话定义：

> 围绕一个或多个长期账号档案，帮助用户持续完成选题、内容包生成、发布数据记录、AI 复盘和下一轮内容迭代。

它不是：

- 一次性 AI 文案生成器。
- 随手帮用户写任何硬广的工具。
- 小红书自动评论、自动私信、养号或截流工具。
- 企业级投放数据平台。
- 矩阵号批量铺内容系统。

它要做的是：

- 帮用户想清楚自己是谁、面向谁、卖什么、如何建立信任。
- 把真实经历、专业能力、用户痛点和商业承接口组织成可信内容。
- 根据历史发布数据判断内容是否更接近目标。
- 让内容运营从临时动作变成可复盘、可迭代的长期工作流。

## 3. 目标用户

### 3.1 v0 首个用户

wangyongcheng 自己。

主要使用场景：

- 小红书独立开发者获客线。
- 记录小游戏失败复盘、AI 工具制作、接单能力、技术美术能力。
- 为未来小游戏、AI 应用、技术咨询、旅行 IP 获客。

### 3.2 后续可扩展用户

- 独立开发者：做游戏、App、AI 工具、开源工具或插件。
- 自由职业者 / 接单者：Unity、TA、Shader、程序、美术、AI 应用开发。
- 小团队创业者：需要持续内容获客，但没有专职运营。
- 个人 IP 创作者：旅行、课程、咨询、工具、服务等方向。
- 普通创业大众：想通过小红书、抖音、视频号、B 站等平台建立账号和用户池。

### 3.3 暂不服务用户

- 需要批量铺号的 MCN。
- 以自动评论、自动私信、截流为目标的用户。
- 大企业品牌投放团队。
- 只想随机写一条租房、卖货、招聘、清仓等脱离账号定位内容的用户。

## 4. 核心问题

产品要解决的不是“AI 能不能写一篇文案”，而是“用户能不能长期运营一个有明确人设和目标的账号”。

核心问题包括：

1. 用户不知道今天发什么。
2. 用户不知道内容是否符合账号人设。
3. 用户不知道内容是否服务当前目标。
4. 用户没有稳定的选题、生成、发布、记录、复盘流程。
5. 用户发布后只看感觉，没有数据对比。
6. 用户不知道什么时候该发信任内容，什么时候该发转化内容。
7. 用户有评论、私信、咨询后，没有形成线索跟进机制。
8. 用户没有把爆款竞品拆成可学习的结构。
9. 用户容易把主账号发乱，导致账号标签和人设被污染。

## 5. 产品原则

### 5.1 长期账号优先

每条内容必须绑定一个运营档案。运营档案记录人设、业务、目标用户、内容风格、禁忌表达、历史内容和数据表现。

v0 不提供“脱离账号档案的随机硬广生成主路径”。

### 5.2 内容不是广告，内容是信任资产

产品不鼓励直接生成“我要接单”“我要卖课”“我要招募”的硬广。

产品鼓励生成：

- 真实经历。
- 失败复盘。
- 专业解决方案。
- 项目过程。
- 用户痛点拆解。
- 服务边界说明。
- 产品制作记录。
- 有事实支撑的转化内容。

### 5.3 转化内容可以做，但必须融入账号策略

产品支持获客、咨询、招募、报名、预约、报价等商业目标。

但转化内容必须基于：

- 当前运营档案。
- 已有真实经历。
- 用户痛点。
- 明确服务边界。
- 清晰承接口。

不支持突兀硬广污染账号人设。

### 5.4 来源标注和事实核查

AI 生成内容必须基于：

- 运营档案。
- 用户本次输入。
- 用户手动粘贴的竞品参考。
- 历史内容和历史数据。

输出时必须区分：

- 用户已提供事实。
- AI 基于上下文的推断。
- 发布前需要用户核实的内容。

### 5.5 人工审核发布

v0 不做自动发布。用户必须人工审核事实、语气、图片、封面、平台规则和商业承诺后再发布。

### 5.6 数据驱动迭代

产品不承诺爆款。产品目标是让用户持续提高内容质量、账号一致性和复盘能力。

### 6.1 第一条验证路径

- 主平台：小红书。

- 使用者：用户自己。
- 语言：中文。
- 支付：v0 暂不接入。

### 6.2 v0 支持的平台选项

页面上允许选择：

- 小红书。
- B 站。
- 抖音。
- 微信视频号。
- TikTok。
- YouTube Shorts。

但 v0 只有小红书为完整支持，其它平台为实验支持或基础提示词适配。

### 6.3 v0 支持的账号线模板

1. 独立开发者获客线。
2. 接单服务线。
3. AI 工具创业线。
4. 旅行 IP 线。
5. 自定义账号线。

模板只是预填字段，用户可以编辑。

### 6.4 v0 支持的素材输入

- 文字描述。
- 项目经历。
- 一段原始草稿。
- 可用图片或视频素材的文字说明。
- 手动粘贴竞品参考。

v0 不支持图片上传、AI 读图、视频上传和视频解析。图片和视频相关需求只允许用户用文字描述素材内容。

后续版本再考虑图片上传、图片预览、AI 读图、视频抽帧、转录和视频解析。

## 7. 非目标范围

v0 不做：

- 自动发布。
- 自动评论。
- 自动私信。
- 养号。
- 矩阵号管理。
- 自动截流。
- 自动抓取全网爆款。
- 图片上传和 AI 读图。
- 视频上传和视频解析。
- 完整视频生成。
- 复杂 CRM。
- 多人团队权限。
- 订阅支付。
- 企业级投放数据分析。

## 8. 用户流程

### 8.1 创建运营档案

用户通过模板向导创建一个运营档案。

流程：

```text
选择账号线模板
-> 填写人设、业务、目标用户、内容风格、禁忌表达、承接口
-> 保存档案
-> 进入选题生成
```

一个用户可以创建多个运营档案。每个档案独立记录内容历史和数据表现，避免不同路线互相污染。

### 8.2 生成选题

流程：

```text
选择运营档案
-> 选择平台
-> 选择本次内容目标
-> 输入素材或原始想法
-> 粘贴竞品参考
-> AI 生成 5-10 个选题
-> 用户选择一个选题
```

### 8.3 生成内容包

流程：

```text
选择一个选题
-> AI 生成完整内容包
-> 用户审核事实和语气
-> 标记为待发布
```

### 8.4 人工发布并记录数据

流程：

```text
用户手动发布到平台
-> 回到产品填写发布时间、浏览、点赞、收藏、评论、私信、关注、有效线索等数据
-> 系统按 24 小时、72 小时、7 天提醒补充数据
```

### 8.5 AI 复盘

流程：

```text
用户填写发布数据
-> AI 根据账号目标和历史数据复盘
-> 输出表现判断、原因分析、保留项、避免项、下一条选题建议
```

## 9. 页面模块

### 9.1 工作台

用途：

- 查看所有运营档案。
- 查看最近生成内容。
- 查看待发布内容。
- 查看待补数据内容。
- 查看复盘提醒。
- 查看下一步建议。

### 9.2 运营档案页

用途：

- 创建多个运营档案。
- 编辑账号人设、业务、目标用户、服务边界、禁忌表达。
- 查看该档案下的历史内容和数据概览。

### 9.3 选题生成页

用途：

- 输入本次内容目标和素材。
- 粘贴竞品参考。
- 生成 5-10 个候选选题。
- 对每个选题给出推荐理由和风险提示。

### 9.4 内容包生成页

用途：

- 展开选中的选题。
- 生成标题、正文、脚本、封面文案、素材清单、标签、私信话术、检查清单。
- 标注事实来源和待核查项。

### 9.5 内容库页

用途：

- 查看所有生成过的内容。
- 按档案、平台、状态、目标筛选。
- 标记状态：选题、草稿、待发布、已发布、已复盘、归档。

### 9.6 发布数据页

用途：

- 手动填写发布数据。
- 记录发布时间、平台、链接、浏览、点赞、收藏、评论、私信、关注、有效线索等。
- 记录用户自己的主观判断。

### 9.7 AI 复盘页

用途：

- 根据发布数据、目标和历史表现生成复盘。
- 判断内容是否达成目标。
- 生成下一轮选题建议。

## 10. 运营档案设计

运营档案是产品的核心记忆单元。

字段建议：

| 字段 | 说明 |
| --- | --- |
| 档案名称 | 例如：独立开发者获客线、旅行 IP 线 |
| 账号线类型 | 模板类型或自定义 |
| 主平台 | 小红书 / B 站 / 抖音 / 视频号等 |
| 当前阶段目标 | 曝光、涨粉、建立信任、获客、测试反馈、转化 |
| 我是谁 | 用户身份、人设、真实经历 |
| 我卖什么 | 产品、服务、咨询、课程、工具、接包能力 |
| 目标用户 | 谁会看，谁可能付费 |
| 用户痛点 | 目标用户遇到的问题 |
| 代表经历 | 项目、案例、失败、作品、数据 |
| 内容风格 | 真实复盘、干货、故事、避坑、展示交付能力等 |
| 禁忌表达 | 不装成功学、不夸大收益、不编造经历、不硬广等 |
| 承接口 | 私信关键词、表单、预约、报价单、社群、试玩链接 |
| 账号污染提醒 | 哪类内容不适合发到该账号 |

## 11. 选题生成流程

选题生成必须基于：

- 当前运营档案。
- 平台。
- 本次内容目标。
- 用户输入素材。
- 竞品参考。
- 历史内容和历史数据。

每次生成 5-10 个选题。

每个选题输出：

| 字段 | 说明 |
| --- | --- |
| 选题标题 | 一句话概括 |
| 推荐平台 | 小红书 / B 站 / 抖音等 |
| 内容形式 | 图文 / 视频 / 长文 / 口播 |
| 核心事件 | 这条内容讲什么 |
| 核心卖点 | 为什么用户会看 |
| 对应目标 | 曝光 / 涨粉 / 建立信任 / 获客 / 测试反馈 / 转化 |
| 需要素材 | 截图、照片、项目数据、经历、案例等 |
| 来源依据 | 来自档案、输入、竞品、历史数据的哪一部分 |
| 风险提示 | 是否像硬广、是否事实不足、是否容易夸大 |
| 推荐分 | 人设匹配、目标匹配、制作成本、潜在收益 |

## 12. 内容包生成流程

用户选择一个选题后，AI 生成完整内容包。

默认输出：

1. 3-5 个标题。
2. 1 个推荐标题。
3. 小红书图文正文。
4. 可选短视频脚本。
5. 封面文案。
6. 素材清单。
7. 标签。
8. 私信 3 轮话术。
9. 发布前检查清单。
10. 发布后数据记录表。
11. 事实核查清单。

评论引导默认不输出。只有当内容目标是调研、投票、招募反馈、招募测试者时，才生成互动问题。

## 13. 竞品参考输入

v0 只支持手动粘贴竞品参考。

用户可以输入：

- 竞品标题。
- 竞品正文。
- 竞品链接。
- 截图说明。
- 爆款原因的个人判断。
- 浏览、点赞、收藏、评论等公开数据。

AI 输出：

- 竞品内容结构。
- 标题钩子。
- 情绪或利益点。
- 素材类型。
- 转化方式。
- 可借鉴点。
- 不建议模仿点。

后续版本可升级为自动竞品数据搜集 Agent。

## 14. 发布数据记录

用户手动填写发布数据，后台数据库保存。

基础字段：

| 字段 | 说明 |
| --- | --- |
| 发布平台 | 小红书 / B 站 / 抖音等 |
| 发布链接 | 用户手动填写 |
| 发布时间 | 发布时间 |
| 浏览 / 播放 | 平台曝光数据 |
| 点赞 | 点赞数 |
| 收藏 | 收藏数 |
| 评论 | 评论数 |
| 转发 | 转发数 |
| 关注增长 | 该内容带来的关注 |
| 私信 / 咨询 | 私信或咨询数量 |
| 有效线索 | 明确表达需求的人 |
| 表单 / 预约 / 试玩 | 承接口数据 |
| 成交 / 付费 | 如果有则记录 |
| 用户主观判断 | 用户对内容效果的感受 |

不同账号目标使用不同指标优先级。

## 15. AI 复盘逻辑

AI 复盘必须先判断内容目标。

目标类型：

| 目标 | 核心指标 |
| --- | --- |
| 曝光 | 浏览 / 播放、点赞、转发 |
| 涨粉 | 关注增长、互动率 |
| 建立信任 | 收藏、长评论、私信提问、复访 |
| 获客 | 私信、咨询、有效线索、预约 |
| 测试反馈 | 试玩、报名、评论反馈、进群、表单 |
| 转化 | 付费、订金、成交、合作意向 |

复盘输出：

- 当前目标下表现如何。
- 相比历史同目标内容表现如何。
- 标题是否有效。
- 内容是否符合账号人设。
- 是否有真实素材支撑。
- 是否过度营销。
- 是否产生有效反馈。
- 哪些内容元素应保留。
- 哪些内容元素应避免。
- 下一条适合发信任内容、曝光内容、反馈内容还是转化内容。
- 推荐下一条选题。

## 16. 内容状态机

内容状态：

| 状态 | 含义 |
| --- | --- |
| idea | 选题 |
| draft | 草稿 |
| ready | 待发布 |
| published | 已发布 |
| reviewed | 已复盘 |
| archived | 归档 |

状态流转：

```text
idea -> draft -> ready -> published -> reviewed -> archived
```

允许用户手动归档任意状态内容。

## 17. 复盘提醒

v0 做站内提醒。

默认提醒点：

- 发布后 24 小时：记录初始数据。
- 发布后 72 小时：记录稳定数据。
- 发布后 7 天：做内容复盘。

后续版本可增加：

- 邮件提醒。
- 微信提醒。
- 短信提醒。
- 日历提醒。
- 自动从平台同步数据。

## 18. 数据对象

核心数据对象：

| 对象 | 说明 |

| Reminder | 复盘提醒 |

## 19. Agent 职责拆分

v0 不一定实现为多个独立 Agent，但产品职责按 Agent 拆分，方便后续扩展。

| Agent | 职责 |
| --- | --- |
| 档案记忆 Agent | 读取运营档案，保证内容符合人设和目标 |
| 选题 Agent | 根据档案、素材、平台、目标和历史数据生成选题 |
| 竞品分析 Agent | 分析用户手动粘贴的竞品内容结构 |
| 内容包 Agent | 生成标题、正文、脚本、封面文案、素材清单、标签和私信话术 |
| 审核 Agent | 检查夸大、编造、语气、人设偏移、承接口是否清楚 |
| 复盘 Agent | 根据发布数据判断效果，提出下一轮建议 |
| 提醒 Agent | 根据发布时间和状态生成复盘提醒 |

## 20. 版本路线

### v0：自用验证版

目标：跑通完整闭环。

范围：

- 登录和用户表。
- 多运营档案。
- 模板向导。
- 小红书完整支持。
- 中文内容生成。
- 手动竞品参考。
- 文字和图片素材输入。
- 两步式：选题 -> 内容包。
- 手动发布数据记录。
- AI 复盘。
- 站内复盘提醒。

### v2：增强运营系统

可能增加：

- 更完整 CRM。
- 自动提醒和半自动跟进。

## 21. 成功标准

v0 自用阶段建议验证 4 周。

最低成功标准：

- 创建至少 2 个运营档案。
- 生成至少 20 个选题。
- 发布至少 8 条内容。
- 完成至少 4 次发布数据记录。
- 完成至少 2 次 AI 复盘。
- 用户主观感觉：准备一条内容的时间明显下降。
- 至少有 1 次内容建议影响下一条发布。

更高成功标准：

- 小红书内容带来私信、评论、关注增长、测试者、咨询或合作线索。
- AI 复盘能指出真实可执行的改进方向。
- 用户愿意继续把它作为长期运营工作台使用。
