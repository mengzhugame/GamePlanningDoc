# 功能拆解与页面模块 v0.1

> 2026-06-03 更新：本文件作为未来网页 / SaaS 版本的页面拆解保留。当前 v0 执行路线已调整为“知识库内本地 Agent 工作流”，见 [[03_本地Agent工作流方案_v0.1]]。

## 1. 文档目的

本文档承接 `PRD_AI自动化运营助手_v0.1.md`，用于明确 v0 版本需要实现的页面、模块、用户操作、状态流转和功能优先级。

v0 的目标不是做完整商业化 SaaS，而是先验证自用闭环：

```text
运营档案
-> 选题生成
-> 内容包生成
-> 人工发布
-> 手动数据记录
-> AI 复盘
-> 下一条内容建议
```

## 2. v0 页面总览

v0 做 5 个核心页面。

| 页面 | 核心用途 | v0 必做 |
| --- | --- | --- |
| 工作台 | 看本周目标、待办、提醒和下一步动作 | 是 |
| 运营档案 | 创建和维护长期账号人设与运营目标 | 是 |
| 内容工作流 | 输入素材、竞品洞察、生成选题和内容包 | 是 |
| 内容库 | 管理历史内容、状态流转和复用 | 是 |
| 发布与复盘 | 手动记录发布数据，触发 AI 复盘 | 是 |

登录作为基础能力存在，但不作为内容页面单独展开。

## 3. 页面一：工作台

### 3.1 页面目标

工作台负责告诉用户“现在该做什么”。

它不是数据大屏，也不是营销看板。v0 只做轻量运营指挥盘。

### 3.2 页面模块

| 模块 | 内容 |
| --- | --- |
| 本周目标 | 本周计划发布数、本周计划复盘数、本周重点目标 |
| 当前进度 | 已发布数、已复盘数、待发布数、待补数据数 |
| 运营档案卡片 | 档案名称、账号阶段、当前目标、最近内容、下一步建议 |
| 待办区 | 待生成选题、待发布内容、待填写数据、复盘提醒 |
| 最近内容 | 最近生成或发布的 5-10 条内容 |
| 快捷入口 | 创建运营档案、生成新内容、填写发布数据 |

### 3.3 本周目标

v0 的本周目标只做 3 个字段：

| 字段 | 示例 |
| --- | --- |
| 本周计划发布数 | 2 条 |
| 本周计划复盘数 | 1 条 |
| 本周重点目标 | 建立信任 / 获客 / 测试反馈 |

工作台示例：

```text
本周目标：发布 2 条，复盘 1 条
当前进度：已发布 1 条，待复盘 1 条
下一步：补充 6 月 2 日发布内容的 24h 数据
```

### 3.4 用户操作

- 点击档案进入运营档案页。
- 点击“生成新内容”进入内容工作流页。
- 点击待办进入对应内容或复盘页。
- 点击最近内容进入内容详情。
- 设置或修改本周目标。

### 3.5 v0 验收标准

- 没有档案时，首页引导创建第一个运营档案。
- 有档案时，首页显示本周目标和下一步动作。
- 有待复盘内容时，首页优先显示复盘提醒。
- 工作台能进入内容工作流、内容库和发布复盘页面。

## 4. 页面二：运营档案

### 4.1 页面目标

运营档案是产品的长期记忆中心。

每条内容必须绑定一个运营档案，防止账号人设混乱和内容目标漂移。

### 4.2 页面模块

| 模块 | 内容 |
| --- | --- |
| 档案列表 | 显示用户创建的所有运营档案 |
| 创建档案 | 模板向导或自定义创建 |
| 档案编辑 | 编辑人设、目标用户、承接口、禁忌表达等 |
| 账号阶段 | 初始化期、冷启动期、定位校准期、建立信任期、获客转化期、稳定运营期 |
| 档案概览 | 内容数量、已发布数量、已复盘数量、最近表现摘要 |
| 默认档案 | 设置一个默认运营档案 |

### 4.3 模板向导

v0 提供 5 个模板：

| 模板 | 适合场景 |
| --- | --- |
| 独立开发者获客线 | 游戏、App、AI 工具、个人项目复盘、测试者招募 |
| 接单服务线 | Unity、TA、Shader、小游戏 Demo、AI 应用开发 |
| AI 工具创业线 | 产品制作记录、试用招募、模板和工具验证 |
| 旅行 IP 线 | 旅行内容、旅行英语、路线咨询、海外服务获客 |
| 自定义 | 用户自行填写 |

模板只负责预填字段，用户必须能编辑。

### 4.4 档案字段

| 字段 | 说明 |
| --- | --- |
| 档案名称 | 例如：独立开发者获客线 |
| 主平台 | 默认小红书，可选 B 站、抖音、视频号等 |
| 账号阶段 | 用户手动选择，AI 可给建议 |
| 当前阶段目标 | 曝光、涨粉、建立信任、获客、测试反馈、转化 |
| 我是谁 | 身份、人设、真实经历 |
| 我提供什么 | 产品、服务、咨询、课程、工具、接包能力 |
| 目标用户 | 谁会看，谁可能付费 |
| 用户痛点 | 目标用户遇到的问题 |
| 代表经历 | 项目、案例、失败、作品、数据 |
| 内容风格 | 真实复盘、干货、故事、避坑、展示交付能力 |
| 禁忌表达 | 不装成功学、不夸大、不编造、不硬广 |
| 承接口 | 私信关键词、表单、预约、报价单、社群、试玩链接 |
| 账号污染提醒 | 哪类内容不适合发到该账号 |

### 4.5 账号阶段规则

账号阶段采用“用户手动选择 + AI 建议调整”的方式。v0 不自动修改阶段。

| 阶段 | 参考判断 | 运营重点 |
| --- | --- | --- |
| 初始化期 | 刚建档案，没发或少于 3 条 | 完成人设、承接口、选题池 |
| 冷启动期 | 已发少量内容，但还不知道哪类有效 | 保持垂直，测试 2-3 类内容，不急着转化 |
| 定位校准期 | 已有约 10 条内容，有初步数据波动 | 找出收藏、评论、私信更好的内容结构 |
| 建立信任期 | 有稳定互动、收藏、评论或关注增长 | 做系列内容、案例、复盘、专业文章 |
| 获客转化期 | 开始持续出现私信、咨询、测试者或合作意向 | 加入服务边界、预约、表单、报价说明 |
| 稳定运营期 | 发布、数据、复盘、线索都有固定节奏 | 扩平台、做模板、考虑付费产品或小预算投放 |

### 4.6 冷启动与投流原则

v0 不默认建议用户充值投流。

冷启动阶段优先建议自然内容验证：

- 先发 10-20 条垂直内容。
- 测试真实用户对哪些选题有反应。
- 优先看收藏、评论、关注、私信和有效反馈。
- 不用投流掩盖内容问题。

后续版本可以加入“投流前检查”，但只有当自然内容已有正反馈，且账号档案、承接口、私信话术、服务边界准备好时，才建议小预算官方投放测试。

### 4.7 用户操作

- 创建档案。
- 编辑档案。
- 删除或归档档案。
- 设置默认档案。
- 从档案进入内容工作流。
- 查看 AI 阶段建议。

### 4.8 v0 验收标准

- 用户至少能创建 1 个档案。
- 一个用户可以创建多个档案。
- 创建内容时必须选择档案。
- 模板能预填默认字段。
- 用户能编辑所有关键字段。
- 账号阶段可以手动选择。

## 5. 页面三：内容工作流

### 5.1 页面目标

内容工作流页是 v0 最核心页面，用于完成：

```text
输入目标与素材
-> 竞品洞察与差异化
-> 生成并选择选题
-> 生成内容包
```

### 5.2 步骤结构

| 步骤 | 名称 | 是否可跳过 |
| --- | --- | --- |
| Step 1 | 输入目标与素材 | 否 |
| Step 2 | 竞品洞察与差异化 | 可跳过 |
| Step 3 | 生成并选择选题 | 否 |
| Step 4 | 生成内容包 | 否 |

### 5.3 Step 1：输入目标与素材

输入字段：

| 字段 | 说明 |
| --- | --- |
| 运营档案 | 必选 |
| 平台 | 默认小红书 |
| 内容目标 | 曝光、涨粉、建立信任、获客、测试反馈、转化 |
| 本次素材 / 想法 | 用户输入文字 |
| 真实经历 / 项目背景 | 可选补充 |
| 可用图片或视频素材说明 | 只写文字说明，不上传文件 |
| 限制条件 | 不夸大、不编造、事实待核实、不要营销号等 |
| 竞品参考 | 手动粘贴标题、正文、链接、截图文字描述或数据 |

v0 不做图片上传、AI 读图、视频上传和视频解析。

用户可以用文字描述素材，例如：

```text
我有 3 张图：第一张是 Unity 工程界面，第二张是游戏实机画面，第三张是发行反馈截图。
```

### 5.4 Step 2：竞品洞察与差异化

竞品洞察可以跳过。

如果用户提供竞品参考，AI 输出：

| 输出 | 说明 |
| --- | --- |
| 竞品核心点 | 同类内容主要讲什么 |
| 常见标题结构 | 竞品如何写标题 |
| 常见内容角度 | 竞品从哪些角度切入 |
| 建立信任方式 | 竞品靠案例、数据、经历还是结果建立信任 |
| 已经很卷的点 | 不建议直接模仿的内容 |
| 可切入差异化 | 当前账号可以怎么做不同 |
| 本次内容建议角度 | 本次更适合走哪个方向 |
| 风险提醒 | 是否容易像硬广、事实不足或过度承诺 |

如果用户跳过竞品洞察，系统应标注：

```text
本次选题未使用竞品参考，仅基于运营档案、用户输入和历史数据生成。
```

### 5.5 Step 3：生成并选择选题

每次生成 5-10 个选题。

每个选题卡包含：

| 字段 | 说明 |
| --- | --- |
| 选题标题 | 一句话概括 |
| 内容形式 | 图文 / 视频脚本 / 长文 / 口播 |
| 对应目标 | 曝光、涨粉、建立信任、获客、测试反馈、转化 |
| 需要素材 | 截图、项目经历、数据、照片、视频等 |
| 来源依据 | 来自档案、用户输入、竞品洞察或历史数据 |
| 风险提示 | 是否像硬广、事实不足、容易夸大 |
| 推荐分 | 人设匹配、目标匹配、制作成本、潜在收益 |

用户必须选择一个选题后，才能生成内容包。

### 5.6 Step 4：生成内容包

内容包输出：

| 模块 | 内容 |
| --- | --- |
| 标题备选 | 3-5 个标题 |
| 推荐标题 | AI 推荐一个标题 |
| 正文 / 脚本 | 小红书正文或短视频脚本 |
| 封面文案 | 适合封面的大字文案 |
| 素材清单 | 需要哪些截图、照片、视频或证明材料 |
| 标签 | 平台标签 |
| 私信话术 | 3 轮私信回复话术 |
| 发布前检查清单 | 事实、语气、封面、承接口、平台规则 |
| 事实核查清单 | 已提供事实、AI 推断、待核实内容 |

评论引导默认不输出。只有当内容目标是调研、投票、招募反馈、招募测试者时，才生成互动问题。

### 5.7 一键复制

内容包中每个区块都支持单独复制：

- 复制推荐标题。
- 复制正文。
- 复制视频脚本。
- 复制封面文案。
- 复制标签。
- 复制私信话术。
- 复制发布检查清单。

可选增强：复制完整发布包。

### 5.8 用户操作

- 填写输入。
- 手动粘贴竞品参考。
- 跳过竞品洞察。
- 生成竞品洞察。
- 生成选题。
- 选择选题。
- 生成内容包。
- 重新生成。
- 一键复制。
- 保存草稿。
- 标记为待发布。

### 5.9 v0 验收标准

- 没有运营档案时不能生成内容，提示先创建档案。
- 用户可以跳过竞品洞察直接生成选题。
- 选题必须显示来源依据。
- 内容包必须显示事实核查清单。
- 内容包能保存到内容库。
- 每个内容区块都能单独复制。

## 6. 页面四：内容库

### 6.1 页面目标

内容库负责管理所有内容和状态流转。

### 6.2 页面模块

| 模块 | 内容 |
| --- | --- |
| 筛选栏 | 运营档案、平台、内容目标、状态、日期 |
| 内容列表 | 标题、档案、平台、目标、状态、创建时间、是否发布、是否复盘 |
| 内容详情 | 选题、内容包、竞品洞察摘要、事实核查清单、发布数据摘要、复盘摘要 |
| 状态操作 | 标记待发布、标记已发布、进入复盘、归档 |

### 6.3 内容状态

| 状态 | 含义 |
| --- | --- |
| idea | 选题 |
| draft | 草稿 |
| ready | 待发布 |
| published | 已发布 |
| reviewed | 已复盘 |
| archived | 归档 |

状态流转：

```text
idea -> draft -> ready -> published -> reviewed -> archived
```

允许用户手动归档任意状态内容。

### 6.4 用户操作

- 查看内容。
- 按档案、平台、目标、状态筛选。
- 修改状态。
- 标记待发布。
- 标记已发布。
- 进入发布与复盘页。
- 归档内容。
- 复制内容。

### 6.5 v0 验收标准

- 所有生成内容都能在内容库看到。
- 用户可以按状态筛选。
- `published` 状态内容可以进入数据填写。
- `reviewed` 状态内容可以查看复盘摘要。
- 用户可以归档不再使用的内容。

## 7. 页面五：发布与复盘

### 7.1 页面目标

发布与复盘页用于手动记录发布数据，并触发 AI 复盘。

### 7.2 页面模块

| 模块 | 内容 |
| --- | --- |
| 内容摘要 | 标题、档案、平台、内容目标、发布时间 |
| 数据填写表 | 发布链接、浏览、点赞、收藏、评论、转发、关注、私信、有效线索等 |
| 数据记录节点 | 24h、72h、7d |
| AI 复盘结果 | 表现判断、原因分析、保留项、避免项、下一条建议 |
| 历史复盘 | 查看该内容不同时间点的数据和复盘 |

### 7.3 数据填写字段

| 字段 | 说明 |
| --- | --- |
| 发布链接 | 手动填写 |
| 发布时间 | 手动填写 |
| 浏览 / 播放 | 平台曝光数据 |
| 点赞 | 点赞数 |
| 收藏 | 收藏数 |
| 评论 | 评论数 |
| 转发 | 转发数 |
| 关注增长 | 该内容带来的关注 |
| 私信 / 咨询 | 私信或咨询数量 |
| 有效线索 | 明确表达需求的人 |
| 表单 / 预约 / 试玩 | 承接口数据 |
| 成交 / 付费 | 如果有则记录 |
| 用户主观判断 | 用户对内容效果的感受 |

### 7.4 数据填写频率

v0 采用“2 个必填节点 + 1 个可选节点”。

| 节点 | 规则 |
| --- | --- |
| 24h | 必填，记录初始数据 |
| 72h | 可选，只对重点内容、高表现内容、获客内容提醒 |
| 7d | 必填，记录稳定数据并做复盘 |

普通内容提醒：

```text
24h + 7d
```

重点内容提醒：

```text
24h + 72h + 7d
```

不要频繁提醒用户填写数据。月度复盘可以后续版本加入，不在 v0 做复杂报表。

### 7.5 AI 复盘输出

AI 复盘必须先根据内容目标解释数据。

输出：

- 当前目标下表现如何。
- 相比历史同目标内容表现如何。
- 标题是否有效。
- 人设是否一致。
- 是否过度营销。
- 是否有真实素材支撑。
- 哪些内容元素应保留。
- 哪些内容元素应避免。
- 下一条适合发信任内容、曝光内容、反馈内容还是转化内容。
- 推荐下一条选题。

### 7.6 用户操作

- 填写发布数据。
- 保存数据。
- 更新 24h / 72h / 7d 数据。
- 触发 AI 复盘。
- 查看历史复盘。
- 从复盘建议生成下一条内容。

### 7.7 v0 验收标准

- 用户可以为已发布内容填写数据。
- 用户可以多次更新同一内容的数据。
- AI 复盘必须根据内容目标解释指标。
- 7d 复盘完成后，内容状态变为 `reviewed`。
- 复盘建议可以作为下一次内容工作流输入。

## 8. 功能优先级

### 8.1 v0 必做

| 模块 | 功能 |
| --- | --- |
| 登录 / 用户 | 最小登录、自用账号、用户数据隔离 |
| 工作台 | 本周目标、待发布、待补数据、复盘提醒、最近内容 |
| 运营档案 | 多档案、模板向导、账号阶段、当前目标、人设、目标用户、承接口、禁忌表达 |
| 内容工作流 | 选择档案、选择平台、选择内容目标、输入文字素材、限制条件 |

## 9. v0 开发优先顺序

建议开发顺序：

1. 登录和用户基础。
2. 运营档案。
3. 内容工作流：输入 -> 选题 -> 内容包。
4. 内容库和状态流转。
5. 发布数据记录。
6. AI 复盘。
7. 工作台和提醒。
8. 竞品洞察、一键复制、AI 日志等体验增强。

原因：先让核心数据流跑起来，再做工作台和提醒。
