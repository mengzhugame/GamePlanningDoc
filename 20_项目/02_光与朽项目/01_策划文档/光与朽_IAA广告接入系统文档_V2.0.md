# 《光与朽》IAA广告接入与变现系统设计文档 V2.0

> **文档状态**: 待实装
> **更新说明**: V2.0 在 V1.0 基础上，明确了每个广告位对应的 Unity 面板类名、触发事件、频控规则，并新增技术接入规范章节，可直接指导开发。
> **核心原则**: 把广告做成"玩家求着看的道具"，而不是逼着看的垃圾。通过损失厌恶与 Near-Miss 效应，最大化单次广告的转化率。

---

## 一、核心变现方法论

在《光与朽》这类 Roguelike 塔防游戏中，玩家的爽感（割草期）和挫败感（高压卡关）是交替出现的。

**黄金法则：绝不在玩家心流最顺畅的割草期强插广告。**

广告应出现在以下三类时机：
1. **绝境时**：玩家死亡，沉没成本最高，复活意愿最强
2. **决策时**：技能升级选择，重置卡池需求最迫切
3. **收益时**：结算时双倍奖励，玩家满足感强，付出意愿高

#### 广告位 #1 — 技能重置（污染池保底）

|------|------|
| **面板类** | `SkillChooseOnePanel` |
| **触发事件** | `GameEvents.OnLevelUp` |
| **触发条件** | 玩家升级后弹出技能选择界面，已用完 1 次免费重置次数，再次点击「重置」按钮时 |

| **按钮文案** | 「看视频再抽一次」 |
| **频控** | 每次升级触发 1 次，每日总激励广告上限共享 |
| **心理学** | 损失厌恶：玩家刷出 3 张没用的牌，沮丧情绪驱动看广告意愿 |

#### 广告位 #2 — 结算双倍奖励

| 字段 | 内容 |
|------|------|

| **触发事件** | `GameEvents.OnGameVictory` |
| **触发条件** | 通关后进入结算界面，点击「双倍领取」按钮 |

| **按钮文案** | 「看视频·双倍领取」 |

#### 广告位 #3 — 死亡复活

|------|------|

| **心理学** | Near-Miss 效应：看到 BOSS 还剩 20% HP，沉没成本触发强烈复活意愿 |

## 四、广告预加载策略

### 4.1 预加载铁律

绝不能出现玩家点击「看广告复活」时转圈加载超过 1.5 秒，这会导致 100% 流失。

**预加载时机**：

| 时机 | 预加载内容 |
|------|-----------|
| 进入加载场景（Loading）| 预加载激励视频广告 #3（复活） |
| 主菜单初始化 | 预加载 Banner B1，预加载 #4/#5/#6（资源广告） |
| 波次结束、升级弹窗前 | 预加载激励视频广告 #1（技能重置） |
| 进入 BOSS 波次 | 提前二次预加载广告 #3（复活），确保 BOSS 战结束时广告就绪 |

### 4.2 广告失败降级处理

| 场景 | 处理方式 |
|------|---------|
| 广告加载失败（无网络） | 屏蔽广告按钮，显示「网络异常，请检查网络后重试」 |
| 广告播放中途关闭（未看完） | **不给奖励**，按钮重新可点击，不记录本次观看 |
| 广告平台无填充 | 屏蔽按钮，不显示「看广告」入口，避免玩家感知失败 |
| 断网状态 | 屏蔽所有广告按钮，防止玩家通过卡网络白嫖奖励 |

## 五、技术接入规范

### 5.1 WeChat 小游戏 SDK 接口

#### 激励视频广告

```javascript
// 1. 创建广告实例（在初始化时调用，全局复用）
const rewardedAd = wx.createRewardedVideoAd({
    adUnitId: 'adunit-xxxxxxxxxxxxxxxx'  // 填入微信后台配置的广告位 ID
});

// 2. 监听广告关闭（判断是否看完）
rewardedAd.onClose((res) => {
    if (res && res.isEnded) {
        // 用户完整看完广告，发放奖励
        GrantAdReward(adType);
    } else {
        // 用户中途退出，不发放奖励
        ShowToast("需要看完广告才能获得奖励");
    }
});

// 3. 监听错误
rewardedAd.onError((err) => {
    console.error('广告加载失败:', err.errCode, err.errMsg);
    HideAdButton();  // 隐藏广告按钮
});

// 4. 预加载（在合适时机调用）
rewardedAd.load();

// 5. 展示广告
rewardedAd.show().catch((err) => {
    // show 失败（广告未就绪），触发一次重新加载
    rewardedAd.load().then(() => rewardedAd.show());
});
```

#### Banner 广告

```javascript
// 创建 Banner（在进入对应界面时调用）
const bannerAd = wx.createBannerAd({
    adUnitId: 'adunit-yyyyyyyyyyyyyyyy',
    style: {
        left: 0,
        top: systemInfo.windowHeight - 100,  // 屏幕底部
        width: systemInfo.windowWidth
    }
});
bannerAd.show();

// 离开界面时销毁
bannerAd.destroy();
```

### 5.2 Unity 端 AdManager 设计规范

#### 职责

`AdManager` 是游戏客户端侧广告的统一入口，负责：
- 管理所有广告位 ID（集中配置，方便更换）
- 统一调用广告展示接口
- 维护频控计数（本地存档 + 每日重置）
- 向调用方回调广告结果（成功 / 失败 / 未看完）

#### 广告位枚举

```csharp
public enum AdType
{
    SkillReroll,        // #1 技能重置
    SettlementDouble,   // #2 结算双倍
    Revive,             // #3 死亡复活
    EnergyTopUp,        // #4 体力补充
    GoldTopUp,          // #5 金币补充
    BlueprintTopUp,     // #6 蓝图补充
}
```

#### 核心接口

```csharp
// 展示激励视频广告
// onSuccess: 用户看完广告，发放奖励
// onFail: 广告失败或用户中途退出
AdManager.Instance.ShowRewardedAd(AdType.Revive,
    onSuccess: () => { RevivePlayer(); },
    onFail:    () => { ShowToast("需要看完广告才能复活"); }
);

// 查询某广告位今日是否还有余量
bool canWatch = AdManager.Instance.CanWatchAd(AdType.Revive);

// 查询本场游戏是否已复活（场次内频控）
bool hasRevived = AdManager.Instance.HasRevivedThisGame();
```

#### 频控数据持久化

- 每日观看次数：存入 `PlayerPrefs`，key 为 `ad_watch_count_{date}_{adType}`
- 每日自动重置：通过对比本地存储日期与当日日期判断是否重置
- 场次内状态（如 `HasRevived`）：存于内存，随游戏场次初始化时重置

## 七、运营数据追踪指标

上线后通过微信后台重点监控以下指标：

| 指标 | 计算方式 | 目标值 |
|------|---------|--------|
| 广告渗透率 | 看过 ≥1 次广告的 DAU / 总 DAU | 及格 40%，优秀 60%+ |
| 人均广告展示数 (AIPU) | 总展示次数 / DAU | 目标 4~6 次/人/日 |
| 复活广告转化率 | 点击「复活」/ 触发 RevivePanel 次数 | 目标 > 65% |
| 结算翻倍点击率 | 点击「双倍领取」/ 胜利结算次数 | 目标 > 50% |
| 技能重置广告率 | 使用广告重置次数 / 总升级次数 | 参考值，观察趋势 |
