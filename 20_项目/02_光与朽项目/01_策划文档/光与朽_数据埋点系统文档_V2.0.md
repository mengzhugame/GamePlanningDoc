│                     游戏客户端                            │

### 层一：微信场景分析（一期，现在可做）

- **工具**：微信小游戏后台 → 统计 → 基础数据 → **场景分析 → 新建场景**
- **API**：`wx.reportScene({ sceneId: 'scene_xxx' })`
- **能力**：记录事件触发次数、漏斗转化率、留存对比
- **限制**：**不支持携带自定义参数**，只能记录"发生了几次"

### 层二：深度参数分析（二期，待后续接入）

- **工具**：友盟 Umeng SDK 或自建后端
- **能力**：携带参数的事件（死在第几波、选了哪个技能、构筑类型等）
- **现状**：MVP 阶段深度数据由 `BattleStatistics.cs` 本地 CSV 承担（开发调试用）

## 三、AnalyticsManager 设计规范

**新增文件**：`Assets/Scripts/Core/AnalyticsManager.cs`

### 3.1 核心职责

- 封装 `wx.reportScene()` 调用，屏蔽平台差异
- 生成并持久化 `user_id`（首次启动生成 UUID）
- 根据编译环境自动切换：正式包上报 / Editor 打印日志

### 3.2 核心接口

```csharp
public class AnalyticsManager : MonoBehaviour
{
    public static AnalyticsManager Instance { get; private set; }

    // 上报场景事件（对应微信后台一个「场景」）
    public static void LogScene(string sceneId)
    {
#if !UNITY_EDITOR && !DEVELOPMENT_BUILD
        // 正式包：调用微信 JS 接口
        WXSDKManager.Instance?.ReportScene(sceneId);
#else
        // 开发环境：打印日志，方便调试
        Debug.Log($"[Analytics] Scene: {sceneId}");
#endif
    }

    // 一次性场景（只上报第一次，防重复）
    public static void LogSceneOnce(string sceneId)
    {
        string key = $"Analytics_Done_{sceneId}";
        if (PlayerPrefs.GetInt(key, 0) == 1) return;
        PlayerPrefs.SetInt(key, 1);
        LogScene(sceneId);
    }
}
```

### 3.3 user_id 生成

```csharp
// 在 AnalyticsManager.Awake() 中执行
private void InitUserId()
{
    if (!PlayerPrefs.HasKey("Analytics_UserId"))
    {
        PlayerPrefs.SetString("Analytics_UserId", System.Guid.NewGuid().ToString());
    }
}
```

### 3.4 调用示例

```csharp
// 在 BattleManager 或 GameEvents 监听中调用
AnalyticsManager.LogScene("battle_start_ch1");
AnalyticsManager.LogSceneOnce("tutorial_laser_done");   // 一次性
AnalyticsManager.LogScene("ad_btn_click_revive");
```

## 四、一期：场景分析埋点清单

> 在微信后台「场景分析→新建场景」逐一创建以下场景，获取 sceneId 后填入代码。

### 4.1 基础漏斗（最高优先级）

| 场景名称 | 建议 sceneId | 触发时机 | 触发代码位置 | 是否一次性 |
|---------|-------------|---------|------------|----------|
| 游戏启动 | `app_launch` | 游戏加载完成进入主界面 | `MainSceneUIManager.Start()` | 否 |
| 第一局战斗开始 | `first_battle_start` | 首次进入战斗场景 | `GameEvents.OnGameStart`（isFirstPlay 为 true 时）| **是** |
| 第一局战斗胜利 | `first_battle_win` | 首局胜利结算 | `SettlementPanel.OnGameVictory` + 首局判断 | **是** |
| 第一局战斗失败 | `first_battle_lose` | 首局失败结算 | `SettlementPanel.OnGameDefeat` + 首局判断 | **是** |

### 4.2 新手引导步骤

| 场景名称 | 建议 sceneId | 触发时机 | 是否一次性 |

| 科技树首次打开 | `tutorial_techtree_open` | 首次点击科技树按钮 | **是** |

### 4.3 战斗里程碑

| 场景名称 | 建议 sceneId | 触发时机 | 是否一次性 |

### 6.2 CSV 字段说明

CSV 包含 126+ 列，按章节分组（详见 `BattleStatTypes.cs`）：

| 分组 | 字段数 | 说明 |
|------|--------|------|
| 基础信息 | 5 | 波次、构筑类型、玩家等级、结果、用时 |
| 击杀/生成统计 | 12+ | 各怪物类型的击杀数和生成数 |
| 玩家血量 | 9 | 开始/结束血量、受伤来源拆分 |
| 输出数据 | 9 | 各伤害来源、暴击统计、过量击杀 |
| 面板快照 | 3 | 当波次的 DPS/暴击率/激光宽度 |
| 无人机数据 | 12 | 选择类型、奖励累计 |
| Boss 数据 | 9+ | Boss 技能使用次数、阶段、剩余血量 |
| 技能路径 | 3 | 技能选取路径、各等级、大招次数 |
| 章节特化数据 | 27-40+ | Ch2（岩浆系）/ Ch3（冰冻系）专属字段 |

**文件路径**：`{Application.persistentDataPath}/BattleLog_{timestamp}_{result}.csv`
**触发时机**：`OnGameVictory` 或 `OnGameDefeat`

## 九、接入注意事项

1. **提前在后台注册场景**：`wx.reportScene()` 需要先在微信后台创建场景获取 ID 才能上报，代码调用找不到对应 ID 的数据会被丢弃
2. **场景 ID 集中管理**：将所有 sceneId 定义为常量集中存放，避免字符串散落各处导致笔误
3. **一次性事件用 `LogSceneOnce`**：防止同一玩家多次触发导致漏斗数据失真
4. **测试验证**：接入后在微信开发者工具中使用体验版验证数据是否正常上报（后台实时数据约有 10 分钟延迟）
5. **正式包关闭 CSV**：务必确认打正式包前编译宏设置正确，防止 CSV 逻辑消耗移动端性能
