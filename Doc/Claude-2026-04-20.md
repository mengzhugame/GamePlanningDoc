先直接回答你的三个问题，再给推荐方案。

  Q1：能让 Claude Code / Codex / openclaw 共享一个"记忆大脑"吗？

  能，但要分清两种"记忆"：

  - 物理记忆（store）：git 仓库里的 .md 文件。这是三个工具天然共享的——它们读写同一个文件系统。你现在这套架构已经做到了。
  - 会话上下文记忆（context）：每次 AI 会话装进 prompt
  的那部分。这不能也不应该自动共享，因为每个工具每次会话的目标不同。

  所以答案：物理层共享（yes），会话层不共享（也不该共享）。

  Q2：跨会话永久记忆会让 token 更多吗？

  不会——只要你按需加载。

  - 永久记忆本身存在磁盘上，不消耗任何 token。
  - token 花多少，取决于每次会话实际读入了什么。
  - 三种加载方式：
    - 自动全量加载（把知识库 dump 进 prompt）→ 爆炸，100 个 md 能吃掉半个 context window
    - 按需读取（AI 按当前任务用 Read 工具挑相关文件）→ 省，通常只读 3–10 个文件
    - 入口文件导览（像 CLAUDE.md / AGENTS.md 只放地图）→ 每次会话固定成本 3–5KB，其余按需

  Claude Code 的 Skills 机制本来就是第 3 种——每个 skill 的 frontmatter 启动时加载，body 只在触发时加载。你现在的
  90_系统/skills/ 已经是这个设计，没问题。

  Q3：跨项目永久记忆 vs 新项目新记忆？

  不是二选一，而是分层：

  ┌──────────────────────────────────────────┬───────────────────────────────┬───────────────────────┐
  │                   内容                   │       该不该跨项目共享        │         放哪          │
