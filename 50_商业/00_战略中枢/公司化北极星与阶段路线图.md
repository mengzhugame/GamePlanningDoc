# 公司化北极星与阶段路线图

## 一句话

**先做出被陌生用户验证、留存和盈利表现足够好的游戏，再让公司自然长出来。**

成立游戏公司不是注册执照，而是证明自己拥有一套能持续发现机会、验证产品、沉淀用户、产生收入、组织团队的系统。

2026-05-27 补充：当前入口已从“只讨论游戏公司”扩展为“先用个人能力跑出可收费能力、用户池、产品数据或合作机会”。具体执行见 [[现阶段商业化路线图_2026-05]]；本文件继续保留公司化北极星和阶段闸门。

---

## 北极星

唯一目标：成立游戏公司。

成立公司的前提：

1. 至少一款产品出现清晰留存和盈利正信号。
2. 有真实用户池、发行合作、买量数据或收入流水支撑下一轮项目。
3. 公司化能降低协作成本、合同成本和财务成本，而不是满足“老板身份”。

反向红线：

- 没有产品数据，不为身份注册公司。
- 没有陌生用户信号，不进入完整开发。
- 没有收入 / 合作 / 用户池，不扩团队。
- 没有验证结果，不用“整理知识库”冒充推进。

---

## 当前战略判断（2026-05-18）

已经证明的能力：

- 能独立完成微信小游戏上线。
- Unity / TA / Shader / VFX / 技术管线能力可支撑独立研发。
- 能复盘失败，并把项目拆成可复用资产和规则。

尚未证明的能力：

- 开发前发现市场需求。
- 用 AI 视频或素材验证方向。
- 组织 20-50 个陌生高意图用户试玩。
- 用留存、广告、付费、预约、买量数据决定加码或砍掉。
- 让个人 IP 稳定导向测试池，而不是只获得点赞。

核心转换：

```
旧模式：想法 -> 完整开发 -> 找发行 / 上平台 -> 等数据
新模式：市场观察 -> 概念视频 -> 陌生人反馈 -> 极小 Demo -> 用户池 -> 数据闸门 -> 加码
```

## 8-12 周方法验证期

时间窗：2026-05-18 至 2026-08-16。

核心命题：

> AI 视频反向立项 + 极小 Demo + 用户池，能不能帮我在正式开发前找到更值得做的小游戏方向？

标准流程：

```
1. 选题观察：榜单、评论、竞品、用户痛点、素材爆点
2. 概念表达：AI 概念视频 / 10-15 秒真实玩法素材 / 一句话钩子
3. 陌生反馈：评论、转发、预约、想玩表达、测试报名
4. 极小切片：7 天内做出核心爽点，不做外围系统
5. 用户池：20-50 个高意图试玩者
6. 数据闸门：留存、时长、广告观看、重开、预约、发行反馈
7. 决策：加码 / 修正 / 砍掉 / 归档
```

本阶段成功标准：

- 至少 1 个方向出现“陌生人想试”的明确证据。
- 至少完成 1 个 7 天极小切片。
- 至少积累 20-50 个高意图测试用户。
- 能清楚说出哪个变量有效：题材、机制、视频钩子、前 120 秒、平台表达或商业化节点。

本阶段失败处理：

- 不是继续换灵感，而是判断系统哪里断了：选题、素材、用户池、Demo、数据还是复盘。
- 如果系统连续 8-12 周无法产生外部信号，应启动工作 / 外包 / 进入团队补市场能力的现实期权。

## 公司化闸门

可以考虑注册公司的信号：

- 已有稳定收入或发行合作，对方要求 B2B 合同和发票。
- 广告 / IAP / 混变收入足以覆盖基本运营成本。
- 有版号、IAP、平台主体、合同或税务需求。
- 团队岗位需求真实出现，例如美术、运营、发行、数据。

不应该注册公司的情况：

- 只是想获得“创业成功”的身份感。
- 只是为了更像一个公司。
- 产品没有收入，也没有合作合同。
- 注册后只会增加税务、财务、维护成本。

## 每轮项目必须回答

1. 核心钩子是什么，3 秒能不能看懂？
2. 和市面上最火同类的 3 个核心不同点是什么？
3. 7 天内能做出哪一个最小可玩爽点？
4. 谁是第一批 20-50 个陌生测试者？
5. 这轮失败后能留下什么资产？
6. 加码标准是什么？
7. 砍掉标准是什么？

## 当前主线

当前不是“再做一款游戏”，而是建立验证系统。

最小行动顺序：

1. 从 `00_草稿/游戏创意库/` 选 5-10 个候选。
2. 每个候选写一句话钩子和 10-15 秒视频脚本。
3. 用 `/idea-score` 和 `/iron-rule-check` 过第一道闸。
4. 只挑 1-2 个做概念视频 / 极小切片。
5. 每个方向必须绑定一个承接口：测试群、表单、预约、评论引导或愿望单。

## 已上线项目的继续投入，也要过公司化闸门

《光与朽》上线后的战略问题不是“要不要爱惜自己做出来的项目”，而是：这个项目是否还能用有限投入换来新的判断。

可复用决策：

| 信号 | 判断 |
| --- | --- |
| 平均停留接近 10 分钟 | 核心循环有局部成立可能，值得短期修一版 |
| 运营反馈像竞品、不够精致 | 差异化和完成度不足，不能直接扩量 |
| 熟人样本多、陌生样本少 | 不能判断市场，只能判断明显体验问题 |
| 首局长、爽点晚、广告点晚 | 会影响买量承接，必须先改 P0 |

因此更像公司化的动作是：给项目 2-4 周、500-1000 元复测预算和清晰止损条件；若没有陌生用户正信号，就转长尾并启动下一轮验证。

这条规则也适用于未来所有项目：已经上线不代表自动值得继续投，只有“下一笔投入能买到更清楚的判断”才值得继续。

## 50_商业重构后的战略中枢口径

2026-05-18 对 `50_商业/` 的整理确认了一个结构性原则：商业目录不是资料仓库，而是服务“公司化北极星”的决策系统。整理后的层级应围绕战略中枢、商业模式、个人 IP 与用户池、公司化准备、历史归档展开。

可复用判断：

- 注册公司不是先手动作；先手是跑出产品留存、盈利、发行合作或用户池信号。
- 当前缺的不是“更多商业计划”，而是 `市场信号 -> 用户池 -> 数据复盘 -> 收入/发行` 的闭环。
- 2026-05-18 至 2026-08-16 的 8-12 周，是方法验证期，不是无限期继续创业的情绪缓冲期。
- 个人 IP 不应被当成独立创作者账号，而应被设计成高意图用户池：吸引愿意看开发、评论玩法、参与试玩、留下反馈的人。
- 商业目录里的每个文件都要能回答一个现实问题：是否让下一轮验证更便宜、更快、更硬。

因此，后续讨论公司化时，优先追问：

1. 这条动作能带来哪类外部信号？
2. 是否能把陌生用户从内容平台导入测试池？
3. 能否让下一次 Push / Pivot / Kill 更清楚？
4. 是否只是通过整理系统获得安全感？

## 求职受挫后的公司化路径修正

2026-05-22 的关键修正是：短期不应把“全职个人游戏创业”当成唯一正确身份，也不应把求职受挫解释成个人失败。更稳的路线是：

> 职业资本修复 + 低成本创业实验并行；用游戏行业现金流、团队经验和 AI 工作流资产，重新积累未来公司化的筹码。

新的战略口径：

| 旧问题 | 新问题 |
| --- | --- |
| 下一款小游戏做什么 | 我是否还该全职押注个人游戏创业 |
| 要不要回去上班 | 哪种工作能补现金流、团队经验、行业嵌入和 AI×游戏资产 |
| AI 能不能帮我做爆款 | AI 能不能让我成为更低成本的需求验证机器 |
| 创业是不是失败了 | 当前系统是否能持续产生外部信号和可复用资产 |

对未来公司化最有价值的不是“独自做出下一款爆款”的执念，而是形成一套可复用能力：

- 低成本发现真实玩家需求。
- 用 AI 加速素材、原型、内容和复盘。
- 把每次试错沉淀成流程、模板、数据和用户池。
- 在行业组织或合作网络中获得现金流、发行认知、团队协作和真实项目经验。

如果继续全职个人游戏创业，只靠 1-2 款微信小游戏或 Steam 小品类赌命中，风险已经偏高。更现实的公司化路线，是先成为“AI 放大的游戏验证系统操盘者”，再让产品和团队自然长出来。

## 36 岁后的 90 天反脆弱结构

2026-05-24 的战略判断进一步收窄：当前不该立刻全职上班，也不该把大理、全职旅行或旅游行业当作重启人生的主战场。更稳的结构是：

> 广州 / 游戏行业城市做主基地，90 天同时修复职业资本、低成本创业验证、重建社交生活。

这不是“上班还是创业”的身份选择，而是未来 3 年的反脆弱结构设计。

当前最大风险不只是生存现金，而是：继续一个人闭门开发、没有外部信号、社交断供、职业资本变旧，然后把换环境误当成战略升级。

90 天应拆成 5 条线：

| 线 | 目标 | 红线 |
| --- | --- | --- |
| 工作线 | 投递和约聊 `Unity TA / Pipeline TA / UGC 工具链 / Shader URP / AI 游戏生产流程` | 只用 offer 校准市场价值，不把求职当人生投降 |
| 创业线 | 只保留一个低成本验证方向 | 30 天内没有概念视频、切片、20-50 个陌生反馈，不进完整开发 |
| 城市线 | 广州或同类游戏行业城市为主基地 | 大理只能作为 2-4 周带交付物的工作营 |
| 社交线 | 每周一次低成本线下活动 | 不把社交当娱乐奢侈，它是判断系统的基础设施 |
| 旅行线 | 阶段性交付后的恢复系统 | 项目没交付就旅行，默认先按逃避检查 |

三年路线可以这样判断：

1. 2026-05 至 2026-08：双轨验证。看 offer、创业外部信号和社交生活是否恢复。
2. 2026-09 至 2027-05：二选一。如果高质量 offer 强、创业信号弱，上班 12 个月，把创业降级为周末小实验；如果创业信号强，继续全职，但每 1-2 个月必须完成一轮验证。
3. 2027-2028：形成稳定结构。要么工作现金流 + AI 游戏实验室，要么小团队工作室。
4. 2028-2029：只有产品数据、现金流、用户池或合作机会支撑团队时，才公司化。

## 90 天 AI 创业验证 + 求职/接单保险 + 旅行线下副线

2026-05-25 的进一步判断是：不要继续“去年那种小游戏创业”，也不要立刻把创业关掉去找工作。当前最适合的组合是：

```
60%：AI + 小游戏 / 工具应用验证
20%：作品集、简历、接单或岗位试探
20%：旅行线下实验，约旅游朋友、参加/组织徒步、做真实路线产品测试
```

这条路的核心不是押某个赛道，而是用已有游戏 / AI 能力创造现金流上限，同时强制生活重新接回真实世界。

90 天后只看证据：

| 结果 | 决策 |
| --- | --- |
| 有用户信号 / 收入苗头 / 合作机会 | 继续创业并加码最小验证 |
| 完全没有信号 | 找工作或接单优先，创业降级为副线 |
| 旅行线下实验强烈滋养且有客户线索 | 扩大旅行副线，但不立刻 All-in |

游戏主线也要改口径：不是“继续制作小游戏”，而是“用 AI 搭建小游戏自动化生产流程，并把它做成 TA / AI Pipeline 作品集”。6 月只交付三件事：

1. 一个 `AI 创意 -> 配置 JSON -> Unity 模板生成 -> 可玩首局` 的流程 Demo。
2. 一个 60-90 秒作品集视频，展示工具链和最终小游戏片段。
3. 一个陌生用户测试记录，哪怕只有 20 人。

如果做工作，优先选择能补工具链、AI Pipeline、团队经验、行业嵌入和现金流的岗位；如果只是高强度消耗身体、学不到东西的纯救火岗位，不能只因为薪资接受。

## 平台顺序是在验证不同风险，不是“一版三发”

每日战略归档里有一条可复用的发行判断：同一个游戏到不同平台不是同一门生意。平台顺序应该按要验证的风险排列，而不是按“哪里都上一遍”排列。

| 平台 / 渠道 | 先验证什么 | 不应误读成 |
| --- | --- | --- |
| 短视频 / 小红书 / 抖音 | 3 秒钩子能否让陌生人停下、评论和想试 | 播放量就是需求 |
| Steam Demo / 商店页 | 前 10 分钟是否兑现承诺、愿望单是否精准 | 愿望单数字越大越好 |
| 微信小游戏 | 留存、广告触发、短局重开和混合变现 | 上架就等于商业闭环 |
| 创作者 / 社群 | 别人能否复述卖点、愿不愿意试玩和传播 | 大曝光可以补产品问题 |

对《光与朽》这类项目，更稳的顺序是：先用短视频测“激光折射翻盘”是否能让陌生人停下，再用 Demo 或体验版验证前 10 分钟是否好玩，最后才做微信留存、广告位和混变。

一版三发会把错误同时放大。公司化路线要先打透一个风险，再扩到下一个风险。
