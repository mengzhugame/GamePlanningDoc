# 团队岗位与合伙人计划

当前阶段不是“招人做公司”，而是等一个被验证的产品或流程暴露真实岗位需求。

---

## 3 年后理想团队

- 小团队，10 人以内。
- AI 大幅降低人力需求。
- 每个岗位由专业的人负责审核、判断和流程完善。
- 创始人保留方向、财务、用人、合作和关键产品判断。

---

## 第一批岗位优先级

| 优先级 | 岗位 | 为什么 |
|--------|------|--------|
| 1 | 全能美术 / 特效美术 | TA 和程序可由本人 + AI 承担，美术品质和第一眼钩子是最大短板 |
| 2 | 运营发行 / 数据伙伴 | 补测试池、买量、发行、平台、数据复盘 |
| 3 | 策划 / 产品伙伴 | 帮助审核方向、前 120 秒体验、长期系统 |
| 4 | 程序 | 只有项目复杂度或维护压力超过个人 + AI 时才补 |

---

## 合伙人标准

需要的人：

- 能补创始人短板。
- 能被数据说服。
- 能接受小切片、快验证、快砍掉。
- 能把美术、运营或产品判断落到具体产出。

不适合的人：

- 只想做大项目。
- 只给情绪支持，不补能力。
- 不能接受快速砍方向。
- 只做执行，不参与判断。

---

## 找美术伙伴的话术核心

不是：

> 我有想法，你来帮我画。

而是：

> 我能解决技术、工程和上线流程，现在需要一个能把第一眼视觉、角色气质、UI 和素材表达拔高的人，一起用 7-30 天小切片验证方向。

---

## 什么时候招人

可以招：

- 已有方向过了概念视频和极小切片。
- 明确知道“缺美术 / 缺运营 / 缺数据”会阻碍下一阶段。
- 有钱支撑至少一个验证周期。
- 招人可以换来更快验证，而不是更重成本。

不该招：

- 因为孤独。
- 因为想让自己像老板。

## 外包、兼职和多 Agent 都要按成果管理

早期公司化或半公司化协作，不要先追求“人多”或“Agent 多”。最小复杂度优先：一个清晰交付物对应一个责任人或一个 Agent，主线程负责目标、接口、验收和合并。

协作任务必须前置五件事：

| 项 | 说明 |
| --- | --- |
| 交付物定义 | 例如 3 个敌人立绘、可导入 prefab、可运行功能 |
| 验收标准 | 尺寸、命名、格式、性能、功能、风格 |
| 反馈时限 | 例如 48 小时内集中反馈，避免无限拉扯 |
| 修改轮次 | 默认包含几轮小修，超出另计 |
| 付款 / 合并触发 | 验收通过再付款、合并或进入下一步 |

适用于外包美术、兼职程序、音效、BGM，也适用于 AI Agent 交付代码或文档。

任务卡模板：

```markdown
# 协作任务卡
- 任务名称：
- 交付物：
- 输入资料：
- 禁止事项：
- 验收标准：
- 截止时间：
- 修改轮次：
- 付款/合并条件：
- 需要主创拍板的问题：
```

多 Agent 协作也按同一逻辑：Explorer 只读和找风险，Implementer 只做单一子任务，Reviewer 只查 diff、日志和验收。会写代码的执行单元必须有边界和回滚点，不允许多个 Agent 同时改同一片核心文件。
- 因为项目还没验证，但想靠团队给自己信心。
- 因为不想面对市场反馈。

---

## 创始人必须保留的权力

- 财务决策。
- 团队用人。
- 合作对象选择。
- 最终加码 / 砍项目决策。

产品可以引入更专业的人，但商业目标、资源配置和止损线不能失控。
