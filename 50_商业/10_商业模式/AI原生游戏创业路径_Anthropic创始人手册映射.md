# AI原生游戏创业路径：Anthropic 创始人手册映射

> 结论：AI 原生创业不是“更快把想法做出来”，而是“更快地找到不该做什么、更早建立证据链、更少用人力堆流程”。对游戏创业尤其重要，因为游戏最容易把可玩的原型误当成市场验证。

## 报告核心摘要

Anthropic 的《The Founder's Playbook: Building an AI-Native Startup》把创业分为四个阶段：

| 阶段 | 原报告重点 | 对游戏创业的翻译 |
| --- | --- | --- |
| Idea | 先验证真实问题、目标人群、竞品和反证，再写代码 | 先验证玩家欲望、题材钩子、差异化和陌生人信号，再做切片 |
| MVP | MVP 仍是证据收集，不是功能建设；先定架构、范围、指标 | 7 天切片和 1 个月 Demo 要先定玩法范围、埋点、止损线和假阳性 |
| Launch | 把早期牵引变成可重复增长，创始人不能成为所有流程的瓶颈 | 上线前建立素材、用户反馈、数据、版本、发行沟通的轻量运营系统 |
| Scale | 把创始人知识、用户数据和工作流沉淀成护城河 | 从单品成功进入产品矩阵、用户池、发行关系、AI 上下文和生产管线复用 |

报告最值得吸收的五个判断：

1. AI 把“能不能做出来”的门槛降低了，但把“该不该做”的判断变得更关键。
2. 创始人角色从执行者上移为系统编排者，重点是定义问题、判断证据、安排 AI 和人协作。
3. AI 会放大确认偏误，必须主动让 AI 找反证、竞品威胁和失败理由。
4. MVP 之前要先写范围、架构、指标和安全边界，否则 AI 速度会制造范围蔓延和结构漂移。
5. 真正的护城河来自长期积累的领域知识、用户行为数据、流程嵌入和可复用上下文。

## 对 GamePlanningDoc 的最大启发

当前 vault 已经有一套正确方向：

```
选题观察 -> AI 概念视频 -> 陌生人反馈 -> 7 天极小切片 -> Demo -> 留存 / 广告 / 买量信号
```

Anthropic 手册不是推翻这套流程，而是补三件事：

1. 每次进入 AI 生成前，先有“反证回合”。
2. 每个可玩切片前，先有“范围、架构、指标、假阳性”四件套。
3. 每轮验证结束后，沉淀的不只是素材和代码，还包括 AI 上下文、访谈摘要、竞品反证、数据口径和决策日志。

## 游戏行业的四阶段路径

### 1. Idea：玩家欲望验证，不是点子兴奋

游戏没有传统 SaaS 那种明确工作流痛点，但仍然有可验证的“玩家欲望假设”。

把模糊灵感改写成可测试句式：

```text
哪类玩家
在什么情境下
因为哪种未满足的情绪 / 爽点 / 压力 / 幻想
会被什么 3 秒画面钩住
并愿意追问“在哪玩 / 什么时候出 / 我想试”
```

例：

| 模糊想法 | 可验证假设 |
| --- | --- |
| 做一个花园经营游戏 | 小红书上喜欢收纳、治愈、改造内容的女性用户，会被“荒废花园 15 秒复苏”钩住，并愿意收藏或追问试玩入口 |
| 做一个动作 Boss 战 | B 站动作游戏用户会被“极简操作 + 高压激光 Boss + 30 秒反杀”钩住，并愿意评论讨论机制 |

Idea 阶段必做四件事：

| 动作 | 输出 | 放到哪里 |
| --- | --- | --- |
| 玩家假设 | 玩家画像、使用平台、欲望和反证 | 概念卡 |
| 竞品威胁图 | 直接竞品、间接竞品、相邻爆款、可能替代品 | 概念卡或市场分析 |
| 评论 / 评价挖掘 | 玩家夸什么、骂什么、求什么、为什么离开 | `30_市场分析/` 线索，蒸馏后进知识区 |
| AI 反证 | 为什么这个方向可能不成立 | 概念卡的“反证与红旗” |

Idea 阶段退出条件：

- 不是“我觉得能做”，而是至少有 1 个可被陌生人验证的欲望假设。
- 不是“这个品类很大”，而是知道自己要测试哪类玩家、哪个平台、哪种钩子。
- 不是“AI 能生成好看的图”，而是这个画面能对应未来真实可玩的核心玩法。

### 2. MVP：切片是证据机器，不是缩小版完整游戏

游戏创业里，MVP 对应三层：

| 层级 | 目标 | 常见误区 |
| --- | --- | --- |
| AI 概念视频 | 验证看得懂、想不想玩 | 把点赞当留存，把假玩法当真实需求 |
| 7 天切片 | 验证核心动作、失败条件、反馈是否成立 | 过早加养成、剧情、完整美术 |
| 1 个月 Demo | 验证陌生人是否能玩、愿意回来、愿意看广告或付费 | 把 Demo 做成 80% 完整项目 |

每次开做前写清四件套：

| 文件 / 字段 | 作用 |
| --- | --- |
| 范围定义 | 本轮只验证什么，明确不做什么 |
| AI 上下文 | 项目约束、代码架构、美术规格、命名规则、目录规则 |
| 指标框架 | 看懂、试玩、复玩、广告、预约、愿望单、留存的最低判断线 |
| 假阳性清单 | 熟人夸奖、首发流量、AI 图好看、发行口头喜欢、短期播放 spike 都不等于 PMF |

建议给未来项目新增一个文件：

```text
20_项目/NN_项目名项目/AI_CONTEXT.md
```

最低内容：

```md
# AI_CONTEXT

## 本项目只验证什么

## 本项目明确不做什么

## 核心循环与失败条件

## 技术 / 美术 / 数据约束

## 指标与止损线

## 每次 AI 代码会话结束后更新
- 日期：
- 做了什么：
- 引入了什么假设：
- 哪些决定需要用户确认：
```

### 3. Launch：从“我能上线”到“系统能运行”

上线阶段不只是包体、广告和平台后台，而是把创始人注意力从杂务里释放出来。

游戏创业的 Launch 最小系统：

| 系统 | 最小形态 | AI 可协助 |
| --- | --- | --- |
| 素材系统 | 每周 3-5 条真实玩法素材，记录标题、钩子、数据 | 生成变体、总结高信号评论 |
| 用户反馈系统 | 20-50 个高意图玩家，测试后只问 3 个问题 | 访谈提纲、反馈归类、问题优先级 |
| 数据系统 | 首局完成、失败点、广告触发、广告完成、D1 / D7 | 指标解释、异常诊断、复盘草稿 |
| 版本系统 | 每周只改 1-2 个关键变量 | 版本计划、变更日志、回归清单 |
| 发行系统 | Demo、素材包、数据摘要、红旗清单 | 发行 pitch、FAQ、合同问题清单 |

Launch 阶段退出条件：

- 增长来自明确渠道，而不是偶然曝光。
- 数据能解释玩家为什么留下或离开。
- 版本、素材、反馈、发行沟通不完全靠创始人临时想起来。

### 4. Scale：游戏公司的护城河不是“我会做游戏”

对个人游戏创业者来说，Scale 不应过早理解为融资、扩团队或做大 IP。更现实的 Scale 是：

| 护城河 | 游戏行业表达 |
| --- | --- |
| 领域知识上下文化 | 用户偏好、品类坑位、发行反馈、平台规则、TA 技术资产被写进 vault 和 AI_CONTEXT |
| 用户数据飞轮 | 每个项目都留下评论、试玩、留存、广告、买量、预约、愿望单数据 |
| 工作流嵌入 | 从选题、视频、切片、Demo、上线、复盘形成可重复 SOP |
| 资产复用 | 代码模板、美术管线、Shader、UI、埋点、广告、素材脚本复用 |
| 产品矩阵 | 成功机制做变体，失败项目拆资产，不让项目一次性耗尽 |

Scale 阶段最重要的问题：

> 如果一个资金更多的团队明天抄这个方向，玩家、数据、素材、流程、发行关系和生产管线里有什么是它抄不走的？

## 30 / 60 / 90 天执行路径

### 30 天：建立 AI 原生验证节奏

目标：不是做出完整 Demo，而是让“研究 -> 反证 -> 视频 -> 数据”跑起来。

| 周 | 动作 | 产出 |
| --- | --- | --- |
| Week 1 | 选 3 个候选方向，各写玩家欲望假设和反证 | 3 张概念卡补丁 |
| Week 2 | 每个方向做竞品评论挖掘和 3 秒钩子 | 竞品威胁表、视频脚本 |
| Week 3 | 做 2-3 条真实玩法概念视频 | 概念视频版本 A/B/C |
| Week 4 | 发布、记录、复盘，选 Push / Pivot / Kill | 数据记录和下一轮决策 |

### 60 天：把一个 Push 方向推进到可测切片

目标：让 20-50 个高意图陌生玩家碰到真实玩法。

必须有：

- `AI_CONTEXT.md`。
- 7 天切片范围。
- 21 天可测切片计划。
- 最小埋点表。
- 测试池承接口：群、表单、TapTap、好游快爆、Steam、微信体验版中的一个。
- 三题测试：看懂了吗、哪里卡住、还想不想玩下一关。

### 90 天：判断是否进入商业闭环

目标：看这个方向是否值得继续投入 1-2 个月，而不是凭情绪续命。

进入下一阶段的证据至少来自两类：

- 玩家证据：复玩、主动追问、愿意进测试池、愿意预约、愿意推荐。
- 产品证据：首局理解率、失败点清楚、D1 / D7 或 Demo 回访有正信号。
- 商业证据：广告救助意愿、小额买量数据、发行愿意基于数据继续聊。
- 资产证据：即使停项，也沉淀出代码模板、美术流程、素材经验或用户池。

## 对现有流程的补丁

### 补丁 1：概念卡新增“AI 反证”区

建议未来概念卡增加：

```md
## AI 反证与红旗

- 最强反对理由：
- 最像的直接竞品：
- 最可能替代它的相邻品类：
- 玩家可能看不懂的地方：
- 这个方向最容易出现的假阳性：
- 如果两轮视频无信号，应该如何归档资产：
```

### 补丁 2：视频数据记录新增“假阳性判断”

建议每条视频除了播放、点赞、收藏、评论，还记录：

```md
## 假阳性判断

- 互动是否来自熟人：
- 评论是否真的表达想玩，而不是只夸画面：
- 是否有人追问入口 / 测试 / 上线时间：
- 是否有人复述出核心玩法：
- 是否只是平台偶然推流：
```

### 补丁 3：正式立项前新增“范围和指标冻结”

进入 7 天切片前，先冻结：

- 本轮只验证的 1 个核心动作。
- 本轮不做的功能清单。
- 最小可接受数据或定性信号。
- 三轮迭代仍无改善时的 Pivot / Kill 条件。

### 补丁 4：Demo 前新增“AI 技术债检查”

任何 1 个月 Demo 进入外部测试前，检查：

- 是否有项目级 AI_CONTEXT。
- 是否有统一命名、目录、状态、事件、埋点规则。
- 是否知道广告、存档、登录、数据上报的最小风险。
- 是否有回归测试清单。
- 是否能解释每个主要系统为什么这样设计。

### 补丁 5：周复盘新增“创始人瓶颈审计”

每周多问 3 个问题：

1. 本周哪些事只有我记得做，所以一忙就停了？
2. 哪些重复任务可以变成模板、清单、自动化或 AI 例行任务？
3. 哪个判断必须保留在我手里，不能交给 AI 或外包？

## 可直接使用的 AI 提示词

### 玩家欲望假设反证

```text
请把这个游戏创意改写成可测试的玩家欲望假设：
1. 哪类玩家
2. 在什么情境
3. 因为什么未满足欲望
4. 会被什么 3 秒画面钩住
5. 会做出什么可观察行为

然后请你站在最严厉投资人、发行商、竞品团队和陌生玩家角度，分别提出最强反对理由。
最后列出我最可能误判的 5 个假阳性。
```

### 竞品威胁图

```text
请按四层分析这个游戏方向的竞品：
1. 直接同玩法竞品
2. 同题材但不同玩法竞品
3. 抢同一情绪需求的相邻品类
4. 大厂或已有爆款如果进入，会用什么方式碾压

每一层请回答：
- 玩家为什么会选它而不选我
- 我的 3 个核心差异是否足够
- 哪个差异能在 3 秒视频里拍出来
- 哪个差异只是我自嗨
```

### 切片范围冻结

```text
下面是我的游戏创意和当前想做的功能。请帮我压缩成 7 天切片范围：
- 只保留一个核心动作
- 明确失败条件
- 明确反馈
- 明确本轮不做什么
- 明确外部测试只看哪 3 个信号
- 如果 3 轮迭代无改善，应该 Pivot 还是 Kill
```

### Demo 指标框架

```text
请为这个 1 个月 Demo 设计发布前指标框架：
- 激活指标
- 首局理解指标
- 复玩指标
- 广告或付费意愿指标
- 玩家原话采集方式
- 假阳性清单
- D1 / D7 或等价观察方式
- 72 小时内如何判断继续、修正或止损
```

## 当前最该执行的下一步

从 Anthropic 手册映射到当前 vault，最优先不是搭更复杂的自动化，而是补强现有验证链：

1. 下一张概念卡增加“玩家欲望假设”和“AI 反证与红旗”。
2. 下一轮 AI 概念视频发布前，先写假阳性清单。
3. 下一次进入 7 天切片前，先写 `AI_CONTEXT.md` 和范围冻结。
4. 每周商业复盘增加“创始人瓶颈审计”。
5. 每个项目复盘时，把 AI 上下文、提示词、素材脚本、埋点口径也列为目录资产。

这份手册的精华可以压成一句话：

> AI 让构建变快，所以创业者必须让判断更慢一点、证据更硬一点、系统更早一点。

## Anthropic 手册落地到概念卡和职业表述

这次对话把 AI 原生创业从“读报告”落到了三个具体动作：

1. 概念卡新增 `玩家欲望假设` 和 `AI 反证与红旗`，让每个创意先面对“谁会为什么想玩、为什么可能不成立”。
2. 视频数据记录新增 `假阳性判断`，避免把点赞、熟人互动、画面夸奖、平台偶然推流误判为真实需求。
3. 进入切片或 Demo 前先写 `AI_CONTEXT.md`，冻结范围、指标、技术/美术约束和 AI 会话交接规则。

同一天也确认了求职场景下的 AI 经验表述边界：不要把 AI 说成“直接生成商业最终资产”，而要说成“提高开发管线、工具脚本、概念探索、文档整理和资源预检查效率”。更可信的表达是：

- 用 Claude Code / Codex 辅助 Unity 工具、Python 脚本、项目功能和文档体系。
- 用 Midjourney / GPT Image / Nano Banana 做前期概念探索、风格参考和占位验证。
- 商业资产必须经过版权、合规、安全和人工审查。

AI 原生不是绕过专业判断，而是把专业判断更早写进流程。

## AI×游戏创业的两条验证分支

2026-05-22 的更清晰判断是：`AI + 游戏` 不一定等于玩家能直接感知的 AI 原生游戏。更稳的 90 天验证应拆成两层：

| 分支 | 验证对象 | 成功信号 |
| --- | --- | --- |
| 纯游戏分支 | 玩家是否真的想玩这个推理 / 经营 / 休闲核心循环 | 看懂、想继续、愿意预约/试玩/购买 |
| AI 工作流分支 | AI 是否能降低内容生产、关卡生成、素材验证和复盘成本 | 生成速度、质量稳定性、可复用模板、团队/行业可迁移价值 |

以《怪案侦探社》为例，短期不要急着包装成“AI 原生游戏”。更稳的结构是：

1. 游戏层：做一个 5-10 分钟可玩的证据排序 / 案发重演案件，证明推理循环成立。
2. AI 工作流层：用 AI 辅助生成证据卡、证词、红鲱鱼、约束表、测试变体。
3. 平台/社区层：只有当核心成立后，再考虑可分享、可测试、可生成的案件平台。

AI 行业的价值不是“会用 AI”本身，而是把 AI 嵌入具体行业工作流、真实数据、结果交付和客户/玩家渠道。对当前用户，最值得积累的是“AI 放大的游戏生产与验证系统”，而不是泛泛转去做 AI 概念项目。

## AI 创业产品排序：先做能低成本验证需求的工具

2026-05-25 的产品排序把“AI + 游戏 / 应用 / 旅行”从宏大赛道拉回可验证 Demo。当前排序标准是：明天能做、成本低、能验证付费或需求、不会再次拖进大项目。

优先级：

| 优先级 | 方向 | 第一版验证 |
| --- | --- | --- |
| 1 | 旅行从业者 AI 工具 | 路线 / 报价 / 客户沟通生成器，3 个样例问旅游朋友是否愿付 29 / 99 / 199 |
| 2 | 小游戏立项验证工具 | 概念卡、铁律检查、竞品差异、视频脚本、手动数据记录、Push / Pivot / Kill |
| 3 | IAA 小游戏漏斗 | 概念卡 -> AI 概念视频 -> 陌生反馈 -> 7 天切片 -> 1 个月 Demo |
| 4 | AI 个人冒险日记 / 旅行人生记录 | 旅行经历生成冒险日记、人生地图、徽章和小红书文案；先不用图片生成 |
| 5 | AI 旅行宠物 / 互动短篇 | 只做 15 秒概念视频验证兴趣，不先开发长期记忆或 API 重系统 |
| 6 | AI 玩具 + 旅行游戏 / 硬件 | 现在不做主线；未来也必须先无硬件小样和付费验证 |

小游戏仍可以继续，但规则改成：

- 没有视频信号，不写代码。
- 没有陌生反馈，不做 Demo。
- 没有留存，不加长线。
- 长线和 IAP 等发行合作后再说。

旅行从业者工具之所以排第一，不是因为天花板最大，而是因为它最容易触达真实人、验证付费、让用户走出房间。第一版不接支付、不接 API、不做复杂网站，只做网页或 Markdown 模板，按钮复制 prompt，手动丢给大模型生成。

第一天交付三个样例：

1. 新疆 7 天小团路线生成。
2. 周末徒步活动路线生成。
3. 客户咨询到成交的话术生成。

第二天拿给旅游朋友问三件事：有没有用、哪个输出最有价值、是否愿意为模板或定制付费。创业方式要从“做一个大作品”切到“连续做小验证”。
