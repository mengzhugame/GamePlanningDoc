# 产品矩阵与目录资产

独立工作室真正的商业模式不是做一款卖一波，而是让下一款比上一款更容易卖。

---

## 工作室品牌四层

| 层 | 问题 |
|----|------|
| 母品牌承诺 | 我们持续提供哪类体验？ |
| 产品线 | 围绕哪个主题、情绪、用户群扩同心圆？ |
| 识别体系 | 机制、视觉、情绪、社区、商业是否可识别？ |
| 目录飞轮 | 旧作能否养新作，新作能否抬旧作？ |

当前阶段不急着做品牌口号，但每个项目都要留下可复用资产。

---

## 产品线三层

| 产品线 | 用途 | 当前建议 |
|--------|------|----------|
| 旗舰线 | 代表工作室能力，立口碑 | 还不到阶段，先别重押 |
| 实验线 | 低成本测试机制 / 题材 / 商业化 | 当前主线 |
| 衍生线 | 围绕已验证玩法或世界观做轻量扩展 | 有成功单品后再做 |

---

## 三种矩阵打法

| 打法 | 适合 | 风险 |
|------|------|------|
| 单机制多表达 | 找到特别能打的核心机制 | 容易重复 |
| 同审美 / 同情绪多品类 | 美术气质或世界观强 | 玩法质量不稳会空心 |
| 同用户群多价格带 | 已知核心玩家是谁 | 产品太散会失焦 |

当前最适合：**单机制多表达 + 同生产线复用**。

---

## 项目组合漏斗

```
信号池：AI 视频 / 榜单 / 评论 / 竞品 / 用户痛点
-> 概念筛：一句话钩子 / 3 秒爽点 / 7 天可测 / 生产优势 / 资产复用
-> 原型闸：首爽点秒数 / 首败可复述 / 想再来一局
-> 市场闸：点击 / 下载 / 愿望单 / 留存 / 预约 / 评论
-> 加码层：完整内容 / 买量 / 发行 / 团队 / 平台扩展
```

任何方向 2 项答不上，不立项。

---

## 70/20/10

资源分配建议：

- 70%：已验证主线项目。
- 20%：近邻变体，同受众、同生产线、不同表达。
- 10%：高风险新切口，仅限视频和概念验证。

当前如果没有已验证主线，70% 应投入“方法验证系统”，不是投入单个灵感。

---

## 目录现金流飞轮

```
首发建立种子盘
-> 更新制造二次峰值
-> 折扣触发回流
-> DLC / soundtrack / supporter pack 拉客单
-> 老作给新作导流
```

小游戏同样适用，只是表达变为：

```
首款验证用户和素材
-> 版本更新召回
-> 新玩法 / 新题材复用代码
-> 用户池给下一款冷启动
-> 发行和平台关系复用
```

---

## 每个项目必须沉淀

- 核心机制模板。
- UI / SDK / 广告 / 数据埋点模板。
- 可播素材经验。
- 测试用户池。
- 发行反馈。
- 失败原因。
- 可复用美术 / Shader / VFX。

没有沉淀的项目，是一次性消耗。

## AI 原生目录资产补丁

AI 原生游戏工作室的目录资产不只是代码和美术，还包括能让下一轮验证更快、更准的上下文。

每个项目额外沉淀：

- 玩家欲望假设与反证记录。
- 竞品评论挖掘、玩家原话和高信号评论。
- AI 概念视频脚本、关键帧提示词、发布标题和复盘结论。
- `AI_CONTEXT.md`：范围、架构、命名、数据、广告、存档和美术约束。
- Demo 指标框架、假阳性清单和 72 小时判断口径。
- 发行沟通 FAQ、素材包结构和数据摘要模板。

目标是让下一款游戏少从空白开始，而是从一套更会提问、更会验证、更会复用的系统开始。

## 定价与平台注意

Steam 买断制要预留折扣空间、区域定价、愿望单通知和目录节奏。

微信 / 抖音小游戏优先看留存、广告观看和回收模型。

不要把纯 IAA 广告小游戏直接搬到 Steam。Steam 更适合用商店页、Demo 和愿望单验证“值得买”，不是验证广告变现。
