# 产品矩阵与目录资产

独立工作室真正的商业模式不是做一款卖一波，而是让下一款比上一款更容易卖。

---

## 工作室品牌四层

| 层 | 问题 |
|----|------|
| 母品牌承诺 | 我们持续提供哪类体验？ |
| 产品线 | 围绕哪个主题、情绪、用户群扩同心圆？ |
| 识别体系 | 机制、视觉、情绪、社区、商业是否可识别？ |
| 目录飞轮 | 旧作能否养新作，新作能否抬旧作？ |

当前阶段不急着做品牌口号，但每个项目都要留下可复用资产。

---

## 产品线三层

| 产品线 | 用途 | 当前建议 |
|--------|------|----------|
| 旗舰线 | 代表工作室能力，立口碑 | 还不到阶段，先别重押 |
| 实验线 | 低成本测试机制 / 题材 / 商业化 | 当前主线 |
| 衍生线 | 围绕已验证玩法或世界观做轻量扩展 | 有成功单品后再做 |

---

## 三种矩阵打法

| 打法 | 适合 | 风险 |
|------|------|------|
| 单机制多表达 | 找到特别能打的核心机制 | 容易重复 |
| 同审美 / 同情绪多品类 | 美术气质或世界观强 | 玩法质量不稳会空心 |
| 同用户群多价格带 | 已知核心玩家是谁 | 产品太散会失焦 |

当前最适合：**单机制多表达 + 同生产线复用**。

---

## 项目组合漏斗

```
信号池：AI 视频 / 榜单 / 评论 / 竞品 / 用户痛点
-> 概念筛：一句话钩子 / 3 秒爽点 / 7 天可测 / 生产优势 / 资产复用
-> 原型闸：首爽点秒数 / 首败可复述 / 想再来一局
-> 市场闸：点击 / 下载 / 愿望单 / 留存 / 预约 / 评论
-> 加码层：完整内容 / 买量 / 发行 / 团队 / 平台扩展
```

任何方向 2 项答不上，不立项。

---

## 70/20/10

资源分配建议：

- 70%：已验证主线项目。
- 20%：近邻变体，同受众、同生产线、不同表达。
- 10%：高风险新切口，仅限视频和概念验证。

当前如果没有已验证主线，70% 应投入“方法验证系统”，不是投入单个灵感。

---

## 目录现金流飞轮

```
首发建立种子盘
-> 更新制造二次峰值
-> 折扣触发回流
-> DLC / soundtrack / supporter pack 拉客单
-> 老作给新作导流
```

小游戏同样适用，只是表达变为：

```
首款验证用户和素材
-> 版本更新召回
-> 新玩法 / 新题材复用代码
-> 用户池给下一款冷启动
-> 发行和平台关系复用
```

---

## 每个项目必须沉淀

- 核心机制模板。
- UI / SDK / 广告 / 数据埋点模板。
- 可播素材经验。
- 测试用户池。
- 发行反馈。
- 失败原因。
- 可复用美术 / Shader / VFX。

没有沉淀的项目，是一次性消耗。

## AI 原生目录资产补丁

AI 原生游戏工作室的目录资产不只是代码和美术，还包括能让下一轮验证更快、更准的上下文。

每个项目额外沉淀：

- 玩家欲望假设与反证记录。
- 竞品评论挖掘、玩家原话和高信号评论。
- AI 概念视频脚本、关键帧提示词、发布标题和复盘结论。
- `AI_CONTEXT.md`：范围、架构、命名、数据、广告、存档和美术约束。
- Demo 指标框架、假阳性清单和 72 小时判断口径。
- 发行沟通 FAQ、素材包结构和数据摘要模板。

目标是让下一款游戏少从空白开始，而是从一套更会提问、更会验证、更会复用的系统开始。

## 定价与平台注意

Steam 买断制要预留折扣空间、区域定价、愿望单通知和目录节奏。

微信 / 抖音小游戏优先看留存、广告观看和回收模型。

不要把纯 IAA 广告小游戏直接搬到 Steam。Steam 更适合用商店页、Demo 和愿望单验证“值得买”，不是验证广告变现。

## 矩阵化不是多开项目，而是围绕已验证能力螺旋上升

三七互娱小游戏矩阵的可借鉴点，不是“大公司一年做很多爆款”，而是它的顺序：先在一个玩法上纵向深挖，再把成熟经验横向迁移到新题材、新深度和新品类。

对个人工作室，矩阵化应该被降维成三层：

| 层级 | 小团队版本 |
| --- | --- |
| 纵向深挖 | 同一核心机制做 2-3 个不同题材、难度或时长切片 |
| 横向拓展 | 只迁移已经证明有效的广告点、UI、关卡编辑器、素材模板 |
| 联动续命 | 先做内容更新和小活动，不幻想大 IP 联动 |

没有已验证单品时，不要谈产品矩阵。此时真正的矩阵资产是验证流程、代码模板、买量素材复盘和用户池。

## 每个新品要解决前作的一个明确问题

三七矩阵的关键词是“螺旋上升”，不是简单复刻。每个新品如果都只是换皮，会快速稀释用户和团队注意力；更稳的做法是让下一款回答前作暴露出的一个问题：

| 前作问题 | 下一款可以验证 |
| --- | --- |
| 前期目标单一 | 加密集任务链或副本调剂 |
| 长线不足 | 加外层经营、联动或赛季 |
| 买量成本高 | 换更易播的前菜题材 |
| 社交压力过重 | 做个人专属资源和弱竞争 |
| 关卡产能不足 | 做规则变体和编辑器 |

这和当前个人路线一致：不是同时做很多游戏，而是每轮切片都带回一个可复用资产和一个被验证或证伪的假设。

## 失败项目可以回收，但不能裸卖控制权

失败项目不是废物，可以拆成模板、资源包、教学包和复盘资产继续回血。但底线是：不能用微信转账、无合同、裸发完整工程的方式，把项目控制权交给一个明确要商用投流的人。

正确区分：

| 模式 | 可以做吗 | 边界 |
| --- | --- | --- |
| 学习参考版 | 可以 | 脱敏工程 / 文档，非商用、不可上架、不可转售、无技术支持 |
| 非独占商用模板授权 | 可以 | 可改名、换素材、接广告、上架买家账号；不得转售源码、冒用作者、使用原项目名和账号资料 |
| 完整买断 / 独占 / 可转售源码 | 不建议 | 真要做必须合同、显著更高价格、一次性付清 |

价格口径可以从低到高分层：

- 学习参考版：499-999。
- 非独占商用模板授权：1000-3000 / 款起。
- 两款打包商用授权：3000-6000 起。
- 买断、独占、可转售源码：至少上万起，且必须合同。

模板包产品化清单：

1. 脱敏工程：删 AppID、广告位、密钥、证书、后台、埋点、账号信息。
2. 换名：不用《美妆叠叠乐》《光与朽》原名，改成品类模板名。
3. 写 `授权说明.txt`：非独占、可商用、不可转售源码、不可冒用作者、无买断。
4. 写 `接入说明.md`：如何换图、改关卡、接广告。
5. 保留证据：Git 记录、打包日期、压缩包 hash、聊天确认、转账备注。
6. 明确售后：只含有限答疑，不含定制修改。

这个模式可以成为“失败项目资产回收机制”，但不能成为“为了卖 1000-2000 元源码而做小游戏”的主业。最健康的顺序是：本来就要做 7-10 天验证切片；成功就自己运营或找发行，失败就包装成模板包回血。

## 项目组合管理不是多开坑，而是剥夺弱方向资源

每日洞察里关于工作室品牌、目录资产和项目组合的共同结论是：小团队不能把“多个方向都有点想法”误读成产品矩阵。真正的矩阵必须从已验证能力上长出来。

当前更适合的组合逻辑：

| 轨道 | 作用 | 资源规则 |
| --- | --- | --- |
| 复盘资产轨 | 从《光与朽》等已上线项目榨留存、IAA、失败教训和模板 | 不继续情绪性加码 |
| 7 天切片轨 | 同时测 2-3 个低成本方向的钩子、首爽点和陌生反馈 | 连续两轮弱信号就 Kill |
| 方法资产轨 | 素材脚本、AI 上下文、代码模板、买量记录、用户池 | 每轮失败也必须留下复利资产 |

每个新品或切片都要回答前作暴露出的一个明确问题，例如买量钩子不够强、首局太慢、题材不可复述、广告点太晚、长线不足或素材不易播。不能只换皮再赌一轮。

项目组合周复盘只问四件事：

1. 哪个方向给了最清楚的外部信号？
2. 哪个方向正在消耗时间却没有带回证据？
3. 哪个失败留下了可复用资产？
4. 下周应该把资源从哪个方向拿走，给哪个方向？

目录资产的本质不是数量，而是让下一次验证更便宜、更快、更硬。

## 旧项目清单要改造成资产地图，而不是愿望池

旧项目汇总同时列了《光与朽》《美妆叠叠乐》、塔防储备、超休闲创意和个人 IP 计划。它的长期价值不是证明“手里有很多项目”，而是帮助判断每个项目还能留下哪类资产。

| 项目/方向 | 可回收资产 | 不应继续误读 |
| --- | --- | --- |
| 《光与朽》 | 激光 TA 表现、完整上线链路、发行拒绝与反馈素材、塔防肉鸽经验 | 不等于当前还值得继续重投入 |
| 《美妆叠叠乐》 | 女性向题材经验、订单/收纳/收藏馆思路、失败留存复盘 | 不等于女性向叠放方向被证明成立 |
| 塔防储备 | 元素克制、营地、合成、非固定路线等机制积木 | 不等于可以多开塔防项目 |
| 超休闲创意池 | 画线、圈地、金币倍增、液压解压等低成本钩子 | 不等于每个点子都要进原型 |
| 个人 IP 计划 | 被拒、听劝、上线、数据复盘的内容结构 | 不等于内容号可以脱离产品验证 |

下一轮使用项目清单时，先给每项打三类标签：

1. 已验证资产：代码、素材、埋点、广告点、内容故事、玩家反馈。
2. 未验证假设：题材、核心动词、商业化、平台适配。
3. 禁止加码原因：留存差、差异不够、买量弱、产能不匹配。

只有“已验证资产”能进入产品矩阵；“未验证假设”只能进入概念卡或 7 天切片；“禁止加码原因”要写进下一项目避坑清单。
