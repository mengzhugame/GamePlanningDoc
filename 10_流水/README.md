# 10_流水/ — 每日 append-only 流水层 + 蒸馏入口

## 这是什么

**两个职责合一**：
1. **流水层**（设计本意）：每天一个 `YYYY-MM-DD.md`，临时灵感 / AI 对话 key insight / 调试现象 / 数值实验都先写这里，不分类、不修改历史、不追求结构
2. **蒸馏入口**（实际承担）：跟不同 AI 的对话原稿、旧 Openclaw 知识库、游戏拆解等历史沉淀**也临时落在这里**，等待 `/distill` 蒸馏到对应主题目录

## 命名约定

- 日记流水：`YYYY-MM-DD.md`（按月归到 `YYYY-MM/` 子目录）
- AI 对话：`<平台>_<主题>_<日期>.md` 落到对应子目录（`光与朽项目/`、`美妆叠叠乐项目/`、`历史聊天/`）
- 文件顶部建议加 frontmatter：`date`、`type: daily-log | ai-conversation | analysis | implementation` 等

## 蒸馏流水线

每次执行 `/distill` 会按下面流程走（完整定义见 `90_系统/skills/skill-distill.md`）：

```
[阶段 1] 扫 10_流水/ 下未入表文件 → 加入 蒸馏批次记录.md 状态=未蒸馏
[阶段 2] 挑 5 个未蒸馏文件（默认日期最旧优先）
[阶段 3] AI 自主判断每个文件该追加/新建到哪个目标目录的哪个文件，直接做：
         - 50_商业/、70_用户信息/、40_知识/、20_项目/0N_XX/、30_市场分析/
         - 优先追加到已有主题文件，标「来源: 流水原文件路径 · 提取日期」
         - 必要时新建
         - 一个流水文件可能拆到多个目标
[阶段 4] 思维盲区 / 反复纠结 / 未落地建议 → 追加到 70_用户信息/思维盲区与提升点.md
[阶段 5] 末尾总报：本批蒸了哪些 / 去了哪里 / 进度百分比 / 下批建议优先
         原文 mv 到 10_流水/已蒸馏文件/<原相对路径>/
```

每批默认 5 个，可在调用时覆盖。

## 关键文件

| 路径 | 干什么 |
|------|--------|
| `蒸馏批次记录.md` | **核心**：所有文件的蒸馏状态账本（257 行清单） |
| `已蒸馏文件/` | 蒸馏过的原文归档目录，按原相对路径保留 |

| `历史聊天/` | 所有平台跨项目的历史 AI 对话原稿（蒸馏中） |
| `游戏拆解/` | 50 份游戏拆解原稿（蒸馏到 40_知识/07_游戏拆解库/） |

## 什么东西该写进 10_流水/

- 临时灵感、设计念头（哪怕只有一句话） → 当天 `YYYY-MM-DD.md`
- 读到一篇文章的笔记摘录 → 当天 `YYYY-MM-DD.md`
- 跟 AI 对话中冒出的 key insight → 当天 `YYYY-MM-DD.md`
- 调试过程中的奇怪现象 → 当天 `YYYY-MM-DD.md`
- 某个数值试出来的结果 → 当天 `YYYY-MM-DD.md`
- AI 对话原稿临时存放 → `<项目目录>/<平台>_<主题>_<日期>.md`（等蒸馏）

## 什么东西**不**写这里

- 项目正式文档（写进 `20_项目/NN_XX/`）
- 已经沉淀好的知识条目（写进 `40_知识/`）
- 行业调研、竞品动态、用户痛点等外部资料（先进 `30_市场分析/`）
- 用户画像 / 思维盲区（写进 `70_用户信息/`）

## 为什么这么设计

人写东西分两种状态：**涌现** 和 **整理**。混在一起做两件事会互相打架——整理时总想回头改涌现的原话，涌现时又受格式约束不敢写脏。分开后，流水层负责接住所有原始素材不丢失，蒸馏层负责做结构化的二次加工。

**蒸馏不是丢掉，是把价值合并进主题文件**。下次跟新 AI 聊商业，直接让 AI 读 `50_商业/` + `70_用户信息/`，背景就齐了——不用再从零讲一遍美妆叠叠乐为啥失败、光与朽的当前判断、公司化 vs 独立的纠结点。

## 蒸馏 5 阶段工作流（详细版）

> 完整 skill 定义见 `90_系统/skills/skill-distill.md`。这里给你一个**可以直接走的流程清单**。

### 阶段 1：扫表（新文件入表）

- AI 用 glob 扫 `10_流水/**/*.md`，排除 `已蒸馏文件/`、`蒸馏批次记录.md`、`README.md`
- 对照 `蒸馏批次记录.md` 找未入表文件
- 每个新文件：读首 30 行 + 文件名 + 子目录 → 判断 **类型** + 一句话 **主题摘要** → 追加到记录表，状态填 `未蒸馏`
- 报告：「新入表 N 个，总未蒸馏 M 个」

### 阶段 2：挑批

- 从 `状态: 未蒸馏` 中选 N 个（默认 5，可调用时覆盖）
- 选择策略：**按日期最旧优先** 或 **按主题/项目优先**（你可以指定，例如本次 B-001 就是"商业/创业/战略"主题优先）
- 标记 `状态: 蒸馏中`

### 阶段 3：蒸馏（每个文件）

- 完整读文件内容（大文件分段读）
- 价值评估：没价值 → `状态: 无价值删除` + 备注原因 + 跳过
- **提炼有价值片段** → 匹配目标目录的目标文件：
  - 优先 **追加到已有主题文件**（避免主题碎片化）
  - 已有文件 → `append` 一段，加 markdown 二级标题 `## 来源: <原相对路径> · 提取日期 YYYY-MM-DD`
  - 文件不存在 → 新建，按目标目录现有命名约定
  - **一个流水文件可能拆到多个目标文件**
- 直接执行写入（不需要先报告等审核）
- 填记录表：沉淀去向（多路径逗号分隔）+ 批次 + 蒸馏日期 + 状态 → `已蒸馏`
- 原文 `mv` 到 `10_流水/已蒸馏文件/<原相对路径>/`

### 阶段 4：诊断反馈累积

- 蒸馏过程中持续扫描：**反复出现的纠结点 / 思维盲区 / 未落地的好建议**
- 门槛：**同一类盲区出现 ≥ 2 次** 才入表
- 追加到 `70_用户信息/思维盲区与提升点.md`，按字段填（编号 / 类型 / 标题 / 频次 / 首次发现 / 最近出现 / 建议处理 / 状态）

### 阶段 5：本批总报

完成 N 个后给你：

```
本批蒸馏总结（批次 B-NNN，2026-MM-DD）

蒸了 N 个文件：
  1. <路径> → 沉淀到 [目标文件们]
  2. <路径> → 沉淀到 [目标文件们]
  ...

新增了 X 个目标文件 / 扩充了 Y 个已有文件

思维盲区：本批 flag 了 K 条新条目到 70_用户信息/思维盲区与提升点.md

进度：已蒸馏 X / 总数 257 (X%)
下一批建议优先：<主题/项目>
```

## 调用方式（怎么让 AI 帮你蒸馏）

### 方式 1：默认批次

直接说：「跑一次 /distill」 或 「`/distill 5`」（指定批次数量）

AI 会按 5 阶段流程跑，默认按**日期最旧优先**挑 5 个文件。

### 方式 2：主题批次（推荐）

指定主题：

- 「先把聊天记录中所有关于商业和创业、战略等聊天文件全部蒸馏」 → 本次 B-001 用的就是这种
- 「先蒸馏所有光与朽项目的 AI 对话」
- 「先蒸馏 2026-04 月的日记流水」
- 「先把游戏拆解 50 个文件蒸馏完」

AI 会从记录表筛选符合主题的全部 `未蒸馏` 文件，**不受 5 个上限**（用户主题指令优先于默认数量）。

### 方式 3：按项目批次

指定项目：

- 「蒸馏所有美妆叠叠乐相关」
- 「蒸馏所有 Openclaw 知识库文件」

## 本流程的核心纪律

1. **直接追加到已有主题文件优先**，不要每次新建（避免主题碎片化）
2. **每次追加都标「来源: 流水原文件路径 · 提取日期」**，保持可追溯
3. **流水原文不删，移到 `已蒸馏文件/<原相对路径>/`**（保留子目录结构便于反查）
4. **诊断反馈集中到一份**：`70_用户信息/思维盲区与提升点.md`
5. **AI 自主判断去向**，蒸馏完末尾总报告，不每个文件停下来等审核
6. **「无价值删除」也要在记录表里留一行**（path / 类型 / 摘要 / 状态=无价值删除 / 原因）
7. **大文件（>1000 行）分段读**，重点蒸馏前段；后段读完后状态保持 `未蒸馏` 等下批继续
8. **重复内容去重**：写入前 grep 目标文件检查是否已有相同内容来源
