# 30_市场分析

## 这是什么

这里存放每周或每月收集的游戏行业简报、市场数据、用户痛点、竞品动态、平台趋势和买量观察。

## 现在的定位

旧情报采集系统已退役。以后这里不再存放旧系统目录、记忆、wiki 或自动生成文件。市场信息可以由用户、Claude Code 或 Codex 手动/定期收集后放入这里。

## 推荐结构

| 类型 | 建议文件名 |
|------|------------|
| 索引 | `00_市场分析索引.md` |
| 行业周报 | `YYYY-WNN_游戏行业周报.md` |
| 行业月报 | `YYYY-MM_游戏行业月报.md` |
| 用户痛点扫描 | `YYYY-MM-DD_用户痛点扫描.md` |
| 竞品趋势 | `YYYY-MM-DD_竞品趋势_主题.md` |
| 平台数据截图/原始材料 | 放在日期目录下，并在 README 或索引中说明来源 |
| 模板 | `TEMPLATE_市场周报.md`、`TEMPLATE_用户痛点扫描.md` |

## 使用规则

- 这里是原始情报层，不直接当作最终结论。
- 有价值的洞察需要后续沉淀到 `40_知识/`。
- 游戏拆解类内容最终进入 `40_知识/07_游戏拆解库/`。
- 买量、发行、上线数据相关结论最终进入 `40_知识/06_发行与运营/`。

## 市场情报必须写清“怎么使用”

旧 OpenClaw 情报闭环的长期价值不是旧路径，而是反噪音字段。任何新市场材料进入 `30_市场分析/` 时，至少要能回答：

| 字段 | 作用 |
| --- | --- |
| source_url | 原始来源，无法提供则说明原因 |
| topic_hint | 建议归属主题，如买量、立项、素材、平台规则 |
| evidence_type | 行业数据、竞品案例、素材样本、平台规则、工具方法、个人观察 |
| decision_relevance | 能辅助哪个决策：立项、买量、素材、IAA、软著、发行合作 |
| actionability | high / medium / low |
| distill_priority | P0 / P1 / P2 / archive |
| next_use | 下一步怎么用：进入概念池、等待蒸馏、只作背景观察 |

如果一条材料无法填写这些字段，就先降级为背景观察，不要进入高优先级扫描。市场情报的价值不在“我看到了什么”，而在“它能帮我更快做出哪个决策”。

小游戏视频雷达额外记录：核心动词、视觉风格、爽点来源、是否像真实游戏、评论里是否有人问在哪玩、是否适合 TA 能力实现、是否适合 7 天切片。最终给 Top 候选，不直接给立项结论。
